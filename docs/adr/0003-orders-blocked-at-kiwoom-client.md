# 실전 주문은 KiwoomClient의 관문 한 곳에서 막는다

투자 환경마다 "주문 허용" 스위치를 하나 두고(`config.py`), 스위치가 꺼진 환경에서 돈이 움직이는 TR은 `KiwoomClient`가 키움에 보내기 직전에 막는다. 주문·취소·자동 매도 코드는 실전 여부를 따로 검사하지 않는다.

예전에는 주문·취소·자동 매도가 각자 `is_real`을 검사했다. 새 주문 기능에서 검사 하나를 빠뜨리면 실전 주문이 나갈 수 있었고, 실전을 열려면 흩어진 검사를 모두 찾아야 했다. 모든 키움 요청이 지나는 한 곳에서 막으면 빠뜨릴 길이 없고, 여는 곳도 스위치 하나다.

검토한 대안:
- 관문을 두고 위쪽 검사도 남긴다. 안전은 같지만, 실전을 열 때 고칠 곳이 다시 여러 곳이 된다.
- 주소(`/ordr`, `/crdordr`, `/exchange`)로 막는다. 같은 주소에 조회 TR이 섞여 있어 실전 조회까지 막힌다.
- 실전에서 허용할 TR만 적는다. 조회 기능을 만들 때마다 목록에 넣어야 하고, 빠뜨리면 실전에서 처음 쓸 때에야 드러난다.

## Consequences

- 막을 TR 목록(`MONEY_MOVING_TR_IDS`)은 키움 문서에서 뽑은 고정 목록이다. 키움이 돈이 움직이는 TR을 새로 내면 이 목록에 더해야 한다.
- 실전에서 API를 직접 부르면 입력 검사와 잔고·미체결 재확인(조회)이 관문보다 먼저 일어난다. 화면은 실전에서 주문 버튼을 막으므로 사용자에게는 차이가 없다.
- 화면 규칙(SL / TP 켜기, 미체결 취소 표시, 주문 버튼)은 막는 역할이 아니라 보여주는 역할이다. 같은 스위치를 읽으므로 스위치를 켜면 함께 열린다.
- 스위치는 지금 코드 값이다. 실전을 열 때 `.env`로 옮긴다.
