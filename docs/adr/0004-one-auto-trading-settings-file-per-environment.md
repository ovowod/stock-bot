# 자동매매 설정은 투자 환경마다 파일 하나에 기능별 칸으로 모은다

투자 환경마다 `data/auto-trading/<환경>.json` 파일 하나에 SL / TP(`sl_tp`), Trailing Stop(`trailing_stop`) 같은 자동매매 기능의 설정을 칸으로 나눠 담는다. 저장은 기능 화면마다 따로 하며, 한 기능의 저장은 다른 칸을 바꾸지 않는다. 기능이 늘어도 한 환경의 자동매매 설정을 파일 하나에서 보고 백업할 수 있게 하려는 것이다.

검토한 대안:
- 기능마다 폴더를 따로 둔다(`data/sl-tp/`, `data/trailing-stop/`). 서로 영향은 없지만, 기능이 늘수록 한 환경의 설정이 여러 곳에 흩어진다.
- 파일 하나를 통째로 저장한다. 기능마다 화면이 따로라, 한 화면의 저장이 다른 화면에서 저장하지 않은 변경과 섞인다.

## Consequences

- 한 칸이라도 깨지면 파일 전체를 읽지 못한 것으로 본다. 그 환경의 모든 자동매매 기능 화면과 저장이 막힌다. 깨진 칸을 보존한 채 다른 칸만 다시 쓰는 일을 피하려는 것이다.
- 파일에 없는 칸은 빈 설정으로 본다. 그래서 기능을 더할 때 파일 버전(2)을 올리지 않아도 된다.
- 예전 `data/sl-tp/<환경>.json`(version 1)은 서버가 시작할 때 한 번 옮긴다. 원본은 지우지 않지만 더는 읽지 않는다. 옮기지 못하면 서버가 시작하지 않는다. SL / TP 설정이 빈 설정으로 조용히 바뀌는 것을 막기 위해서다.
- 저장은 파일을 읽어 자기 칸만 바꾼 뒤 파일 전체를 다시 쓴다. 이 과정에 await가 없어서, 두 기능의 저장이 서로 섞이지 않는다.
