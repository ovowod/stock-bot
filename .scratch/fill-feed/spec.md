# 체결 feed

Status: ready-for-agent

## Problem Statement

체결 알림과 SL / TP는 둘 다 내 계좌의 체결을 실시간으로 받아야 한다. 키움은 이 체결을 국내는 `00`, 미국은 `F5` 실시간 항목으로 보낸다. 지금은 두 기능이 이 항목을 각자 다룬다.
- 투자 환경에 맞는 항목 고르기
- 등록이 거부됐을 때 다시 시도하기
- 주문상태 가운데 체결만 남기기

같은 항목을 키움에 두 번 등록하지 않으려고 공유 실시간 연결에 "함께 받기" 장치를 따로 만들었다. 이 장치는 두 기능만 쓰는데도 공유 연결 코드의 큰 부분을 차지한다.

두 기능이 따로 움직여서 사용자에게도 차이가 드러난다.
- 등록이 거부되면 체결 알림은 스스로 계속 다시 시도한다. SL / TP는 판정을 멈추고, 다음 SL/TP 세션이 시작되거나 감시 종목이 바뀔 때에만 다시 시도한다.
- 그래서 Discord 알림이 꺼져 있을 때 체결 등록이 한 번 거부되면, SL / TP 판정이 그 세션 끝까지 멈춰 있을 수 있다.

체결을 다루는 규칙(체결로 치는 주문상태, 거부 시 다시 시도, 등록 단위)을 바꾸려면 세 곳을 함께 고쳐야 하고, 고칠 때마다 두 기능이 서로 어긋날 위험이 있다.

## Solution

내 계좌의 체결을 받는 일을 **체결 feed** 한 곳에 모은다.

체결 feed가 맡는 일:
- 투자 환경별로 `00`/`F5`를 등록한다.
- 거부되면 다시 시도한다.
- 체결로 치는 주문상태만 남긴다.
- 체결 이벤트를 읽기 쉬운 체결 하나로 바꾼다.
- 체결을 신청한 기능에 그 체결과 등록 상태(받는 중 / 거부됨)를 넘긴다.

체결 알림과 SL / TP는 "이 투자 환경의 체결을 달라"고 신청만 한다. 공유 실시간 연결의 "함께 받기" 장치는 없앤다.

사용자 입장에서 바뀌는 것은 셋뿐이다.
1. 체결 등록이 거부되면 SL / TP도 체결 알림처럼 스스로 다시 시도한다. 등록되면 거부된 동안의 체결을 반영하려고 보유종목을 다시 읽은 뒤 판정을 다시 시작한다. 판정 중단 알림 문구도 이에 맞게 바뀐다.
2. 내 계좌 체결을 받으면 SL / TP는 그 즉시 판정을 멈춘다. 같은 메시지나 그 뒤에 온 시세 체결은 바뀐 매입가를 반영한 뒤에만 판정한다. 이 순서는 지금도 지켜지고 있으며, 구조를 바꾼 뒤에도 그대로 지킨다.
3. 체결이 오기 전에 이미 받아서 처리를 기다리던 시세 체결도, 보유종목을 다시 읽는 동안에는 판정하지 않고 건너뛴다.

체결 알림의 내용, 키움에 보내는 등록 메시지, 실시간 연결 동작은 바뀌지 않는다.

## User Stories

**체결 받기**

1. As a 투자자, I want 체결 알림과 SL / TP가 같은 규칙으로 체결을 알아보기를, so that 한 기능은 체결로 보고 다른 기능은 무시하는 일이 없다.
2. As a 투자자, I want 국내는 주문상태 "체결", 미국은 "부분체결"·"체결완료"만 체결로 치기를, so that 접수·확인·취소·거부 이벤트로 알림이 가거나 보유종목을 다시 읽지 않는다.
3. As a 투자자, I want 앱 밖(MTS·HTS)에서 낸 주문의 체결도 지금처럼 체결 알림과 SL / TP에 들어오기를, so that 어디서 주문했든 똑같이 반영된다.
4. As a 투자자, I want 국내 실전과 미국 실전의 체결이 한 실시간 연결로 와도 투자 환경별로 나뉘어 처리되기를, so that 미국 체결이 국내 체결로 알려지지 않는다.
5. As a 투자자, I want 같은 체결 항목이 키움에 한 번만 등록되기를, so that 같은 체결로 알림이 두 번 가지 않는다.
6. As a 투자자, I want 체결 이벤트에서 읽지 못한 값이 있어도 읽은 값으로는 계속 처리되기를, so that 값 하나 때문에 체결 알림이나 SL / TP의 다시 읽기를 놓치지 않는다.
7. As a 투자자, I want 한 메시지에 체결이 여러 개 오면, 하나를 처리하다 오류가 나도 나머지는 처리되기를, so that 한 체결 때문에 다른 체결을 잃지 않는다.

**등록과 해지**

8. As a 투자자, I want Discord 알림이 켜져 있으면 인증정보가 있는 모든 투자 환경의 체결이 늘 등록되어 있기를, so that 체결 알림이 지금처럼 동작한다.
9. As a 투자자, I want Discord 알림이 꺼져 있으면 체결이 켜진 SL/TP 세션 동안만 등록되기를, so that 필요 없을 때 실시간 연결을 열어 두지 않는다.
10. As a 투자자, I want 아무 기능도 체결을 신청하지 않으면 체결 등록을 해지하고, 다른 구독도 없으면 실시간 연결을 닫기를, so that 같은 앱 키를 쓰는 다른 서버를 끊어 내지 않는다(ADR 0001).
11. As a 투자자, I want 실전 연결에서 국내 실전만 신청되면 `00`만, 미국 실전까지 신청되면 `00`과 `F5`를 한 번에 등록하기를, so that 필요한 항목만 받는다.
12. As a 투자자, I want 다시 연결되면 체결 등록도 다른 구독과 함께 다시 되기를, so that 재연결 뒤에도 체결을 받는다.
13. As a 투자자, I want 끊긴 동안의 체결은 지금처럼 보충하지 않기를, so that 동작이 바뀌지 않는다.

**거부와 다시 시도**

14. As a 투자자, I want 체결 등록이 거부되면 체결 feed가 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 시도하기를, so that 일시적인 거부가 저절로 풀린다.
15. As a 투자자, I want 재연결로 먼저 등록되면 기다리던 재시도는 보내지 않기를, so that 같은 등록을 겹쳐 보내지 않는다.
16. As a 투자자, I want 등록에 성공하면 다시 시도 간격이 처음으로 돌아가기를, so that 다음 거부 때 오래 기다리지 않는다.
17. As a 투자자, I want 체결 등록이 거부된 동안 SL / TP가 판정을 멈추기를, so that 바뀐 매입가를 모르는 채 자동 매도를 내지 않는다.
18. As a 투자자, I want 체결 등록이 다시 되면 SL / TP가 보유종목을 다시 읽은 뒤 스스로 판정을 다시 시작하기를, so that Discord 알림이 꺼져 있어도 다음 세션까지 멈춰 있지 않고, 거부된 동안 바뀐 매입가로 판정하지도 않는다.
19. As a 투자자, I want 체결 등록 거부로 판정이 멈추면, 거부가 이어지는 동안 Discord 알림을 한 번만 받기를, so that 다시 시도할 때마다 알림이 쌓이지 않는다.
20. As a 투자자, I want 그 알림이 "자동으로 다시 시도한다"고 알려 주기를, so that 내가 무엇을 해야 하는지 헷갈리지 않는다.
21. As a 투자자, I want 등록에 성공했다가 다시 거부되거나 새 SL/TP 세션이 시작된 뒤 거부되면 다시 알림을 받기를, so that 새로 생긴 문제를 놓치지 않는다.
22. As a 투자자, I want 이미 거부된 상태에서 SL/TP 세션이 시작되면, 키움에 다시 등록하지 않고도 SL / TP가 바로 거부 상태를 알고 판정을 멈추기를, so that 거부된 줄 모르고 판정하지 않는다.

## Implementation Decisions

**체결 feed module**

- 새 module이다. 인증정보마다 공유 실시간 연결에 채널을 하나 열고, 그 채널로 `00`/`F5`를 등록한다.
- 그룹 번호는 지금처럼 `1`, item은 빈 값, refresh는 `1`이다. 키움에 보내는 REG·REMOVE의 모양과 시점은 지금과 같다. 단, 나중에 신청한 기능을 위해 REG를 다시 보내지는 않는다(아래 "상태").
- 투자 환경별 실시간 항목도 이 module에만 둔다(국내 모의 `00`, 미국 모의 `F5`, 국내 실전 `00`, 미국 실전 `F5`). 국내 실전과 미국 실전은 인증정보가 같아 한 연결, 한 등록에 함께 싣는다.
- 체결로 치는 주문상태(913)도 이 module에만 둔다. `00`은 "체결", `F5`는 "부분체결"·"체결완료"다. 그 밖의 상태는 DEBUG 로그만 남기고 버린다.

**신청과 해지**

- 기능은 투자 환경과 콜백 하나를 주고 신청한다. 신청 결과로 해지 수단을 받는다.
- 한 인증정보의 등록 항목은 그 인증정보에 걸린 신청들의 투자 환경 항목을 합친 것이다. 합친 항목이 바뀌면 다시 등록한다. 신청이 모두 빠지면 해지한다.
- 이 해지는 공유 연결의 "구독이 하나도 없으면 연결을 닫는다"는 규칙으로 이어진다.

**넘기는 것**

콜백은 두 가지를 받는다.

- **체결**: 지금 체결 알림이 쓰는 체결 값 전부와 이 체결의 맥락. 체결 알림과 SL / TP는 이것 말고 실시간 이벤트를 직접 보지 않는다.
  - 체결 값: 투자 환경, 시장, 종목코드, 종목명, 주문번호, 매수/매도, 이번 체결가·체결 수량, 주문 수량, 남은 수량, 체결 시각, 국내만 있는 누적 체결 수량·평균 체결가, 미국 매도만 있는 체결분 매입 금액
  - 맥락: 받은 연결 번호, 받은 시각(경과 시간 시계), 체결마다 새로 붙인 요청 ID
- **등록 상태**: "받는 중" 또는 "거부됨(키움의 return_code·return_msg)".

**상태**

- 체결 feed는 인증정보마다 마지막 등록 상태를 기억한다.
- 새로 신청한 기능에는 그 상태를 바로 알려 준다. 등록 결과를 아직 모르면 결과가 나올 때 알려 준다.
- 합친 항목이 바뀌어 다시 등록하면, 그 인증정보의 모든 신청에 새 결과를 알려 준다.
- 기억한 상태는 합친 항목이 바뀔 때, 연결이 끊길 때, 신청이 모두 빠질 때 "모름"으로 되돌린다. 그래서 새 항목이나 새 연결의 등록 결과가 나오기 전에 예전 "받는 중"을 알려 주지 않는다.
- 상태에 등록 버전 번호는 붙이지 않는다. 항목이 둘(`00`+`F5`)인 연결은 실전 연결뿐이고 거기에는 체결 알림만 두 항목을 한꺼번에 신청한다. 모의 연결은 항목이 하나라 합친 항목이 "없음"과 "하나" 사이로만 바뀐다. 그래서 앞선 등록의 늦은 결과를 새 항목의 결과로 착각할 경우가 없다.

**거부와 다시 시도**

- 거부되면 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 등록한다. 지금 체결 알림의 방식이다.
- 등록에 성공하면(재연결로 먼저 등록된 경우 포함) 기다리던 재시도를 취소하고 간격을 처음으로 돌린다.
- 신청이 모두 빠지면 재시도도 멈춘다.
- 밀려나 멈춘 연결에서는 다시 등록해도 연결을 열지 않는다. 이것도 지금과 같다.

**즉시 넘기기**

- 공유 실시간 연결에 대기열을 거치지 않는 받기 방식을 더한다. 메시지를 받는 즉시, 같은 메시지의 다른 항목이 다른 채널 대기열에서 처리되기 전에 handler를 부른다.
- 체결 feed는 이 방식으로 받아 체결로 읽고 신청한 콜백을 바로 부른다.
- 콜백은 기다리지 않고(동기) 빨리 끝나야 한다. 콜백에서 난 오류는 체결 feed가 잡아 로그로 남기고 다음 콜백과 다음 체결을 이어 처리한다.
- 다른 실시간 기능(SL / TP 시세 등)은 지금처럼 채널마다 대기열을 거친다.
- 이 결정은 ADR 0002로 남긴다. ADR은 티켓 03에서 쓴다.

**체결 알림**

- Discord 알림이 켜져 있으면 인증정보가 있는 투자 환경마다 신청한다.
- 콜백은 받은 체결을 자기 대기열에 넣기만 한다.
- 느린 일은 그 대기열에서 순서대로 한다: 자동 매도 맞춰 보기, 매도 손익 계산, 미체결 조회, Discord 전송.
- 미국 매도 손익을 위한 주문별 누적 체결 기억과 자동 매도 맞춰 보기는 체결 알림에 그대로 둔다. 체결 feed는 체결을 기억하지 않는다.
- 로그에는 체결 feed가 붙인 요청 ID를 이어 쓴다.

**SL / TP**

- 켜진 SL/TP 세션이 시작되면 그 투자 환경의 체결을 신청하고, 세션이 끝나면 해지한다.
- 체결 콜백은 지금 세션 실행이 있고 지금 연결의 체결일 때 보유종목 다시 읽기를 요청한다. 이 요청은 즉시 판정을 멈춘다.
- "거부됨"을 받으면 판정을 멈추고, 거부가 이어지는 동안 판정 중단 알림을 한 번 보낸다. 알림 문구는 "자동으로 다시 시도합니다"로 바꾼다.
- "받는 중"을 받으면 판정을 다시 시작할 수 있게 하고, 알림을 다시 보낼 수 있게 한다. 새 세션 실행이 시작될 때도 다시 알릴 수 있게 한다.
- 켜진 세션에서 "거부됨" 다음에 "받는 중"을 받으면 보유종목 다시 읽기를 요청한다. 거부된 동안의 체결을 받지 못했기 때문이다. 다시 읽은 결과가 반영될 때까지 판정하지 않는다.
- SL / TP가 체결을 받았다는 로그에는 체결 feed가 붙인 요청 ID를 남긴다. 여러 체결을 합친 보유종목 다시 읽기의 로그는 요청 ID와 잇지 않는다.
- SL / TP는 체결 등록을 직접 다시 시도하지 않는다. 세션 시작이나 감시 종목 변경 때 체결 등록을 다시 보내던 동작은 없앤다.
- 시세 구독(그룹 `2`)과 그 거부 처리, 연결 끊김·재연결·밀려남 처리는 SL / TP의 시세 채널에서 지금처럼 한다.

**공유 실시간 연결**

- "함께 받기" 장치를 없앤다: 채널의 함께 받기 등록, 연결 안의 대신 등록하는 채널, 등록 결과 전달, 합친 항목 계산.
- 체결 feed의 채널은 일반 구독으로 그룹 `1`을 등록한다. 그룹 `1`은 체결 feed, 그룹 `2`는 SL / TP 시세가 쓴다는 사실을 각 module 주석에 남겨 겹치지 않게 한다.
- 밀려남 중단 알림에 들어가는 기능 이름은 지금과 같아야 한다. 채널은 표시 문자열 하나가 아니라 기능 이름 목록을 가진다. 체결 feed 채널의 목록은 그 채널에 신청한 기능들(체결 감시, SL / TP)이다. 공유 연결은 모든 채널의 이름을 순서대로 모으며 겹치는 이름을 지운다. 그래서 SL / TP가 체결 feed와 시세 채널에 함께 있어도 한 번만 나온다.

**작업 나누기**

티켓 네 개로 나눈다. branch는 하나만 두고 티켓마다 커밋 하나를 쌓으며, PR은 마지막에 하나만 낸다.

1. 체결 feed를 만들고 체결 알림을 그 위로 옮긴다. 체결 알림 콜백은 처음부터 "자기 대기열에 넣기"로 만든다. 등록은 아직 "함께 받기"를 쓴다. SL / TP가 그룹 `1`을 함께 쓰고 있어서다. 동작 변화는 없다.
2. 공유 실시간 연결에 즉시 넘기기를 더하고, 체결 feed가 그 방식으로 받게 한다. 동작 변화는 없다.
3. SL / TP를 체결 feed 위로 옮기고 ADR 0002를 쓴다. 거부 처리 통일, 판정 순서, 먼저 받은 시세 체결 건너뛰기, 알림 문구 변경이 이 티켓에 있다. 동작 변화는 이 티켓에만 있다.
4. "함께 받기" 장치를 없애고, 체결 feed를 일반 구독으로 바꾼다. 키움에 보내는 메시지는 바뀌지 않는다.

## Testing Decisions

- **테스트 지점은 지금 쓰는 것 하나다.** 앱 전체를 띄우고 바깥 세 곳만 가짜로 바꾼다: 가짜 키움 실시간 서버, 가짜 키움 REST, 가짜 Discord. 체결 feed만 따로 시험하는 지점은 만들지 않는다.
- **좋은 테스트는 바깥에서 보이는 결과만 본다.** 키움에 보낸 REG·REMOVE, Discord로 간 알림 내용, 키움 REST로 나간 조회·주문, 로그 이벤트가 그 결과다. 체결 feed 안의 상태나 함수 호출 순서는 직접 보지 않는다.
- **티켓 01·02·04의 기준**: 체결 알림, 공유 실시간 연결, SL / TP의 기존 테스트가 그대로 통과한다. 옮겨 간 상수를 직접 쓰던 테스트는 import만 고친다. 기대값은 고치지 않는다.
- **티켓 03에서 바뀌는 기존 테스트**:
  - "체결 등록 거부 뒤 보유종목 변경 때 다시 등록한다" → "체결 feed가 스스로 다시 등록하고 판정이 다시 시작된다"
  - "거부된 등록에 함께 받기 시작할 때 REG를 다시 보내 결과를 받는다" → "REG를 다시 보내지 않고 기억된 거부 상태를 바로 받는다"
- **티켓 03의 새 테스트**:
  - 한 REAL 메시지에 내 계좌 체결과 시세 체결이 함께 오고, 그 시세 체결이 옛 매입가로는 기준을 넘는다. 이때 자동 매도가 나가지 않고, 보유종목을 다시 읽은 매입가로 판정한다.
  - 체결 알림의 처리가 느린 동안(Discord 응답 지연)에도 SL / TP가 체결을 받자마자 판정을 멈추고 다시 읽는다.
  - Discord 알림이 꺼진 상태에서 체결 등록이 거부된다. Discord 전송은 없고, 판정이 멈추며, 체결 feed가 다시 등록하고, 등록되면 판정이 다시 시작된다.
  - Discord 알림이 켜진 상태에서 거부가 이어지는 동안 판정 중단 알림은 한 번만 가고, 문구는 "자동으로 다시 시도합니다"다.
  - 거부된 동안 매입가가 바뀐다. 다시 등록된 뒤 보유종목을 다시 읽고, 그 뒤 온 시세 체결은 새 매입가로 판정한다. 다시 읽기 전에 온 시세 체결은 판정하지 않는다.
  - SL / TP가 체결을 받았다는 로그에 그 체결의 요청 ID가 있다.
  - 체결 전에 대기열에 있던 시세 체결은 보유종목을 다시 읽는 동안 판정하지 않는다.
- **티켓 04의 테스트**: 체결 알림만, SL / TP만, 둘 다 켜진 경우 각각 키움에 보낸 REG·REMOVE가 지금 테스트의 기대값과 같다. 밀려남 중단 알림 제목은 체결 알림만이면 "체결 감시 중단", 둘 다면 "체결 감시·SL / TP 중단"이다. SL / TP만 동작하는 때는 Discord 알림이 꺼져 있어 알림이 가지 않으므로, 중단 로그의 기능 목록에 SL / TP가 한 번만 있는지로 확인한다. 실전 연결에서 국내·미국 신청에 따라 `00`, `00`+`F5`로 등록되는 것도 같다.
- **기존 테스트(prior art)**: 체결 알림 테스트, 공유 실시간 연결 테스트, SL / TP 보유종목·세션·자동 매도·미국 테스트. 같은 가짜 서버와 체결 이벤트 도우미를 쓴다. 두 항목을 담은 메시지는 가짜 연결의 push에 그대로 넣으면 된다.
- **모의투자 확인은 하지 않는다.** 키움에 보내는 메시지가 같고, 바뀌는 것은 REG를 다시 보내는 횟수가 줄어드는 것뿐이다.
- 각 티켓마다 전체 테스트, lint, format 검사, type check를 돌린다.

## Out of Scope

- 체결 알림 module의 이름 바꾸기와 폴더 정리. 아키텍처 점검의 마지막 단계인 폴더 정리에서 한다.
- 체결이 아닌 주문상태(접수·확인·취소·거부)를 넘기는 일.
- 끊긴 동안 놓친 체결 보충.
- 실시간 등록 메시지의 모양이나 그룹 번호 바꾸기.
- 실전투자에서 SL / TP 동작.
- 밀려남 중단 알림의 기능 이름("체결 감시")을 용어집의 "체결 알림"으로 맞추는 일.
- 여러 체결을 합친 보유종목 다시 읽기 로그에서 원인 체결의 요청 ID를 모두 따라가는 일.
