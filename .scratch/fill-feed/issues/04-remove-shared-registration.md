# 04: 공유 실시간 연결의 "함께 받기" 장치 없애기

**What to build:** 이제 `00`/`F5`를 받는 곳은 체결 feed 하나뿐이다. 그래서 공유 실시간 연결의 "함께 받기" 장치를 없애고, 체결 feed가 일반 구독으로 그룹 `1`을 등록하게 한다. 공유 실시간 연결은 구독 등록·해지와 이벤트 전달만 알게 된다.

키움에 보내는 메시지와 사용자에게 보이는 동작은 바뀌지 않는다.

Spec: `.scratch/fill-feed/spec.md` (Implementation Decisions의 공유 실시간 연결)

**Blocked by:** 03

**Status:** ready-for-agent

**공유 실시간 연결**
- [x] "함께 받기" 장치를 없앤다: 채널의 함께 받기 등록, 연결 안에서 대신 등록하는 채널, 등록 결과 전달, 합친 항목 계산. 이 장치만을 위한 상수와 주석도 정리한다.

**체결 feed**
- [x] 체결 feed의 채널은 일반 구독으로 그룹 `1`, item 빈 값, refresh `1`을 등록한다. 합친 항목이 바뀌면 다시 등록하고, 신청이 모두 빠지면 해지한다.
- [x] 그룹 `1`은 체결 feed, 그룹 `2`는 SL / TP 시세가 쓴다는 사실을 각 module 주석에 남긴다.

**밀려남 중단 알림** (03에서 구현함. 04에서는 함께 받기를 없앤 뒤에도 그대로인지만 확인한다)
- [x] 채널은 표시 문자열 하나가 아니라 기능 이름 목록을 가진다. 체결 feed 채널의 목록은 그 채널에 신청한 기능들이다.
- [x] 공유 연결은 중단 알림 제목을 만들 때 모든 채널의 이름을 순서대로 모으며 겹치는 이름을 지운다. SL / TP가 체결 feed와 시세 채널에 함께 있어도 한 번만 나온다.
- [x] 밀려남 중단 알림 제목이 지금과 같다(테스트로 확인).
  - 체결 알림만: "체결 감시 중단"
  - 둘 다: "체결 감시·SL / TP 중단"
- [x] SL / TP만 동작하는 경우는 Discord 알림이 꺼진 때뿐이라 중단 알림이 가지 않는다. 이 경우는 중단 로그(`realtime_session_replaced`)의 기능 목록에 SL / TP가 한 번만 있는지로 확인한다.

**확인**
- [x] 아래 경우마다 키움에 보낸 REG·REMOVE가 지금 테스트의 기대값과 같다.
  - 체결 알림만 켜짐
  - SL / TP만 켜짐(Discord 꺼짐)
  - 둘 다 켜짐
- [x] 실전 연결에서 국내 실전만 신청하면 `00`, 미국 실전까지 신청하면 `00`+`F5`로 등록된다.
- [x] 마지막 신청이 빠지고 다른 구독도 없으면 실시간 연결을 닫는다.
- [x] 기존 테스트가 기대값을 고치지 않고 통과한다.
- [x] 전체 테스트, lint, format 검사, type check가 통과한다.

## Comments

### 2026-10-27: 구현
- 기능 이름 목록과 겹치는 이름 지우기는 03에서 했다. 이 티켓에서는 중단 로그(`realtime_session_replaced`)에 알림에 쓴 이름 목록(`names`)을 더해, Discord가 꺼진 SL / TP만의 경우도 로그로 확인한다.
- 실전 연결에서 국내 실전만, 미국 실전까지 신청할 때의 등록은 앱으로는 재현할 수 없다(체결 알림이 두 환경을 늘 함께 신청한다). 그래서 공유 연결 테스트처럼 체결 feed를 직접 조립해 확인했다. 가짜 서버만 쓰고 주문 TR은 부르지 않는다.

### 2026-10-28: 코드 리뷰 반영
- SL / TP 보유종목 다시 읽기 로그에 체결의 요청 ID가 새던 것을 막았다. 다시 읽기 작업이 체결 feed 안에서 시작되어 그 context를 물려받았다.
- 재연결 때 Discord가 꺼져 있으면 시세(그룹 2)를 체결(그룹 1)보다 먼저 다시 등록하던 것을 고쳤다. 체결 feed가 인증정보마다 채널을 처음부터 열어 두어, 연 순서대로 하는 다시 등록에서 체결이 먼저 나간다.
- 재시도 로그를 `fill_feed_register_retry`로 바꿨다(티켓 01에서는 옛 이름을 두기로 했었다). 체결 feed 로그의 `feature`는 module 이름(`fill_watch`, `sl_tp`)을 쓰고, 알림용 한글 이름은 따로 받는다.
- 등록 상태가 바뀔 때 `fill_feed_status_changed`(live / rejected / unknown)를 남긴다.
- 공유 연결의 채널을 대기열 채널과 즉시 채널로 나눠, handler 없이 채널을 만들 수 없게 했다.
