# 04: 공유 실시간 연결의 "함께 받기" 장치 없애기

**What to build:** 이제 `00`/`F5`를 받는 곳은 체결 feed 하나뿐이다. 그래서 공유 실시간 연결의 "함께 받기" 장치를 없애고, 체결 feed가 일반 구독으로 그룹 `1`을 등록하게 한다. 공유 실시간 연결은 구독 등록·해지와 이벤트 전달만 알게 된다.

키움에 보내는 메시지와 사용자에게 보이는 동작은 바뀌지 않는다.

Spec: `.scratch/fill-feed/spec.md` (Implementation Decisions의 공유 실시간 연결)

**Blocked by:** 03

**Status:** ready-for-agent

**공유 실시간 연결**
- [ ] "함께 받기" 장치를 없앤다: 채널의 함께 받기 등록, 연결 안에서 대신 등록하는 채널, 등록 결과 전달, 합친 항목 계산. 이 장치만을 위한 상수와 주석도 정리한다.

**체결 feed**
- [ ] 체결 feed의 채널은 일반 구독으로 그룹 `1`, item 빈 값, refresh `1`을 등록한다. 합친 항목이 바뀌면 다시 등록하고, 신청이 모두 빠지면 해지한다.
- [ ] 그룹 `1`은 체결 feed, 그룹 `2`는 SL / TP 시세가 쓴다는 사실을 각 module 주석에 남긴다.

**밀려남 중단 알림**
- [ ] 채널은 표시 문자열 하나가 아니라 기능 이름 목록을 가진다. 체결 feed 채널의 목록은 그 채널에 신청한 기능들이다.
- [ ] 공유 연결은 중단 알림 제목을 만들 때 모든 채널의 이름을 순서대로 모으며 겹치는 이름을 지운다. SL / TP가 체결 feed와 시세 채널에 함께 있어도 한 번만 나온다.
- [ ] 밀려남 중단 알림 제목이 지금과 같다(테스트로 확인).
  - 체결 알림만: "체결 감시 중단"
  - 둘 다: "체결 감시·SL / TP 중단"
- [ ] SL / TP만 동작하는 경우는 Discord 알림이 꺼진 때뿐이라 중단 알림이 가지 않는다. 이 경우는 중단 로그(`realtime_session_replaced`)의 기능 목록에 SL / TP가 한 번만 있는지로 확인한다.

**확인**
- [ ] 아래 경우마다 키움에 보낸 REG·REMOVE가 지금 테스트의 기대값과 같다.
  - 체결 알림만 켜짐
  - SL / TP만 켜짐(Discord 꺼짐)
  - 둘 다 켜짐
- [ ] 실전 연결에서 국내 실전만 신청하면 `00`, 미국 실전까지 신청하면 `00`+`F5`로 등록된다.
- [ ] 마지막 신청이 빠지고 다른 구독도 없으면 실시간 연결을 닫는다.
- [ ] 기존 테스트가 기대값을 고치지 않고 통과한다.
- [ ] 전체 테스트, lint, format 검사, type check가 통과한다.
