# 03: SL / TP를 체결 feed 위로 옮기기

**What to build:** SL / TP가 내 계좌 체결을 직접 등록하지 않고 체결 feed에 신청해서 받는다. 사용자에게 보이는 변화는 세 가지다.
- 체결 등록이 거부되면 SL / TP도 체결 알림처럼 스스로 다시 시도한다. 등록되면 보유종목을 다시 읽은 뒤 판정을 다시 시작한다. Discord 알림이 꺼져 있어도 세션이 끝날 때까지 멈춰 있지 않고, 거부된 동안 바뀐 매입가로 판정하지도 않는다.
- 내 계좌 체결을 받는 즉시 판정을 멈춘다. 같은 메시지나 그 뒤에 온 시세 체결은 바뀐 매입가를 반영한 뒤에만 판정한다.
- 체결 전에 받아 두었던 시세 체결도 보유종목을 다시 읽는 동안에는 건너뛴다.

이 결정의 이유를 ADR 0002로 남긴다. 이 작업에서 동작이 바뀌는 곳은 이 티켓뿐이다.

Spec: `.scratch/fill-feed/spec.md` (Solution, Implementation Decisions의 SL / TP와 즉시 넘기기, Testing Decisions의 티켓 03)

**Blocked by:** 02

**Status:** ready-for-agent

**신청과 체결 처리**
- [x] 켜진 SL/TP 세션이 시작되면 그 투자 환경의 체결을 체결 feed에 신청하고, 세션이 끝나면 해지한다.
- [x] SL / TP는 공유 실시간 연결의 "함께 받기"를 더 쓰지 않는다. 시세 구독(그룹 `2`)은 지금처럼 자기 채널로 한다.
- [x] 체결 콜백은 지금 세션 실행이 있고 지금 연결에서 온 체결일 때 보유종목 다시 읽기를 요청하며, 그 즉시 판정을 멈춘다. 그 밖의 체결은 지금처럼 이유를 남기고 무시한다.
- [x] 체결 전에 시세 채널 대기열에 있던 시세 체결도, 보유종목을 다시 읽는 동안에는 "다시 읽는 중"으로 건너뛴다.
- [x] SL / TP가 체결을 받았다는 로그(`sl_tp_fill_seen`)에 체결 feed가 붙인 요청 ID를 남긴다. 여러 체결을 합친 보유종목 다시 읽기 로그는 요청 ID와 잇지 않는다.

**거부 처리**
- [x] "거부됨"을 받으면 판정을 멈추고, 거부가 이어지는 동안 판정 중단 알림을 한 번만 보낸다. 문구는 "자동으로 다시 시도합니다"로 바꾼다.
- [x] "받는 중"을 받으면 판정을 다시 시작할 수 있고, 알림도 다시 보낼 수 있게 된다. 새 세션 실행이 시작될 때도 다시 알릴 수 있다.
- [x] 켜진 세션에서 "거부됨" 다음에 "받는 중"을 받으면 보유종목 다시 읽기를 요청한다. 다시 읽은 결과가 반영될 때까지 판정하지 않는다.
- [x] SL / TP는 체결 등록을 직접 다시 보내지 않는다. 세션 시작이나 감시 종목 변경 때 체결 등록을 다시 보내던 동작은 없앤다.
- [x] 이미 거부된 상태에서 세션이 시작되면, REG를 다시 보내지 않고 체결 feed가 기억한 거부 상태를 바로 받아 판정을 멈춘다.
- [x] 시세 구독 거부 처리와 그 알림 문구, 연결 끊김·재연결·밀려남 처리는 바꾸지 않는다.

**ADR**
- [x] `docs/adr/0002-...`에 "체결 feed는 대기열 없이 즉시 넘긴다"는 결정을 남긴다. 내용은 세 가지다.
  - 이유: 옛 매입가로 판정해 자동 매도가 나가는 것을 막는다.
  - 검토한 대안: 기능마다 대기열 두기, 순서가 바뀌는 것을 받아들이기.
  - 결과: 콜백은 동기로 빨리 끝나야 하고, 체결 전에 받은 시세 체결은 건너뛴다.

**확인**
- [x] 바뀌는 기존 테스트:
  - 체결 등록 거부 뒤 보유종목 변경 때 다시 등록하던 테스트 → 체결 feed가 스스로 다시 등록하고 판정이 다시 시작된다.
  - 거부된 등록에 SL / TP가 함께 받기 시작할 때 REG를 다시 보내던 테스트 → REG를 다시 보내지 않고 거부 상태를 바로 받는다.
- [x] 새 테스트: 한 REAL 메시지에 내 계좌 체결과 시세 체결이 함께 오고, 그 시세 체결이 옛 매입가로는 기준을 넘는다. 이때 자동 매도가 나가지 않고, 다시 읽은 매입가로 판정한다.
- [x] 새 테스트: 체결 알림의 Discord 응답이 늦는 동안에도 SL / TP는 체결을 받자마자 판정을 멈추고 보유종목을 다시 읽는다.
- [x] 새 테스트: Discord 알림이 꺼진 상태에서 체결 등록이 거부된다. Discord 전송은 없고, 판정이 멈추며, 체결 feed가 다시 등록하고, 등록되면 판정이 다시 시작된다.
- [x] 새 테스트: Discord 알림이 켜진 상태에서 거부가 이어지는 동안 판정 중단 알림은 한 번만 가고, 문구는 "자동으로 다시 시도합니다"다.
- [x] 새 테스트: 거부된 동안 매입가가 바뀐다. 다시 등록된 뒤 보유종목을 다시 읽고, 그 뒤 온 시세 체결은 새 매입가로 판정한다. 다시 읽기 전에 온 시세 체결은 판정하지 않는다.
- [x] 새 테스트: SL / TP가 체결을 받았다는 로그에 그 체결의 요청 ID가 있다.
- [x] 새 테스트: 체결 전에 대기열에 있던 시세 체결은 보유종목을 다시 읽는 동안 판정하지 않는다.
- [x] 그 밖의 SL / TP와 체결 알림 테스트가 기대값을 고치지 않고 통과한다.
- [x] 전체 테스트, lint, format 검사, type check가 통과한다.
