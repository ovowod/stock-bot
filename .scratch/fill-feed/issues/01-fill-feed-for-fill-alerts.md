# 01: 체결 feed를 만들고 체결 알림을 그 위로 옮기기

**What to build:** 체결 알림이 내 계좌의 체결을 직접 등록하고 해석하지 않고, 체결 feed에 투자 환경별로 신청해서 받는다. 체결 feed가 맡는 일은 다음과 같다.
- `00`/`F5` 등록
- 거부되면 다시 시도
- 체결로 치는 주문상태만 남기기
- 체결 이벤트를 체결 하나로 읽기
- 체결과 등록 상태를 신청한 기능에 넘기기

사용자가 받는 체결 알림과 키움에 보내는 메시지는 지금과 똑같다. SL / TP는 이 티켓에서 바뀌지 않는다.

Spec: `.scratch/fill-feed/spec.md` (Implementation Decisions의 체결 feed module, 신청과 해지, 넘기는 것, 상태, 거부와 다시 시도, 체결 알림)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**체결 feed module**
- [ ] 체결 feed module을 새로 만든다. 아래가 모두 이 module에만 있다.
  - 투자 환경별 실시간 항목(국내 `00`, 미국 `F5`. 국내 실전과 미국 실전은 한 연결)
  - 체결로 치는 주문상태(`00` "체결", `F5` "부분체결"·"체결완료")
  - 체결 이벤트를 체결 하나로 읽는 코드. 체결 알림에서 옮겨 온다.

**신청과 해지**
- [ ] 기능은 투자 환경과 콜백 하나로 신청하고, 해지 수단을 돌려받는다.
- [ ] 한 인증정보의 등록 항목은 그 인증정보에 걸린 신청들의 항목을 합친 것이다. 합친 항목이 바뀌면 다시 등록하고, 신청이 모두 빠지면 해지한다.
- [ ] 등록은 이 티켓에서는 아직 공유 실시간 연결의 "함께 받기"로 한다. SL / TP가 그룹 `1`을 함께 쓰고 있어서다.

**넘기는 것**
- [ ] 콜백은 체결과 등록 상태("받는 중" / "거부됨 + return_code·return_msg")를 받는다.
- [ ] 체결에는 지금 체결 알림이 쓰는 값이 모두 들어 있다. 받은 연결 번호, 받은 시각(경과 시간 시계), 체결마다 새로 붙인 요청 ID도 함께 넘긴다.
- [ ] 콜백은 동기 함수다. 콜백에서 오류가 나면 체결 feed가 잡아 로그로 남기고, 다음 콜백과 다음 체결을 이어서 처리한다.

**상태와 다시 시도**
- [ ] 거부되면 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 등록한다.
- [ ] 등록에 성공하면(재연결로 먼저 등록된 경우 포함) 기다리던 재시도를 취소하고 간격을 처음으로 돌린다. 신청이 모두 빠지면 재시도도 멈춘다.
- [ ] 체결 feed는 인증정보마다 마지막 등록 상태를 기억한다. 새로 신청한 기능에는 그 상태를 바로 알려 준다. 상태를 아직 모르면 결과가 나올 때 알려 준다.
- [ ] 기억한 상태는 합친 항목이 바뀔 때, 연결이 끊길 때, 신청이 모두 빠질 때 "모름"으로 되돌린다. 새 항목이나 새 연결의 등록 결과가 나오기 전에는 예전 "받는 중"을 알려 주지 않는다. 등록 버전 번호는 두지 않는다(spec의 "상태" 참고).

**체결 알림**
- [ ] Discord 알림이 켜져 있으면 인증정보가 있는 투자 환경마다 신청한다. 꺼져 있거나 인증정보가 없을 때의 건너뜀과 로그는 지금과 같다.
- [ ] 체결 알림 콜백은 받은 체결을 자기 대기열에 넣기만 한다. 느린 일은 그 대기열에서 순서대로 한다: 자동 매도 맞춰 보기, 매도 손익, 미체결 조회, Discord 전송.
- [ ] 미국 매도 손익을 위한 주문별 누적 체결 기억과 자동 매도 맞춰 보기는 체결 알림에 남는다.
- [ ] 체결 알림의 로그는 체결 feed가 붙인 요청 ID를 이어 쓴다.
- [ ] SL / TP는 체결로 치는 주문상태를 체결 feed에서 가져온다. 다른 SL / TP 동작은 바꾸지 않는다.

**로그**
- [ ] 기존 로그 이벤트 이름은 그대로 둔다(`fill_received`, `fill_skipped`, `fill_notified`, `fill_watch_register_retry` 등).
- [ ] 체결 feed의 신청·해지와 등록 상태 변화를 로그로 남긴다.

**확인**
- [ ] 체결 알림, 공유 실시간 연결, SL / TP의 기존 테스트가 기대값을 고치지 않고 통과한다.
  - 옮겨 간 상수를 직접 쓰던 테스트는 import만 고친다.
  - 체결 알림을 직접 조립하던 테스트는 체결 feed를 넣는 조립만 고친다.
- [ ] 전체 테스트, lint, format 검사, type check가 통과한다.
