# 02: 체결 feed가 대기열 없이 즉시 받기

**What to build:** 공유 실시간 연결에 대기열을 거치지 않는 받기 방식을 더한다. 체결 feed는 이 방식으로 체결을 받는다. 키움 메시지가 도착하면 체결 feed가 그 즉시 체결로 읽어 신청한 콜백을 부른다. 같은 메시지의 다른 항목(시세 체결 등)이 다른 채널 대기열에서 처리되기 전이다.

이 티켓만으로는 사용자에게 보이는 동작이 바뀌지 않는다. 티켓 03에서 SL / TP가 체결 feed로 옮겨 올 때, 시세보다 체결 처리를 먼저 하는 순서를 지키기 위한 준비다.

Spec: `.scratch/fill-feed/spec.md` (Implementation Decisions의 즉시 넘기기)

**Blocked by:** 01

**Status:** ready-for-agent

**공유 실시간 연결**
- [x] 채널을 열 때 "대기열 없이 받기"를 고를 수 있다.
  - 이렇게 연 채널은 이벤트(체결 항목, 연결됨·끊김, 등록됨·거부됨, 멈춤)를 대기열에 넣지 않고, 일어난 순서대로 그 자리에서 handler에 넘긴다.
  - handler는 동기 함수다.
- [x] REAL 메시지 하나에 즉시 받는 채널의 항목과 대기열 채널의 항목이 섞여 오면, 즉시 받는 채널의 handler가 대기열 채널의 handler보다 먼저 끝난다.
- [x] 즉시 받는 handler에서 오류가 나면 로그로 남기고 연결은 계속 받는다. PING 응답과 다른 채널 전달이 멈추지 않는다.
- [x] 다른 실시간 기능은 지금처럼 채널마다 대기열을 거친다.

**체결 feed**
- [x] 체결 feed는 대기열 없이 받는 채널을 쓴다. 신청한 콜백도 그 자리에서 부른다.
- [x] 체결 알림은 01에서 만든 자기 대기열로 계속 처리한다. Discord가 느려도 공유 연결의 받기가 막히지 않는다.

**확인**
- [x] 새 테스트: 공유 실시간 연결에서 한 메시지에 두 종류 항목이 섞여 올 때, 즉시 받는 채널의 handler가 먼저 실행된다.
- [x] 새 테스트: 즉시 받는 handler가 오류를 내도 그 뒤 메시지와 다른 채널의 이벤트를 계속 받는다.
- [x] 새 테스트: Discord 응답이 늦는 동안에도 다음 체결이 체결 feed에 바로 도착하고, 체결 알림은 순서대로 간다.
- [x] 기존 테스트가 기대값을 고치지 않고 통과한다.
- [x] 전체 테스트, lint, format 검사, type check가 통과한다.
