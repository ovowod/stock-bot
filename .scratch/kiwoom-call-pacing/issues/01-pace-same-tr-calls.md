# 01: 같은 TR 호출 간격 맞추기

**What to build:** 같은 인증정보로 같은 TR을 부를 때 키움 클라이언트가 앞 요청과 최소 1초 간격을 두고 보낸다. 5초 넘게 기다려야 하면 보내지 않고 **호출 한도** 오류를 돌려준다. 종목 검색의 1초 대기와 순위 lock은 이 규칙으로 대신하고 없애며, 순위 화면은 네 카드를 동시에 조회한다.

Spec: `.scratch/kiwoom-call-pacing/spec.md` (User Stories 1–7, Implementation Decisions > 간격 맞추기·기존 대응 정리)

**Blocked by:** 없음

**Status:** ready-for-agent

- [x] (인증정보 묶음 `credential_prefix`, TR)마다 앞 요청을 보낸 시각에서 최소 1초 뒤에 보내고, 먼저 온 요청이 먼저 나간다.
- [x] 국내 실전과 미국 실전은 한 단위로 센다. 국내 모의와 미국 모의는 따로 센다.
- [x] 줄에 들어올 때 5초를 넘겨 기다려야 하는 요청은 키움에 보내지 않고 `rate_limited`(기존 안내 문구, 일반 조회 API는 429)를 돌려준다. 이 요청은 뒤 요청의 보낼 시각을 밀지 않는다. 매도·취소 전 재확인이 이 오류를 502로 감싸는 기존 동작은 그대로다.
- [x] 차례가 온 요청은 실제 마지막 전송 시각을 다시 보고 1초가 안 됐으면 더 기다린다. 5초 판단은 줄에 들어올 때 한 번만 한다.
- [x] 연속조회 다음 페이지도 새 요청과 똑같이 1초 간격을 지킨다(spec Implementation Notes 2026-10-10).
- [x] 조회, 주문(`call_once`), 토큰 발급(`au10001`), `8005` 뒤 다시 보내는 요청 모두 같은 규칙을 지킨다. 호출 한도 오류를 받은 뒤 자동으로 다시 보내지 않는다.
- [x] 기다리면 `kiwoom_pacing_wait`, 거부하면 `kiwoom_pacing_rejected`(WARNING) 로그가 api_id·wait_ms·요청 ID·투자 환경과 함께 남는다.
- [x] 종목 검색의 `DOMESTIC_LIST_INTERVAL_SECONDS` 대기를 없앤다.
- [x] 순위의 lock을 없앤다. 지금의 "순위 요청은 한 번에 하나씩" 테스트를 "다른 순위 TR은 동시에 나간다"로 바꾼다.
- [x] 순위 화면이 네 카드 요청을 앞 응답을 기다리지 않고 동시에 시작한다. 카드별 성공·실패 표시와 오래된 응답 무시는 그대로다. 지금의 "카드가 한 번에 하나씩 요청된다" e2e를 "동시에 요청된다"로 바꾼다.
- [x] `.scratch/ranking/spec.md`의 "한 번에 하나씩" 규칙들(서버 잠금, 화면의 카드 순차 조회와 그 검증 항목) 아래에 이 spec으로 바뀌었다는 메모를 남긴다.
- [x] 키움 클라이언트가 시각과 대기를 바꿔 끼울 수 있게 해 간격 테스트를 가짜 시계로 검증한다. 간격을 다루지 않는 기존 테스트는 실제로 기다리지 않는다.
- [x] spec의 Testing Decisions 항목(계좌번호 확인 제외)을 pytest와 Playwright로 검증한다. 기존 테스트, ruff, mypy, 빌드가 모두 통과한다.
