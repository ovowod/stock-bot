# 03: 모의투자에서 호출 한도 확인

**What to build:** 국내·미국 모의투자에서 예전에 호출 한도에 걸리던 흐름을 다시 해 보고, `1700`이 사라졌는지와 대기 로그가 어떻게 남는지 확인한다. 결과는 spec에 기록한다.

Spec: `.scratch/kiwoom-call-pacing/spec.md` (Further Notes)

**Blocked by:** 01, 02

**Status:** ready-for-human

- [ ] 시작 전에 앱이 모의 환경으로 떠 있고, 요청이 모의 도메인으로만 나가는지 로그로 확인한다. 실전 도메인으로 주문 요청이 보이면 멈춘다.
- [ ] 국내 모의에서 작은 스크립트로 키움 클라이언트를 통해 조회 TR `ka00001`을 동시에 7번 부른다. 판정 기준:
  - 앞 6번은 모두 성공하고, 로그의 실제 전송 간격이 1초 이상이며, `1700`이 없다.
  - 7번째는 키움 요청 없이 `rate_limited`로 거부되고 `kiwoom_pacing_rejected` 로그가 남는다.
  - 1~6번째 가운데 기다린 요청마다 `kiwoom_pacing_wait` 로그가 남는다.
- [ ] 미국 모의 계좌 확인 직후 보유종목 매도 최종 확인을 연다. 잔고 재확인이 한도로 실패하지 않는지 확인한다.
- [ ] 순위 화면을 국내·미국에서 열고 조건을 바꾼다. 카드가 동시에 채워지고 `1700`이 나지 않는지 확인한다.
- [ ] 그날 첫 국내 종목 검색이 성공하는지 확인한다(`ka10099` 두 번).
- [ ] 여러 페이지 보유종목이 있다면 연속조회 다음 페이지가 한도에 걸리는지 기록한다.
- [ ] 확인 기간의 로그에서 `1700`/`1701`/`1702`를 검색해 남은 경우가 있으면 TR과 상황을 기록한다.
- [ ] 결과를 spec에 Implementation Notes로 날짜와 함께 기록한다.
