# Dead Cross 상태 보기 (자동 매도 제외)

Status: ready-for-agent

## Problem Statement

Dead Cross 설정 화면은 있지만, 설정한 봉 주기와 이동평균 기간으로 지금 보유종목이 어떤 상태인지 알 방법이 없다. 이대로 자동 매도를 붙이면 이동평균이 어떻게 계산되는지, 언제 하향 돌파로 판정되는지 확인하지 못한 채 실제 주문이 나가게 된다.

자동 매도를 붙이기 전에, 계좌 확인 화면에서 보유종목마다 단기·장기 이동평균 값과 Dead Cross 상태를 보고 싶다. 이 값은 나중에 자동 매도가 판정할 값과 똑같아야 한다. 그래서 화면이 열려 있을 때만 계산하면 안 되고, 진행 중인 봉을 넣어서도 안 된다.

## Solution

모의투자 환경에서는 켜진 Dead Cross 세션 동안 서버가 보유종목의 차트를 조회한다. 완료 봉만으로 단기·장기 이동평균을 계산하고, **하향 돌파**를 판정해 **Dead Cross 상태**를 정한다. 하향 돌파가 일어나도 매도 주문은 내지 않고 상태만 바꾼다.

데드크로스 발생 상태와 마지막으로 판정한 봉은 그 종목을 보유하는 동안 세션과 날짜를 넘겨 기억한다. 이 기억은 파일에 저장하므로 서버를 다시 시작해도 이어 간다.

계좌 확인의 보유종목 목록 위 보기 전환을 **[기본 | Trailing Stop | Dead Cross]**로 늘린다. Dead Cross 보기에서는 각 보유종목에 다음을 보인다.

- 지금 세션의 봉 주기, 단기·장기 이동평균 기간
- 현재 단기·장기 이동평균 값
- 마지막으로 판정한 완료 봉의 시각
- **Dead Cross 상태**: 계산 대기(이유 함께) / 추적 중 / 데드크로스 발생
- 활성 세션 여부, 제외종목 여부

이 보기가 열려 있는 동안 3초마다 상태를 다시 받는다. 상태 조회는 키움을 부르지 않는다.

Dead Cross 설정 화면의 "준비 중 안내"는 "지금은 상태만 계산하고 팔지 않습니다. 계좌 확인 화면의 Dead Cross 보기에서 확인하세요."로 바꾼다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **완료 봉**을 더했고, **하향 돌파**와 **Dead Cross 상태**를 정했다. 코드, 로그, 화면 문구는 이 이름을 따른다.
- 코드와 로그에서 상태는 `waiting`(계산 대기), `tracking`(추적 중), `crossed`(데드크로스 발생)이다.

**키움 TR**

- 차트: 국내 분봉 `ka10080`(`tic_scope`, `base_dt`=오늘, `upd_stkpc_tp`="1"), 국내 일봉 `ka10081`. 미국 분봉 `usa06011`(`tic_scope`, `strt_dt`=오늘(뉴욕), `stex_tp`, `upd_stkpc_tp`="1", `exrt_appl_tp`="0"), 미국 일봉 `usa06012`. 구현 전에 kra-docs로 요청·응답 필드를 다시 확인한다.
- 미국 `stex_tp`(NA/ND/NY)는 보유종목의 거래소에서 정한다. 거래소를 모르면 대상 아님이다.
- 국내 종목코드는 보유종목 코드 그대로(KRX) 쓴다.
- 보유종목은 Trailing Stop처럼 기존 잔고 조회로 읽는다. 새 종목이 들어온 것은 내 계좌 체결(ADR 0002의 체결 피드)로 알아채 다시 읽는다. 시세 실시간 구독은 하지 않는다.
- 매도 주문 TR은 부르지 않는다.

**모의투자 실측으로 확인한 사실** (`.scratch/dead-cross/measure-*.txt`, 2026-11-02·03, 명세에 없음)

- 한 페이지 봉 수: 국내 분봉 900, 국내 일봉 600, 미국 분봉·일봉 100. 최신 봉부터 과거로 온다.
- 맨 앞 행은 진행 중인 봉일 수 있다. `cntr_tm`은 봉의 **시작** 시각이다(미국 120분봉 08:00 봉이 09:47과 11:43 사이에 바뀌었고, 06:00 봉은 그대로였다).
- 분봉에 정규장 밖 봉이 섞인다. 국내는 KRX 코드로도 15:30–20:00 봉이 오고(장전 08시대는 없음), 미국은 장전·장후·야간 봉이 온다. 미국 120분봉은 04:00부터 2시간 간격이다.
- 미국 `cntr_tm`은 뉴욕 시각이며 다음 날 새벽을 24시 넘는 시각(`20261030264000` = 10/31 02:40)으로 적는다.
- 국내 분봉 가격에는 `+`/`-` 부호가 붙는다(전일 대비 표시). 부호를 떼고 쓴다. 일봉은 부호가 없었다.
- 과거 범위는 가장 짧은 미국 120분봉도 약 6개월(1,527봉)이라, 이동평균 기간 상한(단기 119, 장기 120)은 그대로 둔다.

**완료 봉과 이동평균**

- 분봉: `시작 시각 + 봉 주기 ≤ 지금`인 봉만 완료 봉이다. 일봉: 그 시장의 오늘(국내는 한국 시각, 미국은 뉴욕 시각)보다 앞선 날의 봉만 완료 봉이다.
- 키움이 주는 봉을 그대로 쓴다. 정규장 밖 봉을 빼거나, 1분봉을 직접 묶지 않는다.
- 이동평균은 그 봉까지의 완료 봉 N개의 종가 단순 평균이다. 한 봉을 판정하려면 장기 기간 + 1개의 완료 봉이 있어야 한다. 모자라면 계산 대기 · 봉 부족이다.
- 조회는 판정에 필요한 봉이 다 모일 때까지 연속조회한다. 필요한 봉은 "마지막 판정 봉 다음 봉부터 가장 최근 완료 봉까지"와 "그 첫 봉을 판정할 과거 봉(장기 기간 + 1개)"이다. 기억이 없으면 가장 최근 완료 봉을 판정할 만큼이다. 페이지 수 상한은 두지 않는다. 평소에는 국내 1페이지, 미국 2페이지면 되고, 세션 밖에 쌓인 봉을 채울 때는 더 받는다(예: 미국 1분봉을 하룻밤 건너 이어 보면 종목마다 약 12페이지).
- 키움이 주는 과거 범위가 끝나(`cont-yn=N`) 필요한 봉을 다 받지 못하면, 처음 보는 종목처럼 가장 최근 완료 봉 하나만 판정하고 로그를 남긴다.
- 기존 클라이언트의 "최대 10페이지까지 다 받기"는 쓰지 않는다. 필요한 만큼에서 멈추는 조회를 키움 클라이언트에 더한다. 페이지마다 기존 키움 호출 간격 규칙을 지킨다.
- 이동평균은 Decimal로 계산하고, 응답에는 국내 소수 둘째, 미국 소수 넷째 자리로 반올림한 문자열을 담는다. 판정은 반올림하기 전 값으로 한다.

**판정**

- 종목마다 기억한 "마지막 판정 봉"(봉 주기, 단기·장기 기간, 봉 시작 시각) 뒤의 완료 봉을 오래된 것부터 차례로 판정한다. 기억이 없거나, 지금 세션의 봉 주기나 단기·장기 기간 가운데 하나라도 기억과 다르면 가장 최근 완료 봉 하나만 새 기준으로 판정한다. 이때 이미 데드크로스 발생인 종목은 발생을 그대로 두고 풀림만 새 기준으로 판정한다.
- 한 봉의 판정: 직전 봉에서 `단기 ≥ 장기`이고 이 봉에서 `단기 < 장기`이면 하향 돌파다. 발생 시각(판정한 시각)과 발생 봉을 기억하고 상태를 `crossed`로 한다.
- `crossed`인 종목은 판정한 봉에서 `단기 ≥ 장기`가 되면 풀려 `tracking`이 된다.
- 기준 값(봉 주기, 단기·장기 기간)은 판정하는 시각에 켜진 세션의 값이다. 데드크로스 발생은 설정을 바꿔도 남고, 풀림 판정은 지금 설정으로 한다.
- 화면에 보일 이동평균은 조회할 때마다 가장 최근 완료 봉으로 다시 계산한다. 이미 판정한 봉이면 상태는 바꾸지 않는다. 서버를 다시 시작한 뒤 새 봉이 없어도(같은 날 일봉 등) 값이 보이게 하려는 것이다.
- 제외종목이 되거나 보유에서 빠지면 그 종목의 기억을 버린다.
- 차트 응답을 반영하기 전에, 조회를 시작할 때의 세션·Dead Cross 설정·보유종목 상태가 그대로인지 확인한다. 하나라도 바뀌었으면(제외종목 저장, 전량 매도, 세션 변경 등) 그 응답을 버리고 로그를 남긴다. 지운 기록이 되살아나거나 예전 기준의 값이 보이지 않게 하려는 것이다.

**조회 시점**

- 켜진 Dead Cross 세션 동안에만 조회한다. 세션 경계 규칙(시작 포함, 종료 제외, 맞닿은 세션은 뒤 세션)은 다른 기능과 같다.
- 보유종목(대상 아님·제외종목 빼고)마다 다음 때 조회한다.
  - 세션이 시작할 때
  - Dead Cross 설정을 저장할 때
  - 보유종목을 다시 읽어 새 종목이 생겼을 때
  - 분봉은 봉이 하나 끝날 때마다, 끝난 시각 5초 뒤. 봉의 끝은 시작 시각 + 봉 주기이며, 종목과 상관없이 시계로 정한다(국내는 09:00, 미국 120분봉은 04:00을 기준으로 이어지는 시각).
- 투자 환경마다 조회 차례는 하나만 돈다. 도는 동안 들어온 요청(정기 조회, 설정 저장, 새 종목, 다시 시도)은 끝난 뒤 한 차례로 합쳐 다시 돈다. 조회가 봉 주기보다 오래 걸려도 차례가 쌓이지 않고, 마지막 판정 봉은 앞으로만 나아간다.
- 조회 한 차례(위의 각 시점)를 돌기 전마다 보유종목을 한 번 다시 읽는다. 잔고 조회는 종목 수와 상관없이 한 번이다. 체결 연결이 끊기거나 등록이 거부된 동안 사고판 것도 다음 차례에 반영하려는 것이다.
- 조회가 실패하면 그 종목은 마지막 값과 상태(추적 중·데드크로스 발생)를 그대로 두고 이유 `chart_failed`를 붙인다. 판정한 적 없는 종목만 계산 대기 · 차트 조회 실패다. 봉 주기와 상관없이 보유종목 읽기와 같은 방식(짧게 시작해 최대 간격까지 늘림)으로 다시 시도하고, 세션이 끝나면 그만둔다. 빠진 봉은 차례 판정으로 채운다.
- 보유종목이 많으면 기존 키움 호출 간격 규칙에 따라 차례로 조회한다.

**Dead Cross 감시 (서버, 새 모듈)**

- Trailing Stop 감시와 같은 구조의 별도 감시를 투자 환경마다 하나씩 둔다. 모의투자 환경만 만들고, 실전투자 환경과 인증정보가 없는 환경은 만들지 않는다.
- 설정은 자동매매 설정 저장소의 Dead Cross 칸에서 읽는다(ADR 0004). Dead Cross 설정을 저장하면 감시에 알린다.
- 보유종목은 세션이 시작할 때, 조회 차례마다, 내 계좌 체결이 들어올 때, 체결 등록이 다시 성공했을 때 다시 읽는다. 읽기 실패 시 재시도는 Trailing Stop과 같다.
- 공유 실시간 연결이 밀려나면(ADR 0001, `R10001`) Dead Cross 감시도 함께 멈추고 `connection_replaced`로 보인다. 차트는 REST로 받지만, 체결을 받지 못하면 세션 밖 전량 매도를 지우는 동작이 조용히 빠지므로 ADR대로 멈춘다. 지금의 체결 피드는 이 멈춤을 구독자에게 알리지 않으므로, 체결 피드가 멈춤 상태도 알리게 하거나 공유 연결의 상태를 읽는 경로를 더한다.
- 기억이 있는 동안에는 세션 밖에서도 내 계좌 체결을 받고, 체결이 오면 보유종목을 다시 읽어 없는 종목의 기억을 지운다. Trailing Stop과 같다. 세션 밖에서는 차트를 조회하거나 판정하지 않는다.
- 대상 아님 분류(신용 보유분, 같은 종목 여러 줄, 미국 종목의 거래소 확인 불가)는 Trailing Stop과 같은 규칙을 쓴다. 매입가 없음은 대상 아님이 아니다.
- 계산 대기의 이유: `no_session`(켜진 세션 없음), `real`(실전투자), `excluded`(제외종목), `ineligible`(대상 아님. 세부 이유 `credit`·`duplicate`·`unknown_exchange`), `not_enough_bars`(봉 부족), `chart_failed`(차트 조회 실패), `holdings_pending`(보유종목 확인 중), `fills_rejected`(체결 등록 거부), `connection_replaced`(공유 실시간 연결이 밀려남), `settings_unreadable`, `state_unreadable`, `no_credentials`.

**판정 기록 파일**

- 데이터 폴더 아래에 투자 환경마다 파일 하나를 둔다. 자동매매 설정 파일, Trailing Stop 고점 기록과는 따로 둔다. `.env`에 새 변수는 없다.
- 형식(버전 1):

```json
{
  "version": 1,
  "stocks": {
    "005930": {
      "judged_bar": { "bar_period": "5m", "short_period": 5, "long_period": 20, "start": "2026-11-03T01:05:00+00:00" },
      "crossed_at": "2026-11-03T01:10:05+00:00",
      "crossed_bar": "2026-11-03T01:05:00+00:00"
    }
  }
}
```

- 쓰기는 임시 파일에 다 쓴 뒤 바꿔치기한다. 판정할 때마다 바로 쓴다(봉이 끝날 때만 바뀌어 잦지 않다).
- 파일이 없으면 빈 기록이다. 읽지 못하거나 형식이 맞지 않으면 그 환경의 판정을 멈추고 `state_unreadable`로 둔다. 빈 기록으로 대신하지 않는다. 설정을 저장하면 다시 읽는다. Discord 알림은 보내지 않는다.
- 쓰기에 실패하면 메모리의 판정은 계속하고 로그를 남긴 뒤 다음 쓰기 때 다시 시도한다.

**자체 서버 API**

- `GET /api/environments/{environment}/dead-cross/status`. 키움을 부르지 않는다. 3초 갱신 경로로 등록해 Trailing Stop 상태 조회처럼 성공 로그를 줄인다.
- 응답:

```json
{
  "environment": "domestic_paper",
  "market": "domestic",
  "timezone": "Asia/Seoul",
  "watching": true,
  "not_watching_reason": null,
  "session": { "start": "09:00", "end": "15:30", "enabled": true, "bar_period": "5m", "short_period": 5, "long_period": 20 },
  "excluded": ["000660"],
  "stocks": [
    {
      "code": "005930",
      "status": "tracking",
      "reason": null,
      "ineligible_reason": null,
      "short_ma": "61230.40",
      "long_ma": "61012.75",
      "basis": { "bar_period": "5m", "short_period": 5, "long_period": 20 },
      "judged_bar": "2026-11-03T01:05:00+00:00",
      "crossed_at": null,
      "crossed_bar": null
    }
  ]
}
```

- `session`은 지금 시각을 포함하는 Dead Cross 세션이다. 꺼져 있어도 담고, 없으면 `null`이다. 실전 환경에서도 담는다.
- `stocks`에는 감시 중일 때 읽은 보유종목과, 감시 중이 아닐 때 기억이 있는 종목이 종목코드마다 하나씩 든다. 신용 보유분 줄은 넣지 않는다.
- `status`가 `waiting`이면 `reason`에 계산 대기의 이유를 담는다. `crossed`·`tracking`이라도 지금 갱신이 멈췄으면(`no_session`, `chart_failed` 등) `reason`에 그 이유를 담는다.
- `basis`는 `short_ma`·`long_ma`를 계산한 봉 주기와 기간이다. 값이 없으면 `null`이다. 세션이 바뀐 뒤 조회가 실패했거나 세션 밖이면 지금 `session`과 다를 수 있다.
- 실전 환경은 `watching=false`, `not_watching_reason="real"`, `stocks=[]`이다. 로그인 세션이 있어야 하고, 잘못된 환경 값은 기존 규칙대로 거부한다.
- 화면은 이 응답과 계좌 응답을 종목코드로 합쳐 상태를 정한다. 우선순위는 Trailing Stop 보기와 같은 순서다: 실전투자 → 제외종목 → 신용 줄 → 대상 아님 → `crossed`·`tracking`(멈춘 이유 붙임) → 감시 안 함 이유 → `waiting` → 감시 중인데 `stocks`에 없으면 보유종목 확인 중.

**화면**

- 보기 전환을 [기본 | Trailing Stop | Dead Cross]로 늘린다. 고른 값은 기존과 같은 브라우저 저장소 칸에 기억한다. 모르는 값이면 기본 보기다.
- Dead Cross 보기는 Trailing Stop 보기처럼 줄을 눌러 상세를 펼친다.
  - 오른쪽 값: 상태 배지
  - 정보 줄: "단기 61,230.40 · 장기 61,012.75"(값이 없으면 상태 이유)
  - 상세: 지금 세션의 봉 주기와 기간("5분봉 · 단기 5봉 · 장기 20봉"), 단기·장기 이동평균과 그 계산 기준(`basis`가 지금 세션과 다르면 "이전 기준 값 · 30분봉 · 단기 5봉 · 장기 20봉"처럼 표시), 마지막 판정 봉 시각, 발생 시각과 발생 봉, 활성 세션 여부, 제외종목 여부, 상태와 이유
  - 매도 버튼, 거래소 확인 불가 안내, 매도 가능 수량 표시는 그대로 둔다.
- 상태 배지 문구: "계산 대기", "추적 중", "데드크로스 발생". 이유는 "켜진 세션 없음", "실전투자", "제외종목", "대상 아님 · 신용" 등 가운뎃점으로 잇는다.
- 계산할 수 없는 값은 "–"로 보인다. 시각은 투자 환경의 시간대로 보이고, 날짜가 오늘이 아니면 날짜를 붙인다. 봉 시각은 봉의 시작 시각이다.
- 목록 위에 안내를 둔다: "이동평균은 완료된 봉의 종가로 계산하며 진행 중인 봉은 넣지 않습니다. 키움 차트처럼 정규장 밖 봉도 포함합니다. 상태만 계산하고 팔지 않습니다."
- 3초 갱신, 탭이 숨으면 멈춤, 조회 실패 안내는 Trailing Stop 보기와 같다. 상태를 받는 훅은 Trailing Stop 보기의 것과 같은 방식으로 쓰되, 공유할 수 있으면 함께 쓴다.
- Dead Cross 설정 화면의 준비 중 안내 문구를 Solution에 적은 대로 바꾼다.

**로그**

- 이벤트: 감시 시작·중단, 보유종목 다시 읽기(이유, 종목 수, 대상 아님 수), 차트 조회(요청 ID, apiId, 종목, 봉 주기, 페이지 수, 받은 봉 수, 완료 봉 수, 결과), 판정(종목, 봉, 단기·장기 이동평균, 결과), 하향 돌파, 풀림, 기억 삭제(이유), 기록 읽기·쓰기 실패, 상태 조회 실패.
- 판정한 봉이 하향 돌파도 풀림도 아니면 DEBUG로 남긴다. 상태 조회는 실패만 INFO 이상으로 남긴다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 확인한다. 서버는 HTTP 응답, 키움으로 나간 요청, 데이터 폴더의 파일로 확인한다. 화면은 사용자가 보는 글자와 보내는 요청으로 확인한다. 감시 내부 클래스와 이동평균 함수는 직접 부르지 않는다.
- **서버 (pytest)**: Trailing Stop 상태 테스트와 같은 방식으로 한다. 가짜 키움(잔고와 차트 응답, 요청 본문에 따라 고르는 응답), 가짜 실시간 연결(내 계좌 체결), 고정 시계, 임시 데이터 폴더로 실제 앱을 띄우고 상태 조회 API로 확인한다.
  - 진행 중인 맨 앞 봉은 이동평균에 들어가지 않음, 분봉 완료 경계(시작 + 봉 주기와 같으면 완료), 일봉은 오늘 행 제외
  - 미국 24시 넘는 `cntr_tm`과 뉴욕 시각, 국내 가격 부호
  - 하향 돌파 경계(직전 단기 = 장기, 이번 단기 < 장기), 이미 낮은 상태로 시작하면 추적 중
  - 늦게 들어온 봉과 조회 실패 뒤 빠진 봉을 차례로 판정해 하향 돌파를 잡음, 차례 판정 중 다시 올라 풀림
  - 발생 유지(세션 밖, 다음 날, 재시작), 풀림 세 가지(다시 이상, 전량 매도, 제외종목 저장)
  - 봉 주기가 다른 세션으로 바뀌면 새 설정으로 다시 계산, 발생은 남음
  - 세션 밖 완료 봉을 다음 세션 시작에서 판정
  - 봉 부족, 차트 조회 실패, 대상 아님 세 가지, 매입가 없음은 계산함, 실전 환경은 조회하지 않음, 켜진 세션 없음
  - 필요한 페이지만 조회(평소 국내 1페이지, 미국 2페이지), 쌓인 봉을 채울 때는 마지막 판정 봉까지 이어서 조회, 과거 범위가 끝나면 최신 봉 하나만 판정, 봉이 끝난 5초 뒤 조회
  - 기간만 바꿔도 새 기준으로 다시 계산함
  - 조회 중 제외종목 저장·전량 매도·세션 변경이 일어나면 그 응답을 버림
  - 조회 차례마다 보유종목을 다시 읽어, 체결을 받지 못한 매수·매도를 반영함. 체결 등록 거부 동안 이유 표시
  - 차트 조회 실패 뒤 같은 세션에서 다시 시도해 빠진 봉을 판정함(일봉 포함)
  - 세션 밖 전량 매도로 기억이 지워지고, 다시 시작해도 되살아나지 않음
  - 같은 날 일봉을 판정한 뒤 다시 시작해도 이동평균 값이 보이고 상태는 그대로임
  - 설정을 바꾼 뒤 조회가 실패하면 `basis`가 이전 기준을 담음
  - 조회 한 차례가 봉 주기보다 오래 걸려도 차례가 겹치지 않고 합쳐지며, 마지막 판정 봉이 뒤로 가지 않음
  - 조회 실패 때 추적 중·데드크로스 발생은 그대로이고 이유만 붙음
  - 공유 실시간 연결이 밀려나면 판정을 멈추고 `connection_replaced`를 돌려줌
  - 깨진 기록 파일은 판정을 멈추고, 고친 뒤 설정 저장으로 다시 시작함
  - **모든 테스트에서 매도 주문 TR이 한 번도 나가지 않음**
  - 차트 조회·하향 돌파 로그가 요청 ID와 필수 칸을 담음
- **화면 (Playwright e2e)**: Trailing Stop 보기 e2e처럼 `/api` 응답을 가로채 확인한다.
  - 세 보기 전환과 새로고침 뒤 유지
  - 세 상태와 계산 대기 이유 표시, 멈춘 발생 종목의 이유 표시
  - 이동평균 자리수(국내 둘째, 미국 넷째), 값이 없을 때 "–"
  - 설정 요약, 활성 세션 여부, 제외종목 여부
  - 3초 갱신과 탭이 숨으면 멈춤, 조회 실패 안내
  - 모바일 폭에서 잘리지 않음
  - 기본·Trailing Stop 보기의 기존 e2e가 모두 통과함
- 기존 테스트, lint, 타입 검사, 화면 빌드가 모두 통과해야 한다.

## Further Notes

- 봉이 끝난 직후 키움 데이터에 그 봉이 얼마나 늦게 반영되는지는 재지 못했다. 차례 판정으로 늦은 봉도 다음 조회에서 판정하므로 결과는 같고, 표시만 한 봉 늦을 수 있다.
- 국내 60분봉에서 15:00 봉이 15:30 뒤 시간외 거래를 담는지는 확인하지 못했다. 키움 봉을 그대로 쓰므로 판정에는 영향이 없다.
- 자동 매도를 붙일 때 `.scratch/dead-cross/issues/02-next-stage-decisions.md`의 남은 판정 규칙(트리거 횟수, 실패 재시도, 겹침, 호출 한도)을 정한다. 이번 실측으로 봉 수·과거 범위·`base_dt`/`strt_dt` 방향·기간 상한 항목은 답이 나왔다.
- 알려진 한계: 체결 연결이 끊긴 동안 다 팔았다가 다시 산 종목은 다음 다시 읽기에도 보유 중으로 나와 예전 기록(데드크로스 발생 등)이 남는다. Trailing Stop과 같은 한계이며 자동 매도 전에 다시 본다.
- 판정 기록 파일은 `data/` 볼륨 안에 생기므로 Docker 배포에 따로 설정할 것은 없다.
