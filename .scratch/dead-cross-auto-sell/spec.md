# Dead Cross 자동 매도

Status: ready-for-agent

## Problem Statement

Dead Cross는 지금 상태만 계산한다. 모의투자 환경에서 하향 돌파를 판정해 계좌 확인의 Dead Cross 보기에 보여 주지만, 데드크로스 발생이 되어도 매도 주문은 나가지 않는다.

이제 판정 결과대로 실제로 팔고 싶다. 자동 매도는 사용자의 최종 확인 없이 돈이 움직이는 일이므로 다음이 지켜져야 한다.

- 실전투자에서는 감시도 주문도 일어나지 않는다.
- 같은 하향 돌파로 주문이 반복되지 않는다.
- 상태만 계산하던 때의 오래된 데드크로스 발생으로 배포 직후 팔리지 않는다.
- 전량 체결되어 종목이 목록에서 사라져도 왜, 얼마나 팔렸는지 볼 수 있다.

## Solution

모의투자 환경의 켜진 Dead Cross 세션에서 차트를 조회해 판정을 끝까지 돌린 뒤, 그 종목이 **데드크로스 발생**이면 **매도 가능 수량** 전량을 시장가로 파는 **자동 매도**를 낸다. 공용 자동 매도를 그대로 쓰므로 투자 환경과 종목마다 진행 중인 자동 매도는 하나뿐이고, 체결 알림에는 "Dead Cross 자동 매도"가 붙는다.

자동 매도를 따로 켜는 스위치는 없다. Dead Cross 세션을 켜는 것이 곧 그 세션에서 자동 매도를 허락하는 것이다.

매도가 실패하거나 일부만 체결되어 아직 보유 중이고 데드크로스 발생이 남아 있으면, 켜진 Dead Cross 세션이 새로 시작될 때 첫 판정 뒤 한 번 더 낸다. 풀렸으면 내지 않는다.

Dead Cross 설정 화면 위쪽에 감시 상태와 최근 자동 매도 목록을 두고, 계좌 확인의 Dead Cross 보기에는 데드크로스 발생 종목의 자동 매도 진행 상황을 보인다. 접수, 실패, 결과 확인 불가는 Discord로 알린다.

## Implementation Decisions

**언제 파는가**

- 차트 응답을 반영해 그 종목의 판정을 끝낸 뒤에 확인한다. 다음을 모두 만족하면 자동 매도를 낸다.
  - 데드크로스 발생이다.
  - 마지막 판정의 기준과 화면 값의 기준이 지금 세션의 기준과 같다. 기준이 바뀐 뒤 봉이 모자라 풀림을 판정하지 못했으면 내지 않는다.
  - 이번 세션 실행에서 그 발생 봉으로 시도한 적이 없다.
- 이 한 규칙이 첫 매도와 다시 시도를 함께 다룬다. 세션 실행이 새로 시작되면 시도 기록이 비므로 첫 판정 뒤 다시 시도한다. 서버 재시작도 새 실행이다.
- 차트 조회가 실패한 종목은 판정하지 않으므로 내지 않는다. 평균 매입가가 바뀐 것을 처리한 조회에서도 내지 않는다.
- 이번 판정에서 하향 돌파가 일어나 남아 있으면 첫 시도, 그 밖에는 다시 시도다. 알림과 목록에 이 구분을 담는다.
- 조회 차례는 주문 결과를 기다리지 않는다. 매도는 따로 돌린다.
- 공용 자동 매도를 이름 "Dead Cross"로 부른다. 투자 환경과 종목마다 진행 중인 자동 매도 하나, 주문 직전 잔고 재확인, 시장가 전량, 체결 알림 표시는 이 공용 규칙을 그대로 따른다.
- 차트 조회의 요청 ID를 판정, 자동 매도, 주문 키, 체결 알림까지 이어 쓴다.
- 미국 종목은 읽어 둔 보유종목의 거래소로 보낸다.
- 같은 세션에서 기준만 바꿔 저장해도 시도 기록은 그대로다.

**보내기 직전 확인**

- 키움에 보내기 직전에 다음이면 보내지 않고 이유를 로그에 남긴다: 감시가 멈춤(`stopped`), 세션 실행이 바뀜(`session_changed`), 같은 세션에서 기준이 바뀜(`basis_changed`), 제외종목이 됨(`excluded`), 기억이 없어짐(`forgotten`), 발생 봉이 달라졌거나 풀림(`released`).
- 주문 직전에 다시 읽은 평균 매입가가 기억과 다르면 발생을 풀고 보내지 않는다(`purchase_price_changed`).
- 보내지 않은 종목은 발생이 남아 있으면 다음 세션에 다시 시도한다.

**평균 매입가**

- 데드크로스 발생 여부와 관계없이 기억마다 그 보유종목의 평균 매입가를 둔다. 기억의 값이 없으면 다시 읽은 값으로 채운다.
- 보유종목을 다시 읽을 때와 주문 직전에 값이 다르면 체결을 받았든 아니든 발생을 푼다. 팔고 다시 샀을 수 있으므로, 차트를 받으면 그 조회의 가장 최근 완료 봉까지를 판정한 것으로 두고 새 평균 매입가를 기억하며 그 조회에서는 팔지 않는다. 재매수 이전의 하향 돌파가 차례 판정으로 되살아나지 않게 하려는 것이다.
- 추가 매수로도 같은 처리를 한다. 그 조회의 가장 최근 봉에서 일어난 하향 돌파는 놓칠 수 있고, 다음 하향 돌파 때 판다. 잘못되더라도 팔지 않는 쪽이다.
- 차트 조회가 실패하면 기억의 값을 그대로 두어 다음 조회에서 같은 처리를 한다.
- 어느 쪽이든 매입가가 없으면 비교하지 않는다.

**세션**

- 시세가 아니라 시계로 움직이므로 그 시장 날짜가 토·일이면 Dead Cross 세션이 없는 것으로 본다. 감시와 상태 조회의 지금 세션이 같은 규칙을 쓴다. 다른 자동매매 기능의 세션은 바뀌지 않는다.
- 평일 휴장일은 다루지 않는다. 주문이 거부되면 다음 세션에 다시 시도한다.

**판정 기록 파일**

- 형식을 버전 2로 올린다.
- 종목 기억에 `purchase_price`(문자열 소수 또는 `null`)를 더한다.
- 파일 맨 위에 `recent_sells`를 더한다. 최신이 앞이고 10건까지다. 항목은 `code`, `name`, `crossed_bar`, `retry`와 아래 `auto_sell`의 칸이다. 주문을 보내기 전에 `sending`으로 저장하고 결과로 갱신한다. 서버가 시작할 때 남아 있는 `sending`은 `failed`, 이유 `unknown`으로 바꾼다.
- 버전 1 파일을 읽으면 기억을 모두 버리고 빈 버전 2로 다시 쓴다. 한 번만 일어난다. 모든 종목은 처음 보는 종목처럼 가장 최근 완료 봉 하나만 판정한다.
- 그 밖의 파일 규칙(임시 파일 바꿔치기, 읽지 못하면 `state_unreadable`)은 그대로다.

**자체 서버 API**

`GET /api/environments/{environment}/dead-cross/status`에 둘을 더한다.

- `recent_sells`: 위 기록 그대로, 최신부터. 감시하지 않는 환경은 `[]`이다.
- `stocks[].auto_sell`: 이번 세션 실행에서 그 종목의 가장 최근 시도. 없으면 `null`이다. 모양은 Trailing Stop과 같다.
  - `state`: `sending`, `accepted`, `failed`
  - `reason`(`failed`일 때만): `rejected`, `unknown`, `in_progress`, `no_sellable`, `cancelled`
  - `quantity`, `order_no`
  - `at`: 결과가 나온 시각, `sending`이면 시작한 시각. UTC ISO 8601이다.

**화면**

- Dead Cross 설정 화면의 안내 둘째 문단: "하향 돌파가 일어나면 매도 가능 수량 전량을 시장가로 팝니다(모의투자만). 토·일에는 동작하지 않습니다. 종목별 상태는 계좌 확인 화면의 Dead Cross 보기에서 확인하세요."
- 설정 화면 안내 아래에 "감시 상태" 패널을 둔다. 다른 기능의 설정 화면은 바뀌지 않는다. 3초마다 상태를 받고 탭이 숨으면 멈춘다.
  - 감시 상태: "감시 중" 또는 "감시 안 함 · <이유>". 지금 세션과 기준을 함께 보인다.
  - 최근 자동 매도: 최신부터 시각, 종목명(코드), 수량, 결과(보내는 중 포함), 주문번호, 이유, "다시 시도" 표시. 없으면 "최근 자동 매도가 없습니다".
  - 시각은 투자 환경의 시간대로 보이고, 오늘이 아니면 날짜를 붙인다.
  - 조회가 실패하면 마지막 값과 실패 안내를 보인다.
- 계좌 확인의 Dead Cross 보기 안내를 "하향 돌파가 일어나면 매도 가능 수량 전량을 시장가로 팝니다(모의투자만)."로 바꾼다.
- `crossed`인 종목의 상세에 "자동 매도" 칸을 다음 순서로 정해 보인다.
  1. 감시 중이 아니고 이유가 `no_session`이면 "세션 밖 · 다음 세션에 매도"
  2. 감시 중이 아니고 그 밖의 이유면 칸 없음
  3. `auto_sell`이 `null`이면 "다음 조회에서 매도"
  4. `sending`이면 "보내는 중"
  5. `accepted`이면 "접수 · 주문번호 · 수량 · 시각"
  6. `failed`이면 "실패 · 다음 세션에 다시 시도 · <이유>"
- 이유 문구는 Trailing Stop과 같다: 거부, 결과 확인 불가, 다른 자동 매도 진행 중, 매도 가능 수량 없음, 보내기 전 취소.
- 좁은 화면 배지는 상태 이름만 보이고, 자동 매도 값은 펼친 상세에 둔다.

**Discord 알림**

- 접수(`accepted`), 실패(`rejected`), 결과 확인 불가(`unknown`)만 보낸다. `in_progress`, `skipped`, `cancelled`는 로그만 남긴다. 하향 돌파만으로는 보내지 않는다.
- 칸: 투자 환경, 종목(미국은 거래소 포함), Dead Cross 세션, 봉 주기와 기간, 단기·장기 이동평균(판정한 가장 최근 완료 봉), 발생 봉, 주문 수량, 주문번호. 다시 시도면 "시도: 다시 시도"를 더한다.
- 판정에 수익률을 쓰지 않으므로 수익률 칸이 없고 색은 모두 회색이다. 손익은 기존 체결 알림에서 본다.
- 실패 설명은 "다음 Dead Cross 세션에 다시 시도합니다."이고, 확인 불가 설명은 SL / TP와 같다.

**로그**

- 이벤트: `dead_cross_auto_sell_started`(code, run, attempt=`trigger`|`retry`, crossed_bar), `dead_cross_auto_sell_finished`(outcome, quantity, order_no, cause), `dead_cross_send_refused`(reason), `dead_cross_notified`, `dead_cross_released`(reason=`purchase_price_changed`), `dead_cross_judging_restarted`(code, judged_bar, 이전·새 평균 매입가), `dead_cross_record_migrated`(cleared_codes).

**실전투자 차단**

- 지금처럼 실전투자 환경에는 감시를 만들지 않고, 키움 client의 주문 허용 검사가 주문 TR을 한 번 더 막는다(ADR 0003).

**키움 TR**

- 차트는 상태 보기가 쓰는 `ka10080`, `ka10081`, `usa06011`, `usa06012`를 그대로 쓴다. 명세를 `kra-docs`로 다시 확인했고 달라진 것이 없다.
- 주문은 공용 자동 매도가 쓰는 기존 국내·미국 매도 주문 TR을 그대로 쓴다.
- 모의투자는 같은 TR을 1.2초에 1번 보낸다. 종목 30개면 조회 한 차례가 약 36초라 1분봉에서도 대체로 맞다. 종목이 더 많으면 판정이 늦어지고, 차례 판정이 빠진 봉을 채운다. 세션이 한 차례 조회보다 짧으면 조회가 취소되어 뒤쪽 종목이 판정되지 않을 수 있다. 개인 계좌 규모에서는 드물어 받아들였다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 확인한다. 감시 내부 메서드나 판정 기록 모듈을 직접 부르지 않는다.
- 새 테스트 경계는 만들지 않고 기존 경계 두 개를 쓴다.
- **서버(pytest):** 실제 앱을 띄우고 키움, 실시간 연결, Discord, 시계, 데이터 폴더만 가짜로 둔다. 키움으로 나간 요청, 상태 조회 API, Discord 메시지, 판정 기록 파일로 확인한다. 앞선 예는 Dead Cross 감시 테스트와 Trailing Stop 자동 매도 테스트다.
  - 하향 돌파 때 전량 시장가 매도(국내·미국)와 주문 내용
  - 세션 밖 하향 돌파가 다음 세션에 팔림, 같은 판정에서 풀리면 안 팔림
  - 다음 봉에서 같은 발생 봉으로 다시 내지 않음, 풀렸다 다시 하향 돌파하면 같은 세션에서 다시 냄
  - 결과별(접수, 거부, 결과 모름, 매도 가능 수량 0, 진행 중, 보내기 전 취소) 처리와 다음 세션·재시작의 다시 시도
  - 다시 시도 전에 풀리거나 차트 조회가 실패하면 내지 않음, 일부 체결 뒤 남은 수량을 다음 세션에 팖
  - 같은 종목의 SL / TP 자동 매도가 진행 중이면 보내지 않음
  - 평균 매입가: 다시 읽을 때와 주문 직전에 발생이 풀리고 주문 없음, 재시작 뒤 재매수 이전의 하향 돌파로 팔리지 않음(추적 중이던 종목 포함), 차트 조회 실패 뒤 다음 조회에서 같은 처리, 매입가가 없으면 비교 없이 팖
  - 보내기 직전 확인: 세션 끝, 기준 변경, 제외종목 추가, 풀림, 감시 멈춤이면 주문 없음
  - 토·일에 세션과 차트 조회가 없고 월요일에 판정함
  - 버전 1 기록이 비워지고 그 데드크로스 발생만으로는 주문이 나가지 않음, 버전 2 기록이 재시작 뒤 이어짐
  - 실전 환경은 주문 TR 0건
  - Discord 칸, 체결 알림의 "Dead Cross 자동 매도", 상태 API의 `auto_sell`과 `recent_sells`, 10건 제한, 주문 응답 전 종료 뒤 재시작하면 목록에 결과 확인 불가로 남음, 로그의 요청 ID와 필수 칸
- **화면(Playwright e2e):** `/api` 응답을 가로채 사용자가 보는 문구로 확인한다. 앞선 예는 Dead Cross 상태 e2e다.
  - 설정 화면의 감시 상태, 멈춘 이유, 최근 자동 매도 목록, 빈 목록, 조회 실패
  - 자동 매도 칸의 값과 실패 이유 문구, 좁은 화면 배지
  - 바뀐 안내 문구, 기존 Dead Cross·계좌 e2e 통과
- 기존 테스트, lint, 타입 검사, 화면 빌드, e2e가 모두 통과해야 한다.

- 자동 매도를 따로 켜고 끄는 스위치

- 기준 차이나 확인 봉으로 잦은 교차를 거르는 것. 이런 종목은 제외종목에 넣는다
- 최근 자동 매도 목록에 체결 결과를 맞춰 넣는 것

- 지정가 매도, 일부 수량 매도
- 자동매매 감시 코드의 큰 중복 정리

## Further Notes

- 모의투자에서 사람이 확인할 것: 실제 접수와 체결 알림 표시, 평일 휴장일 주문에 대한 키움 응답, 국내 15:20 이후 동시호가 시간대의 시장가 주문 처리.
