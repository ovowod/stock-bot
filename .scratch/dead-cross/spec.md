# Dead Cross 설정 화면 (매도 동작 제외)

Status: ready-for-agent

## Problem Statement

보유종목의 가격 흐름이 꺾일 때 팔고 싶다. SL / TP와 Trailing Stop은 평균 매입가 대비 수익률이나 고점을 기준으로 판다. 그래서 수익률과 관계없이 추세가 아래로 돌아선 것을 신호로 팔 방법이 없다. 차트에서 흔히 쓰는 방식은, 짧은 기간의 이동평균이 긴 기간의 이동평균 아래로 내려가는 것(하향 돌파)을 추세 전환으로 보는 것이다.

자동 매도를 붙이기 전에, Dead Cross를 하루 중 언제, 어떤 봉 주기와 이동평균 기간으로 동작시킬지, 어떤 종목은 팔지 않을지를 투자 환경마다 정해 두는 화면과 저장 기능이 먼저 필요하다. 봉 주기는 키움이 실제로 주는 차트만 고를 수 있어야 한다. 매도 동작이 붙기 전에 실전투자 환경에 켜 둔 설정이 남아 있다가, 나중에 실제 매도가 갑자기 시작되는 일도 없어야 한다.

## Solution

왼쪽 메뉴의 **자동매매** 묶음에서 Trailing Stop 바로 아래에 **Dead Cross** 메뉴를 둔다. 화면은 선택한 투자 환경의 설정을 보여주며, 구성은 SL / TP와 Trailing Stop 화면과 같다.

- 맨 위에 **매도 방식 안내**와 **준비 중 안내**가 있다.
- 그 아래 **제외종목**이 있다. 기존 종목 검색으로 찾아 추가하고 삭제한다. 다른 기능의 제외종목과는 따로 관리한다.
- 그 아래 **Dead Cross 세션** 목록이 있다. 시각 규칙은 다른 기능의 세션과 같다. 그 시장의 **정규장** 안에만 둘 수 있고, Dead Cross 세션끼리는 겹치지 않는다. SL/TP 세션이나 Trailing Stop 세션과는 시간이 겹쳐도 된다.
- 세션마다 다음을 정한다.
  - ON/OFF 스위치(기본 OFF)
  - **봉 주기**: 그 시장의 분봉 단위와 일봉 가운데 하나
  - **단기 이동평균 기간**, **장기 이동평균 기간**: 봉 개수
- **저장** 버튼을 눌러야 서버에 저장된다.
- **실전투자** 환경에서도 설정은 저장할 수 있지만 ON 스위치는 켤 수 없다.

설정은 투자 환경마다 하나인 **자동매매 설정** 파일에 Dead Cross 칸을 더해 담는다(ADR 0004). SL / TP와 Trailing Stop의 화면과 동작은 바뀌지 않는다.

이번에는 차트 조회, 이동평균 계산, 하향 돌파 판정, 매도 주문을 하지 않는다. 설정만 저장한다.

## User Stories

**메뉴와 화면 진입**

1. As a 투자자, I want 왼쪽 메뉴의 "자동매매" 묶음에서 Trailing Stop 아래에 "Dead Cross" 메뉴가 보이기를, so that 자동매매 기능을 한곳에서 찾는다.
2. As a 투자자, I want 모바일 메뉴(서랍)에도 같은 메뉴가 보이기를, so that 휴대폰에서도 설정한다.
3. As a 투자자, I want 화면 제목이 "Dead Cross"이고 그 아래 지금 투자 환경 이름이 보이기를, so that 어느 환경을 고치는지 안다.
4. As a 투자자, I want Dead Cross 화면이 지금 선택한 투자 환경의 설정만 보여주기를, so that 다른 환경의 설정과 섞이지 않는다.
5. As a 투자자, I want 투자 환경을 바꾸면 그 환경에 저장된 설정을 새로 불러오기를, so that 네 환경을 오가며 각각 확인한다.
6. As a 투자자, I want 설정을 불러오는 동안 불러오는 중임이 보이기를, so that 빈 화면을 설정이 없는 것으로 착각하지 않는다.
7. As a 투자자, I want 설정을 불러오지 못하면 원인과 "다시 시도" 버튼이 보이고 편집할 수 없기를, so that 잘못된 상태 위에 덮어쓰지 않는다.
8. As a 투자자, I want 한 번도 저장하지 않은 환경은 제외종목도 세션도 없는 빈 설정으로 열리기를, so that 처음부터 설정을 시작한다.

**안내 문구**

9. As a 투자자, I want 화면 위쪽에 "봉 주기마다 완료된 봉의 종가로 단기·장기 이동평균(단순 이동평균)을 계산해, 단기 이동평균이 장기 이동평균을 하향 돌파하면 그 종목의 매도 가능 수량 전량을 시장가로 매도합니다. 제외종목은 매도하지 않습니다." 안내가 늘 보이기를, so that 어떤 방식으로 팔리는지 안다.
10. As a 투자자, I want "Dead Cross 자동 매도는 아직 동작하지 않습니다. 지금은 설정만 저장됩니다." 안내가 보이기를, so that 켜 둔 세션이 지금 실제로 매도한다고 오해하지 않는다.
11. As a 투자자, I want 실전투자 환경에서는 "실전투자에서는 Dead Cross 세션을 켤 수 없습니다" 안내가 보이기를, so that 스위치가 왜 막혔는지 안다.

**제외종목**

12. As a 투자자, I want 화면 위쪽에 제외종목 검색창이 있기를, so that 팔지 않을 종목을 먼저 정한다.
13. As a 투자자, I want 종목명이나 종목코드(티커)로 검색하면 종목 검색과 같은 결과가 입력창 아래에 펼쳐지기를, so that 익숙한 방식으로 찾는다.
14. As a 투자자, I want 결과의 종목을 누르면 제외종목에 추가되고 검색어가 비워지기를, so that 한 번에 추가하고 다음 종목을 찾는다.
15. As a 투자자, I want 이미 추가된 종목은 결과에 "추가됨"으로 보이고 다시 추가되지 않기를, so that 같은 종목이 두 번 들어가지 않는다.
16. As a 투자자, I want 제외종목 목록에 종목명과 종목코드(미국은 거래소도)가 보이기를, so that 어떤 종목을 뺐는지 안다.
17. As a 투자자, I want 제외종목마다 삭제 버튼이 있기를, so that 다시 팔 대상으로 돌린다.
18. As a 투자자, I want 지금 보유하지 않은 종목도 제외종목에 넣을 수 있기를, so that 나중에 살 종목을 미리 뺀다.
19. As a 투자자, I want 제외종목이 그 환경의 모든 Dead Cross 세션에 똑같이 적용된다는 것이 보이기를, so that 세션마다 따로 정해야 하는지 헷갈리지 않는다.
20. As a 투자자, I want Dead Cross의 제외종목이 SL / TP와 Trailing Stop의 제외종목과 따로 관리되기를, so that 기능마다 빼고 싶은 종목을 나눠 정한다.
21. As a 투자자, I want 검색이 실패하면 제외종목 영역에 원인이 보이기를, so that 다시 검색할지 판단한다.
22. As a 투자자, I want 제외종목이 없으면 "제외종목이 없습니다"가 보이기를, so that 모든 보유종목이 대상임을 안다.

24. As a 투자자, I want 세션 영역에 그 시장의 정규장(국내 09:00–15:30 한국시간, 미국 09:30–16:00 뉴욕시간)이 보이고, 미국은 오늘 기준 한국시간도 함께 보이기를, so that 정할 수 있는 범위를 안다.

26. As a 투자자, I want 마지막 세션이 정규장 끝까지 차 있으면 "세션 추가"가 막히고 이유가 보이기를, so that 더 넣을 수 없는 이유를 안다.

30. As a 투자자, I want 앞 세션의 종료와 다음 세션의 시작이 같은 것(10:00–11:00, 11:00–12:00)은 허용되기를, so that 쉬는 시간 없이 이어지는 세션을 만든다.
31. As a 투자자, I want Dead Cross 세션이 SL/TP 세션이나 Trailing Stop 세션과 같은 시간대에 있어도 저장되기를, so that 여러 기능을 같은 시간에 함께 쓴다.

**봉 주기**

62. As a 투자자, I want 새로고침하거나 탭을 닫으면 브라우저가 경고하기를, so that 입력을 잃지 않는다.

**화면 크기**

63. As a 투자자, I want 모바일 폭에서도 제외종목·세션 영역이 가로 스크롤 없이 보이기를, so that 휴대폰에서도 설정한다.

**기록**

64. As a 운영자(나), I want Dead Cross 설정의 조회·저장·거부·읽기 실패가 투자 환경, 요청 ID, 결과, 원인과 함께 로그에 남기를, so that 문제가 생기면 로그만 보고 언제 무엇이 실패했는지 안다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **Dead Cross**, **Dead Cross 세션**, **봉 주기**, **이동평균**, **단기 이동평균 기간 / 장기 이동평균 기간**, **하향 돌파**를 더했다. 코드·로그·화면 문구도 이 이름을 따른다.
- 화면 안에서는 "세션"으로 줄여 쓴다. 그 밖에서는 늘 "Dead Cross 세션"이라고 쓴다.

**키움 TR (kra-docs로 확인, 이번에는 부르지 않는다)**

- 봉 주기 선택지의 근거는 다음과 같다. 모두 모의투자를 지원한다(국내는 KRX, 미국은 NYSE·NASDAQ·AMEX).
  - 국내 분봉 `ka10080`의 `tic_scope`: 1·3·5·10·15·30·45·60분
  - 국내 일봉 `ka10081`
  - 미국 분봉 `usa06011`의 `tic_scope`: 1·3·5·10·15·30·40·60·120분
  - 미국 일봉 `usa06012`
- 틱봉(`ka10079`, `usa06010`)은 넣지 않는다. 시간이 아니라 체결 횟수로 끊겨 세션 시간과 맞지 않는다. 주·월·년·분기봉은 넣지 않는다. 세션 안에서 완료되는 일이 거의 없다.
- 명세에는 한 번에 받는 봉 개수와 과거 조회 한도가 없다. 그래서 이동평균 기간의 상한은 앱이 정한 값이며, 키움 한도가 아니다. 매도 단계에서 모의투자로 재서 조정한다.
- 설정 조회·저장은 키움을 부르지 않는다. 제외종목 검색은 기존 종목 검색 API를 그대로 쓴다.

**자동매매 설정 저장소**

- ADR 0004대로, 같은 파일(버전 2)에 `dead_cross` 칸을 더한다. 파일 버전은 올리지 않는다. 칸이 없으면 빈 설정이다.
- 저장, 읽기 실패, 깨진 파일, 실전 ON 거부, 모르는 칸 보존은 모두 지금 공용 저장소의 동작을 그대로 따른다. 기능마다 다른 것은 세션의 기준 칸뿐이다.
- 세션을 켤 수 있는지는 다른 자동매매 기능처럼 투자 환경의 **주문 허용**을 따른다(ADR 0003). 지금은 모의투자만 허용되므로 실전에서는 켤 수 없다. Dead Cross만의 예외 정책은 두지 않는다.
- 봉 주기 선택지가 시장마다 달라서, 공용 세션 검사가 기능의 기준 칸 검사에 시장도 넘기게 넓힌다. SL / TP와 Trailing Stop의 기준 칸 검사는 시장을 쓰지 않으며 동작이 바뀌지 않는다.
- 칸 형식:

```json
"dead_cross": {
  "updated_at": "2026-11-02T01:00:00+00:00",
  "excluded": [{ "code": "005930", "name": "삼성전자", "exchange": null }],
  "sessions": [
    { "start": "09:00", "end": "15:30", "enabled": true, "bar_period": "5m", "short_period": 5, "long_period": 20 }
  ]
}
```

**Dead Cross 검사 규칙 (화면과 서버가 같다. 서버가 최종 판정)**

- 제외종목과 세션 시각은 SL / TP·Trailing Stop과 같은 규칙이다.
- `bar_period`는 `null`이거나 그 시장의 선택지 가운데 하나다.
  - 국내: `1m`·`3m`·`5m`·`10m`·`15m`·`30m`·`45m`·`60m`·`1d`
  - 미국: `1m`·`3m`·`5m`·`10m`·`15m`·`30m`·`40m`·`60m`·`120m`·`1d`
- `short_period`는 `null`이거나 2~119의 정수다. `long_period`는 `null`이거나 3~120의 정수다. JSON의 true/false와 소수는 정수로 보지 않는다.
- 두 기간이 모두 있으면 단기 < 장기여야 한다. 켜짐 여부와 관계없이 검사한다.
- `enabled`가 true이면 `bar_period`, `short_period`, `long_period`가 모두 `null`이 아니어야 한다.
- 다른 기능의 세션과 시간이 겹치는지는 검사하지 않는다.

**자체 서버 API**

- `GET /api/environments/{environment}/dead-cross`
  - 응답 모양은 SL / TP·Trailing Stop과 같다: `environment`, `market`, `timezone`, `regular_hours`, `can_enable`, `updated_at`, `excluded`, `sessions`.
  - 읽기 실패: 500, `dead_cross_settings_unreadable`, "Dead Cross 설정 파일을 읽지 못했습니다."
- `PUT /api/environments/{environment}/dead-cross`
  - 요청: `excluded`, `sessions`. 그 밖의 칸은 무시한다.
  - 처리 순서는 다른 기능과 같다: 환경 검사 → 입력 검사(400) → 실전이고 켜진 세션이 있으면 403 → 파일 읽기(500) → 저장 → GET과 같은 응답.
  - 입력 검사 실패: 400, `invalid_dead_cross_settings`. 메시지에 위치를 담는다(예: "2번째 Dead Cross 세션: 단기 이동평균 기간은 장기 이동평균 기간보다 작아야 합니다.").
  - 실전 ON 거부: 403, `dead_cross_enable_not_allowed`, "실전투자에서는 Dead Cross 세션을 켤 수 없습니다." 파일은 바뀌지 않는다.
  - 쓰기 실패: 500, `dead_cross_settings_write_failed`. 기존 파일은 그대로다.
- 둘 다 로그인 세션이 있어야 하고, 다른 사이트에서 온 PUT과 잘못된 환경 값은 기존 규칙대로 거부한다.
- 저장 뒤 알릴 감시가 아직 없으므로 저장 알림은 연결하지 않는다.

**로그**

- 공용 저장소의 이벤트(`dead_cross_settings_read`·`_saved`·`_rejected`·`_unreadable`·`_write_failed`, `dead_cross_enable_refused`)를 그대로 쓴다. 투자 환경, 요청 ID, 결과, 제외종목 수, 세션 수, 켜진 세션 수, 실패 원인과 위치를 담는다.

**화면**

- "자동매매" 묶음의 Trailing Stop 아래에 기능 `Dead Cross`를 더한다. 다른 기능과 같이 투자 환경을 key로 묶어, 환경이 바뀌면 새로 그린다.
- 제외종목, 세션 시각, 세션 추가, 정규장 표시, 불러오기 실패, 저장 막대, 저장하지 않은 변경 보호는 공용 설정 화면을 그대로 쓴다.
- 봉 주기 선택, 두 기간 입력, 그 검사·안내, 요약 줄은 Dead Cross 화면에만 둔다. 봉 주기 선택지는 응답의 `market`으로 고른다. 공용 화면의 기준 칸 영역이 시장을 알 수 있게 넓힌다.
- 기간 입력 칸은 정수만 받고, 칸 뒤에 단위 "봉"을 붙인다.
- 실전 환경(`can_enable=false`)은 스위치를 OFF로 고정하고 누를 수 없게 한다(공용 화면 동작).

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 검증한다. 서버는 자체 API의 요청·응답과 데이터 폴더에 남은 파일을 보고, 화면은 사용자가 보는 것과 밖으로 나간 `/api` 요청을 본다. 내부 함수는 검증하지 않는다.
- 키움 서버(실전·모의)는 호출하지 않는다. 설정 API 테스트에서는 가짜 키움을 "부르면 실패"로 두어, 키움 호출이 없음도 함께 확인한다.
- 새 테스트 지점은 만들지 않는다. Trailing Stop 설정이 쓰는 두 곳을 그대로 쓴다.

**서버 (pytest, 기존 `create_app` + `TestClient` 방식, 데이터 폴더는 임시 폴더)**

- 파일이 없으면 GET은 빈 설정, `updated_at=null`, 그 시장의 정규장과 시간대를 돌려준다. 실전이면 `can_enable=false`, 모의면 true다.
- PUT으로 저장한 값이 GET과, 같은 폴더로 새로 만든 앱에서 그대로 읽힌다. 파일의 `dead_cross` 칸에 담긴다.
- 네 환경에 각각 다른 값을 저장해도 서로 덮어쓰지 않는다.
- Dead Cross를 저장해도 `sl_tp`·`trailing_stop` 칸과 그 `updated_at`이 그대로이고, 반대로 다른 기능을 저장해도 `dead_cross` 칸이 그대로다.
- `dead_cross` 칸만 깨진 파일이면 다른 기능의 GET도 500이고, 실전 파일의 `dead_cross` 칸에 켜진 세션이 있어도 그렇다.
- 봉 주기:
  - 국내에서 45분봉·일봉은 받고, 40·120분봉은 400이다.
  - 미국에서 40·120분봉은 받고, 45분봉은 400이다.
  - 목록 밖 값과 문자열이 아닌 값도 400이다.
- 기간:
  - 경계값(단기 2·119, 장기 3·120)은 받는다.
  - 범위 밖(1, 121), 0, 음수, 소수, 문자열, true/false는 400이다.
  - 단기 ≥ 장기는 OFF 세션이어도 400이다.
- 켜진 세션에 셋 가운데 하나라도 없으면 400이다. 꺼진 세션은 비어 있어도 받는다.
- 세션 시각 규칙(정규장 경계, 맞닿은 세션 허용, 겹침 거부)과 제외종목 규칙이 다른 기능과 같게 적용된다(대표 경우만).
- 실전 환경에 켜진 세션을 PUT하면 403이고 파일이 바뀌지 않는다.
- 잘못된 환경 값, 로그인 세션 없는 요청, 다른 사이트 출처의 PUT은 거부되고 파일이 생기거나 바뀌지 않는다.
- 로그에 저장·거부 이벤트가 환경·결과·개수와 함께 남는다.
- 기존 SL / TP·Trailing Stop 테스트가 모두 통과해, 공용 검사를 넓혀도 두 기능의 동작이 그대로임을 확인한다.
- Prior art: Trailing Stop 설정 API 테스트.

**화면 (Playwright e2e, 가짜 `/api` 응답, 기존 Trailing Stop e2e와 같은 방식)**

- "자동매매" 묶음에서 Trailing Stop 아래에 "Dead Cross" 메뉴가 데스크톱 메뉴와 모바일 서랍에 보이고, 누르면 GET 요청이 나간다.
- 두 안내 문구가 보인다. 실전 환경에서는 ON 불가 안내가 보이고 스위치가 눌리지 않지만, 시각·봉 주기·기간은 저장된다.
- 봉 주기 선택지가 국내와 미국에서 위 목록과 정확히 같다.
- 기간 칸에 "봉" 단위가 보인다. 범위 밖 값, 소수, 단기 ≥ 장기는 그 세션에 안내가 보이고 저장이 막힌다.
- 켜진 세션에 값이 빠지면 안내가 보이고 저장이 막힌다.
- 세션을 켜고 값을 정해 저장하면, PUT 본문이 화면 값과 같고 요약 줄이 보인다.
- 제외종목 추가·삭제, 세션 추가·삭제, 저장 중 편집 막힘과 실패 토스트, 불러오기 실패, 저장하지 않은 변경 확인은 대표 경우만 확인한다. 공용 화면은 SL / TP·Trailing Stop e2e가 이미 덮고 있다.
- 모바일 폭에서 가로 스크롤이 없다.
- 기존 SL / TP·Trailing Stop e2e가 모두 통과한다.

## Out of Scope

- 차트 조회, 이동평균 계산, 하향 돌파 판정, 매도 주문 등 실제 Dead Cross 자동 매도 동작.
- 실전투자 환경에서 Dead Cross 세션 켜기.
- 틱봉, 주·월·년·분기봉.
- 지수이동평균 등 단순 이동평균이 아닌 방식, 수정주가 선택.
- 키움 차트 조회 범위의 실측. 다음 단계에서 한다.
- 휴장일·단축 거래일 같은 특별한 정규장, 장전·장후 시간.
- 종목별로 다른 기준, 세션별 제외종목.
- 두 탭 동시 편집의 충돌 감지.

## Further Notes

- 매도 동작을 붙일 때 정할 것은 `issues/02-next-stage-decisions.md`에 모았다.
- 이동평균 기간 상한(120)은 앱이 정한 값이다. 국내 60분봉으로 장기 120이면 약 17거래일(하루 7개), 1분봉으로 장기 120이면 약 2시간 분량의 봉이 필요하다. 실측 결과에 따라 봉 주기마다 상한을 다르게 둘 수도 있다.
