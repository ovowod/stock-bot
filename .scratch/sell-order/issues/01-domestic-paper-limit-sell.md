# 01: 국내 모의투자 지정가 매도 주문 접수

**What to build:** 국내 계좌 확인의 보유종목마다 매도 버튼을 두고, 누르면 주문 패널이 매도 주문으로 열린다. 패널은 보유수량과 매도 가능 수량을 보여주고, 수량은 매도 가능 수량으로 채운 채 시작하며 매도 가능 수량을 넘는 주문을 막는다. 최종 확인을 거쳐 "주문하기"를 누르면 서버가 `kt00018`로 잔고를 다시 확인한 뒤 키움 `kt10001`로 지정가 매도 주문을 보낸다. 넘치거나 잔고를 확인하지 못하면 주문을 보내지 않고 실패로 알린다. 접수되면 계좌 확인을 다시 조회한다. 실전투자 환경에서는 화면과 서버 양쪽에서 막는다.

Spec: `.scratch/sell-order/spec.md` (키움 TR, 잔고 재확인, 주문 서비스 확장, 화면, 로그)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 주문 요청에 매수·매도 구분(`side`: `buy`·`sell`)이 필수로 들어간다. 없거나 그 밖의 값이면 400이고 키움을 부르지 않는다. 기존 매수 패널은 `side=buy`를 보내고, 기존 매수 동작과 테스트는 그대로 통과한다.
- [ ] 국내 지정가 매도는 `kt10001`에 `dmst_stex_tp=KRX`, `stk_cd`, `ord_qty`, `ord_uv`, `trde_tp=0`, `cond_uv` 빈 값으로 모의 도메인에 보낸다. 주문번호는 `ord_no`다.
- [ ] 처리 순서는 실전 차단(403) → 입력 검사(400) → 주문 키 중복 검사(409) → 잔고 재확인 → 주문 TR 한 번 호출이다. 매수 주문에는 잔고 조회가 나가지 않는다.
- [ ] 계좌 서비스가 한 종목의 보유수량(`rmnd_qty`)과 매도 가능 수량(`trde_able_qty`)을 돌려준다. `kt00018`을 계좌 확인과 같은 본문(`qry_tp=1`, `dmst_stex_tp=KRX`)으로 연속조회까지 받아 접두어를 뗀 종목코드로 찾는다. 신용구분 `crd_tp=00`(현금잔고) 줄만 세고, 신용 보유분만 있으면 두 수량 0, `crd_tp` 칸이 없으면 응답 형식 오류다. 같은 종목의 현금잔고가 여러 줄이면 지원하지 않는 잔고 형태로 잔고 확인 실패이고 이유에 "같은 종목이 여러 줄"을 적는다. 매도 가능 수량이 비었거나 깨졌으면 확인 실패, 종목이 없으면 두 수량 0이다.
- [ ] 수량이 매도 가능 수량을 넘으면(미보유 포함) 400, 오류 종류 "매도 가능 수량 초과", 메시지에 매도 가능 수량을 담고 주문 TR을 부르지 않는다. 같으면 접수된다.
- [ ] 잔고 재확인이 어떤 이유로든 실패하면 502, 오류 종류 "잔고 확인 실패", "잔고를 확인하지 못해 주문하지 않았습니다"에 원인을 붙이고 주문 TR을 부르지 않는다. "접수 여부 확인 불가"로 분류하지 않는다.
- [ ] 같은 투자 환경·같은 종목의 매도는 잔고 재확인부터 주문 TR 응답(또는 실패)까지 한 번에 하나씩 처리한다. 서로 다른 주문 키로 동시에 와도 뒤 요청의 잔고 조회는 앞 요청의 주문 TR 응답 뒤에 나간다. 다른 종목의 매도는 서로 기다리지 않는다.
- [ ] 실전 환경 매도는 403이고 토큰 발급·잔고 조회·주문 요청이 하나도 나가지 않는다.
- [ ] 같은 주문 키의 두 번째 매도는 409이고 잔고 조회·주문 TR 모두 한 번뿐이다. 주문 TR 이후의 결과 분류·재전송 금지·토큰 무효 처리는 매수와 같다.
- [ ] 국내 계좌 확인의 보유종목 한 줄마다 매도 버튼이 있고(매도 가능 수량 0이어도, 실전투자에서도), 누르면 패널이 종목코드·종목명·보유수량·매도 가능 수량을 받아 매도로 열린다. 열린 동안 매수로 바꿀 수 없다.
- [ ] 매도 패널은 제목·버튼에 "매도"를 보여주고, 보유수량과 매도 가능 수량을 항상 보여준다. 수량은 매도 가능 수량, 가격은 매수와 같이 조회한 현재가로 시작한다.
- [ ] 수량이 매도 가능 수량을 넘으면 안내가 보이고 매도 버튼이 눌리지 않는다. 매도 가능 수량이 0이면 "매도 가능 수량이 없습니다" 안내와 함께 막힌다. 그 밖의 입력 검사는 매수와 같다.
- [ ] 계좌 확인의 매도 가능 수량이 `null`이면 패널에 "매도 가능 수량 확인 불가"가 보이고 수량 칸이 비어 있으며, 수량 상한 검사 없이 매도 버튼을 누를 수 있다. 보유수량이 `null`이면 "확인 불가"로 보인다.
- [ ] 최종 확인에 "매도 주문"과 매수와 같은 주문 내용이 보인다. 실전투자 패널은 주문 버튼 대신 "실전투자에서는 주문할 수 없습니다"를 보여주고 최종 확인을 열지 않는다.
- [ ] "매도 가능 수량 초과"·"잔고 확인 실패"는 서버 메시지의 실패 알림이고 패널은 입력 값과 함께 입력 화면으로 돌아간다.
- [ ] 접수되면 "매도 주문이 접수되었습니다 · 주문번호 N" 알림이 보이고, 패널이 닫히고, 계좌 확인이 다시 조회된다.
- [ ] 주문 요청 수신 로그에 매수·매도 구분이 들어가고, 잔고 재확인 결과(주문 키, 종목, 보유수량, 매도 가능 수량), 매도 가능 수량 초과 거부, 잔고 확인 실패가 기존 형식으로 남는다. 비밀값은 가려진다.
- [ ] 테스트에 신용 보유분만 있는 종목, 현금·신용이 섞인 종목, `kt00018` 문서 예제 그대로의 응답(같은 종목 현금잔고 두 줄), 서로 다른 키의 동시 매도를 포함한다.
- [ ] pytest(가짜 키움 서버)와 Playwright(가짜 `/api` 응답)로 위 동작을 검증하고, 모바일 폭에서 보유종목의 매도 버튼과 패널이 가로 스크롤을 만들지 않는다. 기존 테스트가 모두 통과한다.
