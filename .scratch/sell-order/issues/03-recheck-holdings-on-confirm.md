# 03: 최종 확인에서 잔고 다시 조회

**What to build:** 매도 패널에서 최종 확인을 열면 그 종목의 잔고를 다시 조회해 최신 보유수량과 매도 가능 수량을 보여준다. 수량이 줄었거나, 종목이 잔고에 없거나, 조회가 실패하면 "주문하기"를 막고 이유를 보여준다. 국내·미국 모두 같다.

Spec: `.scratch/sell-order/spec.md` (잔고 재확인의 자체 서버 API, 화면의 최종 확인 단계)

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [ ] 자체 서버에 `GET /api/environments/{environment}/holdings/{code}`가 있고, 01·02의 잔고 확인 기능을 그대로 쓴다. 응답은 종목코드, 보유 여부, 보유수량, 매도 가능 수량, 조회 시각이다. 미국은 티커만 받는다.
- [ ] 미보유 종목은 200에 보유 여부 false, 두 수량 0이다. 조회 실패는 기존 오류 분류(502·429 등)를 따른다.
- [ ] 매도 패널의 최종 확인을 열면 holdings 요청이 나가고, 조회하는 동안 확인 중임이 보이며 "주문하기"가 막힌다. 매수 패널은 이 요청을 보내지 않는다.
- [ ] 확인되면 최종 확인에 최신 보유수량과 매도 가능 수량이 보이고, 패널의 두 수량 표시도 최신 값으로 바뀐다. 입력한 수량은 바뀌지 않는다.
- [ ] 최신 매도 가능 수량이 입력 수량보다 적으면 "매도 가능 수량이 N주로 줄었습니다" 안내와 함께 "주문하기"가 막힌다. 취소하면 입력 수량은 그대로이고 표시 수량은 최신 값이다.
- [ ] 미보유면 "보유하고 있지 않은 종목입니다" 안내와 함께 "주문하기"가 막힌다.
- [ ] 조회가 실패하면 "잔고를 확인하지 못했습니다" 안내와 "다시 확인" 버튼이 보이고 "주문하기"가 막힌다. "다시 확인"은 다시 요청하고, 그 결과도 처음 조회와 같은 규칙으로 판정한다. 충분하면 "주문하기"가 풀리고, 부족·미보유면 각각의 안내와 함께 막힌다. 세 경우를 각각 검증한다.
- [ ] 최종 확인을 닫거나 패널을 닫으면 진행 중인 holdings 요청을 취소하고 그 응답은 반영하지 않는다.
- [ ] 실전투자에서는 최종 확인을 열지 않으므로 holdings 요청이 나가지 않는다.
- [ ] pytest와 Playwright로 위 동작을 국내·미국에서 검증한다. 기존 테스트가 모두 통과한다.
