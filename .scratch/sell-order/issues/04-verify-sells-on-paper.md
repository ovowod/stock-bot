# 04: 모의투자 서버에서 매도 직접 확인

**What to build:** 국내 모의와 미국 모의 서버에 실제로 매도 주문을 넣어, 문서로 확인되지 않은 매도·잔고 동작을 확인하고 결과를 spec에 기록한다. 실전 서버로는 조회를 포함해 어떤 요청도 보내지 않으므로, 앱에서 실전 환경을 고르지 않는다. 실전 차단은 01·02의 자동 테스트로 이미 검증한다.

Spec: `.scratch/sell-order/spec.md` (Further Notes)

**Blocked by:** 03

**Status:** ready-for-human

- [ ] 국내 모의·미국 모의 환경에서만 확인한다. 실전 환경으로 전환하지 않는다.
- [ ] 국내 보유종목에 지정가 매도를 걸어 둔 채 계좌 확인을 다시 조회해, `trde_able_qty`가 미체결 매도 수량만큼 줄어드는지 확인한다. 미국 `sell_alowq`도 같은 방식으로 확인한다. 줄지 않으면 결과를 기록하고 spec을 바꿀지 결정을 받는다. (미국 확인 완료 2026-10-06: 줄어든다. 국내 남음)
- [ ] 국내 `kt00018` 합산 조회에서 같은 종목의 현금잔고가 여러 줄 오는지, 온다면 무엇으로 나뉘는지 확인한다. 의미가 확인되면 여러 줄 처리 규칙(지금은 차단)을 다시 정할지 결정을 받는다.
- [ ] 국내·미국 모의에서 지정가·시장가 1주 매도가 접수되는지, 주문번호가 오는지 확인한다. (미국 확인 완료 2026-10-06: 지정가·시장가 접수. 국내 남음)
- [x] NYSE Arca ETF(SPY 등)를 보유하고 있다면, 종목 목록 기준 거래소(`NY`)로 보낸 매도가 접수되는지 확인한다. 거부되면 메시지를 기록한다. (2026-10-06: EWZ를 `NY`로 매도해 접수)
- [ ] 장 시간 밖 매도의 키움 거부 메시지가 알림에 어떻게 보이는지 확인한다.
- [ ] 결과를 spec 끝의 `## Implementation Notes`에 날짜와 함께 기록한다. 로그나 기록에 인증정보·토큰·계좌번호가 남지 않게 한다.
- [ ] 확인 결과로 spec이나 구현을 바꿔야 할 점이 있으면 정리해서 결정을 받는다.
