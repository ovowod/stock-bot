# 보유종목 매도 주문 (모의투자)

Status: ready-for-agent

## Problem Statement

계좌 확인에서 보유종목을 보고 있어도 그 자리에서 팔 수 없다. 주문 패널은 매수 주문만 보낼 수 있어서, 갖고 있는 종목을 정리하려면 키움 앱을 따로 열어야 한다. 자동매매로 가기 전에 모의투자에서 매도 주문도 직접 넣어 보고 접수 결과를 확인하고 싶다. 이때 키움이 알려 주는 매도 가능 수량을 넘는 주문은 키움에 보내기 전에 막아야 하고, 실전투자 계좌로 실제 매도가 나가서도 안 된다.

## Solution

계좌 확인의 보유종목마다 **매도** 버튼을 둔다. 누르면 주문 패널이 **매도 주문**으로 열리고, 종목과 보유수량, **매도 가능 수량**이 채워진다. 수량은 매도 가능 수량을 넘을 수 없다. **최종 확인**을 열 때 잔고를 다시 조회해 최신 수량을 보여주고, 서버도 주문을 보내기 직전에 잔고를 한 번 더 확인한다. 수량이 넘치거나 잔고를 확인하지 못하면 주문을 보내지 않는다. 같은 종목의 매도는 서버가 한 번에 하나씩 처리한다. 서버는 키움이 알려 준 매도 가능 수량을 기준으로 막으며, 그 값이 미체결 매도를 반영하지 않으면 키움의 거부가 마지막 방어선이다. 접수되면 계좌 확인을 새로 조회한다. **실전투자** 환경에서는 매수와 같이 화면과 서버 양쪽에서 주문을 막는다.

## User Stories

**매도 버튼과 패널 열기**

1. As a 투자자, I want 계좌 확인의 보유종목마다 매도 버튼이 있기를, so that 보유종목을 보다가 바로 판다.
2. As a 투자자, I want 매도 버튼을 누르면 주문 패널이 매도 주문으로 열리기를, so that 종목을 다시 찾지 않는다.
3. As a 투자자, I want 패널 제목과 버튼에 "매도"가 분명히 보이기를, so that 매수와 헷갈리지 않는다.
4. As a 투자자, I want 매도로 연 패널은 닫을 때까지 매도로만 남기를, so that 실수로 매수로 바꿔 주문하지 않는다.
5. As a 투자자, I want 패널에 종목명, 종목코드(티커), 거래소(미국)가 보이기를, so that 어느 종목을 파는지 안다.
6. As a 투자자, I want 패널에 보유수량과 매도 가능 수량이 함께 보이기를, so that 얼마나 팔 수 있는지 안다.
7. As a 투자자, I want 수량 칸이 매도 가능 수량(전량)으로 채워진 채 시작하기를, so that 전량 매도할 때 수량을 입력하지 않는다.
8. As a 투자자, I want 가격 칸에 패널을 열 때 조회한 현재가가 채워지기를(매수와 같은 규칙), so that 계좌를 조회한 시점의 오래된 가격으로 주문하지 않는다.
9. As a 투자자, I want 주문 유형은 매수와 같이 지정가와 시장가를 고를 수 있기를, so that 익숙한 방식으로 판다.
10. As a 투자자, I want 매도 가능 수량이 0인 종목도 매도 버튼이 보이고, 패널을 열면 "매도 가능 수량이 없습니다" 안내와 함께 주문이 막히기를, so that 왜 팔 수 없는지 안다.
11. As a 투자자, I want 매수할 수 없는 거래소의 미국 종목이 매도에서도 같은 이유로 막히기를, so that 키움이 받지 않을 주문을 보내지 않는다.
12. As a 투자자, I want 계좌 확인에서 매도 가능 수량을 읽지 못한 종목은 패널에 "매도 가능 수량 확인 불가"가 보이고 수량 칸이 비어 있기를, so that 틀린 수량을 믿지 않고, 최종 확인의 재조회로 실제 수량을 본다.

**수량 제한**

13. As a 투자자, I want 수량이 매도 가능 수량을 넘으면 안내가 보이고 매도 버튼이 눌리지 않기를, so that 거부될 주문을 보내지 않는다.
14. As a 투자자, I want 수량 검사(1주 이상, 12자리 이하 정수)와 가격 검사가 매수와 같기를, so that 매도에서만 다른 규칙을 외우지 않는다.

**최종 확인과 잔고 재확인**

15. As a 모의투자 사용자, I want 매도 버튼을 누르면 바로 전송되지 않고 최종 확인이 열리기를, so that 잘못 누른 매도가 나가지 않는다.
16. As a 모의투자 사용자, I want 최종 확인을 열 때 그 종목의 잔고를 다시 조회하고, 조회하는 동안 확인 중임이 보이기를, so that 최신 수량을 보고 판단한다.
17. As a 모의투자 사용자, I want 최종 확인에 "매도 주문", 투자 환경, 종목, 거래소, 주문 유형, 가격 또는 "시장가", 수량, 예상 주문금액, 최신 보유수량과 매도 가능 수량이 보이기를, so that 보낼 내용을 마지막으로 확인한다.
18. As a 모의투자 사용자, I want 다시 조회한 매도 가능 수량이 입력한 수량보다 적으면 "매도 가능 수량이 N주로 줄었습니다" 안내가 보이고 "주문하기"가 막히기를, so that 수량이 내 모르게 바뀌지 않는다.
19. As a 모의투자 사용자, I want 그때 입력 화면의 보유수량·매도 가능 수량 표시도 최신 값으로 바뀌기를(입력한 수량은 그대로), so that 취소하고 돌아가 바로 고친다.
20. As a 모의투자 사용자, I want 다시 조회했을 때 종목이 잔고에 없으면 "보유하고 있지 않은 종목입니다" 안내가 보이고 "주문하기"가 막히기를, so that 이미 팔린 종목을 또 팔지 않는다.
21. As a 모의투자 사용자, I want 잔고 조회가 실패하면 "잔고를 확인하지 못했습니다" 안내와 "다시 확인" 버튼이 보이고 "주문하기"가 막히기를, so that 확인되지 않은 수량으로 주문하지 않는다.
22. As a 모의투자 사용자, I want 최종 확인에서 "취소"하면 입력 값 그대로 돌아가기를, so that 고쳐서 다시 주문한다.

**서버의 마지막 확인**

23. As a 투자자, I want 서버가 매도 주문을 키움에 보내기 직전에 잔고를 다시 조회하기를, so that 화면에 문제가 있거나 그 사이 수량이 바뀌어도 넘치는 주문이 나가지 않는다.
24. As a 투자자, I want 서버가 확인한 매도 가능 수량을 넘으면 주문을 보내지 않고 "매도 가능 수량(N주)을 넘어 주문하지 않았습니다" 실패 알림을 보기를, so that 무엇을 고칠지 안다.
25. As a 투자자, I want 서버가 잔고를 확인하지 못하면 주문을 보내지 않고 "잔고를 확인하지 못해 주문하지 않았습니다" 실패 알림을 보기를, so that 주문이 나가지 않았음을 확실히 안다.
26. As a 투자자, I want 이 두 경우가 "접수 여부 확인 불가"가 아니라 실패로 보이기를, so that 나가지 않은 주문을 키움에서 찾느라 헛수고하지 않는다.
27. As a 투자자, I want 화면을 우회해 넘치는 수량의 매도 요청이 서버에 와도 키움 주문이 나가지 않기를, so that 화면 버그가 있어도 안전하다.
28. As a 투자자, I want 두 탭에서 같은 종목을 동시에 매도해도 서버가 하나씩 잔고를 확인하고 보내기를, so that 두 주문이 같은 매도 가능 수량을 함께 써 버리지 않는다.
29. As a 투자자, I want 국내 신용 보유분은 현금 매도 가능 수량에 들어가지 않기를, so that 이 화면에서 다루지 않는 신용 잔고를 현금 매도로 팔려 하지 않는다.

**실전투자 차단**

30. As a 투자자, I want 실전투자 환경에서도 매도 버튼과 패널은 보이되, 주문 버튼 대신 "실전투자에서는 주문할 수 없습니다" 안내가 보이기를, so that 실수로 실제 보유종목을 팔지 않는다.
31. As a 투자자, I want 실전투자 매도 요청이 서버에 오면 잔고 조회도 주문도 하지 않고 거부되기를, so that 실전 계좌에 어떤 주문 관련 호출도 나가지 않는다.

**전송과 결과**

32. As a 모의투자 사용자, I want 매도에도 매수와 같은 중복 주문 방지(주문 키, 전송 중 잠금, 자동 재전송 없음)가 적용되기를, so that 같은 매도가 두 번 나가지 않는다.
33. As a 모의투자 사용자, I want 접수되면 "매도 주문이 접수되었습니다 · 주문번호 N" 성공 알림을 보고 패널이 닫히기를, so that 접수됐음을 안다.
34. As a 모의투자 사용자, I want 접수되면 계좌 확인이 자동으로 새로 조회되기를, so that 줄어든 매도 가능 수량을 보고 같은 매도를 다시 넣지 않는다.
35. As a 모의투자 사용자, I want 키움 거부와 접수 여부 확인 불가는 매수와 같은 알림으로 보기를, so that 결과를 같은 방식으로 이해한다.

**기록**

36. As a 투자자, I want 매도 주문 요청, 잔고 재확인 결과(보유수량·매도 가능 수량), 수량 초과 거부, 잔고 확인 실패, 접수·거부·확인 불가가 로그에 남기를, so that 문제가 생겼을 때 어느 단계에서 멈췄는지 안다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **매도 주문**과 **매도 가능 수량**을 더했고, **주문 패널**·**지정가**·**시장가**·**최종 확인**을 매도까지 포함하도록 고쳤다.

**키움 TR**

| 용도 | 국내 | 미국 |
|---|---|---|
| 매도 주문 | `kt10001` 주식 매도주문 (`/api/dostk/ordr`) | `ust20001` 미국주식 매도 주문 (`/api/us/ordr`) |
| 잔고 재확인 | `kt00018` 계좌평가잔고내역요청 (`/api/dostk/acnt`) | `ust21070` 미국주식 원장잔고확인 (`/api/us/acnt`) |

- 모두 모의투자를 지원한다(국내 KRX, 미국 O). 주문 TR은 매수와 같은 경로를 쓰고 API ID만 다르다.
- `kt10001` 요청 본문: `dmst_stex_tp=KRX`, `stk_cd`, `ord_qty`, `ord_uv`(시장가는 빈 값), `trde_tp`(`0`·`3`), `cond_uv` 빈 값. 응답의 `ord_no`를 주문번호로 쓴다.
- `ust20001` 요청 본문: `stex_tp`(`NY`·`ND`·`NA`), `stk_cd`, `ord_qty`, `ord_uv`(시장가는 빈 값), `stop_pric` 빈 값, `trde_tp`(`00`·`03`). 응답의 `ord_no`를 주문번호로 쓴다. 응답의 `poss_qty` 등은 쓰지 않는다.
- 국내 재확인: `kt00018`을 계좌 확인과 같은 본문(`qry_tp=1` 합산, `dmst_stex_tp=KRX`)으로 연속조회까지 받아, 접두어를 뗀 종목코드로 한 줄을 찾는다. 이 TR은 종목을 지정해 조회할 수 없다. 보유수량은 `rmnd_qty`, 매도 가능 수량은 `trde_able_qty`(매매가능수량)다.
- 국내는 신용구분 `crd_tp=00`(현금잔고)인 줄만 센다. `03`(자기융자) 등 신용 보유분은 현금 매도(`kt10001`) 대상이 아니므로 세지 않는다. 신용 보유분만 있는 종목은 보유하지 않은 것과 같다(두 수량 0). `crd_tp` 칸이 없으면 응답 형식 오류다. 계좌 확인 화면은 바꾸지 않는다. 미국 `ust21070`에는 신용구분이 없다.
- 미국 재확인: `ust21070`을 `stk_cd`에 티커, `stex_tp`는 빈 값으로 조회한다. 보유종목과 주문의 거래소 표기가 다를 수 있어(아래 Further Notes) 거래소로 거르지 않는다. 보유수량은 `poss_qty`, 매도 가능 수량은 `sell_alowq`다.
- 같은 종목이 여러 줄 오면(국내는 현금잔고 줄 기준) 지원하지 않는 잔고 형태로 보고 잔고 확인 실패로 처리한다. 이유에 "같은 종목이 여러 줄"을 적는다. `kt00018` 문서 예제가 합산 조회인데도 같은 종목의 현금잔고 두 줄을 주므로, 의미를 확인하기 전에는 더하지도 고르지도 않는다(중복이면 더한 값이 넘치는 주문을 허용한다). 매도 가능 수량 칸이 비었거나 숫자가 아니면(계좌 확인은 그 칸만 비우는 깨진 값 포함) 잔고 확인 실패로 본다. 종목이 없으면 보유하지 않은 것으로 본다(보유수량·매도 가능 수량 0).

**잔고 재확인 (계좌 서비스에 추가)**

- 계좌 서비스에 "한 종목의 보유수량과 매도 가능 수량"을 돌려주는 기능을 더한다. 주문 서비스의 마지막 확인과 아래 자체 서버 API가 같은 기능을 쓴다.
- 자체 서버 API: `GET /api/environments/{environment}/holdings/{code}` (미국은 `?exchange=` 없이 티커만).
  - 응답: 종목코드, 보유 여부, 보유수량, 매도 가능 수량, 조회 시각. 보유하지 않으면 200에 보유 여부 false, 두 수량 0이다.
  - 조회 실패는 기존 오류 분류(502 키움 오류, 429 호출 제한 등)를 따른다.
  - 조회 전용이라 실전·모의 모두 받는다. 실전 화면은 최종 확인을 열지 않으므로 실제로는 부르지 않는다.

**주문 서비스 확장**

- 주문 요청에 매수·매도 구분(`side`: `buy`·`sell`)을 더한다. 필수이고 그 밖의 값이면 400이다. 화면은 매수·매도 모두 항상 보낸다.
- 처리 순서: 실전 차단(403) → 입력 검사(400) → 주문 키 중복 검사(409) → (매도만) 잔고 재확인 → 키움 주문 TR 한 번 호출.
  - 실전 차단이 맨 앞이므로 실전 매도 요청에는 잔고 조회 요청도 나가지 않는다.
  - 주문 키는 재확인 전에 등록되므로, 재확인에서 막힌 주문의 키도 다시 쓰지 않는다. 화면은 최종 확인마다 새 키를 만든다.
- 같은 투자 환경·같은 종목의 매도는 잔고 재확인부터 주문 TR 응답(또는 실패)까지 한 번에 하나씩 처리한다. 서로 다른 주문 키로 동시에 와도 뒤 요청은 앞 요청이 끝난 뒤 잔고를 다시 확인한다. 접수 여부 확인 불가 뒤에 따로 막는 규칙은 두지 않고, 다음 요청의 잔고 재확인 값을 따른다. 서버가 다시 시작되면 사라지는 메모리 안 잠금이다.
- 수량이 서버가 확인한 매도 가능 수량을 넘으면 400, 오류 종류 "매도 가능 수량 초과", 메시지에 매도 가능 수량을 담는다. 키움 주문 TR은 부르지 않는다.
- 잔고 재확인 호출이 어떤 이유로든 실패하면(연결 실패, 응답 형식 오류, 키움 오류, 호출 한도) 502, 오류 종류 "잔고 확인 실패", 메시지 "잔고를 확인하지 못해 주문하지 않았습니다"에 원인을 붙인다. 이 실패는 주문 TR을 부르기 전이므로 "접수 여부 확인 불가"로 분류하지 않는다. 잔고 조회 TR은 기존 조회 TR처럼 토큰 재발급 후 재시도를 해도 된다(주문이 아니므로).
- 주문 TR 호출 이후의 결과 분류(접수, 키움 거부, 접수 여부 확인 불가)와 재전송 금지, 토큰 무효 처리는 매수와 같다.
- 성공 응답은 매수와 같다(주문 키, 주문번호, 접수 시각).

**화면**

- 주문 패널을 여는 정보에 매수·매도 구분, 보유수량, 매도 가능 수량을 더한다. 매도로 열 때만 두 수량을 넘긴다. 패널은 열린 동안 구분을 바꾸지 않는다.
- 계좌 확인의 보유종목 한 줄마다 매도 버튼을 둔다. 국내는 종목코드·종목명, 미국은 거기에 거래소를 넘긴다. 국내 보유종목은 종목 구분을 모르므로 호가 단위는 기존 규칙대로 주식 단위를 쓴다.
- 계좌 확인 목록의 "매도가능" 표시 규칙(보유수량보다 적을 때만)은 그대로 둔다. 패널에서는 항상 두 수량을 보여준다.
- 매도 패널의 입력 검사: 매수 검사에 더해 수량 ≤ 매도 가능 수량. 매도 가능 수량이 0이면 수량 칸과 무관하게 안내를 보여주고 매도 버튼을 막는다.
- 계좌 확인에서 받은 매도 가능 수량이 없으면(`null`, 깨진 값) 패널은 "매도 가능 수량 확인 불가"를 보여주고 수량 칸을 비운 채 시작한다. 수량 상한 검사는 하지 않고 매도 버튼은 누를 수 있다. 실제 판정은 최종 확인의 재조회와 서버의 마지막 확인이 한다. 보유수량이 없으면 "확인 불가"로만 보여준다.
- 최종 확인 단계: 입력 → 최종 확인(잔고 확인 중 → 확인됨 / 수량 부족 / 미보유 / 확인 실패) → 전송 중. "주문하기"는 확인됨이고 수량 ≤ 최신 매도 가능 수량일 때만 누를 수 있다. 확인 실패에서는 "다시 확인"으로 재조회하고, 그 결과도 처음 조회와 같은 규칙(충분·부족·미보유)으로 판정한다. 최신 수량을 받으면 패널의 보유수량·매도 가능 수량 표시를 갱신하고, 입력한 수량은 바꾸지 않는다.
- 최종 확인을 닫거나 패널을 닫으면 진행 중인 잔고 조회를 취소하고 그 응답은 반영하지 않는다.
- 서버의 "매도 가능 수량 초과"와 "잔고 확인 실패"는 실패 알림(서버 메시지)이고, 입력 화면으로 돌아가 값을 남긴다.
- 성공 알림 제목은 매도면 "매도 주문이 접수되었습니다"다. 접수되면 패널을 닫고, 패널을 연 계좌 확인 화면이 다시 조회된다.
- 실전투자: 매수와 같이 주문 버튼 대신 안내를 보여주고 최종 확인을 열지 않는다.

**로그**

- 기존 형식과 마스킹을 따른다.
- 주문 요청 수신 이벤트에 매수·매도 구분을 더한다.
- 새 이벤트: 잔고 재확인 결과(주문 키, 종목, 보유수량, 매도 가능 수량), 매도 가능 수량 초과 거부(주문 키, 요청 수량, 매도 가능 수량), 잔고 확인 실패(주문 키, 오류 종류, 원인).

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 검증한다. 서버는 자체 API의 요청·응답과 가짜 키움에 실제로 나간 요청을, 화면은 사용자가 보는 것을 본다. 내부 함수나 상태 이름은 검증하지 않는다.
- 키움 서버(실전·모의)는 호출하지 않는다.

**서버 API (pytest + 가짜 키움 서버, 기존 주문·계좌 테스트와 같은 방식)**

- 국내 지정가·시장가 매도는 `kt10001`로, 미국 지정가·시장가 매도는 `ust20001`로 모의 도메인에 맞는 본문(`trde_tp`, `ord_uv` 빈 값, `dmst_stex_tp=KRX`, `stex_tp`, `stop_pric` 빈 값)과 함께 나간다.
- 매도 주문 앞에 국내 `kt00018`, 미국 `ust21070`(`stk_cd`=티커) 잔고 조회가 나간다. 매수 주문에는 잔고 조회가 나가지 않는다.
- 국내 잔고가 여러 페이지면 이어 받아 뒤 페이지의 종목도 찾는다.
- 수량이 매도 가능 수량과 같으면 접수되고, 넘으면 400 "매도 가능 수량 초과"이며 주문 TR 요청이 없다.
- 종목이 잔고에 없으면 400 "매도 가능 수량 초과"(매도 가능 0)이며 주문 TR 요청이 없다.
- 잔고 조회의 연결 실패·응답 형식 오류·키움 오류·깨진 매도 가능 수량은 "잔고 확인 실패"이고 주문 TR 요청이 없다. "접수 여부 확인 불가"가 아니다.
- 국내 신용 보유분(`crd_tp=03`)만 있는 종목은 매도 가능 0으로 거부되고, 현금·신용이 섞이면 현금잔고 줄만 센다. `crd_tp` 칸이 없으면 잔고 확인 실패다.
- `kt00018` 문서 예제처럼 같은 종목의 현금잔고가 두 줄이면 잔고 확인 실패(같은 종목이 여러 줄)이고 주문 TR 요청이 없다.
- 서로 다른 주문 키로 같은 종목을 동시에 매도하면, 뒤 요청의 잔고 조회는 앞 요청의 주문 TR 응답 뒤에 나간다. 다른 종목의 매도는 서로 기다리지 않는다.
- 실전 환경 매도는 403이고 토큰 발급·잔고 조회·주문 요청이 하나도 없다.
- `side`가 없거나 잘못되면 400이고 키움을 부르지 않는다.
- 같은 주문 키로 두 번 보낸 매도는 두 번째가 409이고, 잔고 조회·주문 TR 모두 한 번뿐이다.
- 주문 TR 이후의 연결 실패·형식 오류는 매수와 같이 "접수 여부 확인 불가"이고 재전송하지 않는다.
- holdings API: 보유 종목의 두 수량, 미보유 종목의 보유 여부 false, 조회 실패의 오류 분류.
- 로그에 잔고 재확인·수량 초과·잔고 확인 실패 이벤트가 주문 키와 함께 남고, 비밀값은 가려진다.

**화면 (Playwright e2e + 가짜 `/api` 응답, 기존 주문 패널·계좌 e2e와 같은 방식)**

- 계좌 확인의 보유종목에 매도 버튼이 있고, 누르면 "매도" 패널이 종목·보유수량·매도 가능 수량과 함께 열린다. 수량은 매도 가능 수량, 가격은 현재가 조회 값이다.
- 매도 가능 수량을 넘는 수량, 매도 가능 수량 0이면 안내가 보이고 매도 버튼이 눌리지 않는다.
- 최종 확인을 열면 holdings 요청이 나가고 최신 수량이 보인다. 수량이 줄었으면 안내와 함께 "주문하기"가 막히고, 취소하면 입력 수량은 그대로이고 표시 수량은 최신 값이다.
- 미보유 응답이면 안내와 함께 "주문하기"가 막힌다.
- 조회 실패면 "다시 확인"이 보이고, 누르면 다시 요청한다. 다시 받은 결과가 충분하면 "주문하기"가 풀리고, 부족·미보유면 각각의 안내와 함께 막힌다.
- 계좌 확인의 매도 가능 수량이 `null`이면 패널에 "매도 가능 수량 확인 불가"가 보이고 수량 칸이 비어 있으며, 수량을 입력하면 최종 확인으로 갈 수 있다.
- 주문 요청 본문에 `side=sell`이 들어간다. 매수 패널의 주문 요청에는 `side=buy`가 들어간다.
- 서버의 "매도 가능 수량 초과"·"잔고 확인 실패" 응답은 실패 알림이고(확인 불가 문구가 아님) 패널은 입력 값과 함께 남는다.
- 접수되면 "매도 주문이 접수되었습니다" 알림과 주문번호가 보이고, 패널이 닫히고, 계좌 요청이 다시 나간다.
- 실전 환경에서는 매도 패널에 안내가 보이고 holdings·주문 요청이 나가지 않는다.
- 미국 모의에서 거래소와 USD 금액이 보이고 매도 주문이 나간다.
- 모바일 폭에서 보유종목의 매도 버튼과 패널이 가로 스크롤을 만들지 않는다.

## Out of Scope

- 실전투자 매도 주문.
- 순위·종목 검색에서 연 주문 패널의 매도, 패널 안 매수·매도 전환.
- 지정가·시장가 외 매도 주문 유형. 국내 `kt10001`의 IOC·FOK·최유리·중간가·시간외·스톱지정가(`cond_uv`), 미국 `ust20001`의 LOC·MOC·VWAP·TWAP·STOP·STOP LIMIT(`stop_pric`), 예약 매도(`ust21201`)는 이후 다룬다.
- 신용 보유분 상환 매도. 현금 매도 TR(`kt10001`)만 쓴다.
- 국내 NXT·SOR 거래소 매도와 NXT 잔고.
- 비율 버튼(50%·전량 등), 체결 확인, 미체결 조회, 정정·취소 주문.
- 매도 가능 수량을 서버가 직접 계산하는 것. 키움 값을 그대로 쓴다.

## Further Notes

- 모의투자에서 직접 확인할 것:
  - 국내 `kt00018`의 `trde_able_qty`, 미국 `ust21070`의 `sell_alowq`가 미체결 매도 수량만큼 줄어드는지. 줄지 않으면 넘치는 매도는 키움 거부가 마지막 방어선이므로, 결과를 기록하고 spec을 바꿀지 결정을 받는다.
  - NYSE Arca ETF(SPY 등) 매도 주문의 `stex_tp`. 보유종목은 종목 목록 기준(NYSE)으로 보여주지만 잔고 TR은 아멕스로 준다. 매수와 같이 종목 목록의 거래소로 보내고, 거부되면 기록한다.
  - 매도 시장가 주문이 모의투자에서 접수되는지, 장 시간 밖 매도의 거부 메시지.
  - 국내 `kt00018` 합산 조회(`qry_tp=1`)에서 같은 종목의 현금잔고가 여러 줄 오는지, 온다면 무엇으로 나뉘는지(매입일, 중복 등). 의미가 확인되면 여러 줄 처리 규칙을 다시 정한다.
- 문서로 확인하지 못한 것: 매도 주문 TR의 호출 한도, 현금 매도가 보유수량을 넘으면 키움이 거부하는지, 모의투자의 신용 잔고 지원 여부.
- 잔고 재확인은 화면(최종 확인)과 서버(전송 직전) 두 번 일어나 키움 호출이 한 번 늘어난다. 서버 확인이 안전장치이고, 화면 확인은 사용자가 최신 값을 보고 판단하게 하려는 것이다.
