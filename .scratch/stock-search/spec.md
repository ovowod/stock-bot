# 종목 검색

Status: ready-for-agent

## Problem Statement

대시보드에서 특정 종목을 찾으려면 종목코드나 티커를 미리 알고 있거나 키움 앱을 따로 열어야 한다. 이름 일부만 기억나거나(예: "하이닉") 미국 종목의 티커가 헷갈릴 때(예: 애플 → AAPL) 대시보드 안에서 바로 찾을 방법이 없다. 이후 종목 조회·주문 기능을 붙이려면 먼저 종목을 찾는 기능이 필요하다.

## Solution

왼쪽 메뉴의 "시세" 분류에 **종목 검색**을 추가한다. 선택한 투자 환경의 시장(국내/미국)에서 종목명이나 종목코드(티커)로 검색하면 결과를 목록으로 보여준다. 키움에는 이름으로 검색하는 TR이 없으므로, 서버가 시장 전체의 **종목 목록**을 받아 투자 환경별로 메모리에 보관하고 그 안에서 검색한다. 목록은 첫 검색 때 받고, 한국시간으로 날짜가 바뀌면 다시 받는다. 이번에는 검색만 구현하고, 결과를 눌러 종목을 조회하거나 주문하는 기능은 만들지 않는다.

## User Stories

1. As a 투자자, I want 왼쪽 메뉴의 "시세" 분류에서 "종목 검색"을 고를 수 있기를, so that 다른 기능과 같은 방식으로 검색 화면을 찾는다.
2. As a 투자자, I want 종목 검색이 순위보다 위에 있기를, so that 자주 쓰는 검색을 먼저 찾는다.
3. As a 투자자, I want 앱을 처음 열면 지금처럼 계좌 확인이 선택되어 있기를, so that 기존 사용 흐름이 바뀌지 않는다.
4. As a 투자자, I want 검색창에 종목명이나 종목코드를 입력하기를, so that 둘 중 아는 것으로 종목을 찾는다.
5. As a 투자자, I want 입력을 멈추면 따로 버튼을 누르지 않아도 검색되기를, so that 빠르게 결과를 본다.
6. As a 투자자, I want 입력하는 도중에는 검색이 계속 다시 실행되지 않기를, so that 결과가 깜빡이지 않는다.
7. As a 투자자, I want 검색창이 비어 있으면 검색 방법 안내가 보이기를, so that 무엇을 입력해야 하는지 안다.
8. As a 국내 투자자, I want 코스피·코스닥 종목에서 검색하기를, so that 국내 상장 종목을 찾는다.
9. As a 국내 투자자, I want ETF·ETN·리츠도 검색되기를, so that 주식이 아닌 상품도 같은 방법으로 찾는다.
10. As a 미국 투자자, I want NYSE·NASDAQ·AMEX 종목과 ETF에서 검색하기를, so that 주문할 수 있는 미국 종목을 찾는다.
11. As a 투자자, I want 종목코드나 티커의 앞부분만 입력해도 찾기를(예: `0059` → `005930`, `aap` → `AAPL`), so that 코드를 다 외우지 않아도 된다.
12. As a 투자자, I want 티커를 소문자로 입력해도 찾기를, so that 대소문자를 신경 쓰지 않는다.
13. As a 투자자, I want 종목명의 일부만 입력해도 찾기를(예: "하이닉" → "SK하이닉스"), so that 정확한 이름을 몰라도 된다.
14. As a 투자자, I want 띄어쓰기가 달라도 찾기를(예: "kodex200" → "KODEX 200"), so that 띄어쓰기를 정확히 기억하지 않아도 된다.
15. As a 미국 투자자, I want 한글명과 영문명 어느 쪽으로도 찾기를(예: "애플", "apple"), so that 아는 이름으로 검색한다.
16. As a 투자자, I want 코드가 정확히 일치하는 종목이 맨 위에 오기를, so that 코드를 입력했을 때 바로 그 종목을 본다.
17. As a 투자자, I want 이름이 검색어로 시작하는 종목이 이름 중간에 포함된 종목보다 위에 오기를, so that 더 가까운 결과를 먼저 본다.
18. As a 국내 투자자, I want 결과마다 종목명, 종목코드, 종목 구분(코스피/코스닥/ETF/ETN/리츠 등), 업종을 보기를, so that 같은 이름의 종목을 구분한다.

20. As a 국내 투자자, I want 코스피 종목이 "거래소"가 아니라 "코스피"로 표시되기를, so that 용어집의 거래소 개념과 헷갈리지 않는다.
21. As a 미국 투자자, I want 결과마다 한글 종목명, 영문명, 티커, 거래소, 업종, ETF 여부를 보기를, so that 비슷한 이름의 종목을 구분한다.
22. As a 투자자, I want 결과가 많으면 50개까지만 보이고 검색어를 더 구체적으로 입력하라는 안내가 보이기를, so that 긴 목록에서 헤매지 않는다.

## Implementation Decisions

**TR**

| 시장 | TR | 요청 본문 | 목록 필드 |
|---|---|---|---|
| 국내 | `ka10099` 종목정보 리스트 (`/api/dostk/stkinfo`) | `mrkt_tp=0`(코스피), `mrkt_tp=10`(코스닥) 두 번 | `list` |
| 미국 | `usa10099` 미국주식 종목리스트 (`/api/us/stkinfo`) | `stex_tp=%`(전체) | `list` |

둘 다 모의투자를 지원한다(국내 KRX, 미국 O). 연속조회를 지원하는 TR이므로 기존 연속조회 호출을 쓴다. 모의 서버에서는 모두 한 페이지로 왔다.

**종목 목록 변환**

- 국내 `ka10099` 항목 → 종목코드 `code`, 종목명 `name`, 종목 구분 `marketName`, 업종 `upName`, 상태 `auditInfo`.
  - `mrkt_tp=0` 결과에는 코스피 주식 외에 ETF·ETN·리츠 등이 섞여 오며, 종목 구분은 `marketName`으로 나뉜다. `marketName`이 `거래소`면 "코스피"로 바꾸고, 나머지(`코스닥`, `ETF`, `ETN`, `ETN(손실제한)`, `ETN(변동성)`, `리츠`, `인프라투자금융`, `뮤추얼펀드` 등)는 받은 값을 그대로 쓴다.
  - 상태는 `auditInfo`가 `정상`이 아니고 비어 있지 않을 때만 담는다.
  - 업종 `upName`이 빈 문자열이면 `null`이다.
- 미국 `usa10099` 항목 → 티커 `stk_cd`, 한글명 `stk_nm`, 영문명 `stk_enm`, 거래소 `stex_tp`, 업종 `upgb`, ETF 여부 `isEtf`.
  - `stex_tp`가 `NY`·`ND`·`NA`인 항목만 남기고 NYSE·NASDAQ·AMEX로 바꿔 표시한다. 문서에 없는 `NP` 등은 버린다.
  - 거래소+티커가 같은 중복 항목은 첫 항목 하나만 남긴다.
  - ETF 여부는 `isEtf`가 `Y`일 때만 참이다.
- 목록 필드가 없거나 목록이 아니면 "응답 형식 오류"(502)다. 연속조회로 여러 페이지를 받을 때는 페이지마다 `list`를 검사한다. 두 번째 이후 페이지에서 `list`가 빠지거나 목록이 아니어도 502로 처리하고, 그 목록은 보관하지 않는다(첫 페이지만으로 된 불완전한 목록을 보관하지 않기 위해서다). 항목의 종목코드·종목명이 없으면 응답 형식 오류다(순위와 같은 값 처리 규칙).
- 문서에 없는 응답 필드(예: 모의 서버가 보낸 `kind`)는 쓰지 않는다.

**종목 목록 보관 (새 모듈: 종목 검색 서비스)**

- 인터페이스: "투자 환경과 검색어를 받아 검색 결과를 돌려준다".
- 종목 목록은 서버 메모리에 투자 환경별로 보관한다. 각 목록은 받은 날짜(한국시간)와 받은 시각을 함께 가진다.
- 검색할 때 그 투자 환경의 목록이 없거나, 받은 날짜가 오늘(한국시간)과 다르면 새로 받는다.
- 목록 받기는 투자 환경마다 진행 중인 받기 작업 하나를 공유한다. 받기가 진행 중일 때 들어온 검색은 새로 받지 않고 그 작업을 기다리며, 성공이든 실패든 같은 결과를 받는다. 실패가 확정된 뒤 새로 들어온 검색부터 다시 받는다. 순위 기능의 잠금과는 따로 둔다.
- 받기에 실패하면 오류를 그대로 돌려주고, 기존 목록이 있었으면 그것도 쓰지 않는다(어제 목록으로 검색하지 않는다). 실패한 결과는 보관하지 않으므로 다음 검색 때 다시 받는다.
- 국내는 `mrkt_tp=0`과 `mrkt_tp=10` 두 호출이 모두 성공했을 때만 합쳐서 보관한다.
- "오늘 날짜(한국시간)"는 서버를 만들 때 바꿔 끼울 수 있게 한다. 기본값은 실제 한국시간 날짜다. 테스트에서 날짜 변경을 흉내 내는 지점이다.

**검색 규칙**

- 검색어는 앞뒤 공백을 지운다. 비교할 때는 띄어쓰기를 모두 지우고 대소문자를 무시한다.
- 일치 단계(작을수록 위):
  0. 종목코드(티커)가 검색어와 정확히 같다.
  1. 종목코드(티커)가 검색어로 시작한다.
  2. 종목명(미국은 한글명 또는 영문명)이 검색어로 시작한다.
  3. 종목명(미국은 한글명 또는 영문명)에 검색어가 들어 있다.
- 어느 단계에도 맞지 않으면 결과에서 뺀다. 같은 단계 안에서는 종목명순, 같으면 종목코드순이다.
- 결과는 50개까지 담고, 전체 일치 개수와 잘렸는지 여부를 함께 돌려준다.

**자체 서버 API 계약**

- `GET /api/environments/{environment}/stocks?q=<검색어>`
- 응답: 투자 환경, 시장, 검색어, 전체 일치 개수, 50개로 잘렸는지 여부, 종목 목록을 받은 시각, 결과 항목 목록.
- 결과 항목 필드: 종목코드, 종목명, 영문명(국내는 `null`), 거래소(국내는 `null`), 종목 구분(미국은 `null`), 업종, 상태(미국은 `null`), ETF 여부(국내는 `null`).
- 검색어가 없거나 공백뿐이면, 또는 50자를 넘으면 "잘못된 요청"(400)으로 거부하고 키움을 호출하지 않는다.
- 잘못된 투자 환경은 기존처럼 404다. 설정 오류 503, 호출 제한 429, 키움 오류·응답 형식 오류·연결 실패 502는 기존 분류를 따른다.

**화면**

- 메뉴: "시세" 분류의 순위 위에 "종목 검색"(lucide `Search` 아이콘)을 더한다. 처음 선택되는 기능은 계좌 확인 그대로다.
- 화면 위쪽에 제목, 투자 환경 이름, 검색창을 둔다. 검색창 안내 문구는 시장에 맞게 바꾼다(국내: "종목명 또는 종목코드", 미국: "종목명(한글·영문) 또는 티커").
- 입력을 멈추고 0.3초가 지나면 검색한다. 검색어가 공백뿐이면 요청하지 않고 안내 문구를 보여준다.
- 입력이 바뀌는 즉시(검색어를 지운 경우 포함) 진행 중인 이전 요청을 취소하고, 그 응답은 반영하지 않는다. 새 요청은 입력을 멈추고 0.3초 뒤에만 보낸다.
- 상태: 안내(검색어 없음), 검색 중(이전 결과가 있으면 유지하고 검색 중 표시), 결과 목록, 결과 없음 안내, 오류(오류 종류별 메시지 + "다시 시도").
- 결과 줄: 국내는 종목명 + 종목코드·종목 구분·업종, 상태 배지. 미국은 한글명 + 티커·거래소·영문명·업종, ETF 배지. 결과는 누를 수 없는 단순 목록이다.
- 결과가 50개로 잘렸으면 목록 아래에 "50개까지만 표시합니다. 검색어를 더 구체적으로 입력하세요."를 보여준다.
- 투자 환경을 바꾸면 화면 상태(검색어, 결과)를 통째로 버리고 빈 검색창으로 시작한다.
- 모바일에서 화면 전체가 가로로 밀리지 않게 한다. 긴 이름은 줄임표로 자른다.

## Testing Decisions

- 좋은 테스트는 밖에서 보이는 동작만 확인한다. 자체 서버 API의 응답과 키움으로 나가는 요청(도메인, 경로, `api-id`, 본문, 횟수)을 확인하고, 내부 구조는 확인하지 않는다.
- **Seam 1 (주력)**: FastAPI 테스트 클라이언트로 `/api/environments/{environment}/stocks`를 호출한다. 키움 쪽은 기존 가짜 키움 서버(httpx MockTransport)에 `ka10099`(시장별)·`usa10099` 응답을 추가한다. 오늘 날짜 함수는 테스트에서 바꿔 끼운다. 확인할 동작:
  - 국내는 `ka10099`를 `mrkt_tp=0`, `10`으로, 미국은 `usa10099`를 `stex_tp=%`로 호출하는지. 모의/실전 도메인을 맞게 쓰는지.
  - 종목코드 앞부분 일치, 대소문자 무시, 종목명 부분 일치, 띄어쓰기 무시, 미국 영문명 검색이 되는지.
  - 결과 순서가 일치 단계 → 종목명순인지.
  - 50개 제한과 전체 일치 개수, 잘림 여부.
  - 국내 `거래소` → "코스피" 변환, 정상이 아닌 상태만 담기, 빈 업종은 `null`.
  - 미국 `NP` 제외, 거래소+티커 중복 제거, ETF 여부.
  - 두 번째 검색은 키움을 다시 호출하지 않는지. 날짜를 바꾸면 다시 받는지. 투자 환경마다 따로 받는지.
  - 같은 투자 환경에 동시에 들어온 첫 검색들이 목록을 한 번만 받는지. 그 받기가 실패하면 기다리던 검색 모두 같은 오류를 받고 키움을 다시 호출하지 않는지, 실패 뒤 새 검색은 다시 받는지.
  - 두 번째 페이지의 `list`가 빠지거나 목록이 아니면 502이고, 목록을 보관하지 않아 다음 검색 때 다시 받는지.
  - 국내 두 호출 중 하나가 실패하면 오류를 돌려주고 보관하지 않으며, 다음 검색 때 다시 받는지.
  - 빈 검색어, 공백뿐인 검색어, 50자 초과를 400으로 거부하고 키움을 호출하지 않는지.
  - 목록 필드 누락, 종목코드·종목명 누락이 502인지. 호출 제한이 429인지.
- **Seam 2 (화면)**: 기존 Playwright 테스트처럼 브라우저의 `/api` 요청을 가로채 가짜 응답을 준다. 확인할 동작:
  - 메뉴에서 종목 검색을 고르면 검색 화면이 나오고, 처음 화면은 여전히 계좌 확인인지.
  - 입력을 멈춘 뒤 한 번만 요청하는지(입력 중 요청이 쌓이지 않는지). 검색어가 비면 요청하지 않고 안내를 보여주는지.
  - 국내·미국 결과 항목과 상태·ETF 배지가 보이는지.
  - 결과 없음, 50개 잘림 안내, 검색 중 표시, 오류와 다시 시도.
  - 늦게 도착한 이전 검색 응답이 반영되지 않는지. 검색 중 입력을 모두 지운 뒤 이전 응답이 도착해도 안내 화면이 유지되는지, 다른 검색어로 바꾼 뒤 0.3초 대기 중에 이전 응답이 도착해도 반영되지 않는지.
  - 투자 환경을 바꾸면 검색어와 결과가 지워지는지.
  - 데스크톱(1440px)과 모바일(390px) 스크린샷, 모바일에서 가로 밀림이 없는지.
- 실제 서버 확인은 국내 모의와 미국 모의로만 한다. 실전 환경은 가짜 응답으로 화면만 확인한다.
- 화면 단위 테스트(컴포넌트 테스트)는 기존과 같이 범위에서 제외한다.

## Out of Scope

- 검색 결과를 눌러 종목 시세·차트·상세 정보를 조회하는 기능
- 주문 패널 등 거래 기능
- 관심종목 추가, 최근 검색어 저장
- K-OTC, 코넥스, ELW 등 코스피·코스닥 밖의 국내 시장
- 문서에 없는 미국 거래소 코드(`NP` 등)의 종목
- 초성 검색, 오타 보정 같은 검색 품질 기능
- 결과 순서 다듬기(예: 같은 일치 단계에서 이름이 짧은 종목이나 일반 주식을 먼저 보여주기). 지금은 같은 단계 안에서 종목명순이라 "하이닉" 검색에서 SK하이닉스보다 관련 ETF가 먼저 나온다. 검색 고도화 때 다룬다.
- 종목 목록을 직접 새로 받는 버튼, 종목 목록의 디스크 저장

## Further Notes

- 모의 서버 확인 결과(2026-10-05, 실전 서버는 호출하지 않음):
  - `ka10099` `mrkt_tp=0`은 2,480개(시장명 `거래소` 916, `ETF` 1,171, `ETN` 358, `리츠` 23 등), `mrkt_tp=10`은 1,825개가 한 페이지(`cont-yn=N`)로 왔다.
  - `ka10099`를 간격 없이 두 번(`0`, `10`) 호출해도 호출 한도에 걸리지 않았다.
  - `usa10099` `stex_tp=%`는 19,338개(약 3MB)가 한 페이지로 왔다. 거래소는 `NY` 8,391, `ND` 6,494, `NA` 3,608, 문서에 없는 `NP` 845였고, ETF(`isEtf=Y`)가 11,498개였다. `SPY`처럼 같은 거래소+티커가 두 번 나오는 항목이 있었다.
  - `ka10099` 항목에는 문서에 없는 `kind` 필드가 왔다(쓰지 않는다).
- 실전 서버의 종목 목록이 모의와 같은 형태인지는 확인하지 않았다. 실전 환경 검색은 사용자가 직접 확인한다.
- 미국 목록은 한 번에 약 3MB라, 첫 검색은 목록을 받는 만큼 더 걸린다. 서버 메모리에는 투자 환경별로 최대 네 벌이 남는다.
- 키움에는 종목 개수만 알려주는 TR이 없어서, "개수가 바뀌었을 때만 다시 받기"는 하지 않는다. 날짜가 바뀌면 다시 받는다.
- 용어는 CONTEXT.md의 종목 검색, 종목 목록, 종목 구분, 거래소를 따른다.

## Implementation Notes (2026-10-05)

- 서버에서 `ka10099`를 코스피(`0`)로 받은 직후 4ms 만에 코스닥(`10`)을 요청하자 호출 한도(HTTP 429, `return_code=5`, 메시지 안 `1700`)가 났다. 별도 스크립트로는 같은 간격에서도 통과해 정확한 한도는 알 수 없다. 두 국내 목록 호출 사이에 1초 간격을 두었고, 이후 국내 모의 검색이 정상 동작했다. 그날 첫 국내 검색만 1초 늦어진다.
- 연속조회 이어 붙이기에서, 앞 페이지에서 목록이던 필드가 다음 페이지에서 빠지거나 목록이 아니면 응답 형식 오류(502)로 처리하도록 키움 클라이언트를 고쳤다. 계좌 확인의 연속조회도 같은 규칙을 따른다.
- 국내 모의 실제 확인에서 업종명은 `전기/전자`처럼 왔다.
