# Trailing Stop 상태 보기 (자동 매도 제외)

Status: ready-for-agent

## Problem Statement

Trailing Stop 설정 화면은 있지만, 설정한 기준으로 지금 보유종목이 어떤 상태인지 알 방법이 없다. 이대로 자동 매도를 붙이면 언제, 왜 팔렸는지(또는 왜 안 팔렸는지)를 미리 확인하지 못한 채 실제 주문이 나가게 된다.

자동 매도를 붙이기 전에, 계좌 확인 화면에서 보유종목마다 Trailing Stop 기준의 수익률, 활성화 여부, 고점 대비 하락률, 상태를 보고 싶다. 이 값은 나중에 자동 매도가 판정할 값과 똑같아야 한다. 화면이 열려 있을 때만 계산하거나 당일 최고가를 고점으로 쓰면, 자동 매도가 실제로 볼 숫자와 달라져 미리 확인하는 의미가 없다.

## Solution

모의투자 환경에서는 서버가 켜진 Trailing Stop 세션 동안 보유종목의 시세 체결을 실시간으로 받는다. 이를 바탕으로 **활성화**를 판정하고 **고점**을 따라가며, **Trailing Stop 트리거**를 판정한다. 트리거가 일어나도 매도 주문은 내지 않고 상태만 바꾼다.

활성화와 고점은 그 종목을 보유하는 동안 세션과 날짜를 넘겨 기억하고, 파일에 저장해 서버를 다시 시작해도 이어 간다. 이것은 증권사 GTC Trailing Stop이나 freqtrade와 같은 방식이다(`.scratch/trailing-stop/research.md`).

계좌 확인의 보유종목 목록 위에 **[기본 | Trailing Stop]** 보기 전환을 둔다. Trailing Stop 보기에서는 각 보유종목에 다음을 보인다.

- 평균 매입가 대비 현재 수익률(수수료·세금 제외)
- 활성화 수익률 도달 여부
- 활성화 이후 고점 대비 현재 하락률
- **Trailing Stop 상태**: 활성화 대기 / 고점 추적 중 / 매도 조건 충족 / 감시 안 함 / 대상 아님 / 제외종목
- 제외종목 여부

이 보기가 열려 있는 동안 3초마다 상태를 다시 받는다. 상태 조회는 키움을 부르지 않는다.

Trailing Stop 설정 화면의 "준비 중 안내"는 "지금은 상태만 계산하고 팔지 않습니다. 계좌 확인 화면의 Trailing Stop 보기에서 확인하세요."로 바꾼다.

## User Stories

**보기 전환**

1. As a 투자자, I want 계좌 확인의 보유종목 목록 위에서 [기본 | Trailing Stop] 보기를 바꾸기를, so that 평소 화면은 그대로 두고 필요할 때만 Trailing Stop 기준으로 본다.
2. As a 투자자, I want 고른 보기가 새로고침 뒤에도 유지되기를, so that 매번 다시 고르지 않는다.
3. As a 투자자, I want 국내와 미국 투자 환경 모두에서 같은 보기 전환을 쓰기를, so that 시장마다 다른 방법을 익히지 않는다.
4. As a 투자자, I want 휴대폰 폭에서도 Trailing Stop 보기의 값이 잘리지 않기를, so that 밖에서도 상태를 확인한다.
5. As a 투자자, I want Trailing Stop 보기에서도 매도 버튼과 상세 펼치기가 그대로 동작하기를, so that 상태를 보고 바로 직접 매도 주문을 낸다.

**수익률과 활성화**

6. As a 투자자, I want 평균 매입가 대비 수익률을 시세 체결가로 계산해 보기를, so that 자동 매도가 판정할 수익률과 같은 숫자를 본다.
7. As a 투자자, I want 그 수익률이 수수료·세금을 빼지 않은 값이라는 안내를 보기를, so that 기본 보기의 키움 수익률과 다른 이유를 안다.
8. As a 투자자, I want 활성화된 종목에는 처음 활성화된 시각을 보기를, so that 언제부터 고점을 따라갔는지 안다.
9. As a 투자자, I want 아직 활성화되지 않은 종목에는 지금 수익률을 지금 시각의 세션 기준과 비교한 결과("미도달 (기준 5%)")를 보기를, so that 얼마나 남았는지 안다.

## Implementation Decisions

**용어**

- `CONTEXT.md`의 **활성화**, **고점**, **고점 대비 하락률**을 넓혔고, **Trailing Stop 트리거**와 **Trailing Stop 상태**를 더했다. 코드, 로그, 화면 문구는 이 이름을 따른다.
- 화면의 상태 이름 "매도 조건 충족"은 Trailing Stop 트리거가 일어난 상태를 뜻한다. 코드와 로그에서는 trigger라고 쓴다.

**키움 TR**

- 보유종목은 SL / TP처럼 기존 잔고 조회(국내 kt00018, 미국은 기존 잔고 TR)로 읽는다. 새 TR은 없다.
- 시세는 SL / TP처럼 공유 실시간 연결(ADR 0001)로 받는다. 국내는 0B, 미국은 FE이고, 정규장 장구분 값만 판정한다.
- **구현 전에 kra-docs로 확인한다**: 같은 연결에서 SL / TP(그룹 2)와 Trailing Stop이 같은 종목을 다른 그룹으로 등록할 때, 200종목 한도에서 어떻게 세는지 확인한다. 문서로 확인되지 않으면 추측하지 말고 사용자에게 알린다.
- 매도 주문 TR은 부르지 않는다.

**Trailing Stop 감시 (서버, 새 모듈)**

- SL / TP 감시와 같은 구조의 별도 감시를 둔다. 투자 환경마다 하나씩 둔다.
  - 모의투자 환경만 만든다. 실전투자 환경과 인증정보가 없는 환경은 만들지 않는다.
  - 설정은 자동매매 설정 저장소의 Trailing Stop 칸에서 읽는다(ADR 0004). Trailing Stop 설정을 저장하면 감시에 알린다. SL / TP 저장 알림과 같은 방식이다.
  - 켜진 Trailing Stop 세션 동안에만 보유종목을 읽고 시세를 구독한다. 세션 경계 규칙(시작 포함, 종료 제외, 맞닿은 세션은 뒤 세션)은 SL / TP와 같다.
  - 보유종목은 세션이 시작할 때, 다시 연결될 때, 내 계좌 체결이 들어올 때 다시 읽는다. 읽기 실패 시 재시도와 알림은 SL / TP와 같다.
  - 내 계좌 체결을 받으면 그 자리에서(체결 콜백 안에서) 판정을 멈추고 `holdings_pending`으로 바꾼다. 다시 읽기를 마치기 전에 받은 시세 체결은 판정하지 않는다. 체결이 대기 중인 시세보다 먼저 전달된다는 ADR 0002에 기대는 순서이며, SL / TP와 같다.
  - 연결이 밀려남(ADR 0001), 체결 등록 거부, 시세 등록 거부 때는 SL / TP와 같은 조건으로 판정을 멈추고, 같은 조건으로 자동으로 다시 시작한다.
- 대상 아님 분류는 SL / TP와 같다: 신용 보유분, 매입가 없음, 같은 종목 여러 줄, 미국 종목의 거래소 확인 불가. 이 분류는 두 기능이 같은 규칙을 함께 쓴다.
- 시세 체결 한 건의 판정은 다음 순서로 한다. 제외종목, 대상 아님, 판정할 수 없는 가격(SL / TP와 같은 규칙)은 건너뛴다.
  - 활성화 전: `가격 ≥ 평균 매입가 × (1 + 활성화 수익률/100)`이면 활성화한다. 그 가격이 첫 고점이다.
  - 활성화 뒤, 트리거 전: 가격이 고점보다 높으면 고점을 갱신한다. 아니면 `가격 ≤ 고점 × (1 − 고점 대비 하락률/100)`일 때 트리거한다.
  - 트리거 뒤: 아무것도 바꾸지 않는다.
  - 기준 값은 그 시세 체결 시각에 켜진 세션의 값을 쓴다.
- 기억(종목마다): 활성화 시각, 고점, 고점 시각, 트리거 시각, 트리거 가격.
  - 보유종목을 다시 읽었을 때 없는 종목의 기억은 버린다.
  - 감시는 기억이 있는 종목마다 마지막으로 읽은 보유 수량(현금 보유분)을 들고 있다. 매도 체결을 받으면 그 수량을 바로 빼고, 0 이하가 되면 다시 읽기를 기다리지 않고 그 자리에서 기억을 버린다. 전량 매도 직후 다시 사서, 묶여 처리된 다시 읽기에 그 종목이 보유 중으로 나와도 예전 고점이 남지 않게 하려는 것이다. 세션 밖에서도 기억이 있는 종목의 체결은 이렇게 처리하고 보유종목을 다시 읽는다.
  - Trailing Stop 설정을 저장할 때 제외종목에 든 종목의 기억은 버린다.
  - 세션 기준을 바꾸거나 일부만 팔거나 추가 매수해서 평균 매입가가 바뀌는 것만으로는 버리지 않는다.
- 감시 안 함의 이유: `no_session`(지금 켜진 세션 없음), `real`(실전투자), `holdings_pending`(보유종목 확인 중, 체결 뒤 다시 읽는 중, 읽기 실패 중), `settings_unreadable`(자동매매 설정 파일을 읽지 못함), `state_unreadable`(고점 기록을 읽지 못함), `no_credentials`(인증정보 없음), `connection_replaced`(실시간 연결이 밀려남), `fills_rejected`(주문체결 실시간 등록 거부), `quotes_rejected`(시세 실시간 등록 거부).

**고점 기록 파일**

- 데이터 폴더 아래에 투자 환경마다 파일 하나를 둔다. 자동매매 설정 파일과는 따로 둔다. 설정은 사용자가 저장할 때만 바뀌지만, 고점 기록은 장중에 계속 바뀌기 때문이다. `.env`에 새 변수는 없다.
- 형식(버전 1):

```json
{
  "version": 1,
  "stocks": {
    "005930": {
      "activated_at": "2026-11-02T01:03:00+00:00",
      "peak": "61800",
      "peak_at": "2026-11-02T02:10:12+00:00",
      "triggered_at": null,
      "triggered_price": null
    }
  }
}
```

- 쓰기는 자동매매 설정과 같이 임시 파일에 다 쓴 뒤 바꿔치기한다. 활성화, 트리거, 기억 삭제는 바로 쓴다. 고점 갱신은 모아서 5초에 한 번 쓰고, 감시를 멈출 때(세션 끝, 서버 종료) 남은 것을 쓴다.
- 파일은 서버가 시작할 때와 `state_unreadable`에서 복구할 때만 읽는다. 그 밖에는 메모리가 기준이다. 쓰기에 실패해 파일이 메모리보다 뒤처져 있을 때, 세션이 바뀌거나 설정을 저장하면서 파일을 다시 읽어 최신 고점을 되돌리지 않게 하려는 것이다.
- 파일이 없으면 빈 기록이다. 파일을 읽지 못하거나 형식이 맞지 않으면 그 환경의 판정을 멈추고 `state_unreadable`로 둔다. 빈 기록으로 대신하지 않는다. Discord로 한 번 알린다. 문구는 "Trailing Stop 고점 기록을 읽지 못해 이 환경의 Trailing Stop 판정을 멈췄습니다. 파일을 고치거나 지운 뒤 Trailing Stop 화면에서 다시 저장하면 그때부터 동작합니다. 지우면 기억하던 고점이 사라집니다."이다. `state_unreadable`인 동안 설정을 저장하면 감시가 파일을 다시 읽는다.
- 쓰기에 실패하면 메모리의 판정은 계속하고, 로그와 Discord 알림을 한 번 남긴 뒤 다음 쓰기 때 다시 시도한다.

**자체 서버 API**

- `GET /api/environments/{environment}/trailing-stop/status`
  - 키움을 부르지 않는다. 감시하는 환경은 감시의 메모리와, 감시가 쓰고 있는 설정(세션·제외종목)으로 답한다. 실행 중에 설정 파일이 깨져도 감시는 시작·저장 때 읽은 설정으로 계속 판정하기 때문이다. 감시하지 않는 환경(실전, 인증정보 없음)만 자동매매 설정 파일을 읽는다.
  - 응답:

```json
{
  "environment": "domestic_paper",
  "market": "domestic",
  "timezone": "Asia/Seoul",
  "watching": true,
  "not_watching_reason": null,
  "session": { "start": "09:00", "end": "15:30", "enabled": true, "activation_profit": "5", "drop_from_peak": "3" },
  "excluded": ["000660"],
  "stocks": [
    {
      "code": "005930",
      "status": "tracking",
      "ineligible_reason": null,
      "purchase_price": "58000",
      "last_price": "61200",
      "last_price_at": "2026-11-02T02:11:00+00:00",
      "activated_at": "2026-11-02T01:03:00+00:00",
      "peak": "61800",
      "peak_at": "2026-11-02T02:10:12+00:00",
      "triggered_at": null,
      "triggered_price": null
    }
  ]
}
```

  - `session`은 지금 시각을 포함하는 Trailing Stop 세션이다. 꺼져 있어도 담는다. 없으면 `null`이다. 실전 환경에서도 담는다.
  - `stocks`에는 감시 중일 때 읽은 보유종목과, 감시 중이 아닐 때 기억이 있는 종목이 종목코드마다 하나씩 든다. 신용 보유분 줄은 넣지 않는다. 같은 코드의 현금 보유분이 감시 대상이면 그 줄의 상태다. `status`는 `waiting`(활성화 대기), `tracking`(고점 추적 중), `triggered`(매도 조건 충족), `ineligible`(대상 아님) 가운데 하나다. `ineligible_reason`은 `no_purchase_price`, `duplicate`, `unknown_exchange` 가운데 하나다.
  - `purchase_price`는 서버가 판정에 쓰는 평균 매입가다. 판정 대상이 아니면 `null`이다.
  - 가격은 문자열 소수다. 시각은 UTC ISO 8601이다.
  - 실전 환경은 `watching=false`, `not_watching_reason="real"`, `stocks=[]`이다.
  - 로그인 세션이 있어야 하고, 잘못된 환경 값은 기존 규칙대로 거부한다.
- 계좌 API(국내·미국)의 보유종목 줄에 신용 보유분인지(`credit`)를 더한다. 미국은 늘 `false`다. 기존 칸은 바뀌지 않는다.
- 화면은 이 응답과 계좌 응답을 합쳐 상태를 정한다. 신용 줄은 `stocks`와 합치지 않고, 나머지 줄은 종목코드로 합친다. 우선순위는 다음과 같다.
  1. 실전 환경이면 감시 안 함 · 실전투자
  2. 제외종목
  3. 신용 줄이면 대상 아님 · 신용
  4. `stocks`의 `ineligible`
  5. `stocks`의 `triggered`·`tracking`. 감시 중이 아니면 이유를 붙인다. 이유가 `no_session`이면 "세션 밖, 갱신 멈춤", 그 밖에는 멈춘 이유다.
  6. 감시 중이 아니면 감시 안 함(이유 표시)
  7. `stocks`의 `waiting`
  8. 감시 중인데 `stocks`에 없으면 감시 안 함 · 보유종목 확인 중
- 수익률 계산에 쓰는 값: 가격은 `last_price`가 있으면 그것을, 없으면 계좌 응답의 현재가를 쓴다. 평균 매입가는 `purchase_price`가 있으면 그것을, 없으면 계좌 응답의 값을 쓴다. 추가 매수 뒤 계좌를 새로고침하지 않아도 서버 판정과 같은 수익률이 보이게 하려는 것이다.

**화면**

- 보유종목 목록 위에 [기본 | Trailing Stop] 전환을 둔다. 고른 값은 브라우저 저장소에 기억한다. 저장소를 쓸 수 없으면 기본 보기로 둔다.
- Trailing Stop 보기에서는 넓은 화면도 좁은 화면처럼 줄을 눌러 상세를 펼친다. 정보 줄에는 핵심 하나(활성화됐으면 고점 대비 하락률, 아니면 도달 여부)만 두어 줄마다 높이가 같다. 기본 보기는 그대로다.
- Trailing Stop 보기에서는 기존 목록 부품의 오른쪽 값, 정보 줄, 상세 칸을 바꾼다.
  - 오른쪽 값: 상태 배지와 수익률
  - 정보 줄: 도달 여부, 고점 대비 하락률
  - 상세: 고점, 고점 시각, 활성화 시각, 트리거 시각과 가격, 지금 세션 기준, 제외종목 여부
  - 매도 버튼, 거래소 확인 불가 안내, 매도 가능 수량 표시는 그대로 둔다.
- 계산할 수 없는 값은 기존 화면의 빈 값 표시 "–"로 보인다. 화면 전체의 빈 값 표시와 맞추려고 처음 정한 "—" 대신 이것을 쓴다. 평균 매입가나 가격이 없거나 0이면 수익률과 도달 여부가, 고점이 없으면 하락률이 그렇다.
- 도달 여부는 "미도달 (기준 5%)", "도달 (세션 밖)"(켜진 세션 없음), "도달 (감시 안 함)"(장애·실전투자로 멈춤), "도달 (판정 전)"(감시 중이지만 계좌 현재가로만 기준을 넘었고 그 가격의 시세 체결은 아직 판정하지 않음), "기준 없음 (세션 없음)"(지금 시각을 포함하는 세션 없음), "기준 없음"(그 세션에 활성화 수익률 없음), "–"(가격·매입가를 몰라 계산할 수 없음) 가운데 하나다. "–"이면 넓은 화면 정보 줄에서는 뺀다.
- 좁은 화면의 상태 배지는 상태 이름만 한 줄로 보이고, 이유까지 담은 상태는 줄을 눌러 펼친 상세의 "상태"에 둔다. 활성화된 종목은 "도달 · 시각"이다.
- 하락률은 "고점 대비 −1.0%"처럼 보인다. 수익률은 기존 부호·색 규칙(parts의 Change)을 따른다. 미국은 기존 외화 표기를 따른다.
- 시각은 투자 환경의 시간대로 보인다. 날짜가 오늘이 아니면 날짜를 붙인다.
- Trailing Stop 보기가 열려 있고 탭이 보이는 동안 3초마다 상태를 다시 받는다. 처음 열 때와 탭이 다시 보일 때는 바로 받는다. 계좌 잔고는 지금처럼 직접 새로고침할 때만 받는다.
- 상태 조회가 실패하면 마지막 값을 두고 목록 위에 실패 안내를 보인다. 한 번도 받지 못했으면 상태 칸을 "—"로 둔다.
- 목록 위에 "수익률은 시세 체결가 기준이며 수수료·세금은 빼지 않습니다. 고점은 켜진 세션 동안의 체결가로 정합니다." 안내를 둔다.
- Trailing Stop 설정 화면의 준비 중 안내 문구를 Solution에 적은 대로 바꾼다.

**로그**

- 이벤트: 감시 시작·중단·재개, 보유종목 다시 읽기(이유, 종목 수, 대상 아님 수), 활성화, 트리거, 기억 삭제(이유), 고점 기록 읽기·쓰기 실패, 상태 조회.
- 활성화와 트리거 로그에는 투자 환경, 요청 ID, 종목코드, 가격, 평균 매입가, 적용한 기준, 고점을 담는다.
- 고점 갱신은 시세 체결마다 남기지 않는다. 고점 기록을 쓸 때 갱신된 종목 수만 DEBUG로 남긴다.
- 상태 조회 로그는 실패만 INFO 이상으로 남긴다. 3초 갱신이 로그를 채우지 않게 한다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 확인한다. 서버는 HTTP 응답·키움으로 나간 요청·Discord 메시지·데이터 폴더의 파일로, 화면은 사용자가 보는 글자와 보내는 요청으로 확인한다. 감시 내부 클래스와 메서드는 직접 부르지 않는다.
- **서버 (pytest)**: SL / TP 자동 매도 테스트와 같은 방식이다. 가짜 키움(잔고 응답), 가짜 실시간 연결(시세 체결 메시지), 고정 시계, 임시 데이터 폴더로 실제 앱을 띄운다. 상태 조회 API로 결과를 확인한다. 기존 SL / TP 테스트의 도우미를 함께 쓰거나 같은 모양으로 만든다.
  - 활성화 경계(기준과 같으면 활성화), 트리거 경계(기준과 같으면 트리거), 고점 갱신, 활성화 뒤 다시 내려가도 유지, 트리거 뒤 다시 올라도 유지
  - 세션 밖 시세 체결과 정규장 밖 장구분은 판정하지 않음, 세션 사이 고점 유지, 뒤 세션의 하락률 적용
  - 날짜를 넘겨 유지: 시계를 다음 날로 옮긴다.
  - 재시작해도 유지: 같은 데이터 폴더로 앱을 다시 띄운다.
  - 전량 매도 뒤 기억 삭제(세션 밖 체결 포함), 전량 매도 직후 다시 사서 다시 읽기가 묶여도 기억 삭제, 일부 매도·추가 매수 뒤 유지, 제외종목 저장 뒤 기억 삭제
  - 추가 매수 뒤 `purchase_price`가 새 평균 매입가로 바뀜
  - 체결을 받은 직후 같은 메시지나 다시 읽는 도중의 시세 체결은 판정하지 않음, 다시 읽는 도중 체결이 또 오면 마지막 체결까지 반영한 뒤 판정함
  - 연결이 밀려남, 체결 등록 거부, 시세 등록 거부 때 판정을 멈추고 이유를 돌려주며 복구되면 다시 판정함
  - 대상 아님 네 가지(신용은 `stocks`에서 빠지고 같은 코드의 현금 보유분은 감시됨), 실전 환경은 감시하지 않음, 켜진 세션 없음
  - 깨진 고점 기록 파일은 판정을 멈추고 알리며, 고친 뒤 설정 저장으로 다시 시작함
  - 쓰기에 실패한 채 세션이 바뀌거나 설정을 저장해도 메모리의 고점과 트리거가 유지됨
  - **모든 테스트에서 매도 주문 TR이 한 번도 나가지 않음**
  - 활성화·트리거 로그가 요청 ID와 필수 칸을 담음
- **화면 (Playwright e2e)**: 기존 SL / TP, Trailing Stop, 계좌 화면 e2e처럼 `/api` 응답을 가로채 확인한다. 키움이나 실전 서버를 부르지 않는다.
  - 보기 전환과 새로고침 뒤 유지
  - 상태 여섯 가지와 이유 표시, 세션 밖 활성화 종목과 장애로 멈춘 활성화 종목의 구분, 도달 여부 세 가지 표시
  - 실전 환경의 제외종목도 감시 안 함 · 실전투자, 현금·신용 같은 코드 두 줄의 상태 구분
  - `purchase_price`로 계산한 수익률, 기준·매입가·가격이 비거나 0일 때 "—"
  - 3초 갱신과 탭이 숨으면 멈춤, 조회 실패 안내
  - 국내·미국 금액 표기, 모바일 폭에서 잘리지 않음
  - 기본 보기의 기존 e2e가 모두 통과함
- 기존 테스트, lint, 타입 검사, 화면 빌드가 모두 통과해야 한다.

## Out of Scope

- 실제 Trailing Stop 자동 매도 주문, 그 결과 알림, 체결 알림의 "Trailing Stop 자동 매도" 표시
- 같은 종목에서 SL / TP 트리거와 Trailing Stop 트리거가 겹칠 때의 처리
- 트리거 시 Discord 알림
- 세션 밖 가격을 분봉 등으로 채워 고점에 넣는 것
- 고점 기록을 화면에서 지우거나 고치는 기능
- 실전투자 환경의 감시

## Further Notes

- 자동 매도를 붙일 때 정할 것:
  - 트리거된 채 남아 있는 종목(이번 단계에서 실제로 팔지 않았기 때문)을 자동 매도가 켜지는 순간 바로 팔지, 기억을 지우고 시작할지
  - SL / TP와 같은 종목에서 겹칠 때(**자동 매도** 규칙대로 하나만 진행)
  - 매도가 거부되거나 결과를 모를 때 트리거 상태를 어떻게 할지
- 알려진 한계: 서버가 꺼져 있거나 연결이 끊긴 동안 전량 팔고 다시 산 종목은 체결을 받지 못해 알아낼 수 없고, 예전 고점이 남는다. 자동 매도를 붙이기 전에 다시 본다(예: 다시 읽은 보유 수량·평균 매입가를 기록과 비교).
- 알려진 한계: 서버를 다시 시작한 뒤 보유종목을 처음 다시 읽기 전에는 보유 수량을 모른다. 그사이 전량 팔고 바로 다시 사서 다시 읽기가 묶이면 예전 고점이 남는다. 판정할 수 없게 된 종목(대상 아님)도 보유 수량을 들고 있지 않아 매도 체결로 바로 버리지 못하고, 다시 읽어 보유하지 않을 때 버린다. 자동 매도 전에 실시간 잔고 항목과 함께 다시 본다.
- 알려진 한계: 다시 읽은 보유종목에 이미 반영된 매도 체결이 그 뒤에 들어오면 수량을 두 번 빼서, 아직 보유 중인 종목의 기억을 일찍 버릴 수 있다. 한 주문이 여러 번에 나눠 체결될 때 생길 수 있다. 일찍 버리면 고점을 잃을 뿐 잘못 팔리는 쪽은 아니어서 받아들였다. 자동 매도 전에 키움의 실시간 잔고 항목으로 보유 수량을 받는 방법을 kra-docs로 확인한다.
- 다음 날 시가가 고점 대비 하락률보다 낮게 시작하면 첫 시세 체결에서 바로 트리거된다. 다른 시스템과 같은 동작이다.
- 고점 기록 파일은 `data/` 볼륨 안에 생기므로 Docker 배포에 따로 설정할 것은 없다.
- 고점 기록을 자동매매 설정 파일과 따로 두는 결정은 필요하면 ADR로 남긴다.
