# 04: 고점 기록 파일과 기억 지우기 규칙

**What to build:** 활성화와 고점이 날짜를 넘기고 서버를 다시 시작해도 이어진다. 세션 밖에서 전량 팔거나 제외종목에 넣은 종목의 기억은 지워진다. 고점 기록 파일이 깨지면 판정을 멈추고 알리며, 고친 뒤 설정을 저장하면 다시 동작한다. 세션 밖에서도 활성화된 종목은 Trailing Stop 보기에 "고점 추적 중 · 세션 밖, 갱신 멈춤"으로 보인다.

Spec: `.scratch/trailing-stop-status/spec.md` (Trailing Stop 감시의 기억, 고점 기록 파일, 자체 서버 API, 화면)

**Blocked by:** 03

**Status:** ready-for-agent

- [x] 투자 환경마다 데이터 폴더 아래 고점 기록 파일 하나를 spec의 형식(버전 1)으로 둔다. 자동매매 설정 파일과 따로 둔다. `.env`에 새 변수는 없다.
- [x] 쓰기는 임시 파일에 다 쓴 뒤 바꿔치기한다. 활성화·트리거·기억 삭제는 바로 쓰고, 고점 갱신은 5초에 한 번 모아서 쓰며, 감시를 멈출 때(세션 끝, 서버 종료) 남은 것을 쓴다.
- [x] 서버가 시작할 때 기록을 읽어 이어 간다. 파일이 없으면 빈 기록이다. 그 밖에는 `state_unreadable`에서 복구할 때만 파일을 읽고, 세션이 바뀌거나 설정을 저장할 때는 메모리를 그대로 쓴다.
- [x] 파일을 읽지 못하거나 형식이 맞지 않으면 그 환경의 판정을 멈추고 `state_unreadable`로 둔다. Discord로 spec의 문구를 한 번 알린다. 파일을 고치거나 지운 뒤 Trailing Stop 설정을 저장하면 다시 읽고 동작한다.
- [x] 쓰기에 실패하면 메모리 판정은 계속하고 로그와 Discord 알림을 한 번 남기며, 다음 쓰기 때 다시 시도한다.
- [x] 세션 밖에서도 기억이 있는 종목에 내 계좌 체결이 들어오면 03과 같이 매도 수량을 바로 빼서 0 이하면 기억을 버리고, 보유종목을 다시 읽어 없으면 기억을 버린다.
- [x] Trailing Stop 설정을 저장할 때 제외종목에 든 종목의 기억을 버린다. 세션 기준만 바꾼 저장으로는 버리지 않는다.
- [x] 상태 조회 API가 감시 중이 아닐 때도 기억이 있는 종목을 `stocks`에 담는다. 화면은 이 종목을 "고점 추적 중" 또는 "매도 조건 충족"으로 보이고, 이유가 `no_session`이면 "세션 밖, 갱신 멈춤"을, 그 밖에는 멈춘 이유를 붙인다.
- [x] 로그: 기록 읽기·쓰기 실패(경로, 원인), 기억 삭제(이유)를 남긴다. 고점 기록을 쓸 때 갱신된 종목 수를 DEBUG로 남긴다.
- [x] 테스트(pytest, 앱 전체를 HTTP로): 시계를 다음 날로 옮겨도 유지, 같은 데이터 폴더로 앱을 다시 띄워도 유지, 세션 밖 체결 뒤 전량 매도면 삭제·일부 매도면 유지, 제외종목 저장 뒤 삭제, 깨진 파일은 판정 중단·알림·저장으로 재개, 쓰기 실패 알림, 쓰기에 실패한 채 세션이 바뀌거나 설정을 저장해도 메모리의 고점·트리거 유지, 다음 날 첫 시세 체결이 하락률 아래면 바로 트리거됨을 확인한다. **모든 테스트에서 매도 주문 TR이 한 번도 나가지 않는다.**
- [x] 테스트(Playwright): 세션 밖 활성화 종목과 매도 조건 충족 종목 표시, `state_unreadable`로 멈춘 활성화 종목이 "세션 밖"이 아니라 멈춘 이유로 보임을 확인한다.
- [x] 기존 테스트, lint, 타입 검사, 화면 빌드가 모두 통과한다.

## Comments

- 파일: `data/trailing-stop/<환경>.json`(국내 모의 `domestic_paper.json`, 미국 모의 `us_paper.json`). 형식은 spec의 버전 1이고 종목코드 순으로 쓴다. 가격은 끝의 0을 뗀 문자열 소수, 시각은 초까지의 UTC ISO 8601이다(상태 조회 API와 같은 표기). 읽기·쓰기는 `trailing_stop/record.py`에 두었고, 임시 파일에 쓴 뒤 바꿔치기하는 부분은 자동매매 설정 파일과 같은 함수(`auto_trading/settings.py`의 `write_atomic`)로 뽑아 함께 쓴다.
- 형식 검사: version이 1, `stocks`가 객체, 종목마다 `activated_at`·`peak`·`peak_at`이 있고 시각은 시간대가 붙은 ISO 8601, 가격은 양수 문자열 소수, `triggered_at`과 `triggered_price`는 함께 있거나 함께 비어야 한다. 하나라도 어긋나면 파일 전체를 읽지 못한 것으로 본다.
- 읽기 순서: 서버가 시작할 때 자동매매 설정보다 먼저 읽는다. 설정 파일이 깨져 있어도 기억을 잃지 않고, 그 뒤 첫 쓰기가 기억을 빈 기록으로 덮어쓰지 않게 하려는 것이다. `state_unreadable`인 동안은 쓰지 않아 깨진 파일을 그대로 둔다. Trailing Stop 설정을 저장하면(기준만 바꾼 저장도) 다시 읽고, 고치지 않은 채 저장하면 다시 알리지 않고 멈춰 있다.
- 쓰기 실패: 처음 실패할 때 한 번 알리고(제목 "Trailing Stop 고점 기록 저장 실패", 문구는 spec에 없어 새로 정했다), 쓰기가 다시 성공하면 `trailing_stop_record_write_recovered`를 남기고 다음 실패 때 다시 알린다. 서버를 끄는 중의 마지막 쓰기가 실패하면 알림은 보낼 수 없어 로그만 남긴다.
- 알림 로그 이벤트를 `trailing_stop_stop_notified`에서 `trailing_stop_notified`(reason: `holdings_failing`, `state_unreadable`, `record_write_failed`)로 합쳤다. 쓰기 실패는 판정 중단이 아니기 때문이다.
- 세션 밖 체결: 기억이 있는 동안에는 세션 밖에서도 내 계좌 체결을 받는다(기억이 없어지면 해지한다). 서버가 세션 밖에 시작해도 기억이 있으면 체결 등록 때문에 실시간 연결을 연다. 기억이 있는 종목의 체결이면 매도 수량을 빼고, 기억이 남아 있으면 보유종목을 다시 읽어 현금잔고가 없는 종목의 기억만 버린다. 시세 구독·판정은 하지 않는다. 세션 밖 다시 읽기가 실패하면 다시 시도하지 않고 로그만 남긴다. 다음 체결이나 다음 세션 시작의 다시 읽기가 반영한다.
- 상태 조회: 자동매매 설정 파일을 읽지 못할 때도 기억이 있는 종목을 `stocks`에 담도록 바꿨다(전에는 빈 목록). 화면이 "고점 추적 중 · 설정 파일을 읽지 못함"으로 보이게 하려는 것이다. `state_unreadable`일 때는 읽은 기억이 없어 `stocks`가 비어 있으므로, Playwright의 "고점 추적 중 · 고점 기록을 읽지 못함"은 가짜 응답으로만 확인했다.
- 화면 코드는 바꾸지 않았다. 03에서 이미 이유를 구분하고 있어, 이번에는 e2e 테스트만 더했다.
