# 03: 세션 중 활성화·고점·트리거 판정

**What to build:** 모의투자 환경의 켜진 Trailing Stop 세션 동안 서버가 보유종목의 시세 체결을 받아 활성화, 고점, Trailing Stop 트리거를 판정한다. Trailing Stop 보기는 활성화 대기, 고점 추적 중, 매도 조건 충족, 대상 아님 상태와 고점·하락률·시각을 보인다. 매도 주문은 내지 않는다. 이 티켓의 기억은 서버 메모리에만 있다.

Spec: `.scratch/trailing-stop-status/spec.md` (키움 TR, Trailing Stop 감시, 자체 서버 API, 화면, 로그)

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [x] 시작 전에 kra-docs로 같은 연결에서 SL / TP와 Trailing Stop이 같은 종목을 다른 그룹으로 등록할 때 실시간 시세 200종목 한도를 어떻게 세는지 확인한다. 문서로 확인되지 않으면 추측하지 않고 사용자에게 알린다.
- [x] 모의투자 환경만 감시한다. 켜진 세션 동안 보유종목을 읽고 시세를 구독하며, 세션이 시작할 때·다시 연결될 때·내 계좌 체결이 들어올 때 보유종목을 다시 읽는다. 공유 실시간 연결을 쓰고 SL / TP와 다른 그룹 번호를 쓴다.
- [x] 내 계좌 체결을 받으면 체결 콜백 안에서 바로 판정을 멈추고 `holdings_pending`으로 바꾼다. 다시 읽기를 마치기 전에 받은 시세 체결은 판정하지 않는다(ADR 0002, SL / TP와 같음).
- [x] 매도 체결을 받으면 마지막으로 읽은 현금 보유 수량에서 바로 빼고, 0 이하가 되면 다시 읽기를 기다리지 않고 그 종목의 기억을 버린다.
- [x] 연결이 밀려남, 체결 등록 거부, 시세 등록 거부 때 SL / TP와 같은 조건으로 판정을 멈추고 `connection_replaced`·`fills_rejected`·`quotes_rejected`로 돌려주며, 같은 조건으로 다시 시작한다.
- [x] Trailing Stop 설정을 저장하면 감시가 새 설정을 바로 쓴다.
- [x] 판정은 spec의 순서를 따른다. 활성화는 `가격 ≥ 평균 매입가 × (1 + 활성화 수익률/100)`, 트리거는 `가격 ≤ 고점 × (1 − 고점 대비 하락률/100)`이다. 기준 값은 그 시세 체결 시각에 켜진 세션의 값이다. 정규장 장구분이 아니거나 판정할 수 없는 가격은 건너뛴다.
- [x] 활성화 뒤 다시 내려가도 활성화가 유지되고, 트리거 뒤 다시 올라도 매도 조건 충족이 유지되며 고점을 갱신하지 않는다.
- [x] 서버가 켜져 있는 동안 기억은 세션 사이에도 이어진다. 보유종목을 다시 읽었을 때 없는 종목의 기억은 버린다. 일부 매도·추가 매수로는 버리지 않는다.
- [x] 상태 조회 API가 감시 중에는 `watching=true`, 읽은 보유종목을 종목코드마다 하나씩 `stocks`에 담는다(`waiting`·`tracking`·`triggered`·`ineligible`, `purchase_price`·`last_price` 포함). 신용 보유분 줄은 넣지 않고, 같은 코드의 현금 보유분은 감시한다. 보유종목을 아직 읽지 못했으면 `holdings_pending`이다.
- [x] 화면: 상태 배지, 고점 대비 하락률("고점 대비 −1.0%"), 도달 시각("도달 · 11/01 10:03"), 상세의 고점·고점 시각·활성화 시각·트리거 시각과 가격·지금 세션 기준을 보인다. 감시 중인 종목의 수익률은 `last_price`와 `purchase_price`로 계산한다. 하락률은 고점이 없으면 "—"다. 시각은 투자 환경의 시간대이고 오늘이 아니면 날짜를 붙인다.
- [x] Trailing Stop 설정 화면의 준비 중 안내를 "지금은 상태만 계산하고 팔지 않습니다. 계좌 확인 화면의 Trailing Stop 보기에서 확인하세요."로 바꾼다.
- [x] 로그: 감시 시작·중단·재개, 보유종목 다시 읽기, 활성화, 트리거, 기억 삭제를 남긴다. 활성화·트리거 로그는 투자 환경, 요청 ID, 종목코드, 가격, 평균 매입가, 적용한 기준, 고점을 담는다. 고점 갱신은 시세 체결마다 남기지 않는다.
- [x] 테스트(pytest, 앱 전체를 HTTP로): 활성화·트리거 경계(같으면 일어남), 고점 갱신, 활성화 뒤 하락 유지, 트리거 뒤 상승 유지, 세션 밖·정규장 밖 시세 체결 무시, 세션 사이 기억 유지와 뒤 세션 하락률 적용, 보유에서 빠지면 삭제, 전량 매도 직후 다시 사서 다시 읽기가 묶여도 삭제, 일부 매도·추가 매수 뒤 유지, 추가 매수 뒤 `purchase_price` 갱신, 체결 직후 같은 메시지와 다시 읽는 도중의 시세 체결 미판정, 다시 읽는 도중 체결이 또 오면 마지막 체결까지 반영한 뒤 판정, 밀려남·체결 등록 거부·시세 등록 거부 때 멈춤과 복구, 대상 아님 네 가지(현금·신용 같은 코드 두 줄 포함), 실전 미감시, 로그 칸을 확인한다. **모든 테스트에서 매도 주문 TR이 한 번도 나가지 않는다.**
- [x] 테스트(Playwright): 활성화 대기·고점 추적 중·매도 조건 충족·대상 아님과 이유, 고점·하락률·시각 표시, `purchase_price`로 계산한 수익률, 장애로 멈춘 활성화 종목의 "고점 추적 중 · <멈춘 이유>", 미국 표기를 확인한다.
- [x] 기존 SL / TP 테스트를 포함해 기존 테스트, lint, 타입 검사, 화면 빌드가 모두 통과한다.

## Comments

- **200종목 한도 (확인하지 못함)**: kra-docs의 0B·FE 명세에는 `grp_no`가 "여러 종목을 한번에 묶어서 등록/해제 시 사용"이라는 설명뿐이다. 200종목 한도 자체가 kra-docs에 없고(openapi.kiwoom.com/intro의 "세션 당 실시간 시세 200종목"이 근거), 같은 종목을 그룹 2와 3에 함께 등록할 때 한 번으로 세는지 두 번으로 세는지, 키움이 시세를 두 번 보내는지, 그룹 3의 `refresh=0`(기존 등록 해지 후 등록)이 다른 그룹의 같은 종목 등록에 영향을 주는지도 문서로 확인되지 않는다. 추측하지 않고 spec 결정대로 그룹 3을 따로 쓴다. 모의투자에서 직접 확인이 필요하다.
  - 공유 연결은 시세를 그룹이 아니라 실시간 항목(0B·FE)으로 기능에 나눠 주므로, 두 그룹이 같은 종목을 등록해도 각 기능은 자기 보유종목만 판정한다. 같은 시세가 두 번 와도 판정 결과는 같다(같은 가격으로 활성화·고점·트리거가 다시 바뀌지 않는다).
- 구조: `trailing_stop/watch.py`에 `TrailingStopWatcher`(환경마다 `_Watch`)를 새로 두었다. SL / TP 감시를 공통 부품으로 뽑지 않고, 세션 실행·보유종목 다시 읽기(재시도·합치기·5분 알림)·연결 추적·구독을 Trailing Stop용으로 작게 다시 썼다. SL / TP 테스트가 `sl_tp.watch`의 상수와 `_Watch._on_event`를 monkeypatch하므로, 뽑아내면 기존 테스트를 고치지 않고는 통과시킬 수 없었다. 대신 시세 항목(`QUOTE_TYPES`)과 등록 항목 만들기(`quote_items`)만 `auto_trading/judging.py`로 옮겨 함께 쓴다. 감시는 AutoSell·OrderService를 받지 않는다.
- 보유 수량을 알려고 `Holdings.positions`의 줄에 `quantity`를 더했다. 그 모양을 그대로 비교하던 `tests/account/test_holdings.py` 하나를 고쳤다.
- 상태 조회는 감시 중이 아닐 때 기억이 있는 종목을 `stocks`에 담는다(04의 API 항목과 같은 코드다). 03에서는 기억이 세션 사이에만 이어지므로, 장애로 멈춘 활성화 종목이 "고점 추적 중 · <멈춘 이유>"로 보이게 하는 데 썼다. 감시 중이 아니면 `purchase_price`·`last_price`는 비워 화면이 계좌 값을 쓴다. 감시를 시작하기 전(lifespan 없이 띄운 앱)은 `no_session`이다.
- `last_price`는 실행(세션)이 바뀌면 지운다. 앞 세션의 가격이 다음 세션의 수익률로 보이지 않게 하려는 것이다.
- 밀려남은 SL / TP와 같이 서버를 다시 시작해야 다시 동작한다(자동 복구 없음). 체결 등록 거부는 체결 feed가 다시 등록하면 보유종목을 다시 읽고 판정을 잇고, 시세 등록 거부는 다음 세션 시작·감시 종목 변경·재연결 때 다시 등록된다.
- Discord 알림은 보유종목 5분 연속 읽기 실패("Trailing Stop 판정 중단")만 보낸다. 구독 거부는 상태 조회의 이유와 로그로만 알린다. 자동매매 설정 파일을 읽지 못하면 같은 파일로 SL / TP가 이미 알리므로 따로 보내지 않는다.
- 화면: 넓은 화면은 상세를 펼치지 않으므로 고점(시각)과 매도 조건 충족(시각 · 가격)도 정보 줄에 둔다. 지금 세션 기준은 목록 위에 한 줄로도 보인다. 감시 중인데 계좌 현재가로는 도달했지만 아직 활성화되지 않은 종목(시세 체결을 받기 전)은 "도달 (판정 전)"으로 보인다. spec의 세 가지 문구 밖의 문구다.
- 알려진 경계: 다시 읽기가 매도 뒤 수량을 이미 반영한 다음에 그 매도 체결이 늦게 오면 두 번 빼서 기억을 일찍 버릴 수 있다. 체결 feed는 받는 자리에서 바로 넘기므로 드물다.
