# 03: 세션 중 활성화·고점·트리거 판정

**What to build:** 모의투자 환경의 켜진 Trailing Stop 세션 동안 서버가 보유종목의 시세 체결을 받아 활성화, 고점, Trailing Stop 트리거를 판정한다. Trailing Stop 보기는 활성화 대기, 고점 추적 중, 매도 조건 충족, 대상 아님 상태와 고점·하락률·시각을 보인다. 매도 주문은 내지 않는다. 이 티켓의 기억은 서버 메모리에만 있다.

Spec: `.scratch/trailing-stop-status/spec.md` (키움 TR, Trailing Stop 감시, 자체 서버 API, 화면, 로그)

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [ ] 시작 전에 kra-docs로 같은 연결에서 SL / TP와 Trailing Stop이 같은 종목을 다른 그룹으로 등록할 때 실시간 시세 200종목 한도를 어떻게 세는지 확인한다. 문서로 확인되지 않으면 추측하지 않고 사용자에게 알린다.
- [ ] 모의투자 환경만 감시한다. 켜진 세션 동안 보유종목을 읽고 시세를 구독하며, 세션이 시작할 때·다시 연결될 때·내 계좌 체결이 들어올 때 보유종목을 다시 읽는다. 공유 실시간 연결을 쓰고 SL / TP와 다른 그룹 번호를 쓴다.
- [ ] 내 계좌 체결을 받으면 체결 콜백 안에서 바로 판정을 멈추고 `holdings_pending`으로 바꾼다. 다시 읽기를 마치기 전에 받은 시세 체결은 판정하지 않는다(ADR 0002, SL / TP와 같음).
- [ ] 매도 체결을 받으면 마지막으로 읽은 현금 보유 수량에서 바로 빼고, 0 이하가 되면 다시 읽기를 기다리지 않고 그 종목의 기억을 버린다.
- [ ] 연결이 밀려남, 체결 등록 거부, 시세 등록 거부 때 SL / TP와 같은 조건으로 판정을 멈추고 `connection_replaced`·`fills_rejected`·`quotes_rejected`로 돌려주며, 같은 조건으로 다시 시작한다.
- [ ] Trailing Stop 설정을 저장하면 감시가 새 설정을 바로 쓴다.
- [ ] 판정은 spec의 순서를 따른다. 활성화는 `가격 ≥ 평균 매입가 × (1 + 활성화 수익률/100)`, 트리거는 `가격 ≤ 고점 × (1 − 고점 대비 하락률/100)`이다. 기준 값은 그 시세 체결 시각에 켜진 세션의 값이다. 정규장 장구분이 아니거나 판정할 수 없는 가격은 건너뛴다.
- [ ] 활성화 뒤 다시 내려가도 활성화가 유지되고, 트리거 뒤 다시 올라도 매도 조건 충족이 유지되며 고점을 갱신하지 않는다.
- [ ] 서버가 켜져 있는 동안 기억은 세션 사이에도 이어진다. 보유종목을 다시 읽었을 때 없는 종목의 기억은 버린다. 일부 매도·추가 매수로는 버리지 않는다.
- [ ] 상태 조회 API가 감시 중에는 `watching=true`, 읽은 보유종목을 종목코드마다 하나씩 `stocks`에 담는다(`waiting`·`tracking`·`triggered`·`ineligible`, `purchase_price`·`last_price` 포함). 신용 보유분 줄은 넣지 않고, 같은 코드의 현금 보유분은 감시한다. 보유종목을 아직 읽지 못했으면 `holdings_pending`이다.
- [ ] 화면: 상태 배지, 고점 대비 하락률("고점 대비 −1.0%"), 도달 시각("도달 · 11/01 10:03"), 상세의 고점·고점 시각·활성화 시각·트리거 시각과 가격·지금 세션 기준을 보인다. 감시 중인 종목의 수익률은 `last_price`와 `purchase_price`로 계산한다. 하락률은 고점이 없으면 "—"다. 시각은 투자 환경의 시간대이고 오늘이 아니면 날짜를 붙인다.
- [ ] Trailing Stop 설정 화면의 준비 중 안내를 "지금은 상태만 계산하고 팔지 않습니다. 계좌 확인 화면의 Trailing Stop 보기에서 확인하세요."로 바꾼다.
- [ ] 로그: 감시 시작·중단·재개, 보유종목 다시 읽기, 활성화, 트리거, 기억 삭제를 남긴다. 활성화·트리거 로그는 투자 환경, 요청 ID, 종목코드, 가격, 평균 매입가, 적용한 기준, 고점을 담는다. 고점 갱신은 시세 체결마다 남기지 않는다.
- [ ] 테스트(pytest, 앱 전체를 HTTP로): 활성화·트리거 경계(같으면 일어남), 고점 갱신, 활성화 뒤 하락 유지, 트리거 뒤 상승 유지, 세션 밖·정규장 밖 시세 체결 무시, 세션 사이 기억 유지와 뒤 세션 하락률 적용, 보유에서 빠지면 삭제, 전량 매도 직후 다시 사서 다시 읽기가 묶여도 삭제, 일부 매도·추가 매수 뒤 유지, 추가 매수 뒤 `purchase_price` 갱신, 체결 직후 같은 메시지와 다시 읽는 도중의 시세 체결 미판정, 다시 읽는 도중 체결이 또 오면 마지막 체결까지 반영한 뒤 판정, 밀려남·체결 등록 거부·시세 등록 거부 때 멈춤과 복구, 대상 아님 네 가지(현금·신용 같은 코드 두 줄 포함), 실전 미감시, 로그 칸을 확인한다. **모든 테스트에서 매도 주문 TR이 한 번도 나가지 않는다.**
- [ ] 테스트(Playwright): 활성화 대기·고점 추적 중·매도 조건 충족·대상 아님과 이유, 고점·하락률·시각 표시, `purchase_price`로 계산한 수익률, 장애로 멈춘 활성화 종목의 "고점 추적 중 · <멈춘 이유>", 미국 표기를 확인한다.
- [ ] 기존 SL / TP 테스트를 포함해 기존 테스트, lint, 타입 검사, 화면 빌드가 모두 통과한다.
