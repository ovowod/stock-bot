# 04: 체결·재연결 때 보유종목 다시 읽기

**What to build:** 켜진 SL/TP 세션 동안 내 계좌에 체결이 일어나거나(앱 밖 MTS·HTS 주문 포함) 실시간 연결이 다시 붙으면, 서버가 보유종목을 다시 읽어 바뀐 매입가와 새로 산 종목을 반영하고 다 판 종목은 그만 지켜본다. 연결이 끊긴 동안이나 보유종목을 읽지 못한 동안에는 판정하지 않는다. 재연결 뒤에도 같은 세션에서 이미 트리거된 종목은 다시 주문하지 않는다.

Spec: `.scratch/sl-tp-auto-sell/spec.md` (SL / TP 실행의 보유종목 다시 읽기, 판정 중단 상태)

**Blocked by:** 02, 03

**Status:** ready-for-agent

- [ ] 켜진 세션 동안 `00` 체결 이벤트가 오면 보유종목을 다시 읽는다. 짧은 시간에 여러 번 와도 한 번으로 합친다. Discord가 꺼져 있어 체결 알림이 `00`을 구독하지 않아도 SL / TP가 필요하면 구독한다.
- [ ] 보유종목을 읽는 중에 체결이 더 오면 끝난 뒤 한 번 더 읽는다(테스트: 첫 조회 응답을 늦추는 동안 체결을 넣으면 조회가 두 번 나가고, 두 번째 결과의 매입가로 판정한다).
- [ ] 다시 읽기 계기를 받은 뒤 새 결과가 반영될 때까지 판정하지 않는다. 그동안 기준을 넘은 체결가가 와도 주문하지 않는다.
- [ ] 조회를 시작할 때의 세션 실행이나 연결이 바뀐 뒤 도착한 결과는 쓰지 않는다.
- [ ] 재연결 전 연결에서 온 시세는 판정하지 않고 버린다.
- [ ] 다시 읽은 결과로 새 종목은 구독에 더하고 없어진 종목은 빼며, 바뀐 매입가로 판정한다.
- [ ] 연결이 끊기면 판정을 멈춘다. 끊긴 동안 REST 시세로 판정하지 않는다.
- [ ] 다시 연결되면 체결 감시와 SL / TP 구독이 모두 다시 등록되고, 보유종목을 다시 읽은 뒤 판정을 이어 간다.
- [ ] 재연결 뒤 기준을 넘은 체결가가 다시 와도, 그 세션에서 이미 트리거된 종목에는 주문하지 않는다.
- [ ] 보유종목 읽기가 실패하면 성공할 때까지 판정을 멈추고, 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 시도한다. 그동안 체결가가 와도 주문하지 않는다. 성공하면 판정을 이어 간다.
- [ ] 첫 실패 시각을 기억해 06의 판정 중단 알림(5분)이 쓸 수 있게 한다. 한 번이라도 성공하면 지운다.
- [ ] 켜진 세션이 끝나면 다시 시도를 멈추고 실패 기록을 지운다.
- [ ] 보유종목 갱신(종목 수, 뺀 종목), 판정 중단·재개, 다시 시도를 로그로 남긴다.
