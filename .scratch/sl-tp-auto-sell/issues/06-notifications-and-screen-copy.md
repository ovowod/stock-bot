# 06: 자동 매도 Discord 알림과 화면 문구

**What to build:** 자동 매도가 접수되면, 실패하면, 접수 여부를 알 수 없으면 Discord로 알림이 온다. 자동 매도의 체결 알림에는 "SL / TP 자동 매도" 표시가 붙는다. SL / TP가 판정을 멈추면(보유종목 읽기 계속 실패, 구독 거부, 설정 파일 읽기 실패) 한 번 알려 준다. 다른 곳에서 같은 앱 키로 접속해 연결이 밀려나면 멈춘 기능을 모두 적은 알림이 한 번 온다. SL / TP 화면의 "준비 중" 안내가 실제 동작을 설명하는 문구로 바뀐다.

Spec: `.scratch/sl-tp-auto-sell/spec.md` (알림 문구, 체결 알림 이전, 화면)

**Blocked by:** 02, 03, 04

**Status:** ready-for-agent

- [x] 자동 매도 접수 알림: 제목 "SL / TP 자동 매도 접수". 투자 환경 라벨, 종목(이름·코드, 미국은 거래소), 세션 시각(그 시장 시간대), 트리거 구분(익절 트리거·손절 트리거), 트리거 체결가, 매입가, 수익률, 주문 수량, 주문번호를 담는다.
- [x] 자동 매도 실패 알림: 제목 "SL / TP 자동 매도 실패". 같은 종목·세션·트리거 정보, 원인(키움 메시지 또는 잔고 확인 실패), "이번 SL/TP 세션 동안 이 종목은 다시 시도하지 않습니다."를 담는다.
- [x] 결과 불명 알림: 제목 "SL / TP 자동 매도 결과 확인 불가". "접수 여부를 확인할 수 없습니다. 키움에서 주문 내역을 확인하세요."를 담는다.
- [x] 매도 가능 수량이 0이라 건너뛰었거나 보내기 전에 취소된 경우는 알리지 않는다.
- [x] 자동 매도 주문번호의 체결 알림에 "SL / TP 자동 매도" 표시가 붙고, 수동 매도 체결에는 붙지 않는다. 오래된 주문번호 기억은 체결 알림의 매도 체결 기억과 같은 방식으로 지운다.
- [x] 체결된 종목에 진행 중인 자동 매도가 있으면, 체결 알림이 체결 이벤트를 받은 때부터 최대 5초(테스트에서 줄일 수 있음) 동안 그 주문 결과를 기다린 뒤 주문번호를 맞춰 본다.
  - 5초 안에 접수되고 주문번호가 같으면 표시와 `trigger_request_id`를 붙인다(체결을 주문 응답보다 먼저 넣는 테스트).
  - 5초를 넘기면 둘 다 없이 보낸다.
  - 주문이 거부·결과 불명이거나 주문번호가 다르면 둘 다 없이 보낸다.
- [x] 자동 매도 체결 로그에 트리거 요청 ID가 `trigger_request_id`로 남는다. 체결 처리는 지금처럼 체결마다 자기 요청 ID를 쓴다. 부분 체결 여러 건 모두에 같은 `trigger_request_id`가 남는다.
- [x] 판정 중단 알림: 보유종목 읽기가 첫 실패부터 5분 동안 계속 실패할 때(4분 59초에는 보내지 않음), SL / TP 구독이 거부될 때, 시작 때 설정 파일을 읽지 못할 때 각각 한 번 보낸다. 보유종목 읽기는 한 번이라도 성공하거나 세션이 끝나면 다시 알릴 수 있는 상태로 돌아간다.
- [x] 밀려나면 체결 감시와 SL / TP 가운데 그 연결에서 동작하던 기능을 모두 적은 알림을 한 번 보낸다.
- [x] 색은 기존 관례를 따른다: 이익 빨강, 손실 파랑, 실패·확인 불가·중단은 중립 회색.
- [x] Discord가 꺼져 있어도 자동 매도 주문은 나가고, 알림만 없다.
- [x] 접수·실패·결과 불명 알림의 전송 로그가 트리거와 같은 요청 ID로 남는다.
- [x] SL / TP 화면의 "자동매도는 아직 동작하지 않습니다. 지금은 설정만 저장됩니다." 안내를 "이 화면을 닫아도 서버가 켜져 있으면 동작합니다. 서버와 키움의 연결이 끊긴 동안에는 판정하지 않습니다."로 바꾼다. 실전 환경의 ON 불가 안내와 막힌 스위치는 그대로다. e2e를 새 문구에 맞춘다.

## Comments

### 2026-10-25: 구현
- 알림 문구는 `src/stock_bot/sl_tp_alerts.py`에 모았다. 접수 알림 색은 트리거 구분을 따른다(익절 트리거 빨강, 손절 트리거 파랑). 실패·확인 불가·판정 중단은 회색이다.
- 자동 매도 중 예상하지 못한 오류가 나면 키움에 이미 보냈을 수 있으므로 "결과 확인 불가"로 알린다.
- 체결 알림의 표시는 embed 설명에 "SL / TP 자동 매도"로 붙인다. 주문번호는 그대로 같을 때만 맞춘다. 주문 응답(`ord_no`)과 체결 이벤트(`9203`)의 주문번호 형식이 같은지는 07에서 확인한다. 다르면 표시만 빠지고 주문에는 영향이 없다.
- 5초 대기는 공유 연결이 체결 이벤트를 받은 때부터 잰다(큐에서 기다린 시간 포함).
- `trigger_request_id`는 `fill_notified`와 `fill_auto_sell_matched`에 남는다. 그 앞의 `fill_received`는 주문번호를 맞추기 전에 남기므로 빠진다. 트리거 ID로 찾으면 부분 체결마다 위 두 줄이 나온다.
- 판정 중단 알림 가운데 보유종목 읽기 실패는 읽기가 실패할 때마다 5분이 지났는지 본다. 재시도 간격이 최대 60초라 실제 알림은 5분에서 최대 1분 늦을 수 있다. 구독 거부 알림은 등록에 성공하거나 새 세션 실행이 시작되면 다시 보낼 수 있다.
- 밀려남 알림 제목은 멈춘 기능을 모두 적는다(예: "체결 감시·SL / TP 중단"). 체결 감시만 동작했으면 예전처럼 "체결 감시 중단"이다.
