# 03: 세션 전환과 설정 즉시 반영

**What to build:** 서버가 도는 동안 SL/TP 세션이 시작되면 구독하고, 끝나면 해지하고, 다음 세션으로 넘어가면 그 세션의 기준으로 종목을 다시 판정한다. SL / TP 화면에서 설정을 저장하면 바로 반영된다. 제외종목을 추가하면 그 종목은 팔리지 않고, 세션을 끄면 판정과 구독이 멈춘다. 시세 구독이 거부되면 그 환경의 판정만 멈추고 체결 알림은 계속 동작한다.

Spec: `.scratch/sl-tp-auto-sell/spec.md` (SL / TP 실행의 세션 계산, 설정 모듈 변경)

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 일정 간격과 설정 저장 때마다 지금 켜진 SL/TP 세션을 다시 계산한다. 간격은 테스트에서 줄일 수 있다.
- [ ] 켜진 세션이 새로 시작될 때마다(시각이 되어 시작, 다른 세션으로 넘어감, OFF→ON, 다음 날 같은 세션) 새 SL/TP 세션 실행 번호를 붙인다. 트리거 기록, 늦게 도착한 조회 결과를 버릴지, 보내기 직전 확인은 모두 실행 번호로 판단한다. 기준이나 제외종목만 바꾸면 실행 번호를 유지한다.
- [ ] 시세가 속한 세션은 처리하는 시각이 아니라 받은 시각으로 판단한다. 받은 시각의 세션 실행이 지금 켜진 실행과 다르면 판정하지 않고 버린다. 테스트: 09:59:59에 받은 +4% 시세의 처리를 10:00 이후로 늦추면, 10:00부터의 세션 익절 기준이 3이어도 주문하지 않는다.
- [ ] 켜진 세션이 시작되면 보유종목을 읽고 `0B` 구독을 낸다. 켜진 세션이 없어지면 `REMOVE`를 보낸다.
- [ ] 다른 세션으로 넘어가면(맞닿은 세션 포함) 트리거 기록을 비우고 보유종목을 다시 읽어 새 세션의 기준으로 판정한다. 앞 세션에서 트리거된 종목도 다음 세션에서는 다시 판정한다.
- [ ] 저장이 성공하면 그 환경의 새 설정이 바로 반영된다. 저장 API의 요청·응답과 검사 규칙은 그대로다.
- [ ] 같은 세션 안에서 기준이나 제외종목만 바꾸면 트리거 기록을 비우지 않는다. 이미 트리거된 종목은 다시 주문하지 않는다.
- [ ] 제외종목을 추가하면 그 종목의 구독이 빠지고 트리거가 일어나지 않는다. 제외를 풀면 다시 구독한다.
- [ ] 세션을 끄면 `REMOVE`가 나가고, 다시 켜면 새로 시작한 것으로 보고 트리거 기록을 비운다.
- [ ] 이미 나간 자동 매도 주문은 설정 저장으로 취소하지 않는다.
- [ ] 트리거 뒤 잔고 조회, 매도 잠금 대기, 호출 한도 대기를 늦추는 동안 그 종목을 제외종목에 추가하거나, 세션을 끄거나, 세션이 끝나거나 다른 세션으로 넘어가면 주문이 나가지 않고 "보내기 전 취소"로 끝난다. 기준만 바꾼 경우는 주문이 나간다.
- [ ] 트리거 뒤 대기하는 동안 세션을 껐다 다시 켜면, 시작·종료 시각이 같아도 이전 실행의 주문은 나가지 않고 이전 실행에서 시작한 보유종목 조회 결과도 반영되지 않는다.
- [ ] 시작 때 설정 파일을 읽지 못해 멈춘 환경은 "아직 보내도 되는가"에 "아니요"로 답한다.
- [ ] 시작 때 설정 파일을 읽지 못한 환경도, 정상 설정이 저장되면 그때부터 동작한다.
- [ ] SL / TP 구독이 거부되면 그 환경의 판정을 멈추고 로그를 남긴다. 같은 연결의 체결 알림은 계속 동작한다. 다음 세션 시작이나 구독 종목 변경 때 다시 시도한다.
- [ ] 세션 시작·끝·전환, 구독 종목 변경을 로그로 남긴다.
