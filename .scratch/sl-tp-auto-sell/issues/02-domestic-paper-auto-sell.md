# 02: 국내 모의 손절·익절 트리거로 자동 매도

**What to build:** 국내 모의에서 서버가 켜진 SL/TP 세션 동안 보유종목을 `0B` 체결가로 지켜보다가, 매입가 대비 수익률이 익절 기준 이상이거나 손절 기준 이하가 되면 주문 직전 잔고를 다시 확인해 매도 가능 수량 전량을 `kt10001` 시장가로 판다. 같은 시세가 반복돼도 한 SL/TP 세션 동안 종목마다 한 번만 주문한다. 이 티켓은 서버가 세션 안에서 시작하는 경우만 다룬다(세션 전환·설정 반영은 03, 보유종목 다시 읽기는 04). 결과는 로그로 확인하고 Discord 알림은 06에서 붙인다.

Spec: `.scratch/sl-tp-auto-sell/spec.md` (SL / TP 실행, 자동 매도 공통 장치, 앱 조립, 로그)

**Blocked by:** 01

**Status:** ready-for-agent

- [x] **구현 전 확인**: 국내 모의 `kt00018`과 미국 모의 `ust21070`을 조회해(조회 TR, 장 시간 무관), 매입가(`pur_pric`·`frgn_stk_book_uv`)가 `매입금액 ÷ 보유수량`(`pur_amt`÷`rmnd_qty`, `frgn_stk_book_amt`÷`poss_qty`)과 같은지 확인하고 결과를 spec Further Notes에 기록한다. 다르거나 확인할 수 없으면(예: 모의 계좌에 보유종목이 없음) 구현하지 않고 사용자에게 알린다.
- [x] 앱을 만들 때 현재 시각 함수(시간대 포함)를 넘길 수 있다. 기본은 실제 시각이고, 로그인 만료용 `clock`과 따로다.
- [x] 서버 시작 때 국내 모의 설정을 읽는다. 켜진 세션 안이면 `kt00018`로 보유종목을 읽고, 감시 대상 종목만 `0B`로 구독한다(`item`은 접두어 없는 종목코드).
- [x] 감시 대상에서 제외종목, 신용 잔고(`crd_tp≠00`), 매입가가 없거나 0 이하인 종목을 뺀다. ETF·ETN은 포함한다. 뺀 이유별 개수를 로그에 남긴다.
- [x] 판정은 Asia/Seoul 기준으로 켜진 세션 안(시작 포함, 종료 제외, 맞닿은 시각은 뒤 세션)이고 장구분 `290`=`2`일 때만 한다. 체결가는 `10`의 절댓값이다.
- [x] 수익률은 (체결가 − 매입가) ÷ 매입가 × 100을 Decimal로 계산하고 반올림하지 않는다. 익절은 `수익률 ≥ 익절 기준`, 손절은 `수익률 ≤ −손절 기준`이다. 한쪽 기준만 있으면 그쪽만 본다.
- [x] 경계값 테스트: 손절 3에서 −3.00%는 주문하고 −2.99%는 하지 않는다. 익절도 같은 방식으로 확인한다.
- [x] 자동 매도 공통 장치가 (투자 환경, 종목)마다 진행 중인 자동 매도를 하나로 막는다. 차지와 확인 사이에 await가 없다.
- [x] 트리거가 일어나면 그 종목을 "이번 세션에서 트리거됨"으로 먼저 표시하고, 결과와 상관없이 그 세션 동안 다시 판정하지 않는다.
- [x] 주문 서비스에 자동 매도용 전량 시장가 매도 경로를 더한다. 기존 매도와 같은 종목별 매도 잠금 안에서 잔고를 다시 읽고, 그 매도 가능 수량을 주문 수량으로 쓰고, 0이면 주문하지 않고 "건너뜀"을 돌려준다. 실전 차단과 키움 호출 한 번만 규칙은 기존 매도와 같다.
- [x] 판정 때보다 매도 가능 수량이 늘거나 줄어도 재확인한 수량 전량으로 주문한다.
- [x] 키움에 보내기 직전에 "아직 보내도 되는가"를 확인한다. 주문 TR 호출이 확인 함수를 받아 토큰 발급과 호출 한도 대기가 끝난 뒤 HTTP 요청 바로 앞에서 부른다. 트리거가 일어난 SL/TP 세션 실행이 아직 켜져 있고, 제외종목이 아니고, 그 환경의 SL / TP가 멈추지 않았고(밀려남·서버 종료), 모의 환경이어야 한다. 아니면 키움에 아무것도 보내지 않고 "보내기 전 취소"로 끝낸다. 연결 끊김만으로는 취소하지 않는다.
- [x] 잔고 조회, 토큰 발급, 호출 한도 대기를 각각 늦추는 동안 밀려남(`R10001`)이나 서버 종료가 일어나면 주문이 나가지 않는다. 같은 동안 연결이 끊기기만 하면 주문은 나간다.
- [x] 체결가(`10`)가 비었거나, 숫자가 아니거나, 절댓값이 0 이하이면 판정하지 않고 WARNING 로그를 남긴다(같은 이유가 반복되면 한 번만). 트리거 기록은 건드리지 않아, 뒤이은 정상 체결가는 판정된다.
- [x] 결과를 건너뜀, 보내기 전 취소, 접수(주문번호), 거부(키움 오류 응답, 잔고 확인 실패), 결과 불명(연결 오류·응답 형식 오류)으로 구분해 로그에 남긴다. 접수된 자동 매도의 주문번호와 트리거 요청 ID를 메모리에 기억한다.
- [x] 트리거가 일어나면 자동 매도를 별도 작업으로 내고, 시세 처리는 주문 결과를 기다리지 않는다. 주문 응답을 늦추는 동안에도 다른 종목의 트리거는 바로 처리된다.
- [x] 인증정보가 없는 모의 환경은 설정이 켜져 있어도 건너뛰고 로그를 남긴다. 다른 모의 환경은 그대로 동작한다.
- [x] 중복 테스트: 기준을 넘은 체결가를 여러 번 넣어도, 한 메시지에 같은 종목이 여러 번 있어도, 주문 응답을 늦게 주는 동안 다시 와도 `kt10001`은 한 번만 나간다. 거부·결과 불명 뒤에도 그 세션에서는 다시 주문하지 않는다.
- [x] 꺼진 세션, 세션 밖 시각, 정규장이 아닌 장구분, 제외종목, 신용 잔고는 주문하지 않는다.
- [x] 실전 환경은 SL / TP 실행이 없다. 실전 인증정보만 있어도 SL / TP 구독·주문이 나가지 않는다.
- [x] 서버 시작 때 설정 파일을 읽지 못하면 그 환경은 구독·주문하지 않고 로그를 남긴다.
- [x] 트리거 하나에 새 요청 ID를 붙이고, 잔고 재확인·주문·결과 로그가 같은 ID를 쓴다. 체결가 수신은 DEBUG로만 남기고, 판정 건너뜀은 이유가 바뀔 때만 INFO로 남긴다.

- 구현 전 확인: 미국 모의는 평균 매입가임을 확인했고, 국내 모의는 보유종목이 없어 확인하지 못했다. 사용자가 미국 결과를 근거로 진행하고 국내 확인은 07에서 하기로 했다.
