# 01: 체결 감시를 공유 실시간 연결로 옮기기

**What to build:** 키움 실시간 연결을 인증정보마다 하나씩 맡는 공유 실시간 연결을 만들고, 체결 감시가 그 위에 `00`/`F5` 구독을 내는 기능이 되도록 옮긴다. 사용자가 보는 체결 알림 동작은 바뀌지 않는다. 이후 SL / TP가 같은 연결에 시세 구독을 더할 수 있게 하는 사전 정리다(ADR 0001).

Spec: `.scratch/sl-tp-auto-sell/spec.md` (공유 실시간 연결, 체결 알림 이전)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 공유 실시간 연결이 인증정보마다(국내 모의, 미국 모의, 실전 공용) 연결 하나를 맡는다. 연결, LOGIN, PING 응답, 간격을 늘려 가는 재연결, LOGIN 실패 시 토큰 폐기, 밀려남(`R10001`) 처리를 이 모듈이 한다.
- [x] 기능은 투자 환경·실시간 항목·종목으로 구독을 등록·변경·해지하고, 그 구독에 맞는 이벤트를 받는다. 기능마다 `grp_no`를 따로 쓴다. 해지는 `trnm: REMOVE`로 보낸다.
- [x] 연결이 다시 붙으면 살아 있는 구독을 모두 다시 등록하고, 기능에 끊김·다시 연결됨을 알린다.
- [x] 구독 등록이 거부되면 그 구독을 낸 기능에만 실패를 알리고 연결은 유지한다.
- [x] 연결마다 REG/REMOVE를 한 번에 하나씩 보내고, 응답을 받은 뒤 다음을 보낸다. 기다리는 동안 온 `REAL` 이벤트는 그대로 기능에 넘긴다. 응답이 제한 시간 안에 오지 않으면 연결을 닫고 다시 연결해 모든 구독을 다시 등록한다.
- [x] 테스트: 두 기능이 동시에 구독해도 REG가 하나씩 나가고, 한쪽 구독의 거부는 그 기능에만 전달되며 다른 기능은 이벤트를 계속 받는다.
- [x] 구독이 하나도 없는 인증정보는 연결하지 않는다. 연결 여부는 Discord 설정이 아니라 구독 유무로 정한다.
- [x] 받는 쪽은 메시지를 큐에 넣기만 하고 처리는 따로 해서, 처리가 늦어도 PING 응답이 막히지 않는다. 큐는 구독한 기능마다 따로 둔다. 한 기능의 처리가 늦어도 다른 기능의 이벤트 처리는 늦어지지 않는다(테스트: 체결 알림의 조회 응답을 늦춰도 다른 구독의 이벤트가 바로 전달된다).
- [x] 이벤트를 큐에 넣을 때 서버가 받은 시각(주입한 현재 시각 함수 기준)을 붙인다. 기능은 받은 이벤트가 어느 연결(재연결 전후)에서 왔는지와 언제 받았는지 알 수 있다.
- [x] 밀려나면 그 연결을 쓰는 모든 기능을 멈추고 다시 연결하지 않는다. 알림은 지금 체결 감시의 "체결 감시 중단"과 같게 보낸다(여러 기능을 함께 적는 것은 06).
- [x] 체결 감시는 Discord가 켜져 있을 때만 `00`/`F5`를 구독한다. 알림 내용, 매도 손익 계산, 미체결 목록 조회는 그대로다.
- [x] 체결 감시의 구독이 거부되면 연결을 닫지 않고 그 구독만 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 등록한다. 성공하면 간격이 처음으로 돌아간다.
- [x] 가짜 실시간 연결이 한 연결에서 REG/REMOVE를 여러 번 받고 요청마다 응답하며, 특정 구독만 거부하게 할 수 있다.
- [x] 기존 체결 알림 테스트가 모두 통과한다. 연결·재연결·밀려남·토큰 폐기 테스트는 공유 연결로 옮겨도 같은 결과다. 예외는 REG 거부 테스트 두 개(거부 시 연결을 닫는지, 거부 시 재연결 간격이 늘어나는지)다. 이 둘은 "연결은 닫히지 않고, REG가 늘어나는 간격으로 다시 나가며, 성공하면 간격이 처음으로 돌아간다"로 바꾼다. 그 밖에 REG 거부 때 연결이 닫히는 것을 전제로 한 테스트가 있으면 같은 방식으로 바꾸고 바꾼 이유를 남긴다.
- [x] 연결·로그인·구독·해지·재연결·밀려남 로그가 기존 형식(이벤트, 투자 환경, 대상, 결과, 원인)으로 남는다.

## Comments

### 2026-10-25: 구현
- `src/stock_bot/realtime.py`에 공유 실시간 연결을 두고, 체결 감시를 `grp_no` 1의 구독으로 옮겼다.
- 기존 REG 거부 테스트 두 개를 바꿨고, 연결이 닫히는 것을 전제로 하던 테스트 두 개(서버 종료 중 재연결 대기, 실시간 실패 중 웹 API)는 REG 거부 대신 LOGIN 거부로 재연결을 만들게 바꿨다. REG 거부가 더 이상 연결을 닫지 않기 때문이다.
- 다시 연결됨(CONNECTED)은 LOGIN 직후 기능에 알리고, 이어서 구독을 다시 등록한다. 연결 번호가 그 연결의 첫 시세보다 먼저 기능에 닿게 하기 위해서다.
- 남은 것: 모든 구독을 해지해도 연결은 열어 둔다. 지금은 해지하는 기능이 없어 문제없지만, 02에서 SL / TP가 해지하고 Discord가 꺼져 있으면 연결을 닫아야 한다(ADR 0001: 같은 앱 키의 다른 서버를 끊을 수 있음).
- 밀려남 알림 제목은 아직 "체결 감시 중단"이다(여러 기능을 적는 문구는 06).
