# SL / TP 자동 매도 (모의투자)

Status: ready-for-agent

## Problem Statement

SL / TP 화면에서 SL/TP 세션, 익절 기준, 손절 기준, 제외종목을 저장할 수는 있지만 실제로는 아무것도 팔리지 않는다. 보유종목이 정해 둔 수익률이나 손실률에 닿으면 지금도 대시보드를 보면서 직접 매도 주문을 넣어야 한다. 자동으로 팔게 하려면 시세를 실시간으로 지켜보다가 기준에 닿는 순간 주문을 내야 하는데, 시세는 1초에도 여러 번 들어오고 키움 연결은 끊겼다 다시 붙을 수 있다. 같은 종목을 두 번 팔거나, 판 줄 알았는데 접수조차 안 된 것을 모르는 일이 생기면 안 된다. 또 키움은 같은 앱 키로 실시간 연결을 하나만 허용해서, 체결 알림이 이미 쓰는 연결과 따로 연결을 열면 서로를 끊어 버린다.

## Solution

모의투자 환경에서 저장된 SL / TP 설정대로 서버가 보유종목을 지켜보다가, 켜진 SL/TP 세션 동안 실시간 체결가로 계산한 수익률이 익절 기준 이상이거나 손절 기준 이하가 되면(익절 트리거 / 손절 트리거) 그 종목의 매도 가능 수량 전량을 시장가로 판다(자동 매도).

- 브라우저 화면을 닫아도 서버가 켜져 있으면 동작한다. 서버와 키움의 연결이 끊긴 동안에는 판정하지 않는다.
- 서버가 도는 동안 한 SL/TP 세션에서 종목마다 트리거는 한 번만 일어난다. 같은 시세가 반복되거나 연결이 다시 붙어도 주문은 한 번이다.
- 자동 매도가 접수되면, 실패하면, 접수 여부를 알 수 없으면 Discord로 알린다. 체결은 기존 체결 알림이 "SL / TP 자동 매도" 표시와 함께 알린다.
- 실전투자에서는 지금처럼 SL/TP 세션을 켤 수 없고, 서버도 실전 환경은 감시하지 않는다.
- 키움 실시간 연결은 인증정보마다 하나만 열고, 체결 알림과 SL / TP가 함께 쓴다(ADR 0001).

## User Stories

**동작 범위와 안전**

1. As a 투자자, I want SL / TP가 국내 모의와 미국 모의에서만 동작하기를, so that 개발 중에 실제 돈이 팔리지 않는다.
2. As a 투자자, I want 실전투자 환경은 시세 구독도 판정도 하지 않기를, so that 설정 파일이 어떻게 되어 있든 실전에서 자동 매도가 나갈 길이 없다.
3. As a 투자자, I want 자동 매도도 수동 매도와 같은 주문 경로를 거쳐 실전 차단·잔고 재확인을 받기를, so that 안전장치가 한 곳에서 관리된다.
4. As a 투자자, I want 브라우저 화면을 닫아도 서버가 켜져 있으면 SL / TP가 동작하기를, so that 대시보드를 계속 켜 두지 않아도 된다.
5. As a 투자자, I want Discord 알림이 꺼져 있어도 자동 매도는 동작하기를, so that 알림 설정과 매도 동작이 서로 묶이지 않는다.
6. As a 투자자, I want 인증정보가 없는 모의 환경은 SL / TP를 건너뛰기를, so that 한 환경의 설정 누락이 다른 환경을 막지 않는다.

**판정**

7. As a 투자자, I want 수익률을 (실시간 체결가 − 매입가) ÷ 매입가로 계산하기를, so that 화면 안내의 "평균 매입가 대비 수익률"과 같은 뜻이다.
8. As a 투자자, I want 수익률에 수수료·세금을 빼지 않기를, so that 체결 알림의 매도 손익과 같은 기준으로 이해한다.
9. As a 투자자, I want 익절 기준 5는 수익률 +5% 이상, 손절 기준 3은 −3% 이하에서 트리거가 일어나기를, so that 화면에 적은 숫자가 그대로 경계값이 된다.
10. As a 투자자, I want 익절 기준이나 손절 기준 한쪽만 정한 세션은 정한 쪽으로만 트리거가 일어나기를, so that 손절만 걸어 둘 수 있다.
11. As a 투자자, I want 켜진 SL/TP 세션 안에서만 판정하기를, so that 정해 둔 시간 밖에서는 팔리지 않는다.
12. As a 투자자, I want 세션 시작 시각은 포함하고 종료 시각은 빼며, 맞닿은 시각은 뒤 세션의 기준을 쓰기를, so that 설정 화면의 규칙과 실제 동작이 같다.
13. As a 투자자, I want 세션 안이라도 정규장 체결(국내 장중, 미국 정규장)일 때만 판정하기를, so that 장전·장후 체결이나 특별한 날의 체결로 팔리지 않는다.
14. As a 투자자, I want 시각은 국내는 한국시간, 미국은 뉴욕시간으로 판단하기를, so that 설정 화면에 보이는 시각대로 동작한다.
15. As a 투자자, I want 제외종목은 판정하지 않기를, so that 팔지 않기로 한 종목이 팔리지 않는다.
16. As a 투자자, I want 국내 신용 잔고는 SL / TP가 다루지 않기를, so that 현금 매도 주문으로 신용 보유분을 팔려다 실패하지 않는다.
17. As a 투자자, I want 미국 종목 가운데 종목 목록에서 거래소를 찾지 못한 종목은 판정하지 않고 로그에 남기기를, so that 거래소 없이 주문을 보내다 실패하지 않는다.
18. As a 투자자, I want ETF·ETN도 주식과 똑같이 판정하기를, so that 보유 형태와 상관없이 같은 규칙이 적용된다.

**보유종목과 시세 구독**

19. As a 투자자, I want SL/TP 세션이 시작될 때 보유종목을 새로 읽기를, so that 세션 사이에 사고판 결과가 반영된다.
20. As a 투자자, I want 내 계좌에 체결이 일어나면(앱 밖 MTS·HTS 주문 포함) 보유종목을 다시 읽기를, so that 추가 매수로 바뀐 매입가나 새로 산 종목이 바로 반영된다.
21. As a 투자자, I want 실시간 연결이 다시 붙으면 보유종목을 다시 읽기를, so that 끊긴 동안 놓친 체결이 반영된다.
22. As a 투자자, I want 보유종목을 읽지 못하면 성공할 때까지 그 환경의 판정을 멈추기를, so that 틀린 매입가로 전량이 팔리지 않는다.
23. As a 투자자, I want 보유종목 읽기가 계속 실패하면 Discord로 한 번 알려 주기를, so that SL / TP가 멈춘 것을 안다.
24. As a 투자자, I want 켜진 세션 동안 감시 대상 종목의 시세만 구독하기를, so that 필요 없는 시세와 로그가 쌓이지 않는다.
25. As a 투자자, I want 세션이 끝나면 그 시세 구독을 해지하기를, so that 세션 밖에서는 판정할 거리 자체가 없다.
26. As a 투자자, I want 보유종목이 바뀌면 구독 종목도 그에 맞춰 더하고 빼기를, so that 새로 산 종목도 지켜보고 다 판 종목은 그만 받는다.
27. As a 투자자, I want 시세 구독이 거부되면 그 환경의 SL / TP 판정을 멈추고 Discord로 알려 주기를, so that 지켜보지 못하는 상태를 모르고 지나치지 않는다.
28. As a 투자자, I want 시세 구독이 거부돼도 체결 알림은 그대로 동작하기를, so that 한 기능의 문제가 다른 기능을 멈추지 않는다.

**자동 매도와 중복 방지**

29. As a 투자자, I want 트리거가 일어나면 주문 직전에 잔고를 다시 읽어 그 매도 가능 수량 전량을 시장가로 팔기를, so that 판정 뒤에 바뀐 수량이 반영된다.
30. As a 투자자, I want 매도 가능 수량이 0이면 주문하지 않고 로그만 남기기를, so that 이미 걸려 있는 매도 주문과 겹치지 않는다.
31. As a 투자자, I want 투자 환경과 종목마다 진행 중인 자동 매도가 하나뿐이기를, so that 같은 순간에 여러 트리거가 일어나도 주문이 한 번만 나간다.
32. As a 투자자, I want 한 SL/TP 세션 동안 종목마다 트리거가 한 번만 일어나기를, so that 기준을 넘은 시세가 계속 들어와도 주문이 반복되지 않는다.
33. As a 투자자, I want 자동 매도가 거부되거나 결과를 알 수 없으면 그 세션 동안 그 종목을 다시 시도하지 않기를, so that 키움이 계속 거부하는 상황에서 주문이 쏟아지지 않는다.
34. As a 투자자, I want 다음 SL/TP 세션이 시작되면 그 종목을 다시 판정하기를, so that 세션마다 정한 기준이 새로 적용된다.
35. As a 투자자, I want 연결이 끊겼다 다시 붙어도 이미 트리거가 일어난 종목에 다시 주문하지 않기를, so that 재연결로 중복 주문이 생기지 않는다.
36. As a 투자자, I want 서버를 다시 시작한 뒤에도 주문 직전 잔고 재확인이 이미 팔렸거나 매도 주문이 걸린 종목의 중복 주문을 막기를, so that 기억이 사라져도 같은 수량이 두 번 팔리지 않는다. 트리거 기록은 파일에 남기지 않으므로, 재시작 뒤에는 거부됐던 종목, 직접 취소한 종목, 다시 산 종목이 같은 세션에서 다시 판정될 수 있다.
37. As a 투자자, I want 자동 매도 주문을 키움에 자동으로 다시 보내지 않기를, so that 접수 여부를 모르는 주문이 두 번 나가지 않는다.
38. As a 투자자, I want 자동 매도가 미체결로 남아도 서버가 취소하지 않기를, so that 서버가 사용자 모르게 주문을 거둬들이지 않는다.
39. As a 투자자, I want 대시보드에서 직접 내는 매도는 자동 매도 규칙에 묶이지 않기를, so that 자동 매도가 진행 중이어도 직접 판단해 주문할 수 있다(매도 가능 수량을 넘으면 기존처럼 막힌다).

**설정 반영**

40. As a 투자자, I want SL / TP 설정을 저장하면 바로 반영되기를, so that 제외종목을 추가한 순간부터 그 종목이 팔리지 않는다.
41. As a 투자자, I want 저장한 세션을 끄면 그 세션의 판정과 구독이 바로 멈추기를, so that 급할 때 스위치로 멈출 수 있다.
42. As a 투자자, I want 설정을 바꿔도 이미 나간 자동 매도 주문은 그대로 두기를, so that 설정 저장이 주문 취소로 이어지지 않는다.
43. As a 투자자, I want 서버 시작 때 설정 파일을 읽지 못하면 그 환경의 SL / TP를 동작시키지 않고 Discord로 한 번 알려 주기를, so that 깨진 설정을 빈 설정이나 옛 설정으로 착각해 동작하지 않는다.
44. As a 투자자, I want 깨진 파일을 고치고 화면에서 다시 저장하면 그때부터 동작하기를, so that 서버를 다시 시작하지 않아도 된다.

**상태 구분과 알림**

45. As a 투자자, I want 자동 매도가 접수되면 투자 환경, 종목, SL/TP 세션 시각, 익절·손절 트리거 구분, 트리거가 일어난 체결가, 매입가, 수익률, 주문 수량, 주문번호를 담은 알림을 받기를, so that 왜 팔렸는지 바로 안다.
46. As a 투자자, I want 키움이 자동 매도를 거부하거나 주문 전 잔고 확인이 실패하면 원인과 "이번 세션 동안 다시 시도하지 않음"을 담은 알림을 받기를, so that 직접 처리해야 하는지 안다.
47. As a 투자자, I want 접수 여부를 알 수 없으면 키움에서 주문 내역을 확인하라는 알림을 받기를, so that 팔렸는지 모르는 채로 지나치지 않는다.
48. As a 투자자, I want 자동 매도의 체결 알림에 "SL / TP 자동 매도" 표시가 붙기를, so that 내가 낸 매도와 구분한다.
49. As a 투자자, I want 서버를 다시 시작하기 전에 낸 자동 매도의 체결에는 표시가 빠질 수 있다는 것을 받아들이기를, so that 표시를 위해 주문 기록을 파일에 남기지 않는다.
50. As a 투자자, I want 다른 곳에서 같은 앱 키로 접속해 연결이 밀려나면 체결 감시와 SL / TP가 함께 멈추고, 멈춘 기능을 모두 적은 알림을 한 번 받기를, so that 두 서버가 같은 계좌를 자동 매도하지 않는다.

**화면**

51. As a 투자자, I want SL / TP 화면의 "자동매도는 아직 동작하지 않습니다" 안내가 "이 화면을 닫아도 서버가 켜져 있으면 동작합니다. 서버와 키움의 연결이 끊긴 동안에는 판정하지 않습니다."로 바뀌기를, so that 언제 동작하는지 정확히 안다.
52. As a 투자자, I want 실전투자 환경의 ON 불가 안내와 막힌 스위치는 그대로이기를, so that 실전에서 켤 수 없다는 것을 안다.

**로그**

53. As a 개발자, I want 실시간 연결·로그인·구독·해지·재연결·밀려남을 로그로 남기기를, so that 시세가 왜 안 들어왔는지 로그만 보고 안다.
54. As a 개발자, I want SL/TP 세션 시작·끝, 보유종목 갱신(종목 수, 제외·신용·거래소 불명으로 뺀 종목), 구독 종목 변경을 로그로 남기기를, so that 무엇을 지켜보고 있었는지 안다.
55. As a 개발자, I want 트리거마다 종목, 세션, 트리거 구분, 체결가, 매입가, 수익률, 기준을 로그로 남기고, 그 뒤 잔고 재확인·주문 요청·접수·거부·결과 불명·체결을 같은 요청 ID로 묶기를, so that 자동 매도 하나의 흐름을 처음부터 끝까지 따라간다.
56. As a 개발자, I want 반복되는 체결가 수신은 기본 로그 수준에서 남기지 않고, 트리거·판정 건너뜀(이미 트리거됨, 세션 밖, 장구분 밖) 같은 상태 변화만 남기기를, so that 로그가 시세로 넘치지 않는다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **자동 매도**, **익절 트리거 / 손절 트리거**를 더했고, **SL / TP**에 "실시간 체결가 기준, 수수료·세금 미반영, 모의투자에서만 동작"을 넣었다. 코드·로그·알림 문구도 이 이름을 따른다("발동", "조건 충족", "자동매도"를 쓰지 않는다).

**키움 TR**

- 시세: 국내 `0B` 주식체결, 미국 `FE` 미국주식 실시간 체결가(WebSocket, 둘 다 모의 지원).
  - 국내 등록 `item`은 접두어 없는 종목코드 문자열(KRX)이다. 미국 등록 `item`은 `{"jmcode": 티커, "stex_tp": ND|NY|NA}` 객체다.
  - 체결가는 `10`의 절댓값(부호는 등락 방향)이다. 장구분 `290`은 국내 `2`(장중), 미국 `0`(정규장)만 판정한다.
  - 해지는 `trnm: REMOVE`. 그룹 번호(`grp_no`)는 기능마다 따로 쓴다.
- 체결 이벤트: 국내 `00`, 미국 `F5`(이미 체결 알림에서 씀). 보유종목 다시 읽기와 체결 알림의 자동 매도 표시에 쓴다.
- 보유종목: 국내 `kt00018`(`pur_pric` 매입가, `trde_able_qty` 매도 가능 수량, `crd_tp`), 미국 `ust21070`(`frgn_stk_book_uv` 매입단가, `sell_alowq` 매도 가능 수량). 미국 거래소는 지금처럼 종목 목록(`usa10099`)에서 찾는다.
- 매도: 국내 `kt10001`(`trde_tp=3`, `dmst_stex_tp=KRX`), 미국 `ust20001`(`trde_tp=03`). 기존 주문 경로를 그대로 쓴다.
- `04` 잔고, `0s` 장시작시간은 쓰지 않는다.

**공유 실시간 연결 (새 모듈, ADR 0001)**

- 인증정보마다 키움 실시간 연결을 하나 맡는다: 국내 모의, 미국 모의, 실전(국내·미국 공용).
- 연결, LOGIN, PING 응답, 재연결(간격을 늘려 가며), 토큰 폐기 후 재발급, 같은 앱 키로 밀려남(`R10001`) 처리를 이 모듈이 한다. 지금 체결 감시에 있는 이 동작을 옮겨 온다.
- 기능은 "어느 투자 환경에서, 어떤 실시간 항목을, 어떤 종목으로 받겠다"는 구독을 등록·변경·해지하고, 그 구독에 맞는 이벤트를 받는다. 연결이 다시 붙으면 모듈이 살아 있는 구독을 모두 다시 등록하고, 기능에 "다시 연결됨"을 알린다. 끊기면 "끊김"을 알린다.
- 구독 등록이 거부되면 그 구독을 낸 기능에만 실패를 알리고 연결은 유지한다.
- 키움의 REG/REMOVE 응답에는 어느 요청의 응답인지 알 단서(그룹 번호 등)가 없다. 그래서 연결마다 REG/REMOVE를 한 번에 하나씩 보내고 응답을 받은 뒤 다음을 보낸다. 기다리는 동안 온 `REAL` 이벤트는 그대로 기능에 넘긴다. 응답이 제한 시간 안에 오지 않으면 연결을 닫고 다시 연결한다(늦은 응답을 다음 요청의 응답으로 착각하지 않게).
- 구독이 하나도 없는 인증정보는 연결하지 않는다. Discord 설정과 상관없다.
- 밀려나면 그 연결을 쓰는 모든 기능을 멈추고, 멈춘 기능을 모두 적은 알림을 한 번 보낸다. 다시 연결하지 않는다(지금 체결 감시와 같음).
- 받는 쪽은 메시지를 큐에 넣기만 하고 처리는 따로 해서, 처리가 늦어도 PING 응답이 막히지 않게 한다. 큐는 구독한 기능마다 따로 둬서, 체결 알림의 REST 조회가 시세 처리를 늦추지 않게 한다. 큐 크기 제한과 시세 유효기간은 두지 않는다.
- 이벤트를 큐에 넣을 때 서버가 받은 시각을 붙인다. 기능은 받은 이벤트가 어느 연결(재연결 전후)에서 왔는지와 언제 받았는지 알 수 있다.

**체결 알림 이전**

- 체결 감시는 공유 실시간 연결에 `00`/`F5` 구독을 내는 기능이 된다. Discord가 꺼져 있으면 구독하지 않는다(지금과 같은 결과).
- 체결 감시의 구독이 거부되면 연결은 그대로 두고 그 구독만 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 등록한다. 성공하면 간격을 처음으로 되돌린다. 지금은 REG가 거부되면 연결을 닫고 다시 연결하는데, 이 동작이 바뀐다.
- 알림 내용·매도 손익 계산·미체결 목록 등 체결 알림의 동작은 바꾸지 않는다. 체결이 자동 매도의 주문번호이면 "SL / TP 자동 매도" 표시를 더하는 것만 새로 생긴다.

**자동 매도 공통 장치 (새로 만든다)**

- "(투자 환경, 종목)마다 진행 중인 자동 매도는 하나"라는 규칙만 갖는 작은 장치다. 자동 매도를 내려는 기능은 먼저 그 종목을 차지하고, 주문 결과(접수·거부·결과 불명)가 나오면 놓는다. 이미 차지된 종목이면 주문하지 않는다.
- 차지와 확인 사이에 await가 없게 해서 같은 순간의 두 요청 가운데 하나만 통과한다.
- 주문 서비스에 자동 매도용 "전량 시장가 매도" 경로를 더한다. 기존 매도와 같은 종목별 매도 잠금 안에서 다음을 차례로 한다.
  1. 잔고를 다시 읽는다.
  2. 그 매도 가능 수량을 주문 수량으로 정한다. 0이면 주문하지 않고 "건너뜀"을 돌려준다.
  3. 키움에 보내기 직전에 호출한 쪽에 "아직 보내도 되는가"를 묻는다. 주문 TR 호출이 확인 함수를 받아, 토큰 발급과 호출 한도 대기가 모두 끝난 뒤 HTTP 요청 바로 앞에서 부른다. SL / TP는 트리거가 일어난 SL/TP 세션 실행이 아직 켜져 있고, 종목이 제외종목이 아니고, 그 환경의 SL / TP가 멈추지 않았고(밀려남·설정 읽기 실패·서버 종료), 모의 환경일 때만 "예"라고 답한다. 아니면 주문하지 않고 "보내기 전 취소"를 돌려준다. 연결 끊김만으로는 취소하지 않는다(끊기기 전 체결가는 실제 체결이었다).
  4. 주문 TR을 한 번만 호출한다.
  - 실전 차단과 키움 호출 한 번만 규칙은 기존 매도와 같다. 이미 키움에 보낸 주문은 어떤 일이 있어도 취소하지 않는다.
- 결과를 구분한다. 주문을 보내지 않은 것: 건너뜀(매도 가능 수량 0), 보내기 전 취소. 주문을 보낸 것: 접수(주문번호 받음), 거부(키움 오류 응답, 잔고 확인 실패 포함), 결과 불명(연결 오류·응답 형식 오류로 키움까지 갔는지 모름). 건너뜀과 보내기 전 취소는 로그만 남긴다.
- 접수된 자동 매도의 (투자 환경, 주문번호)와 트리거 요청 ID를 메모리에 기억해 체결 알림이 표시를 붙이게 한다. 체결 알림의 매도 체결 기억과 같은 방식으로 오래된 항목을 지운다. 재시작하면 사라진다.
- 시장가는 주문 응답보다 체결 통보가 먼저 올 수 있다. 체결 알림은 체결된 종목에 진행 중인 자동 매도가 있으면, 체결 이벤트를 받은 때부터 최대 5초 동안 그 주문 결과를 기다린 뒤 주문번호를 맞춰 본다. 5초 안에 접수되고 주문번호가 같으면 표시와 `trigger_request_id`를 붙인다. 5초를 넘기거나, 거부·결과 불명이거나, 주문번호가 다르면 둘 다 없이 보낸다.
- 수동 매도는 이 장치를 거치지 않는다.

**SL / TP 실행 (새 모듈)**

- 모의 환경마다(국내 모의, 미국 모의) 하나씩 돈다. 실전 환경은 만들지 않는다.
- 설정은 기존 설정 모듈에서 받는다. 서버 시작 때 한 번 읽고, 저장이 성공할 때마다 새 설정을 바로 넘겨받는다. 시작 때 읽기에 실패하면 그 환경은 멈춘 채로 있다가, 저장이 성공하면 동작을 시작한다.
- 현재 시각은 주입받은 시계로 구해 그 시장의 시간대로 바꾼다. 일정 간격과 설정 저장 때마다 "지금 켜진 SL/TP 세션"을 다시 계산한다.
  - **SL/TP 세션 실행**: 켜진 세션이 새로 시작될 때마다(시각이 되어 시작, 다른 세션으로 넘어감, OFF→ON, 다음 날 같은 세션) 새 실행 번호를 붙인다. 트리거 기록, 늦게 도착한 조회 결과를 버릴지, 보내기 직전 확인은 모두 이 실행 번호로 판단한다. 시작·종료 시각이 같아도 실행이 다르면 다른 세션으로 본다.
  - 새 세션 실행이 시작되면 "이번 세션에서 트리거된 종목" 기록을 비우고 보유종목을 다시 읽은 뒤 구독을 맞춘다.
  - 같은 세션 안에서 기준이나 제외종목만 바뀌면 실행 번호와 기록을 유지한다. 설정 저장으로 같은 종목의 트리거가 다시 일어나지 않게 하기 위해서다. 제외종목이 바뀌면 구독만 맞춘다.
  - 켜진 세션이 없으면 구독을 해지한다. 사용자가 세션을 껐다가 다시 켜면 새 실행으로 보고 기록을 비운다. 실패한 종목을 직접 다시 시도하게 하는 방법이 된다. 껐다 켜기 전 실행에서 대기 중이던 조회 결과와 주문은 반영·전송하지 않는다.
- 감시 대상: 보유종목 가운데 제외종목, 국내 신용 잔고(`crd_tp≠00`), 거래소를 모르는 미국 종목, 매입가가 0 이하이거나 없는 종목을 뺀 나머지.
- 체결가 이벤트마다: 지금 연결에서 온 이벤트인지, 받은 시각이 속한 세션 실행이 지금 켜진 세션 실행과 같은지, 장구분이 정규장인지, 체결가가 올바른지, 감시 대상인지, 이번 세션에서 이미 트리거됐는지를 확인한 뒤 그 실행의 기준으로 수익률을 계산해 비교한다.
  - 세션 안인지는 처리하는 시각이 아니라 서버가 받은 시각으로 판단한다. 큐 처리가 세션 경계를 넘어 밀려도 앞 세션의 시세를 다음 세션 기준으로 판정하지 않는다.
  - 이전 연결에서 온 시세, 받은 시각의 세션 실행이 지금과 다른 시세는 판정하지 않고 버린다(DEBUG 로그).
  - 체결가(`10`)가 비었거나, 숫자가 아니거나, 절댓값이 0 이하이면 판정하지 않는다. WARNING 로그를 남기되 같은 이유가 반복되면 한 번만 남기고, 트리거 기록은 건드리지 않는다. 트리거가 일어나면 그 종목을 "이번 세션에서 트리거됨"으로 먼저 표시하고(이후 결과와 상관없이 유지), 공통 장치를 거쳐 자동 매도를 별도 작업으로 낸다. 시세 처리는 주문 결과를 기다리지 않는다.
- 수익률 비교는 Decimal로 한다. 익절은 `수익률 ≥ 익절 기준`, 손절은 `수익률 ≤ −손절 기준`이다. 반올림하지 않는다.
- 판정 중단 상태: 연결이 끊긴 동안, 보유종목을 읽지 못한 동안, 구독이 거부된 동안에는 체결가가 와도 판정하지 않는다.
- 보유종목 다시 읽기의 계기는 세션 시작·변경, 내 계좌 체결 이벤트(`00`/`F5`, 앱 밖 주문 포함), 재연결이다.
  - 짧은 시간에 여러 번 와도 한 번으로 합쳐 읽는다. 읽는 중에 계기가 더 오면 끝난 뒤 한 번 더 읽는다.
  - 계기를 받은 뒤 새 결과가 반영될 때까지 그 환경의 판정을 멈춘다(옛 매입가로 판정하지 않는다).
  - 조회를 시작할 때의 세션 실행이나 연결이 바뀌었으면 그 결과는 버린다.
  - 실패하면 1초에서 시작해 두 배씩, 최대 60초 간격으로 다시 시도한다. 첫 실패부터 5분 동안 계속 실패하면 Discord로 한 번 알린다. 한 번이라도 성공하면 다시 알릴 수 있는 상태로 돌아간다.
  - 켜진 세션이 끝나면 다시 시도를 멈추고 실패 기록을 지운다.
- 구독이 거부되면 Discord로 한 번 알리고 판정을 멈춘다. 다음 세션 시작이나 보유종목 변경으로 구독을 다시 맞출 때 다시 시도한다.

**설정 모듈 변경**

- 저장이 성공하면 그 환경의 새 설정을 SL / TP 실행에 넘긴다. 저장 API의 요청·응답 형식과 검사 규칙은 바꾸지 않는다.
- 실전 ON 차단(저장 403, 읽기 500)은 그대로 둔다.

**앱 조립**

- 앱을 만들 때 현재 시각을 돌려주는 함수를 넘길 수 있게 한다(기본은 실제 시각, 시간대 정보 포함). 기존 `clock`(로그인 만료용 경과 시간)과는 다른 값이다.
- 앱이 시작할 때 공유 실시간 연결, 체결 감시, SL / TP 실행을 띄우고, 끝날 때 함께 멈춘다. 서버가 꺼질 때 진행 중인 주문 호출은 기다리지 않는다.

**알림 문구**

- 자동 매도 접수: 제목 "SL / TP 자동 매도 접수", 투자 환경 라벨, 종목(이름·코드, 미국은 거래소), 세션 시각(그 시장 시간대), 트리거 구분(익절 트리거·손절 트리거), 트리거 체결가, 매입가, 수익률, 주문 수량, 주문번호.
- 자동 매도 실패: 제목 "SL / TP 자동 매도 실패", 같은 종목·세션·트리거 정보, 원인(키움 메시지 또는 잔고 확인 실패), "이번 SL/TP 세션 동안 이 종목은 다시 시도하지 않습니다."
- 결과 불명: 제목 "SL / TP 자동 매도 결과 확인 불가", "접수 여부를 확인할 수 없습니다. 키움에서 주문 내역을 확인하세요."
- 판정 중단: 보유종목 읽기 계속 실패, 구독 거부, 설정 파일 읽기 실패를 각각 한 번씩 알린다.
- 색은 기존 알림 관례(손실 파랑, 이익 빨강, 중립 회색)를 따른다. 실패·확인 불가는 중립 회색이다.

**로그**

- 기존 로그 형식(이벤트 이름, 투자 환경, 요청 ID, api_id, 대상, 결과, 오류 종류·원인)을 따른다.
- 트리거 하나에 새 요청 ID를 붙이고, 그 뒤 잔고 재확인·주문·결과·알림 로그가 같은 ID를 쓴다.
- 자동 매도의 체결은 체결 알림이 지금처럼 체결마다 자기 요청 ID를 쓰고, 로그에 `trigger_request_id` 필드를 더한다. 트리거 ID로 찾으면 부분 체결을 포함한 체결 로그까지 나온다.
- 체결가 수신은 DEBUG로만 남긴다. 판정 건너뜀은 이유가 바뀔 때만 INFO로 남겨 같은 이유가 반복해 쌓이지 않게 한다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 확인한다. 이벤트를 넣으면 키움에 어떤 주문·조회·구독 요청이 나가고, Discord에 어떤 알림이 가는지를 본다. 내부 모듈·상태 이름은 확인하지 않는다.
- 키움 서버(실전·모의)는 부르지 않는다.

**seam: 앱 전체 (pytest)**

- 기존 체결 알림 테스트처럼 앱을 만들고 수명(lifespan)을 실행한 채로 확인한다.
  - 가짜 키움 REST: 잔고·종목 목록·주문 응답을 주고, 나간 요청을 확인한다.
  - 가짜 실시간 연결: 이벤트를 넣고, 연결을 끊고, 밀려남을 보내고, 나간 LOGIN/REG/REMOVE를 확인한다.
  - 가짜 Discord: 나간 알림을 확인한다.
  - 임시 저장 폴더: 설정을 미리 두거나, 설정 API로 저장한다.
- 새 seam은 앱에 넘기는 현재 시각 함수 하나다. 테스트는 시각을 정하고 앞으로 넘겨 세션 시작·끝을 만든다. 세션을 다시 계산하는 간격 같은 대기 시간은 기존 재연결 대기 시간처럼 테스트에서 줄인다.
- 가짜 실시간 연결은 한 연결에서 REG/REMOVE를 여러 번 받고 요청마다 응답하도록 늘린다. 특정 구독만 거부하게 할 수 있어야 한다.

**확인할 동작**

- 판정
  - 국내 모의, 켜진 세션 안, 손절 기준 3: 매입가 대비 −3.00% 체결가에서 `kt10001` 시장가 매도가 한 번 나가고, −2.99%에서는 나가지 않는다. 익절도 경계값으로 같은 확인을 한다.
  - 한쪽 기준만 있는 세션은 그쪽으로만 트리거가 일어난다.
  - 세션 시작 시각의 체결은 판정하고 종료 시각의 체결은 판정하지 않는다. 맞닿은 시각은 뒤 세션의 기준을 쓴다.
  - 꺼진 세션, 세션 밖 시각, 장구분이 정규장이 아닌 체결은 판정하지 않는다.
  - 제외종목, 신용 잔고, 거래소를 모르는 미국 종목은 판정하지 않는다.
  - 미국 모의: `FE` 체결가로 `ust20001` 시장가 매도가 종목 목록의 거래소와 함께 나가고, 시각은 뉴욕시간으로 판단한다.
- 중복 방지
  - 기준을 넘은 체결가를 여러 번 넣어도 주문은 한 번이다.
  - 같은 이벤트 메시지에 같은 종목이 여러 번 있어도 한 번이다.
  - 연결을 끊었다 다시 붙인 뒤 기준을 넘은 체결가를 다시 넣어도 그 세션에서는 주문하지 않는다.
  - 주문 응답을 늦게 주는 동안 같은 종목의 트리거가 다시 와도 주문은 한 번이다.
  - 거부·결과 불명 뒤에도 그 세션에서는 다시 주문하지 않고, 다음 세션에서는 다시 판정한다.
  - 주문 직전 잔고 재확인에서 매도 가능 수량이 0이면 주문하지 않는다. 판정 때보다 수량이 늘거나 줄어도 재확인한 수량 전량으로 주문한다.
  - 주문 요청은 키움에 한 번만 나간다(연결 오류여도 다시 보내지 않음).
  - 잔고 조회, 매도 잠금 대기, 토큰 발급, 호출 한도 대기를 늦추는 동안 제외종목 추가, 세션 OFF, 밀려남, 서버 종료가 일어나면 주문이 나가지 않는다. 연결 끊김만으로는 주문이 취소되지 않는다.
  - 대기 중에 세션을 껐다 켜도 이전 실행의 주문과 조회 결과는 전송·반영되지 않는다.
  - 재연결 전 연결에서 온 시세는 판정하지 않는다. 09:59:59에 받은 시세의 처리를 10:00 이후로 늦춰도 다음 세션 기준으로 주문하지 않는다.
  - 체결가가 0, 빈 값, 문자이면 주문하지 않고, 뒤이은 정상 체결가는 판정한다.
- 보유종목·구독
  - 세션이 시작되면 보유종목을 읽고 감시 대상 종목으로 REG가 나간다. 세션이 끝나면 REMOVE가 나간다.
  - 체결 이벤트가 오면 보유종목을 다시 읽고, 새 종목은 구독에 더하고 없어진 종목은 뺀다.
  - 재연결하면 LOGIN 뒤 체결 감시와 SL / TP 구독이 모두 다시 등록되고 보유종목을 다시 읽는다.
  - 보유종목 읽기가 실패하면 체결가가 와도 주문하지 않고, 성공한 뒤에는 판정한다. 첫 실패부터 4분 59초에는 알림이 없고 5분에 한 번 간다.
  - 보유종목을 읽는 중에 체결이 더 오면 끝난 뒤 한 번 더 읽는다. 다시 읽기를 기다리는 동안 체결가가 와도 주문하지 않는다. 세션이 바뀐 뒤 도착한 이전 조회 결과는 쓰지 않는다.
  - 인증정보가 없는 모의 환경은 설정이 켜져 있어도 건너뛰고, 다른 모의 환경은 그대로 동작한다.
  - SL / TP 구독이 거부되면 판정 중단 알림이 가고, 체결 알림은 계속 동작한다.
- 설정 반영
  - 동작 중에 제외종목을 저장하면 그 종목의 트리거가 일어나지 않는다. 세션을 끄면 REMOVE가 나간다.
  - 같은 세션 안에서 기준만 바꿔 저장해도, 이미 트리거된 종목은 다시 주문하지 않는다.
  - 서버 시작 때 설정 파일이 깨져 있으면 그 환경은 연결·주문하지 않고 알림이 한 번 간다. 정상 설정을 저장하면 동작한다.
- 실전 차단
  - 실전 인증정보만 있는 환경에서는 SL / TP 구독·주문이 나가지 않는다(실전 연결은 체결 감시용 구독만).
- 알림
  - 접수·실패·결과 불명 알림의 제목과 필드. 자동 매도 주문번호의 체결 알림에 "SL / TP 자동 매도" 표시가 붙고, 수동 매도 체결에는 붙지 않는다.
  - 체결 이벤트를 주문 응답보다 먼저 넣어도 5초 안에 접수되면 표시가 붙는다. 5초를 넘기거나 거부·결과 불명이면 표시 없이 간다.
  - Discord가 꺼져 있어도 자동 매도 주문은 나간다.
  - 밀려나면 체결 감시와 SL / TP가 모두 멈추고 알림이 한 번 간다.
- 로그: 트리거·주문·결과 로그가 같은 요청 ID로 묶이고, 부분 체결을 포함한 체결 로그에 그 ID가 `trigger_request_id`로 남는다.
- 체결 알림 이전: 기존 체결 알림 테스트가 모두 그대로 통과한다. 연결·재연결·밀려남 테스트는 공유 연결로 옮겨도 같은 결과여야 한다. 예외는 REG 거부 테스트 두 개(거부 시 연결을 닫음, 거부 시 재연결 간격이 늘어남)다. 이 둘은 "연결은 유지하고 REG만 늘어나는 간격으로 다시 보내며, 성공하면 간격이 처음으로 돌아간다"로 바꾼다.
- 공유 연결: 두 기능이 동시에 구독해도 REG가 하나씩 나가고, 거부는 그 기능에만 전달된다. REG 응답이 제한 시간을 넘기면 연결을 닫고 다시 연결해 모든 구독을 다시 등록한다.
- Prior art: 체결 알림 테스트(가짜 실시간 연결·가짜 Discord·앱 수명), 주문 API 테스트(실전 차단, 잔고 재확인, 결과 분류), SL / TP 설정 API 테스트(임시 저장 폴더).

**화면 (Playwright e2e)**

- 바뀐 안내 문구가 보이고 "아직 동작하지 않습니다" 문구가 없다. 실전 환경 안내와 막힌 스위치는 그대로다.

**모의투자에서 직접 확인 (마지막 티켓)**

- 국내 모의 시장가 매도 접수(기존 sell-order 확인 항목 중 남은 것).
- 모의 서버에서 `0B`/`FE` 체결이 오는지, 빈도와 장구분 값.
- 한 연결에 실시간 등록을 몇 종목까지 받는지.
- 실제 보유종목 1주로 트리거 → 접수 알림 → 체결 알림(자동 매도 표시)까지 이어지는지. 국내는 한국 장중, 미국은 한국시간 밤에 한다.
