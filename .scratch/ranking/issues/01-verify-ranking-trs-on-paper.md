# 01: 모의 서버로 순위 TR 응답 확인

**What to build:** 구현에 앞서, 키움 문서만으로 확인되지 않은 순위 TR의 실제 동작을 국내 모의와 미국 모의 서버로 확인하고 결과를 spec에 기록한다. 화면이나 서버 기능은 만들지 않는다. 확인 결과에 따라 02·04의 내용이 바뀌는 사항이 있으면 다음 티켓으로 넘어가기 전에 사용자에게 보고하고 결정을 받는다.

Spec: `.scratch/ranking/spec.md`

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 국내 모의로 `ka10032`, `ka10027`, `ka10030`, `ka00198`을, 미국 모의로 `usa20540`, `usa20910`, `usa20530`, `usa01980`을 spec의 요청 본문대로 한 번씩 호출한다. 실전 서버는 호출하지 않는다.
- [ ] 국내 순위 TR이 `stex_tp=3`(통합)을 받아들이는지 확인한다. 거부되면 KRX로 바꾸지 않고 사용자에게 보고한다.
- [ ] `stex_tp=3`일 때 국내 `stk_cd`에 `_NX`·`_AL` 같은 접미어가 붙는지 확인한다.
- [ ] TR마다 첫 페이지에 몇 개가 오는지, `cont-yn=Y`가 오는지 확인한다.
- [ ] `usa01980`의 `sign`과 `chg_val` 값을 보고 `sign`이 순위 변동 방향인지 판단한다. 애매하면 미국 인기 종목의 순위 변동 칸을 빼는 쪽으로 사용자에게 보고한다.
- [ ] `ka00198`의 `rank_chg`·`rank_chg_sign` 형태와, 항목별 `dt`·`tm`이 모두 같은지 확인한다.
- [ ] 8개 TR을 연달아 호출할 때 호출 횟수 제한(1700~1702)에 걸리는지 확인한다.
- [ ] 응답 필드가 문서와 다른 점이 있으면 기록한다.
- [ ] 결과를 spec 끝의 `## Implementation Notes`에 날짜와 함께 기록한다. 로그나 기록에 인증정보·토큰·계좌번호가 남지 않게 한다.
