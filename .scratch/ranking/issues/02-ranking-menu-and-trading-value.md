# 02: 순위 메뉴와 거래대금 상위 카드

**What to build:** 왼쪽 메뉴에 "시세" 분류와 "순위" 기능이 생기고, 순위 화면에 선택한 투자 환경 시장의 **거래대금 상위** 카드가 30위까지 표시된다. 화면 위쪽에 거래소 선택(기본값 전체), 마지막 조회 시각, 새로고침 버튼이 있다. 이 티켓이 순위 기능의 서버 기반(첫 페이지만 받기, 순위용 서버 잠금, 순위 API, 값 처리 규칙)과 화면 뼈대(카드 상태, 반응형 배치, 숫자 표시)를 처음으로 관통한다.

Spec: `.scratch/ranking/spec.md`

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 키움 클라이언트에 "첫 페이지만 받는" 호출 방식이 생긴다. `cont-yn=Y`여도 다음 페이지를 요청하지 않고 오류로 처리하지 않는다. 기존 계좌 확인의 연속조회 동작과 테스트는 그대로다.
- [ ] 순위용 키움 호출이 서버 잠금으로 한 번에 하나만 실행된다. 동시에 들어온 요청 두 개가 키움에는 겹치지 않고 순서대로 나간다.
- [ ] `GET /api/environments/{environment}/rankings/trading_value`가 국내는 `ka10032`, 미국은 `usa20540`을 spec의 요청 본문으로 호출하고, 30위까지 잘라 화면용 형태로 돌려준다. 거래대금은 원·USD 단위로 환산하고, 국내는 전일 순위를 담는다.
- [ ] `exchange` 쿼리를 시장에 맞게 키움 코드로 바꾼다(국내 `all`/`kospi`/`kosdaq`, 미국 `all`/`nyse`/`nasdaq`/`amex`, 없으면 `all`). 시장에 맞지 않는 값은 400으로 거부하고 키움을 호출하지 않는다. 잘못된 순위 종류는 404다.
- [ ] 값 처리 규칙을 따른다: 목록 필드가 없거나 목록이 아니면 502, 종목코드·종목명이 없으면 502, 빈 숫자는 `null`, 숫자가 아닌 문자열은 502, 알 수 없는 등락 방향은 "알 수 없음", 알 수 없는 미국 거래소 코드는 원래 값. 국내 가격은 부호를 뗀 절댓값이다.
- [ ] 호출 제한 429, 설정 누락 503 등 오류 분류와 형식이 계좌 확인과 같다.
- [ ] 메뉴에 "시세 → 순위"가 생기고, 앱을 처음 열면 여전히 계좌 확인이 선택된다.
- [ ] 카드의 각 줄에 순위, 종목명(아래에 코드·티커, 미국은 거래소), 가격(아래에 등락률), 거래대금(국내는 전일 순위 함께)이 보인다. 큰 숫자는 원은 조·억·만, USD는 K·M·B로 짧게 표시한다. `null`은 "−"로 표시한다.
- [ ] 상승 빨강 ▲ +, 하락 파랑 ▼ −, 보합과 알 수 없음은 중립 색이다.
- [ ] 카드 상태: 처음 불러오는 중 skeleton, 새로고침 중 기존 목록 유지와 갱신 표시, 오류 메시지와 "다시 시도", 빈 목록 안내.
- [ ] 거래소를 바꾸면 카드가 즉시 skeleton으로 바뀌고 다시 조회한다. 기존 목록 유지는 같은 조건의 새로고침에만 적용한다. 투자 환경을 바꾸면 데이터·조회 시각·거래소 선택을 버리고 처음부터 조회한다. 늦게 도착한 이전 조건의 응답은 반영하지 않는다.
- [ ] 데스크톱은 2×2 격자(이 티켓에서는 카드 1개), 모바일은 1열이다. 카드 높이를 정해 두고 목록만 카드 안에서 스크롤하며, 화면 전체가 가로로 밀리지 않는다.
- [ ] 가짜 응답 테스트(Seam 1)와 Playwright 화면 테스트(Seam 2)가 위 동작을 확인하고, 기존 테스트도 모두 통과한다.
- [ ] 국내 모의와 미국 모의 서버로 실제 조회해 화면에 표시되는 것을 확인한다.
