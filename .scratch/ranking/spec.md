# 순위: 거래대금·상승률·거래량·인기 종목

Status: ready-for-agent

## Problem Statement

지금 대시보드는 계좌 확인만 할 수 있다. 시장에서 어떤 종목에 돈과 거래가 몰리는지, 어떤 종목이 많이 올랐는지, 다른 투자자가 어떤 종목을 많이 보는지 확인하려면 키움 앱을 따로 열어야 한다. 자동매매 대상 종목을 고르려면 이런 시장 흐름을 같은 대시보드에서 한눈에 볼 수 있어야 한다.

## Solution

왼쪽 메뉴에 "시세" 분류와 **순위** 기능을 추가한다. 순위 화면은 선택한 투자 환경의 시장(국내/미국)에서 **거래대금 상위**, **상승률 상위**, **거래량 상위**, **인기 종목**을 카드 4개로 동시에 보여준다. 화면 위쪽에서 거래소를 고르면 거래대금·상승률·거래량 카드에 적용된다. 인기 종목 카드에서는 집계 구간을 고른다. 키움 호출은 한 번에 하나씩 순서대로 하고, 카드마다 성공과 실패를 따로 보여준다. 조회는 화면에 들어올 때, 조건을 바꿀 때, 새로고침 버튼을 누를 때만 한다.

**키움 클라이언트**

- 지금은 연속조회를 끝까지 이어 받고, 10페이지를 넘으면 "조회 불완전" 오류를 낸다. 여기에 "첫 페이지만 받는" 호출 방식을 추가한다. 이 방식은 응답 헤더가 `cont-yn=Y`여도 다음 페이지를 요청하지 않고, 오류로 처리하지도 않는다.
- 순위 조회는 모두 이 방식을 쓴다. 기존 계좌 확인의 동작은 바꾸지 않는다.
- 순위용 키움 호출은 서버 안에서 잠금(lock)으로 한 번에 하나만 실행한다. 다시 시도, 조건 변경, 여러 브라우저 창에서 동시에 온 요청도 앞 호출이 끝날 때까지 기다렸다가 순서대로 나간다.

**순위 서비스 (새 모듈)**

- 인터페이스: "투자 환경, 순위 종류, 거래소(또는 집계 구간)를 받아 화면용 순위 결과를 돌려준다".
- 투자 환경의 시장에 따라 국내/미국 TR을 고르고 요청 본문을 만든다. 첫 페이지만 받아 30위까지 자른다.
- 응답 목록 필드: `trde_prica_upper`(ka10032), `pred_pre_flu_rt_upper`(ka10027), `tdy_trde_qty_upper`(ka10030), `item_inq_rank`(ka00198), 미국은 모두 `result_list`. 목록 필드가 없거나 목록이 아니면 "응답 형식 오류"(502), 빈 목록이면 정상 응답으로 빈 순위를 돌려준다.
- 값 처리 규칙은 계좌 확인과 같다.
  - 반드시 있어야 하는 항목 필드: 종목코드, 종목명. 없으면 502.
  - 비어 있어도 되는 필드: 가격, 등락률, 거래대금, 거래량, 전일 순위, 순위 변동. 빈 문자열이면 `null`로 보내고 화면에는 "−"로 표시한다.
  - 숫자여야 하는 필드에 숫자가 아닌 문자열이 오면 502.
  - 알 수 없는 등락 방향 코드는 "알 수 없음"으로 보내고, 화면에서 색과 ▲▼ 없이 중립으로 표시한다. 보합으로 단정하지 않는다.
  - 알 수 없는 미국 거래소 코드는 받은 코드 그대로 표시한다.
- 각 항목의 공통 필드: 순위, 종목코드, 종목명, 가격, 등락 방향, 등락률. 미국은 거래소도 담는다.
  - 순위: `now_rank`(ka10032), `bigd_rank`(ka00198), `rank`(미국 TR). `ka10027`·`ka10030`에는 순위 필드가 없으므로 응답 목록 순서(1부터)를 순위로 쓴다.
  - 가격: 국내 `cur_prc`, 미국 `cur_prc`. 인기 종목은 국내 `past_curr_prc`, 미국 `curr_pric`(집계 시점 가격). 국내 가격의 부호는 등락 방향을 뜻하므로 절댓값을 가격으로 쓴다.
  - 등락 방향: 국내 `pred_pre_sig`(1·2 상승, 3 보합, 4·5 하락), 미국 순위 TR도 `pred_pre_sig`. 인기 종목은 국내 `base_comp_sign`, 미국 `sign_for_gjga`(+/−/빈값).
  - 등락률: `flu_rt`. 인기 종목은 국내 `base_comp_chgr`, 미국 `diff_rate_for_gjga`.
  - 미국 거래소: `stex_tp` 값 `NY`→NYSE, `ND`→NASDAQ, `NA`→AMEX.
- 순위별 추가 필드:
  - 거래대금 상위: 거래대금. 국내 `trde_prica`(백만원), 미국 `trde_prica`(천 USD)를 각각 원·USD 단위로 바꿔 담는다. 국내는 전일 순위 `pred_rank`도 담는다.
  - 상승률 상위: 거래량. 국내 `now_trde_qty`, 미국 `trde_qty`.
  - 거래량 상위: 거래량. 국내 `trde_qty`, 미국 `acc_trde_qty`.
  - 인기 종목: 순위 변동(올라간 칸 수는 양수, 내려간 칸 수는 음수, 변동 없음은 0)과 집계 시각. 국내는 `rank_chg`·`rank_chg_sign`과 1위 항목의 `dt`·`tm`, 미국은 `chg_val`·`sign`과 최상위 `base_date`·`base_time`(KST)을 쓴다. 집계 시각을 구할 수 없으면(국내 빈 목록 등) `null`로 보내고 화면에서 "기준" 표시를 숨긴다.
- 키움 원본 응답을 브라우저로 그대로 넘기지 않는다. 화면에 쓰는 필드만 담는다.

**자체 서버 API 계약**

- `GET /api/environments/{environment}/rankings/{kind}`
  - `kind`: `trading_value`, `gainers`, `volume`, `popular`
  - 거래대금·상승률·거래량은 `exchange` 쿼리를 받는다. 국내는 `all`/`kospi`/`kosdaq`, 미국은 `all`/`nyse`/`nasdaq`/`amex`다. 없으면 `all`이다.
  - 인기 종목은 `period` 쿼리를 받는다: `30s`/`1m`/`10m`/`1h`/`today`. 없으면 `1h`다.
  - 응답: 투자 환경, 시장, 순위 종류, 적용한 거래소 또는 집계 구간, 조회 시각, 순위 항목 목록. 인기 종목은 집계 시각도 담는다.
- 잘못된 투자 환경은 기존처럼 404다. 잘못된 `kind`도 404다.
- 시장에 맞지 않는 거래소(예: 미국 환경에 `kospi`)나 목록에 없는 집계 구간은 "잘못된 요청"(400)으로 거부하고 키움을 호출하지 않는다. 오류 응답 형식은 기존과 같다.
- 나머지 오류 분류와 HTTP 상태(설정 오류 503, 호출 제한 429, 키움 오류·응답 형식 오류·연결 실패 502)는 계좌 확인과 같다.

**화면**

- 메뉴: 기존 기능 목록 데이터에 "시세" 분류와 "순위" 항목을 더한다. 아이콘은 lucide에서 고른다. 처음 선택되는 기능은 계좌 확인 그대로다.
- 레이아웃: 위쪽에 거래소 선택, 마지막 조회 시각, 새로고침 버튼을 둔다. 그 아래 카드 4개를 거래대금 → 상승률 → 거래량 → 인기 종목 순서로 놓는다. 데스크톱은 2×2, 모바일은 1열이다. 카드는 높이를 정해 두고 목록만 카드 안에서 스크롤한다.
- 각 줄: 순위 | 종목명(아래에 코드·티커를 작게, 미국은 거래소도) | 가격(아래에 등락률을 작게) | 순위별 지표 1개.
  - 거래대금: 거래대금(국내는 전일 순위를 작게 함께)
  - 상승률: 등락률을 크게
  - 거래량: 거래량
  - 인기 종목: 순위 변동(▲2 / ▼1 / −)
- 큰 숫자는 짧게 표시한다. 원은 조·억·만 단위, USD는 K·M·B 단위다.
- 인기 종목 카드: 카드 안에 집계 구간 선택을 두고, "전체 거래소"와 "기준 HH:MM"을 표시한다. 가격 칸 제목은 "기준가"처럼 집계 시점 가격임을 드러낸다.
- 조회 흐름
  - 화면에 들어오거나 새로고침을 누르면 네 카드를 위에서부터 **한 번에 하나씩** 조회한다. 앞 카드의 조회가 끝난 뒤(성공이든 실패든) 다음 카드를 조회한다.
  - 거래소를 바꾸면 거래대금·상승률·거래량 카드만 같은 방식으로 다시 조회한다. 집계 구간을 바꾸면 인기 종목 카드만 다시 조회한다.
  - 한 카드가 실패해도 다음 카드의 조회는 계속한다.
  - 다시 시도와 조건 변경은 브라우저에서 바로 요청을 보낸다. 키움 호출이 겹치지 않게 하는 일은 서버 잠금이 맡는다.
  - 조건을 바꾸거나 새로고침한 뒤에 늦게 도착한 이전 조건의 응답은 화면에 반영하지 않는다.
  - 거래소나 집계 구간을 바꾸면 영향받는 카드의 기존 목록을 즉시 지우고 "처음 불러오는 중"으로 돌린다. 기존 목록 유지는 같은 조건의 새로고침에만 적용한다.
  - 투자 환경을 바꾸면 계좌 확인처럼 화면 상태를 통째로 버리고(데이터, 조회 시각, 거래소, 집계 구간) 처음부터 조회한다.
- 카드 상태: 처음 불러오는 중(skeleton), 새로고침 중(기존 목록 유지 + 갱신 표시), 오류(오류 종류별 메시지 + "다시 시도"), 빈 목록 안내, 성공.
- 새로고침 버튼은 어느 카드든 조회 중이면 비활성화한다. 마지막 조회 시각은 가장 최근에 성공한 카드 조회의 시각이다.
- 색상과 부호 규칙은 계좌 확인과 같다: 상승 빨강 ▲ +, 하락 파랑 ▼ −, 보합 중립 색.

## Testing Decisions

- 좋은 테스트는 밖에서 보이는 동작만 확인한다. 자체 서버 API의 응답과 키움으로 나가는 요청(도메인, 경로, `api-id`, 본문)을 확인하고, 내부 함수 구조는 확인하지 않는다.
- **Seam 1 (주력)**: FastAPI 테스트 클라이언트로 `/api/environments/{environment}/rankings/{kind}`를 호출한다. 키움 쪽은 기존 가짜 키움 서버(httpx MockTransport)에 8개 TR의 응답 예시를 추가한다. 확인할 동작:
  - 국내·미국 환경에서 순위 종류마다 올바른 TR, 경로, 요청 본문으로 호출하는지. 거래소·집계 구간 값이 키움 코드로 맞게 바뀌는지.
  - 모의 환경은 모의 도메인을, 실전 환경은 실전 도메인을 쓰는지.
  - 응답 헤더가 `cont-yn=Y`여도 다음 페이지를 요청하지 않고 정상 응답하는지. 30개보다 많으면 30위까지 자르는지.
  - 순위 필드가 없는 TR(`ka10027`, `ka10030`)에서 목록 순서가 순위가 되는지.
  - 부호가 붙은 국내 가격, 거래대금 단위 환산, 미국 거래소 코드, 인기 종목 순위 변동과 집계 시각이 맞게 바뀌는지.
  - 빈 목록은 정상 응답, 목록 필드가 없거나 목록이 아니면 502인지.
  - 종목코드·종목명이 빠지면 502, 숫자 필드가 빈 문자열이면 `null`, 숫자가 아닌 문자열이면 502인지.
  - 알 수 없는 등락 방향 코드는 "알 수 없음", 알 수 없는 미국 거래소 코드는 원래 값으로 오는지.
  - 국내 인기 종목이 빈 목록이면 집계 시각이 `null`인지. 국내는 1위 항목의 시각을 쓰는지.
  - 같은 시점에 들어온 순위 요청 두 개가 키움에는 겹치지 않고 하나씩 나가는지.
  - 시장에 맞지 않는 거래소, 잘못된 집계 구간, 잘못된 순위 종류를 거부하고 키움을 호출하지 않는지.
  - 호출 제한은 429, 설정 누락은 503으로 기존 오류 형식을 따르는지.
  - 기존 계좌 확인 테스트가 그대로 통과하는지(연속조회 동작 유지).
- **Seam 2 (화면)**: 기존 Playwright 테스트처럼 브라우저의 `/api` 요청을 가로채 가짜 응답을 준다. 확인할 동작:
  - 메뉴에서 순위를 고르면 카드 4개가 보이고, 처음 화면은 여전히 계좌 확인인지.
  - 카드가 순서대로 한 번에 하나씩 요청되는지.
  - 한 카드만 실패하면 그 카드에만 오류와 "다시 시도"가 보이고, 다시 시도하면 그 카드만 다시 요청하는지.
  - 거래소를 바꾸면 세 카드만, 집계 구간을 바꾸면 인기 종목 카드만 다시 요청하는지.
  - 투자 환경을 바꾸면 이전 시장의 데이터가 즉시 사라지고 늦은 응답이 반영되지 않는지.
  - 거래소나 집계 구간을 바꾸면 영향받는 카드가 즉시 skeleton으로 바뀌고, 새로고침 때만 기존 목록이 유지되는지.
  - 값이 `null`인 칸이 "−"로, 알 수 없는 등락 방향이 중립으로 표시되는지.
  - 미국 환경에서 거래소 선택지가 바뀌고 USD와 거래소가 표시되는지.
  - 빈 목록 안내, 처음 불러오는 중, 새로고침 중 상태.
  - 데스크톱(1440px)과 모바일(390px) 스크린샷. 모바일에서 화면 전체가 가로로 밀리지 않는지.
- 실제 서버 확인은 국내 모의와 미국 모의로만 한다. 네 순위를 실제로 조회해 응답 필드가 문서와 맞는지 확인한다. 실전 환경은 가짜 응답으로 화면만 확인한다.
- 화면 단위 테스트(컴포넌트 테스트)는 계좌 확인과 같이 범위에서 제외한다.

## Out of Scope

- 하락률 상위 등 요청한 네 가지 이외의 순위
- 관리종목·ETF·가격대·거래량 조건 등 추가 걸러내기 조건
- 연속조회로 30위를 넘는 순위 가져오기
- 자동 주기 새로고침과 WebSocket 실시간 순위
- 종목을 눌러 상세 화면이나 주문 화면으로 이동하기
- 국내 업종·미국 업종(`inds_cd`)과 지수 구성(`inds_cls_tp`) 필터
- 주문 관련 모든 기능

## Further Notes

- 문서로 확인되지 않아 국내·미국 모의 서버로 확인할 사항:
  - 모의 서버가 국내 `stex_tp=3`(통합)을 받아주는지. 거부하면 KRX로 몰래 바꾸지 않고 구현을 멈추고 사용자에게 보고한다.
  - `stex_tp=3`일 때 국내 `stk_cd`에 `_NX`·`_AL` 같은 접미어가 붙는지. 붙으면 사용자에게 보고하고 표시 방식을 정한다.
  - 순위 TR의 첫 페이지에 몇 개가 오는지. 30개보다 적으면 받은 만큼만 보여준다.
  - 미국 인기 종목의 `sign`이 순위 변동 방향인지. 문서에는 "등락부호"로만 적혀 있어 확인 전에는 구현하지 않는다. 구현 첫 단계에서 미국 모의 서버로 `usa01980`을 호출해 `sign`과 `chg_val` 값을 확인한다. 순위 변동 방향임이 분명하면 그대로 구현하고, 애매하면 미국 인기 종목의 순위 변동 칸만 빼고 사용자에게 보고한다. 국내 `rank_chg_sign`은 문서에 "순위 등락 부호"로 명시되어 있어 그대로 쓴다.
  - 국내 인기 종목의 `rank_chg`에 부호가 포함되는지(문서 예시는 `"-1"`과 `rank_chg_sign="-"`를 함께 보낸다). 방향은 `rank_chg_sign`으로 정하고 크기는 `rank_chg`의 절댓값으로 쓴다.
  - 국내 인기 종목의 항목별 `dt`·`tm`이 모두 같은지. 다르게 오면 보고한다.
  - 각 TR의 호출 횟수 제한. 네 TR을 연달아 호출할 때 제한에 걸리면 사용자에게 보고한다.
- 실전 환경에서 순위를 조회하면 실전 인증정보로 키움 실전 서버를 호출한다. 시세만 읽는 조회이고 주문은 없다.
- 화면에 표시하는 값은 키움이 돌려준 값을 쓴다. 단위 환산과 부호 정리만 서버에서 하고, 등락률 등을 다시 계산하지 않는다.
- 용어는 CONTEXT.md의 순위, 거래소, 상승률, 인기 종목, 집계 구간을 따른다.

## Implementation Notes (2026-10-05)

티켓 01: 국내 모의·미국 모의 서버로 순위 TR 8개를 확인했다(17:50 KST, 국내·미국 정규장 마감 후). 실전 서버는 호출하지 않았다.

- 국내 순위 TR 3개는 `stex_tp=3`(통합)을 정상 처리했다.
- 국내 순위 TR 3개(`ka10032`·`ka10027`·`ka10030`)의 `stk_cd`에는 `_AL` 접미어가 붙는다(예: `005930_AL`). `ka00198`은 6자리 코드만 온다.
- 첫 페이지 개수와 연속조회: `ka10032` 100개, `ka10027` 200개, `ka10030` 100개, 미국 순위 TR 20~25개이며 모두 `cont-yn=Y`다. 인기 종목은 국내·미국 모두 20개이고 `cont-yn=N`이다. 인기 종목은 30위가 아니라 20위까지만 나온다.
- 미국 순위 TR의 `cur_prc`·`pred_pre`도 국내처럼 부호가 등락 방향을 뜻한다(예: `-162.6000`, `pred_pre_sig=5`). 가격은 국내·미국 모두 절댓값을 쓴다.
