# 비밀번호 로그인

Status: ready-for-agent

## Problem Statement

대시보드는 주소만 알면 누구나 열 수 있다. 계좌 확인으로 예수금·보유종목이 보이고, 모의투자 주문도 보낼 수 있다. 서버를 집 안 네트워크나 VPN에서 다른 기기로 열어 둘 때, 비밀번호를 아는 사람만 쓸 수 있어야 한다. 자리를 떠나 탭을 닫았거나 다른 사이트로 갔다 돌아왔을 때는 다시 비밀번호를 물어야 하고, 단순 새로고침 때마다 묻지는 않아야 한다. 누군가 로그인했거나 비밀번호를 맞히려 하면 Discord로 바로 알고 싶다. HTTPS는 아직 없다.

## Solution

`.env`의 `PASSWORD`로 로그인한다. 로그인하지 않은 채 열면 비밀번호 입력 화면만 보인다. 맞히면 서버가 무작위 세션 ID를 만들어 서버 메모리에 기억하고, 브라우저를 닫으면 사라지는 `HttpOnly`·`SameSite=Strict` 쿠키로 준다. 로그인·로그아웃·세션 확인을 뺀 모든 `/api` 요청은 이 쿠키가 없으면 401이다. 화면은 페이지가 열릴 때 브라우저가 알려 주는 "어떻게 열렸는지"를 보고, 새로고침이 아니면 로그인 세션을 끝내고 비밀번호를 다시 묻는다. 쿠키는 같은 브라우저의 탭들이 함께 쓰므로 로그인 세션은 브라우저 단위다. 로그인 세션은 하나뿐이라 다른 기기에서 새로 로그인하면 이전 세션은 끝난다. 30분 동안 요청이 없거나 로그인 후 12시간이 지나도 끝나고, 화면도 30분 동안 입력이 없으면 스스로 잠근다. 로그인 세션이 끝나면 화면의 토스트도 지운다. 같은 IP에서 연속 5번 틀리면 그 IP는 15분 동안 로그인할 수 없다. 로그인 성공과 시도 제한은 접속 정보와 함께 Discord로 알린다.

## User Stories

**로그인**

1. As a 사용자, I want 로그인하지 않고 열면 비밀번호 입력 화면만 보이기를, so that 비밀번호를 모르는 사람은 계좌를 보지 못한다.
2. As a 사용자, I want 비밀번호를 맞히면 바로 계좌 확인 화면으로 가기를, so that 평소처럼 쓴다.
3. As a 사용자, I want 틀리면 "비밀번호가 올바르지 않습니다"가 보이고 입력 칸이 비워지기를, so that 다시 입력한다.
4. As a 사용자, I want 5번 연속 틀려 잠기면 "로그인 시도가 너무 많습니다. N분 후 다시 시도하세요"가 보이기를, so that 언제 다시 할 수 있는지 안다.
5. As a 사용자, I want 로그인 화면에서 Enter로 제출되고, 보내는 동안 버튼이 잠기기를, so that 두 번 보내지 않는다.

**로그인 유지와 종료**

6. As a 사용자, I want 새로고침해도 로그인이 유지되기를, so that 화면이 이상할 때 새로고침할 수 있다.
7. As a 사용자, I want 계좌 확인·종목 검색·순위를 오가도 로그인이 유지되기를, so that 화면마다 비밀번호를 넣지 않는다.
8. As a 사용자, I want 탭을 닫았다가 다시 열면 비밀번호를 다시 묻기를, so that 자리를 비운 사이 다른 사람이 열어도 보지 못한다.
9. As a 사용자, I want 다른 사이트로 갔다가 뒤로가기나 주소 입력으로 돌아오면 비밀번호를 다시 묻기를, so that 떠났다 온 것을 새 접속으로 본다.
10. As a 사용자, I want 새 탭으로 열면 그 브라우저의 로그인 세션이 끝나고 비밀번호를 묻기를, 다시 로그인하면 그 브라우저의 탭들이 함께 쓰기를, so that 새 탭도 새 접속으로 본다.
10a. As a 사용자, I want 다른 기기에서 로그인하면 이 브라우저는 로그아웃되지만, 다른 기기에서 로그인하지 않고 열기만 해서는 이 브라우저가 로그아웃되지 않기를, so that 로그인 세션이 하나만 있고 남이 주소만 열어 내 세션을 끊지 못한다.
11. As a 사용자, I want 30분 동안 아무 요청이 없거나 로그인 후 12시간이 지나면 다음 요청에서 로그인 화면으로 돌아가고 "로그인이 만료되었습니다"가 보이기를, so that 열어 둔 탭도 언젠가 잠긴다.
11a. As a 사용자, I want 화면에서 30분 동안 마우스·키보드·터치 입력이 없으면 요청을 기다리지 않고 바로 로그인 화면으로 바뀌기를, so that 자리를 비운 사이 예수금·보유종목이 화면에 남아 있지 않다.
11b. As a 사용자, I want 로그인 세션이 끝나면(로그아웃·만료·재접속) 화면의 토스트가 모두 사라지고, 그 뒤에 도착한 이전 주문 응답은 토스트로 뜨지 않기를, so that 로그인 화면 위에 주문 내용이 남지 않는다.
12. As a 사용자, I want 사이드바(모바일은 메뉴)에 로그아웃 버튼이 있기를, so that 직접 끝낼 수 있다.
13. As a 사용자, I want 서버를 다시 시작하면 다시 로그인해야 하기를, so that 세션이 서버 밖에 남지 않는다.

**보호 범위**

14. As a 사용자, I want 로그인하지 않은 요청은 계좌·순위·종목 검색·시세·주문 등 모든 `/api` 요청이 401로 거부되고 키움에 아무 요청도 나가지 않기를, so that 화면을 우회해도 데이터를 얻지 못한다.
15. As a 사용자, I want 주문 중 로그인이 만료되어 401을 받으면 "접수 여부 확인 불가"가 아니라 "주문하지 않았습니다"로 보이기를, so that 나가지 않은 주문을 키움에서 찾지 않는다.

**알림**

16. As a 사용자, I want 로그인에 성공하면 Discord로 시각과 접속 정보(IP, 브라우저·OS)가 오기를, so that 내가 아닌 로그인을 바로 안다.
17. As a 사용자, I want IP가 시도 제한에 걸리면 Discord로 그 IP와 잠긴 시간이 오기를, so that 누가 비밀번호를 맞히려 한다는 것을 안다.
18. As a 사용자, I want Discord가 꺼져 있거나 실패해도 로그인은 정상 동작하기를, so that 알림 때문에 못 들어가지 않는다.

**설정과 비밀값**

19. As a 사용자, I want `PASSWORD`가 비어 있으면 서버가 시작되지 않고 원인이 로그에 남기를, so that 비밀번호 없이 열린 채로 운영되지 않는다.
20. As a 사용자, I want 비밀번호, 세션 ID, 키움 인증정보가 화면 응답·로그·Discord 알림 어디에도 나오지 않기를, so that 로그를 보여줘도 안전하다.

**기록**

21. As a 사용자, I want 로그인 성공·실패·잠김, 로그아웃, 세션 만료·교체, 로그인 없이 온 요청이 로그에 남기를, so that 무슨 일이 있었는지 나중에 확인한다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **로그인 세션**, **접속 정보**, **토스트**를 더했다. 화면 구석의 결과 안내는 토스트이고, 알림은 Discord 메시지만 뜻한다. 요청의 "어떤 환경에서 접속"은 투자 환경이 아니라 접속 정보다.

**설정**

- `PASSWORD` 하나만 새로 쓴다(`.env.example`에 추가). 사용자가 요청한 변수이므로 AGENTS.md의 "새 `.env` 변수 금지"(요청받지 않은 변수)에 해당하지 않는다. 앞뒤 공백은 떼지 않고 그대로 비교한다. 비었거나 공백뿐이면 `create_app`이 시작을 거부한다. 길이 규칙은 두지 않는다.
- 비밀번호는 `masking.secrets`에 등록한다.
- 세션 비밀키는 두지 않는다. 세션 ID는 `secrets.token_urlsafe(32)` 무작위 값이고 서버 메모리에만 기억하므로 서명할 키가 필요 없다. 새 의존성도 없다.

**세션**

- 서버 메모리에 로그인 세션 하나만 둔다: 세션 ID, 로그인 시각, 마지막 요청 시각, 접속 정보.
- 새로 로그인하면 이전 세션을 버린다(로그 `session_replaced`). 쿠키는 브라우저의 탭들이 함께 쓰므로 "이전 세션"은 다른 브라우저·기기의 세션이다.
- 만료: 마지막 요청 후 30분, 로그인 후 12시간. 만료된 세션으로 온 요청은 401이고 세션을 지운다.
- 쿠키: 이름 `stock_bot_session`, `HttpOnly`, `SameSite=Strict`, `Path=/`, `Max-Age`·`Expires` 없음(브라우저 세션 쿠키). 요청이 HTTPS일 때만 `Secure`를 붙인다. HTTP에서 `Secure`를 붙이면 쿠키가 저장되지 않기 때문이다.

**API**

| 경로 | 인증 | 동작 |
|---|---|---|
| `POST /api/auth/login` `{password}` | 불필요 | 맞으면 204 + 쿠키, 틀리면 401 `invalid_password`, 잠김이면 429 `login_locked`(`retry_after_seconds`), 본문 형식 오류면 400 `invalid_request` |
| `POST /api/auth/logout` | 불필요 | 요청 쿠키가 현재 세션과 같을 때만 세션을 지운다. 쿠키가 없거나 예전 것이면 현재 세션은 그대로 둔다. 어느 경우든 쿠키를 지우고 204 |
| `GET /api/auth/session` | 불필요 | 유효하면 200, 아니면 401 `unauthorized` |
| 그 밖의 `/api/*` | 필요 | 세션이 없거나 만료면 401 `unauthorized`, 키움을 부르지 않는다 |

- 로그인 본문은 FastAPI 자동 입력 검사를 쓰지 않고 `place_order`처럼 직접 읽는다. 깨진 JSON, 객체가 아님, `password` 없음, 문자열이 아님은 모두 400 `invalid_request`이고, 응답·로그에 보낸 값을 담지 않는다. 실패 횟수에 넣지 않는다.
- 인증 검사는 HTTP middleware에서 한다. middleware의 예외는 exception handler로 가지 않으므로 `_error_response`를 직접 돌려준다. 요청 ID를 만드는 기존 middleware의 안쪽에서 돌아 401 로그에도 요청 ID가 남는다.
- 정적 파일(`index.html`, JS, CSS)은 인증 없이 준다. 요청의 "모든 페이지 보호"와 다르게 정한 것이다. 로그인 화면이 이 파일로 그려지고, 보호할 데이터는 모두 `/api`로만 나간다. 개발 모드에서는 화면을 Vite가 내보내므로 어차피 막을 수 없다.
- CSRF: `SameSite=Strict`에 더해, `POST` 요청에 `Origin` 헤더가 있으면 요청 Host와 같아야 한다. 다르면 403 `forbidden_origin`.

**시도 제한**

- IP(`request.client.host`)별 연속 실패 수를 메모리에 둔다. 5번째 실패에서 15분 잠그고, 그 응답부터 429 `login_locked`다. 성공하면 그 IP의 실패 수를 지운다.
- 잠긴 IP의 로그인 요청은 비밀번호를 확인하지 않고 429다(맞는 비밀번호여도). 잠긴 동안의 시도는 실패 수에 넣지 않는다.
- 잠금이 풀리면 실패 수는 0부터 다시 센다. 풀린 IP의 기록은 메모리에서 지운다.
- 비밀번호 비교는 설정값과 입력값을 둘 다 UTF-8 바이트로 바꾼 뒤 `hmac.compare_digest`로 한다. 문자열을 그대로 넣으면 ASCII 밖의 글자(한글 등)에서 `TypeError`가 난다.
- 프록시 뒤에 두지 않으므로 `X-Forwarded-For`는 읽지 않는다.

**Discord 알림**

- `create_app`이 `DiscordNotifier`를 만든다. 테스트가 가짜 Discord를 넘길 수 있게 `create_app`이 notifier를 인자로도 받는다. 키움용 `transport`와 섞지 않는다.
- 로그인 응답이 알림을 기다리지 않게 background task로 보낸다. 작업이 중간에 정리되지 않도록 앱이 진행 중인 작업을 모아 두고, 끝나면 뺀다. 서버가 꺼질 때 남은 알림은 버린다. 알림 실패는 로그만 남는다.
- 로그인 성공: embed 제목 "로그인", 항목 시각(KST), IP, 브라우저·OS.
- 시도 제한: embed 제목 "로그인 시도 제한", 항목 IP, 연속 실패 수, 풀리는 시각(KST), 브라우저·OS.
- 투자 환경 머리말은 붙이지 않는다(`spec` 없음).
- 브라우저·OS는 User-Agent에서 간단히 고른다(Edge, Chrome, Firefox, Safari / Windows, Android, iOS, macOS, Linux, 그 밖은 "알 수 없음"). 원문 User-Agent는 로그에만 남긴다.
- 입력한 비밀번호는 틀린 것이라도 알림·로그에 넣지 않는다.

**화면**

- 앱 최상단에서 인증 상태로 분기한다: 확인 중 → 로그인 화면 또는 대시보드.
- 페이지가 열릴 때 `performance.getEntriesByType("navigation")[0].type`이 `reload`이면 `GET /api/auth/session`으로 확인한다. 그 밖(`navigate`, `back_forward`, 값 없음)이면 `POST /api/auth/logout` 후 로그인 화면을 보여준다.
- `pageshow` 이벤트의 `persisted`가 true(브라우저가 저장해 둔 페이지를 뒤로가기로 그대로 보여줌)여도 로그아웃하고 로그인 화면을 보여준다.
- 아무 API든 401 `unauthorized`를 받으면 로그인 화면으로 돌아가고 "로그인이 만료되었습니다"를 보여준다. 공용 `getJson`과 `placeOrder` 둘 다 해당한다. `placeOrder`의 401은 "접수 여부 확인 불가"가 아니라 주문하지 않은 실패다. 401이 오면 로그인 세션이 끝나 토스트가 지워지므로, 주문하지 않았다는 사실은 로그인 화면의 안내("로그인이 만료되어 주문하지 않았습니다")로 알린다.
- 화면에 30분 입력 타이머를 둔다. 마우스·키보드·터치 입력이 있으면 다시 센다. 시간이 다 되면 `POST /api/auth/logout` 후 로그인 화면과 "로그인이 만료되었습니다"를 보여준다.
- 로그인 세션이 끝나면(로그아웃 버튼, 401, 입력 타이머, 새로고침이 아닌 열기) 토스트를 모두 지운다. 그 뒤에 도착한 이전 로그인 세션의 주문 응답은 토스트로 띄우지 않는다. 다시 로그인한 뒤 보여주는 장치는 만들지 않는다. 결과는 서버 로그와 계좌 확인에서 본다.
- 로그아웃 버튼은 데스크톱 사이드바와 모바일 메뉴에 둔다.
- 투자 환경 선택(localStorage)은 로그아웃해도 그대로 둔다.

**로그**

- 이벤트: `login_succeeded`, `login_failed`(연속 실패 수), `login_locked`, `login_rejected_locked`, `logout`, `session_expired`(idle/absolute), `session_replaced`, `unauthorized_request`(경로), `origin_rejected`.
- 필드: IP, 브라우저·OS, 원문 User-Agent(앞 200자). 비밀번호·세션 ID·쿠키 헤더는 넣지 않는다.

## Testing Decisions

- 바깥에서 보이는 동작만 검증한다. 키움과 Discord 실제 서버는 부르지 않는다.

**서버 API (pytest, 기존 `make_client` 방식)**

- `FAKE_ENV`에 `PASSWORD`를 넣고, `make_client`는 로그인한 클라이언트를 돌려준다. `create_app`을 직접 부르는 테스트(5곳)도 로그인하게 고친다. 기존 테스트는 그대로 통과한다.
- 로그인 없이 계좌·순위·종목 검색·시세·주문 요청은 401 `unauthorized`이고 가짜 키움에 요청이 없다.
- 맞는 비밀번호: 204, 쿠키에 `HttpOnly`, `SameSite=Strict`가 있고 `Max-Age`·`Expires`가 없다. HTTP에서는 `Secure`가 없고 HTTPS(`base_url="https://..."`)에서는 있다.
- 틀린 비밀번호 401. 같은 IP 5번 연속 실패 후에는 맞는 비밀번호도 429이고 `retry_after_seconds`가 있다. 15분이 지나면(시계 주입) 다시 된다. 성공하면 실패 수가 초기화된다.
- 새로 로그인하면 이전 쿠키는 401이다.
- 쿠키 없이, 또는 예전 쿠키로 logout을 부르면 204이고 현재 세션은 그대로 유효하다.
- 한글이 섞인 비밀번호로 성공하고, 틀린 한글 비밀번호는 401이며 실패 수가 쌓인다.
- 깨진 JSON, `password` 없음, 문자열이 아닌 `password`는 400 `invalid_request`이고 응답·로그에 보낸 값이 없으며 실패 수가 늘지 않는다.
- 잠금이 풀린 뒤 한 번 틀려도 다시 잠기지 않는다. 잠긴 동안의 시도는 실패 수에 들어가지 않는다.
- 30분 idle, 12시간 absolute가 지나면(시계 주입) 401이다. 그 전의 요청은 idle 시간을 늘린다.
- 로그아웃 후 같은 쿠키는 401이다.
- `PASSWORD`가 없거나 빈 값이면 `create_app`이 실패한다.
- 다른 `Origin`의 `POST`는 403이다.
- 로그인 성공과 잠김에서 가짜 Discord에 embed가 나가고, 내용에 IP·브라우저·OS가 있고 비밀번호는 없다. Discord가 실패해도 로그인은 204다.
- 로그에 비밀번호와 세션 ID가 없다.

**화면 (Playwright e2e + 가짜 `/api`)**

- `page.goto`는 새로고침이 아니므로 로그인 화면이 뜬다. 공용 함수 `openDashboard(page)`가 `/api/auth/*`를 가짜로 응답하게 하고, 페이지를 열어 로그인 화면에서 비밀번호를 넣는다. 기존 `page.goto("/")`(약 40곳)는 이 함수로 바꾼다. `page.reload()`를 쓰는 기존 테스트는 새로고침 규칙으로 그대로 동작한다.
- 일부 경로만 가로채는 spec도 `/api/auth/*`가 실제 서버로 새지 않게 이 함수를 거친다. `**/api/**`를 통째로 가로채는 3개 spec은 `/api/auth/*` 분기를 더한다. 기존 기대는 그대로 통과한다.
- 처음 열면 로그인 화면이 보이고 계좌 요청이 나가지 않는다.
- 맞는 비밀번호면 계좌 확인이 보인다. 틀리면 안내, 429면 남은 분이 보인다.
- 로그인 후 새로고침하면 세션 확인만 하고 대시보드가 유지된다. 새로 `goto`하면 logout 요청이 나가고 로그인 화면이다.
- 계좌 요청이 401이면 로그인 화면과 만료 안내가 보인다.
- 주문 요청이 401이면 "접수 여부 확인 불가"가 아닌 실패 안내가 보인다.
- 로그아웃 버튼을 누르면 logout 요청이 나가고 로그인 화면이다. 모바일 메뉴에도 있다.
- 같은 브라우저 컨텍스트에서 두 번째 탭을 열면 logout 요청이 나가고, 첫 탭의 다음 요청이 401이면 첫 탭도 로그인 화면이다. 두 번째 탭에서 로그인하면 첫 탭을 새로고침했을 때 대시보드가 보인다.
- 30분 동안 입력이 없으면(시계 조작) 로그인 화면과 만료 안내가 보인다. 그 전에 입력하면 대시보드가 유지된다.
- 실패 토스트가 떠 있을 때 로그아웃하면 토스트가 사라진다. 로그아웃 뒤에 도착한 주문 응답은 토스트로 뜨지 않는다.
- `@live` 테스트는 실행할 때 `PASSWORD` 환경변수로 로그인한다. 실행 방법을 README에 적는다.

**그 밖**

- `uv run pytest`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy`, `pnpm --dir web typecheck`, `pnpm --dir web build`, `pnpm --dir web test:e2e`. 웹에는 lint 명령이 없다.

## Out of Scope

- HTTPS 적용(인증서, reverse proxy). HTTP에서는 비밀번호와 쿠키가 암호화되지 않은 채 네트워크를 지나간다. LAN 또는 VPN에서만 접속한다는 전제이며, README에 적는다.
- 여러 사용자, 사용자별 비밀번호, 비밀번호 변경 화면, 2단계 인증.
- 재시작 후에도 남는 세션 저장(파일·DB).
- 로그인 실패마다 보내는 알림, 로그아웃·만료 알림.
- 탭을 닫는 순간 서버 세션을 지우는 것. 서버 세션은 다음 접속·30분 미사용·새 로그인 때 끝난다.

## Further Notes

- 탭을 닫아도 서버 세션은 바로 지워지지 않는다. 그 사이 같은 브라우저로 다시 열면 화면이 새로고침이 아님을 보고 로그아웃하므로 비밀번호를 다시 묻는다. 화면을 거치지 않고 같은 쿠키로 API를 직접 부르는 경우만 30분 안에 통한다.
- 브라우저가 탭 복원(재시작 후 이어 열기) 때 navigation type을 무엇으로 주는지는 확인하지 않았다. `reload`만 유지하므로 다른 값이면 로그아웃되는 쪽이다.
- `SameSite=Strict`라서 다른 사이트의 링크로 들어온 첫 요청에는 쿠키가 붙지 않는다. 그 경우도 화면은 새로고침이 아니므로 로그아웃하므로 동작이 달라지지 않는다.
- 기존 백엔드 테스트는 모두 `FAKE_ENV`를 펼쳐 환경변수를 만든다(`tests/test_domestic_account.py:118` 등). `FAKE_ENV`에 `PASSWORD`만 넣으면 시작 실패가 나지 않는다.
- 인터넷에 공개하게 되면 시도 제한에 전체 실패 상한(1시간 20번)을 더하고 HTTPS를 먼저 적용한다.
