# 03: 재접속하면 로그인 세션 끝내기, 로그아웃

**What to build:** 새로고침하면 로그인이 유지되지만, 탭을 새로 열거나 주소를 입력하거나 다른 사이트에서 뒤로가기로 돌아오면 로그인 세션이 끝나고 비밀번호를 다시 묻는다. 로그인 세션은 브라우저 단위다. 사용자는 로그아웃 버튼으로 직접 끝낼 수도 있다. 로그인 세션이 끝나면 화면의 토스트도 사라진다.

Spec: `.scratch/password-auth/spec.md` (User Stories 6~10a·11b·12, API, 화면)

**Blocked by:** 02

**Status:** ready-for-agent

- [x] `POST /api/auth/logout`: 요청 쿠키가 현재 세션과 같을 때만 세션을 지운다. 쿠키가 없거나 예전 쿠키면 현재 세션은 유효하게 남는다. 어느 경우든 쿠키를 지우고 204. 로그 `logout`.
- [x] 화면: 페이지가 열릴 때 navigation type이 `reload`면 세션 확인만 하고 대시보드를 유지한다. 그 밖(`navigate`, `back_forward`, 값 없음)이면 logout을 부른 뒤 로그인 화면을 보여준다.
- [x] 화면: `pageshow`의 `persisted`가 true여도 logout 후 로그인 화면이다.
- [x] 화면: 데스크톱 사이드바와 모바일 메뉴에 로그아웃 버튼이 있고, 누르면 logout 후 로그인 화면이다. 투자 환경 선택은 그대로 남는다.
- [x] 화면: 로그인 세션이 끝나면(로그아웃 버튼, 401, 새로고침이 아닌 열기) 토스트가 모두 사라진다. 그 뒤에 도착한 이전 로그인 세션의 주문 응답은 토스트로 뜨지 않는다.
- [x] 백엔드 테스트: 로그아웃 후 같은 쿠키는 401. 쿠키 없이·예전 쿠키로 부른 logout은 204이고 현재 세션이 유효하다.
- [x] e2e: 로그인 후 새로고침하면 logout 요청 없이 대시보드가 유지된다. 다시 열면(`goto`) logout 요청이 나가고 로그인 화면이다.
- [x] e2e: 같은 브라우저 컨텍스트에서 두 번째 탭을 열면 logout 요청이 나가고, 첫 탭의 다음 요청이 401이면 첫 탭도 로그인 화면이다. 두 번째 탭에서 로그인하면 첫 탭을 새로고침했을 때 대시보드가 보인다.
- [x] e2e: 실패 토스트가 떠 있을 때 로그아웃하면 사라진다. 로그아웃 뒤 도착한 주문 응답은 토스트로 뜨지 않는다. 모바일 메뉴의 로그아웃도 동작한다.
- [x] 전체 검증 명령 통과.
