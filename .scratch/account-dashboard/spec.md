# 주식 자동매매 대시보드: 전체 구조와 계좌 확인

Status: ready-for-agent

## Problem Statement

키움 REST API로 국내·미국 주식을 자동매매하려 하지만, 아직 투자 환경을 고르고 계좌 상태를 한눈에 볼 수 있는 도구가 없다. 실전투자 1개와 모의투자 2개의 인증정보를 따로 관리해야 하고, 잘못된 투자 환경이나 엉뚱한 계좌로 API를 호출할 위험이 있다. 앱 키, 시크릿, 접근 토큰이 브라우저나 로그로 새어나가서도 안 된다. 나중에 자동주문 기능을 붙이려면 안전한 기반 구조가 먼저 필요하다.

## Solution

개인용 웹 대시보드를 만든다. 상단에서 투자 환경(국내 실전, 미국 실전, 국내 모의, 미국 모의)을 고르고, 왼쪽 메뉴에서 기능을 고르면 오른쪽에 그 기능의 화면이 표시된다. 첫 기능은 **계좌 확인**이다. 선택한 투자 환경의 자산 요약, 예수금, 보유종목을 카드와 표로 보여준다. 키움 API는 자체 서버에서만 호출하고, 브라우저는 자체 서버 API만 호출한다. 투자 환경이 없거나 잘못되면 조회를 거부하고, 다른 투자 환경으로 대신 넘어가지 않는다. 자동주문은 이번 범위가 아니다.

## User Stories

1. As a 투자자, I want 상단에 국내 실전·미국 실전·국내 모의·미국 모의 버튼이 있기를, so that 한 번의 클릭으로 투자 환경을 바꿀 수 있다.
2. As a 투자자, I want 처음 열면 국내 모의가 선택되어 있기를, so that 실수로 실전 계좌를 다루지 않는다.
3. As a 투자자, I want 다시 열면 마지막으로 고른 투자 환경으로 열리기를, so that 매번 다시 고르지 않아도 된다.
4. As a 투자자, I want 저장된 투자 환경 값이 없거나 잘못되면 국내 모의로 열리기를, so that 어떤 경우에도 실전으로 넘어가지 않는다.
5. As a 투자자, I want 실전 환경을 고르면 경고 색과 "실전" 배지가 보이기를, so that 지금 실제 돈을 다루는 화면임을 바로 알 수 있다.
6. As a 투자자, I want 현재 선택된 투자 환경 버튼이 강조되기를, so that 어떤 환경을 보고 있는지 헷갈리지 않는다.

## Implementation Decisions

**전체 구조**
- 서버는 Python(FastAPI)이고 기존 uv 프로젝트에 둔다. 화면은 React, Vite, TypeScript, Tailwind CSS로 만든 별도 frontend 패키지다. 아이콘은 lucide 하나로 통일한다.
- 개발 모드에서는 Vite 개발 서버가 `/api` 요청을 FastAPI로 넘긴다(proxy). 빌드한 뒤에는 FastAPI가 빌드 결과물을 직접 제공한다.
- 브라우저는 자체 서버 `/api`만 호출한다. 키움 호출은 서버 안에서만 일어난다.

**투자 환경**
- 투자 환경은 `domestic_real`, `us_real`, `domestic_paper`, `us_paper` 네 값만 허용하는 고정 목록이다. 이 밖의 값은 서버가 거부한다. 기본값으로 대신 처리하지 않는다.
- 투자 환경마다 다음 정보를 가진다: 시장(국내/미국), 거래 구분(실전/모의), 사용할 인증정보 묶음, REST 도메인.
- 국내 실전과 미국 실전은 `REAL_*` 인증정보를, 국내 모의는 `PAPER_KR_*`를, 미국 모의는 `PAPER_US_*`를 쓴다. 새 환경변수는 추가하지 않는다.
- 도메인: 실전은 `https://api.kiwoom.com`, 모의는 `https://mockapi.kiwoom.com`. 미국 모의도 같은 모의 도메인을 쓴다.

**설정 로딩**
- 프로젝트 최상위 `.env`의 절대경로를 코드 파일 위치로 계산한다. 파일이 있을 때만 읽는다.
- 이미 설정된 환경변수는 `.env` 값으로 덮어쓰지 않는다.
- 필요한 변수(앱 키, 시크릿, 계좌번호)가 하나라도 없으면 그 투자 환경의 요청은 "설정 누락" 오류가 된다. 오류에는 빠진 변수의 이름만 담고 값은 담지 않는다.

**키움 클라이언트 (깊은 모듈)**
- 인터페이스: "투자 환경과 TR 호출(API ID, 경로, 요청 본문)을 받아 응답 본문을 돌려준다". 내부에서 처리하는 일은 다음과 같다.
  - 투자 환경에 맞는 도메인과 인증정보 선택
  - 접근 토큰 발급(`au10001`)과 투자 환경별 메모리 캐시
  - 공통 헤더 구성: `api-id`, `authorization: Bearer …`, `cont-yn`, `next-key`, `Content-Type: application/json;charset=UTF-8`
  - 연속조회: 응답 헤더가 `cont-yn=Y`면 `next-key`로 이어서 요청한다. 최대 10페이지까지만 가져오고, 목록 필드를 이어 붙인다. 10번째 페이지에도 `cont-yn=Y`가 있으면 일부 결과를 돌려주지 않고 "조회 불완전" 오류로 처리한다.
  - `return_code` 해석과 오류 분류
  - 요청 ID를 붙인 구조화 로그
- 토큰 만료 판단: `expires_dt`(YYYYMMDDHHMMSS)를 한국시간으로 보고 5분 여유를 둔다. 시간대는 문서로 확인되지 않은 가정이다. 실제 시간대가 UTC라면 한국시간 해석은 9시간 일찍 재발급하게 될 뿐이고, 반대로 UTC로 해석했는데 실제가 한국시간이면 만료된 토큰을 쓰게 된다. 그래서 틀려도 안전한 쪽인 한국시간을 택한다. 이 근거를 코드에도 남긴다.
- 토큰 발급은 투자 환경마다 잠금(lock)으로 보호한다. 동시에 들어온 요청은 진행 중인 발급 하나의 결과를 함께 쓰고, 토큰을 중복 발급하지 않는다.
- `8005`(토큰 무효)를 받으면 새 토큰을 받아 한 번만 다시 시도한다. 캐시는 실패한 요청이 사용한 토큰이 현재 캐시의 토큰과 같을 때만 지운다. 늦게 도착한 `8005`가 이미 갱신된 토큰을 지우지 않게 하기 위해서다.
- 오류 분류:
  - 응답 본문에 `return_code`가 있으면 HTTP 상태와 관계없이 아래 분류를 따른다.
  - `8030`/`8031`(실전/모의 키 불일치): 설정 오류. 다시 시도하지 않는다.
  - `1700`/`1701`/`1702`(호출 횟수 초과): 다시 시도하지 않고 "호출 제한" 오류로 돌려준다.
  - 그 밖의 0이 아닌 `return_code`: 키움 오류. `return_msg` 원문을 사용자에게 전달하되, 아래 비밀값 가림을 거친다.
  - 본문이 JSON이 아니거나 `return_code`가 없는 경우, 또는 성공 응답인데 화면에 필요한 필드가 빠진 경우: "응답 형식 오류". 로그에는 HTTP 상태와 본문 앞부분을 가림 처리해서 남긴다.
  - 네트워크 실패나 시간 초과: "연결 실패" 오류.
- 비밀값 가림: 키움 메시지를 브라우저로 보내거나 로그에 쓰기 전에, 현재 설정된 앱 키, 시크릿, 접근 토큰, 계좌번호 값이 문자열 안에 나타나면 가린다. 응답 경로와 로그 경로는 같은 가림 함수를 쓴다.
- HTTP 전송 계층은 외부에서 바꿔 끼울 수 있게 한다. 테스트에서 가짜 응답을 넣는 지점이다.

**계좌 확인 서비스**
- 공통 순서: 먼저 `ka00001`(계좌번호조회)로 토큰이 가리키는 계좌번호를 받는다. 그 값을 투자 환경의 `*_ACCOUNT_NO`와 비교한다(하이픈 등 구분 기호는 무시). 다르면 "계좌 불일치" 오류로 멈추고 뒤의 TR은 호출하지 않는다.
- 국내: `kt00018` 계좌평가잔고내역(`qry_tp=1`, `dmst_stex_tp=KRX`)과 `kt00001` 예수금상세현황(`qry_tp=3`)을 순서대로 호출한다.
- 미국: `ust21070` 미국주식 원장잔고확인(`stex_tp=""`, `stk_cd=""`)과 `ust21110` 해외주식 예수금을 순서대로 호출한다.
- 국내 응답 변환:
  - 0으로 앞자리를 채운 부호 포함 문자열(예: `-00000000196888`)은 숫자로 바꾼다.
  - 종목코드 앞의 구분 접두어(A/J/Q)는 떼서 표시용 코드를 만든다.
- 미국 응답 변환:
  - USD 소수 문자열과 0으로 채운 KRW 문자열을 각각 숫자로 바꾼다.
- 미국 보유종목의 거래소는 `result_list.stex_nm`(거래소명) 값을 바꾸지 않고 그대로 표시한다. 문서 예시 값이 "미국"이라 실제로 어떤 값이 오는지는 모의 서버 확인 때 보고한다.
- 문서에 없는 응답 필드는 쓰지 않는다. 예를 들어 `ust21070` 예시 응답의 최상위에만 나오는 `stex_tp`는 무시한다.
- 화면에 쓰는 필드만 골라 서버 쪽 응답 형태로 정리한다. 키움 원본 응답을 브라우저로 그대로 넘기지 않는다.

**자체 서버 API 계약**
- `GET /api/environments`: 투자 환경 목록을 돌려준다(값, 표시 이름, 시장, 실전 여부). 인증정보는 담지 않는다.
- `GET /api/environments/{environment}/account`: 계좌 확인 결과를 돌려준다.
  - 공통 필드: 투자 환경, 시장, 가린 계좌번호, 조회 시각.
  - 국내 결과: 요약(추정예탁자산, 총평가금액, 총매입금액, 총평가손익, 총수익률), 예수금(예수금, 주문가능금액, 출금가능금액, D+1·D+2 추정예수금), 보유종목 목록.
  - 미국 결과: USD 요약, KRW 환산 요약, 당일손익, 원화예수금, 통화별 외화예수금 목록, 보유종목 목록.
  - 결과의 형태는 시장 필드로 구분한다.
- 오류 응답은 일정한 형태(오류 종류, 사용자용 메시지, 요청 ID)로 통일하고, 오류 종류별로 HTTP 상태를 정한다.
  - 잘못된 투자 환경: 404
  - 설정 오류(환경변수 누락, 실전/모의 키 불일치): 503
  - 계좌 불일치: 409
  - 호출 제한: 429
  - 키움 오류, 응답 형식 오류, 조회 불완전, 연결 실패: 502
- 계좌번호 가림 규칙: 앞 4자리와 끝 2자리만 남긴다.

**로그**
- 로그는 표준 logging에 구조화된 key=value(또는 JSON 한 줄) 형식으로 남긴다. 필드: 시각, 레벨, 모듈, 투자 환경, API ID, 요청 대상, 결과, 오류 원인, 요청 ID.
- 출력은 stdout과 `logs/` 폴더 양쪽이다. 파일은 날짜별로 나누고 14일간 보관한다.
- 다음 값은 로그에 남기기 전에 가린다: `authorization` 헤더, `appkey`, `secretkey`, `token`, 계좌번호.

**화면**
- 레이아웃:
  - 상단 헤더: 제목과 투자 환경 선택 버튼
  - 왼쪽: 메뉴 바
  - 오른쪽: 기능 화면
  - 메뉴는 기능 목록 데이터로 만들어서, 기능을 추가할 때 항목 하나만 더하면 되게 한다. 지금은 계좌 확인 하나뿐이다.
- 마지막 투자 환경은 localStorage에 저장한다. 읽거나 쓰다 실패하거나 값이 목록에 없으면 국내 모의로 연다.
- 실전 환경을 고르면 헤더에 경고 색과 "실전" 배지를 표시한다.
- 계좌 확인 화면의 상태:
  - 처음 불러오는 중: 자리표시(skeleton)
  - 새로고침 중: 기존 데이터를 유지하고 회전하는 아이콘을 표시하며 버튼은 비활성화한다
  - 오류: 오류 종류별 메시지와 다시 시도 버튼
  - 보유종목 없음: 빈 상태 안내. 요약과 예수금은 그대로 보여준다.
  - 성공
- 기존 데이터를 유지하는 것은 같은 투자 환경의 새로고침에만 적용한다. 투자 환경을 바꾸면 계좌 데이터와 조회 시각을 즉시 지우고 "처음 불러오는 중" 상태로 돌아간다. 이전 환경의 응답이 늦게 도착해도 화면에 반영하지 않는다.
- 색상 규칙:
  - 양수(수익·상승): 빨강과 ▲, `+` 부호
  - 음수(손실·하락): 파랑과 ▼, `−` 부호
  - 0: 중립 회색
- 반응형:
  - 데스크톱: 왼쪽 고정 메뉴
  - 모바일: 햄버거 버튼으로 여는 메뉴 서랍(drawer), 헤더 아래 한 줄 4칸 환경 버튼
  - 보유종목 표는 모바일에서 카드형 목록으로 바꾸거나, 표 영역만 가로로 스크롤되게 한다. 화면 전체가 가로로 밀리는 일은 없게 한다.
- 디자인 톤은 차분한 짙은 녹색 계열(참고 이미지의 선택 버튼 색)을 강조색으로, 중립 회색 배경 위에 카드를 올린다.

## Testing Decisions

- 좋은 테스트는 외부에서 보이는 동작만 검증한다. 우리 서버 API의 응답과, 키움으로 나가는 요청의 도메인·헤더·본문을 확인한다. 내부 함수 구조나 호출 순서 같은 구현 세부는 검증하지 않는다.
- **Seam 1 (주력)**: FastAPI 테스트 클라이언트로 자체 서버 `/api`를 호출한다. 키움 쪽은 HTTP 전송 계층에 가짜 응답(httpx MockTransport)을 끼운다. 환경변수는 테스트에서 직접 넣고 실제 `.env`는 읽지 않는다. 검증할 동작:
  - 투자 환경 4개 각각이 올바른 도메인과 인증정보 묶음으로 요청하는지. 특히 국내 실전과 미국 실전은 같은 `REAL_*`를 쓰고, 두 모의 환경은 서로 다른 묶음을 쓰는지 확인한다.
  - 잘못된 투자 환경 값을 404로 거부하고 키움을 호출하지 않는지.
  - 필요한 환경변수가 빠지면 503과 함께 빠진 변수의 이름을 돌려주고, 값이나 다른 환경의 정보는 노출하지 않는지.
  - 토큰을 한 번 발급받아 다음 요청에 재사용하는지. `8005` 뒤에 재발급과 재시도를 한 번만 하는지.
  - `cont-yn=Y` 연속조회로 목록을 이어 붙이는지. 10번째 페이지에도 `cont-yn=Y`가 있으면 "조회 불완전" 오류(502)를 돌려주는지.
  - 계좌번호가 다르면 409를 돌려주고 잔고 TR을 호출하지 않는지.
  - 국내·미국 응답 변환: 0으로 채운 부호 포함 숫자, 종목코드 접두어, USD 소수.
  - 보유종목이 빈 목록일 때 정상 응답이 오는지.
  - 호출 제한(`1700`)은 429로, 키 불일치(`8030`)는 재시도 없이 설정 오류(503)로 돌려주는지.
  - JSON이 아닌 본문, `return_code`가 없는 본문, 필수 필드가 빠진 성공 응답을 "응답 형식 오류"(502)로 돌려주는지. 모든 오류가 같은 오류 응답 형식을 쓰는지.
  - 같은 투자 환경에 동시에 들어온 첫 조회들이 토큰을 한 번만 발급받는지. 늦게 도착한 `8005`가 이미 갱신된 토큰을 지우지 않는지.
  - 앱 키, 시크릿, 토큰, 계좌번호가 들어간 가짜 `return_msg`가 API 응답과 로그 양쪽에서 가려지는지.
  - 로그(caplog)와 API 응답에 앱 키, 시크릿, 토큰, 전체 계좌번호가 나타나지 않는지.
- **Seam 2 (화면 확인)**: Playwright로 브라우저의 `/api` 요청을 가로채 가짜 응답을 준다. 이 방법으로 실전 환경 표시, 오류, 결과 없음, 불러오는 중, 새로고침 중 상태를 확인한다. 응답을 늦춘 상태에서 투자 환경을 바꿨을 때 이전 환경의 데이터가 즉시 사라지고 늦은 응답이 반영되지 않는지도 확인한다. 데스크톱(1440px)과 모바일(390px) 크기에서 스크린샷을 찍는다. 운영 코드에는 테스트용 분기를 넣지 않는다.
- 실제 서버 확인은 국내 모의와 미국 모의만 한다. 실전 환경은 가짜 응답으로 화면만 확인하고, 실제 조회는 사용자가 직접 확인한다.
- 기존 코드베이스에는 참고할 테스트가 없다. 이번 테스트가 첫 사례가 된다.
- 화면 단위 테스트(컴포넌트 테스트)는 이번 범위에서 제외한다.

## Further Notes

- 키움 문서로 확인되지 않은 사항:
  - 요청 필드 중 어떤 것이 필수인지
  - `expires_dt`의 시간대
  - 호출 횟수 제한의 구체적인 수치
  - 미국 모의 인증정보로 `ka00001`(국내 계좌 TR)이 동작하는지
  - 국내 모의와 미국 모의가 실제로 다른 앱 키를 써야 하는지

  요청 필드는 추측하지 않고 문서 예시에 나온 값으로 모두 보낸다. `expires_dt` 시간대만은 구현에 가정이 필요해서, 틀려도 안전한 쪽(한국시간)을 택하고 근거를 남긴다.
- 미국 모의 환경에서 `ka00001`이 실패하면 구현을 멈추고 사용자에게 보고한다. 이때 계좌번호 비교를 건너뛸지는 사용자가 정한다.
- 화면에 표시하는 금액은 키움이 돌려준 값을 그대로 쓴다. 클라이언트에서 다시 계산하지 않는다. 다만 미국 보유종목의 보유비중처럼 응답에 없는 값은 표시하지 않는다.
- 참고 화면 구조: 상단 왼쪽에 제목 "주식 자동매매 대시보드", 상단 오른쪽에 둥근 그룹 안의 투자 환경 버튼 4개(선택된 버튼은 짙은 녹색 배경), 왼쪽에 메뉴 바(선택 항목은 옅은 녹색 배경과 `>` 표시), 오른쪽에 기능 화면.

## Implementation Notes (2026-10-05)

구현과 모의 서버 확인 중에 확정되거나 바뀐 사항.

- 계좌번호 비교: `ka00001`은 10자리(뒤 2자리는 키움의 계좌 분류값)를 돌려준다. `.env` 값이 8자리면 앞 8자리만 비교한다(사용자 확인).
- 오류 코드: 실제 모의 서버는 호출 한도 초과를 `return_code=5`와 함께 메시지 안의 `[1700:...]`로 보냈다. 메시지에 `[4자리코드:`가 있으면 그 코드로 분류한다. 다른 오류 코드도 같은 형식이라고 가정했다.
- 호출 한도: `ka00001`은 유량=1이다. React StrictMode의 개발 모드 이중 요청이 한도에 걸려 StrictMode를 쓰지 않는다.
- 토큰 캐시: 투자 환경별이 아니라 인증정보 묶음별로 보관한다. 국내 실전과 미국 실전이 같은 앱 키로 토큰을 따로 발급받지 않게 하기 위해서다.
- `ka00001`은 미국 모의 인증정보로도 동작한다.
- 모의 계좌 두 곳 모두 보유종목이 없어 `stex_nm`의 실제 값은 아직 확인하지 못했다.

- ✏️ 미국 보유종목 거래소 출처: Codex가 최상위 `stex_tp`와 목록 안의 `stex_nm`을 혼동했다. 문서에 있는 `result_list.stex_nm`을 출처로 명시하고 값을 그대로 표시한다.
- ✏️ 토큰 만료 시간대 추측: 한국시간 해석은 유지한다. 틀려도 일찍 재발급할 뿐인 안전한 방향이라는 근거를 스펙에 명시하고, 추측 금지 문장을 이에 맞게 고쳤다.
- ✏️ HTTP 오류와 비정상 응답: 세분화하지 않고 단순 규칙으로 정했다. `return_code`가 있으면 기존 분류를 따르고, 없거나 형식이 이상하면 "응답 형식 오류"(502)로 처리한다. 설정 누락과 키 불일치는 "설정 오류"(503)로 묶었다.
- ✅ 환경 전환 시 이전 데이터 표시: 기존 데이터 유지는 같은 환경의 새로고침에만 적용하고, 환경을 바꾸면 즉시 지운다. 응답을 늦춘 전환 확인을 추가했다.
- ✅ 동시 요청의 토큰 발급과 무효화: 투자 환경마다 발급을 lock으로 보호하고, 실패한 요청의 토큰이 현재 캐시 토큰과 같을 때만 캐시를 지운다. 관련 테스트를 추가했다.
