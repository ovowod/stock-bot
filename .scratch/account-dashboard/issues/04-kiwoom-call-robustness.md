# 04: 키움 호출 안정성 보강

**What to build:** 보유종목이 여러 페이지로 나뉘어 와도 모두 표시되고, 토큰이 무효가 되어도 한 번은 자동으로 복구된다. 키움이 오류나 이상한 응답을 돌려주거나 연결이 실패해도, 사용자는 원인별로 알맞은 안내를 보고 비밀값은 어디에도 노출되지 않는다.

Spec: `.scratch/account-dashboard/spec.md`

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 응답 헤더 `cont-yn=Y`면 `next-key`로 이어서 요청해 목록을 이어 붙이고, 10번째 페이지에도 `cont-yn=Y`가 있으면 "조회 불완전" 오류(502)를 돌려준다.
- [ ] `8005`를 받으면 새 토큰으로 한 번만 다시 시도하고, 캐시는 실패한 요청이 쓴 토큰이 현재 캐시 토큰과 같을 때만 지운다.
- [ ] 같은 투자 환경의 토큰 발급은 lock으로 보호되어, 동시에 들어온 첫 조회들이 토큰을 한 번만 발급받는다.
- [ ] 본문에 `return_code`가 있으면 HTTP 상태와 관계없이 분류한다: `8030`/`8031`은 재시도 없이 설정 오류(503), `1700`/`1701`/`1702`는 재시도 없이 호출 제한(429), 그 밖의 0이 아닌 값은 키움 오류(502).
- [ ] JSON이 아닌 본문, `return_code`가 없는 본문, 필요한 필드가 빠진 성공 응답은 "응답 형식 오류"(502)가 되고, 로그에 HTTP 상태와 가림 처리한 본문 앞부분이 남는다.
- [ ] 네트워크 실패나 시간 초과는 "연결 실패"(502)가 된다.
- [ ] 키움 `return_msg` 원문은 유지하되, 브라우저 응답과 로그 모두 같은 가림 함수를 거쳐 현재 설정된 앱 키·시크릿·토큰·계좌번호 값이 가려진다.
- [ ] 화면이 오류 종류별로 알맞은 안내를 보여준다(설정 오류는 빠진 변수 이름, 호출 제한은 "잠시 후 다시 시도", 계좌 불일치는 경고 등).
- [ ] 위 동작을 모두 가짜 응답 테스트로 검증한다: 연속조회 이어 붙이기와 10페이지 한도, `8005` 1회 재시도, 동시 첫 조회의 단일 발급, 늦게 도착한 `8005`, 오류 분류별 상태 코드, 공통 오류 형식, 비밀값이 든 `return_msg` 가림.
