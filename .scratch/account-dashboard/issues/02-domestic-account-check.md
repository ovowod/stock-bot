# 02: 국내 계좌 확인

**What to build:** 국내 모의(또는 국내 실전)를 고르면 계좌 확인 화면에 그 투자 환경 계좌의 자산 요약, 예수금, 보유종목이 카드와 표로 표시된다. 서버는 투자 환경에 맞는 인증정보와 도메인으로 접근 토큰을 받아 키움을 호출하고, 토큰이 가리키는 계좌가 `.env`의 계좌번호와 같을 때만 잔고를 조회한다. 불러오는 중, 새로고침 중, 오류, 보유종목 없음 상태가 각각 구분되어 보인다. 이 티켓이 서버의 키움 클라이언트와 계좌 확인 흐름 전체를 처음으로 관통한다.

Spec: `.scratch/account-dashboard/spec.md`

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 키움 클라이언트가 투자 환경별 도메인과 인증정보를 선택하고, `au10001`로 받은 접근 토큰을 투자 환경별로 서버 메모리에 보관해 재사용한다(만료는 한국시간 해석 + 5분 여유, 근거를 코드에 남김).
- [ ] 키움 요청에 공통 헤더(`api-id`, `authorization`, `cont-yn`, `next-key`, Content-Type)를 붙이고, HTTP 전송 계층을 테스트에서 바꿔 끼울 수 있다.
- [ ] `GET /api/environments/{environment}/account`가 `ka00001` 계좌번호를 `*_ACCOUNT_NO`와 비교하고(구분 기호 무시), 다르면 409를 돌려주며 잔고 TR을 호출하지 않는다.
- [ ] 국내는 `kt00018`(`qry_tp=1`, `dmst_stex_tp=KRX`)과 `kt00001`(`qry_tp=3`)을 호출해 요약, 예수금, 보유종목으로 변환한다. 0으로 채운 부호 포함 숫자를 숫자로 바꾸고, 종목코드 접두어(A/J/Q)를 뗀다.
- [ ] 응답에 가린 계좌번호(앞 4자리·끝 2자리만 노출)와 조회 시각이 담기고, 키움 원본 응답은 브라우저로 넘기지 않는다.
- [ ] 필요한 환경변수가 없으면 503과 빠진 변수 이름만 돌려준다. 0이 아닌 `return_code`는 기본적으로 502 키움 오류가 된다.
- [ ] 키움 요청·응답, 토큰 발급, 오류가 요청 ID와 함께 로그에 남고, 앱 키·시크릿·토큰·계좌번호는 가려진다.
- [ ] 화면에 요약 카드(추정예탁자산, 총평가금액, 총매입금액, 총평가손익·수익률), 예수금 카드(예수금, 주문가능금액, 출금가능금액, D+1·D+2 추정예수금), 보유종목 표가 보인다.
- [ ] 양수는 빨강·▲·`+`, 음수는 파랑·▼·`−`, 0은 회색으로 표시하고, 금액에 천 단위 구분과 통화 표기가 붙는다.
- [ ] 처음 불러오는 중에는 skeleton, 새로고침 중에는 기존 데이터를 유지하며 버튼을 비활성화, 오류는 메시지와 다시 시도 버튼, 보유종목이 없으면 빈 상태 안내(요약·예수금은 유지)가 보인다. 마지막 조회 시각이 표시된다.
- [ ] 투자 환경을 바꾸면 계좌 데이터와 조회 시각을 즉시 지우고, 이전 환경의 늦은 응답은 반영하지 않는다.
- [ ] 모바일에서 보유종목 표 때문에 화면 전체가 가로로 밀리지 않는다.
- [ ] 가짜 응답 테스트가 통과한다: 투자 환경 4개의 도메인·인증정보 선택(실전 2개는 같은 `REAL_*`, 모의 2개는 서로 다른 묶음), 토큰 재사용, 계좌 불일치, 국내 응답 변환, 빈 보유종목, 설정 누락, 로그·응답에 비밀값 미노출.
- [ ] 국내 모의 서버로 실제 조회해 화면에 표시되는 것을 확인한다. 국내 실전 서버는 호출하지 않는다.
