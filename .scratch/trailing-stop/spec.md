# Trailing Stop 설정 화면 (매도 동작 제외)

Status: ready-for-agent

## Problem Statement

보유종목이 어느 정도 오른 뒤에는 오른 만큼을 지키면서 더 오를 여지도 남기고 싶다. 익절 기준처럼 정해 둔 수익률에서 바로 팔면 그 뒤의 상승을 놓친다. 그 대신 고점을 따라가다가 고점에서 정해 둔 만큼 떨어질 때 팔고 싶다.

자동 매도를 붙이기 전에, Trailing Stop을 하루 중 언제 어떤 기준으로 동작시킬지, 어떤 종목은 팔지 않을지를 투자 환경마다 정해 두는 화면과 저장 기능이 먼저 필요하다. 지금 SL / TP 설정은 SL / TP 전용 파일에만 저장된다. 앞으로 자동매매 기능이 늘어날 때마다 설정 파일이 흩어지지 않게, 한 투자 환경의 자동매매 설정을 한곳에 모아야 한다. 매도 동작이 붙기 전에 실전투자 환경에 켜 둔 설정이 남아 있다가, 나중에 실제 매도가 갑자기 시작되는 일도 없어야 한다.

## Solution

왼쪽 메뉴의 **자동매매** 묶음에서 SL / TP 바로 아래에 **Trailing Stop** 메뉴를 둔다. 화면은 선택한 투자 환경의 설정을 보여주며, 구성은 SL / TP 화면과 같다.

- 맨 위에 **매도 방식 안내**와 **준비 중 안내**가 있다.
- 그 아래 **제외종목**이 있다. 기존 종목 검색으로 찾아 추가하고 삭제한다. SL / TP의 제외종목과는 따로 관리한다.
- 그 아래 **Trailing Stop 세션** 목록이 있다. 시각 규칙은 SL/TP 세션과 같다. 그 시장의 **정규장** 안에만 둘 수 있고, Trailing Stop 세션끼리는 겹치지 않는다. SL/TP 세션과는 시간이 겹쳐도 된다.
- 세션마다 ON/OFF 스위치(기본 OFF), **활성화 수익률**, **고점 대비 하락률**을 정한다.
- **저장** 버튼을 눌러야 서버에 저장된다.
- **실전투자** 환경에서도 설정은 저장할 수 있지만 ON 스위치는 켤 수 없다.

서버는 투자 환경마다 **자동매매 설정** 파일 하나에 SL / TP와 Trailing Stop의 설정을 칸을 나눠 담는다. 이 결정의 이유는 ADR 0004에 있다. 지금 있는 SL / TP 설정은 서버가 시작할 때 새 파일로 옮긴다. SL / TP 화면과 동작은 바뀌지 않는다.

이번에는 실제 시세 감시와 매도 주문을 하지 않는다. 설정만 저장한다.

## User Stories

**메뉴와 화면 진입**

1. As a 투자자, I want 왼쪽 메뉴의 "자동매매" 묶음에서 SL / TP 아래에 "Trailing Stop" 메뉴가 보이기를, so that 자동매매 기능을 한곳에서 찾는다.
2. As a 투자자, I want 모바일 메뉴(서랍)에도 같은 메뉴가 보이기를, so that 휴대폰에서도 설정한다.
3. As a 투자자, I want 화면 제목이 "Trailing Stop"이고 그 아래 지금 투자 환경 이름이 보이기를, so that 어느 환경을 고치는지 안다.
4. As a 투자자, I want Trailing Stop 화면이 지금 선택한 투자 환경의 설정만 보여주기를, so that 다른 환경의 설정과 섞이지 않는다.
5. As a 투자자, I want 투자 환경을 바꾸면 그 환경에 저장된 설정을 새로 불러오기를, so that 네 환경을 오가며 각각 확인한다.
6. As a 투자자, I want 설정을 불러오는 동안 불러오는 중임이 보이기를, so that 빈 화면을 설정이 없는 것으로 착각하지 않는다.
7. As a 투자자, I want 설정을 불러오지 못하면 원인과 "다시 시도" 버튼이 보이고 편집할 수 없기를, so that 잘못된 상태 위에 덮어쓰지 않는다.
8. As a 투자자, I want 한 번도 저장하지 않은 환경은 제외종목도 세션도 없는 빈 설정으로 열리기를, so that 처음부터 설정을 시작한다.

**안내 문구**

9. As a 투자자, I want 화면 위쪽에 "평균 매입가 대비 수익률이 활성화 수익률 이상이 되면 그때부터 고점을 따라가고, 시세 체결가가 고점 대비 하락률만큼 떨어지면 그 종목의 매도 가능 수량 전량을 시장가로 매도합니다. 제외종목은 매도하지 않습니다." 안내가 늘 보이기를, so that 어떤 방식으로 팔리는지 안다.
10. As a 투자자, I want "Trailing Stop 자동 매도는 아직 동작하지 않습니다. 지금은 설정만 저장됩니다." 안내가 보이기를, so that 켜 둔 세션이 지금 실제로 매도한다고 오해하지 않는다.
11. As a 투자자, I want 실전투자 환경에서는 "실전투자에서는 Trailing Stop 세션을 켤 수 없습니다" 안내가 보이기를, so that 스위치가 왜 막혔는지 안다.

**제외종목**

12. As a 투자자, I want 화면 위쪽에 제외종목 검색창이 있기를, so that 팔지 않을 종목을 먼저 정한다.
13. As a 투자자, I want 종목명이나 종목코드(티커)로 검색하면 종목 검색과 같은 결과가 입력창 아래에 펼쳐지기를, so that 익숙한 방식으로 찾는다.
14. As a 투자자, I want 결과의 종목을 누르면 제외종목에 추가되고 검색어가 비워지기를, so that 한 번에 추가하고 다음 종목을 찾는다.
15. As a 투자자, I want 이미 추가된 종목은 결과에 "추가됨"으로 보이고 다시 추가되지 않기를, so that 같은 종목이 두 번 들어가지 않는다.
16. As a 투자자, I want 제외종목 목록에 종목명과 종목코드(미국은 거래소도)가 보이기를, so that 어떤 종목을 뺐는지 안다.
17. As a 투자자, I want 제외종목마다 삭제 버튼이 있기를, so that 다시 팔 대상으로 돌린다.
18. As a 투자자, I want 지금 보유하지 않은 종목도 제외종목에 넣을 수 있기를, so that 나중에 살 종목을 미리 뺀다.
19. As a 투자자, I want 제외종목이 그 환경의 모든 Trailing Stop 세션에 똑같이 적용된다는 것이 보이기를, so that 세션마다 따로 정해야 하는지 헷갈리지 않는다.
20. As a 투자자, I want Trailing Stop의 제외종목이 SL / TP의 제외종목과 따로 관리되기를, so that SL / TP에서만 빼고 싶은 종목과 Trailing Stop에서만 빼고 싶은 종목을 나눠 정한다.
21. As a 투자자, I want Trailing Stop 화면에서 제외종목을 바꿔도 SL / TP 화면의 제외종목이 그대로이기를, so that 한 기능을 고치다 다른 기능의 설정을 바꾸지 않는다.
22. As a 투자자, I want 검색이 실패하면 제외종목 영역에 원인이 보이기를, so that 다시 검색할지 판단한다.
23. As a 투자자, I want 제외종목이 없으면 "제외종목이 없습니다"가 보이기를, so that 모든 보유종목이 대상임을 안다.

**Trailing Stop 세션 목록**

24. As a 투자자, I want 세션이 없으면 "Trailing Stop 세션이 없습니다" 안내와 "세션 추가" 버튼이 보이기를, so that 어디서 시작할지 안다.
25. As a 투자자, I want 세션 영역에 그 시장의 정규장(국내 09:00–15:30 한국시간, 미국 09:30–16:00 뉴욕시간)이 보이고, 미국은 오늘 기준 한국시간도 함께 보이기를, so that 정할 수 있는 범위를 안다.
26. As a 투자자, I want "세션 추가"를 누르면 마지막 세션의 종료 시각(세션이 없으면 정규장 시작)에서 시작해 1시간 뒤에 끝나는 세션이 채워지되, 정규장 끝을 넘지 않기를, so that 이어지는 세션을 빠르게 만든다.
27. As a 투자자, I want 마지막 세션이 정규장 끝까지 차 있으면 "세션 추가"가 막히고 이유가 보이기를, so that 더 넣을 수 없는 이유를 안다.
28. As a 투자자, I want 새 세션은 OFF이고, 활성화 수익률과 고점 대비 하락률이 비어 있는 채로 시작하기를, so that 의도하지 않은 설정이 켜지지 않는다.
29. As a 투자자, I want 시작·종료 시각을 분 단위로 고칠 수 있기를, so that 원하는 시간에 맞춘다.
30. As a 투자자, I want 시작이 종료보다 같거나 늦으면 그 세션에 안내가 보이기를, so that 잘못된 세션을 바로 고친다.
31. As a 투자자, I want 시각이 정규장을 벗어나면 그 세션에 안내가 보이기를, so that 장이 열리지 않는 시간에 세션을 두지 않는다.
32. As a 투자자, I want 세션의 시작이 바로 앞 세션의 종료보다 이르면 그 세션에 안내가 보이기를, so that Trailing Stop 세션끼리 겹치지 않는다.
33. As a 투자자, I want 앞 세션의 종료와 다음 세션의 시작이 같은 것(10:00–11:00, 11:00–12:00)은 허용되기를, so that 쉬는 시간 없이 이어지는 세션을 만든다.
34. As a 투자자, I want Trailing Stop 세션이 SL/TP 세션과 같은 시간대에 있어도 저장되기를, so that 두 기능을 같은 시간에 함께 쓴다.
35. As a 투자자, I want 세션마다 삭제 버튼이 있기를, so that 필요 없는 세션을 지운다.
36. As a 투자자, I want 저장된 세션 목록이 시간 순서로 보이기를, so that 하루의 흐름대로 읽는다.

**세션별 설정**

37. As a 투자자, I want 세션마다 ON/OFF 스위치가 있고 기본값이 OFF이기를, so that 세션별로 켜고 끈다.
38. As a 투자자, I want 활성화 수익률을 퍼센트로 입력하고 화면에 "+5%"처럼 보이기를, so that 얼마나 오른 뒤부터 고점을 따라갈지 정한다.
39. As a 투자자, I want 고점 대비 하락률을 양수로 입력하고 화면에 "고점 대비 −3%"처럼 보이기를, so that 부호를 헷갈리지 않는다.
40. As a 투자자, I want ON인 세션은 활성화 수익률과 고점 대비 하락률이 둘 다 있어야 하기를, so that 한쪽 기준이 빠진 채 켜진 세션이 생기지 않는다.
41. As a 투자자, I want OFF인 세션은 두 값이 비어 있어도 저장되기를, so that 시간만 먼저 정해 둔다.
42. As a 투자자, I want 두 값이 소수점 둘째 자리까지만 받고, 활성화 수익률은 0.01~1000, 고점 대비 하락률은 0.01~99.99 범위만 받기를, so that 말이 안 되는 값을 저장하지 않는다.
43. As a 투자자, I want 0이나 음수 활성화 수익률이 거부되기를, so that 사자마자 고점을 따라가는 설정이 실수로 생기지 않는다.
44. As a 투자자, I want 고점 대비 하락률이 활성화 수익률보다 커도 저장되기를, so that 손실로 팔릴 수 있음을 알고도 넓게 잡은 설정을 쓴다.
45. As a 투자자, I want 잘못된 값이면 그 칸에 안내가 보이기를, so that 어느 값을 고칠지 안다.

**실전투자**

46. As a 투자자, I want 실전투자 환경에서도 제외종목과 세션 시각·기준을 정하고 저장할 수 있기를, so that 미리 설정을 준비한다.
47. As a 투자자, I want 실전투자 환경에서는 ON 스위치가 꺼진 채 눌리지 않기를, so that 나중에 매도 동작이 붙어도 실제 계좌가 갑자기 매도되지 않는다.
48. As a 투자자, I want 화면을 우회해 실전투자 환경에 켜진 세션을 저장하려 해도 서버가 거부하기를, so that 화면 버그가 있어도 안전하다.

**저장**

49. As a 투자자, I want 바꾼 내용은 "저장"을 눌러야 서버에 저장되기를, so that 고치는 도중의 상태가 저장되지 않는다.
50. As a 투자자, I want 저장하지 않은 변경이 있으면 그 사실이 보이기를, so that 저장을 잊지 않는다.
51. As a 투자자, I want 바꾼 것이 없거나 잘못된 값이 남아 있으면 "저장"이 눌리지 않기를, so that 헛된 저장이나 거부될 저장을 하지 않는다.
52. As a 투자자, I want 저장하는 동안 저장 버튼과 모든 편집이 막히기를, so that 두 번 저장하지 않고, 저장 중에 고친 내용이 서버 응답에 덮어써지지 않는다.
53. As a 투자자, I want 저장되면 "Trailing Stop 설정을 저장했습니다" 토스트가 보이고, 화면이 서버가 돌려준 값으로 바뀌기를, so that 저장된 내용을 그대로 본다.
54. As a 투자자, I want 저장이 실패하면 원인이 담긴 실패 토스트가 보이고 입력한 값은 그대로 남기를(로그인 만료로 인한 401은 제외), so that 고쳐서 다시 저장한다.
55. As a 투자자, I want 서버도 화면과 같은 규칙으로 검사해, 어긋나면 몇 번째 세션의 무엇이 틀렸는지 알려 주기를, so that 화면 버그가 있어도 잘못된 설정이 저장되지 않는다.
56. As a 투자자, I want Trailing Stop을 저장해도 같은 환경의 SL / TP 설정이 바뀌지 않기를, so that 두 화면을 오가며 고쳐도 서로 덮어쓰지 않는다.
57. As a 투자자, I want 저장한 설정이 서버를 다시 시작해도 남기를, so that 매번 다시 입력하지 않는다.
58. As a 투자자, I want 국내 실전·미국 실전·국내 모의·미국 모의의 설정이 서로 덮어쓰지 않기를, so that 환경별로 다른 전략을 둔다.

**저장하지 않은 변경 보호**

59. As a 투자자, I want 저장하지 않은 변경이 있을 때 투자 환경을 바꾸거나, 다른 메뉴로 가거나, 로그아웃하려 하면 "저장하지 않은 변경이 사라집니다. 이동할까요?"라고 묻기를, so that 실수로 입력을 잃지 않는다.
60. As a 투자자, I want Trailing Stop에서 SL / TP 메뉴로 옮겨 갈 때도 같은 확인을 받기를, so that 자동매매 메뉴 안에서 옮겨 가도 입력을 잃지 않는다.
61. As a 투자자, I want 확인에서 취소하면 지금 화면과 입력이 그대로 남기를, so that 돌아가 저장한다.
62. As a 투자자, I want 새로고침하거나 탭을 닫으면 브라우저가 경고하기를, so that 입력을 잃지 않는다.
63. As a 투자자, I want 로그인이 만료되면 확인 없이 입력이 버려지고 로그인 화면으로 가기를, so that 다른 화면과 같은 만료 동작을 따른다.
64. As a 투자자, I want 변경이 없으면 아무것도 묻지 않고 이동하기를, so that 불필요한 확인을 누르지 않는다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **자동매매 설정**, **Trailing Stop**, **Trailing Stop 세션**, **활성화 수익률**, **고점 대비 하락률**, **활성화**, **고점**을 더했다. **제외종목**은 기능마다, 투자 환경마다 따로 정한다고 넓혔다. 코드·로그·화면 문구도 이 이름을 따른다.
- 화면 안에서는 "세션"으로 줄여 쓴다. 그 밖에서는 늘 "Trailing Stop 세션"이라고 쓴다.

**키움 TR**

- 설정 조회·저장·이전은 키움을 부르지 않는다.
- 제외종목 검색은 기존 종목 검색 API를 그대로 쓴다. 새 TR은 없다.

**자동매매 설정 저장소 (서버, SL / TP 설정 모듈을 넓힌다)**

- ADR 0004대로, 투자 환경마다 파일 하나에 기능별 칸(`sl_tp`, `trailing_stop`)을 둔다. 저장 위치는 데이터 폴더 아래 `auto-trading/<환경 값>.json`이다. `.env`에 새 변수는 없다.
- 파일 형식(버전 2):

```json
{
  "version": 2,
  "sl_tp": {
    "updated_at": "2026-10-24T01:23:45+00:00",
    "excluded": [{ "code": "005930", "name": "삼성전자", "exchange": null }],
    "sessions": [
      { "start": "09:00", "end": "10:30", "enabled": true, "take_profit": "5", "stop_loss": "3" }
    ]
  },
  "trailing_stop": {
    "updated_at": "2026-11-01T02:00:00+00:00",
    "excluded": [],
    "sessions": [
      { "start": "09:00", "end": "15:30", "enabled": true, "activation_profit": "5", "drop_from_peak": "2.5" }
    ]
  }
}
```

- 파일이 없거나 파일에 그 기능의 칸이 없으면 그 기능은 빈 설정이다(제외종목·세션 없음, 저장 시각 없음). 알 수 없는 칸은 무시한다.
- 파일을 읽지 못하거나(권한, 깨진 JSON, 버전이 2가 아님) **어느 칸이든** 검사 규칙에 맞지 않으면, 그 환경의 모든 기능에서 조회·저장이 실패한다. 실전 환경에서 어느 기능에든 켜진 세션이 있는 것도 규칙에 맞지 않는 것으로 본다. 빈 설정으로 대신하지 않는다.
- 저장은 파일을 읽어 검사한 뒤, 그 기능의 칸과 그 칸의 `updated_at`만 바꾸고 파일 전체를 다시 쓴다. 쓰기 방식은 지금처럼 임시 파일에 다 쓴 뒤 바꿔치기한다. 읽기부터 쓰기까지 await가 없어서 같은 환경의 저장이 서로 섞이지 않는다.
- SL / TP의 바깥 동작은 두 가지를 빼고 그대로다. 같은 API, 응답, 오류 종류와 메시지, 저장 뒤 감시 쪽에 새 설정을 알리는 동작이 모두 유지된다. SL / TP 감시는 지금처럼 저장소를 통해 설정을 읽는다. Trailing Stop 저장은 SL / TP 감시에 알리지 않는다. 바뀌는 두 가지는 다음과 같다.
  - 깨진 파일 위의 PUT: 지금은 저장할 때 기존 파일을 읽지 않아 깨진 파일 위에도 PUT이 성공한다. 이제는 파일을 먼저 읽으므로, 파일이 깨져 있으면 어느 기능의 PUT이든 그 기능의 읽기 실패(500)이고 파일은 그대로다.
  - 감시가 멈출 때의 알림 문구: "자동매매 설정 파일을 읽지 못해 이 환경의 SL / TP를 멈췄습니다. 자동매매 설정 파일을 고치거나 지운 뒤 SL / TP 화면에서 다시 저장하면 그때부터 동작합니다. 지우면 이 환경의 Trailing Stop 설정도 사라집니다."
- 깨진 파일을 되살리는 순서: 사용자가 파일을 고치거나 지운다. 그러면 화면이 다시 열리고, SL / TP 화면에서 저장하면 감시가 저장 알림을 받아 바로 다시 동작한다. 서버를 다시 시작하지 않아도 된다.
- 세션 시각 검사(형식, 시작 < 종료, 정규장 안, 앞 세션과 겹치지 않음)와 제외종목 검사는 두 기능이 함께 쓴다. 기준 칸의 검사만 기능마다 따로 둔다.

**예전 SL / TP 파일 이전**

- 앱을 만들 때 네 투자 환경마다 다음을 한다. 새 파일이 없고 예전 `sl-tp/<환경 값>.json`(버전 1)이 있으면, 예전 파일을 지금의 SL / TP 규칙으로 검사한다. 맞으면 내용을 `sl_tp` 칸에 담은 새 파일을 쓴다. 이때 `updated_at`도 그대로 옮긴다.
- 새 파일이 이미 있으면 예전 파일은 보지 않는다.
- 예전 파일은 지우거나 고치지 않는다.
- 예전 파일을 읽지 못하거나 규칙에 맞지 않으면(실전 환경에 켜진 세션이 있는 경우 포함) 새 파일을 쓰지 않는다. 경로와 원인을 로그에 남기고 앱 만들기를 실패시켜 서버가 시작하지 않게 한다. 사용자가 예전 파일을 고치거나 지워야 다시 시작된다.

**Trailing Stop 검사 규칙 (화면과 서버가 같다. 서버가 최종 판정)**

- 제외종목과 세션 시각은 SL / TP와 같은 규칙이다.
  - 같은 코드는 한 번만 넣을 수 있다.
  - 국내 종목은 거래소를 `null`로 두고, 미국 종목은 NYSE·NASDAQ·AMEX 중 하나다.
  - 시각은 `HH:MM` 형식이고, `start < end`이며, 정규장 안에 있다.
  - 목록 순서대로 각 세션의 `start`는 앞 세션의 `end` 이상이다. 같으면 맞닿은 것으로 허용한다.
- `activation_profit`은 `null`이거나, 소수점 둘째 자리까지의 양수 문자열로 0.01~1000이다.
- `drop_from_peak`은 `null`이거나, 소수점 둘째 자리까지의 양수 문자열로 0.01~99.99다.
- `enabled`가 true이면 두 값 모두 `null`이 아니어야 한다.
- 두 값의 크기는 서로 비교하지 않는다. 하락률이 활성화 수익률보다 커도 받는다.
- SL/TP 세션과 시간이 겹치는지는 검사하지 않는다.

**자체 서버 API**

- `GET /api/environments/{environment}/trailing-stop`
  - 응답 모양은 SL / TP와 같다: `environment`, `market`, `timezone`, `regular_hours`, `can_enable`, `updated_at`, `excluded`, `sessions`. 세션은 위 형식을 따른다.
  - 읽기 실패: 500, `trailing_stop_settings_unreadable`, "Trailing Stop 설정 파일을 읽지 못했습니다."
- `PUT /api/environments/{environment}/trailing-stop`
  - 요청: `excluded`, `sessions`. 그 밖의 칸은 무시한다.
  - 처리 순서는 SL / TP와 같다: 환경 검사 → 입력 검사(400) → 실전이고 켜진 세션이 있으면 403 → 파일 읽기(500) → 저장 → GET과 같은 응답.
  - 입력 검사 실패: 400, `invalid_trailing_stop_settings`. 메시지에 위치를 담는다(예: "2번째 Trailing Stop 세션: 켜진 세션에는 활성화 수익률과 고점 대비 하락률이 모두 있어야 합니다.").
  - 실전 ON 거부: 403, `trailing_stop_enable_not_allowed`, "실전투자에서는 Trailing Stop 세션을 켤 수 없습니다." 파일은 바뀌지 않는다.
  - 쓰기 실패: 500, `trailing_stop_settings_write_failed`. 기존 파일은 그대로다.
- 둘 다 로그인 세션이 있어야 하고, 다른 사이트에서 온 PUT은 기존 규칙대로 거부한다. 잘못된 환경 값도 기존 규칙대로 거부한다.

**로그**

- Trailing Stop의 조회·저장·검사 실패·실전 ON 거부·읽기 실패·쓰기 실패마다 이벤트를 남긴다. 투자 환경, 요청 ID, 결과, 제외종목 수, 세션 수, 켜진 세션 수, 실패 원인과 위치를 담는다. 설정 내용 전체는 남기지 않는다.
- 이전은 환경마다 성공(옮김)과 실패를 남긴다. 투자 환경, 예전 경로, 새 경로, 실패 원인을 담는다. 옮길 것이 없으면 남기지 않는다.

**화면**

- "자동매매" 묶음의 SL / TP 아래에 기능 `Trailing Stop`을 더한다. 아이콘은 하락 추세 모양이다. 다른 기능과 같이 투자 환경을 key로 묶어, 환경이 바뀌면 새로 그린다.
- 화면 상태, 저장, 토스트, 저장하지 않은 변경 보호는 SL / TP 화면과 같은 방식이다.
- SL / TP 화면에서 다음을 공통 부품으로 빼서 두 화면이 함께 쓴다.
  - 제외종목 영역(검색, 결과, 추가됨 표시, 목록, 삭제)
  - 세션 시각 입력과 그 검사
  - "세션 추가" 기본값 계산
  - 정규장·시간대 표시
  - 불러오기 실패 안내
  - 저장 막대
  - SL / TP 화면의 겉모습과 동작은 바뀌지 않는다.
- 기준 칸(활성화 수익률, 고점 대비 하락률)과 그 검사·안내는 Trailing Stop 화면에만 둔다.
- 실전 환경(`can_enable=false`)은 스위치를 OFF로 고정하고 누를 수 없게 한다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 검증한다. 서버는 자체 API의 요청·응답과 저장 폴더에 남은 파일을 보고, 화면은 사용자가 보는 것과 밖으로 나간 `/api` 요청을 본다. 내부 함수나 상태 이름은 검증하지 않는다.
- 키움 서버(실전·모의)는 호출하지 않는다. 설정 API와 이전 테스트에서는 가짜 키움을 "부르면 실패"로 두어, 키움 호출이 없음도 함께 확인한다.
- 새 테스트 지점은 만들지 않는다. 지금 SL / TP 설정이 쓰는 두 곳을 그대로 쓴다.

**서버 (pytest, 기존 `create_app` + `TestClient` 방식에 데이터 폴더만 임시 폴더로 넘김)**

- 자동매매 설정 합치기
  - SL / TP를 저장하면 새 위치에 버전 2 파일이 생기고, `sl_tp` 칸에 담긴다.
  - 테스트 도우미는 새 위치에 버전 2 파일을 쓰도록 바꾼다. 기존 SL / TP 테스트가 확인하던 동작은 모두 계속 확인된다. 깨진 파일을 두는 기존 테스트는 새 위치에 둔다. 예전 위치에 깨진 파일이 있으면 이전에 실패해 앱이 시작하지 않기 때문이다.
  - 깨진 파일에 SL / TP PUT을 보내면 500이고 파일은 그대로다. 파일을 고친 뒤 PUT하면 감시가 다시 동작한다. 이것으로 "다시 저장하면 감시가 재개된다"던 기존 테스트를 대신한다.
  - 감시가 멈출 때의 알림 문구가 위 문구와 같다.
  - 같은 환경에서 SL / TP를 저장해도 `trailing_stop` 칸이 그대로이고, 반대로 Trailing Stop을 저장해도 `sl_tp` 칸과 그 `updated_at`이 그대로다.
  - `trailing_stop` 칸만 깨진 파일이면 SL / TP GET·PUT도 500이고 파일은 그대로다.
  - 실전 파일의 `trailing_stop` 칸에 켜진 세션이 있으면 두 기능의 GET이 모두 500이다.
- 이전
  - 임시 폴더에 예전 버전 1 파일을 두고 앱을 만들면 새 파일이 생기고, SL / TP GET이 예전 내용과 `updated_at`을 그대로 돌려준다. 예전 파일은 바이트 그대로 남는다.
  - 새 파일이 이미 있으면 예전 파일은 무시된다.
  - 깨진 예전 파일이나 실전 환경에 켜진 세션이 있는 예전 파일이 있으면 앱 만들기가 실패하고, 새 파일이 생기지 않는다.
  - 이전 성공·실패 로그 이벤트가 남는다.
- Trailing Stop API
  - 파일이 없으면 GET은 빈 설정, `updated_at=null`, 그 시장의 정규장과 시간대를 돌려준다. 실전이면 `can_enable=false`, 모의면 true다.
  - PUT으로 저장한 값이 GET과, 같은 폴더로 새로 만든 앱에서 그대로 읽힌다.
  - 네 환경에 각각 다른 값을 저장해도 서로 덮어쓰지 않는다.
  - 정규장 경계, 맞닿은 세션 허용, 겹침 거부(몇 번째 세션인지 메시지에 담김)를 확인한다.
  - 기준 값: 소수점 셋째 자리, 0, 음수, 범위 초과, 숫자가 아닌 값은 400이다.
  - 켜진 세션에 값이 하나라도 없으면 400이다. 꺼진 세션은 비어 있어도 받는다.
  - 하락률이 활성화 수익률보다 큰 값도 받는다.
  - 제외종목: 같은 코드 두 번, 빈 코드·이름, 국내에 거래소 값, 미국에 목록 밖 거래소는 400이다.
  - 실전 환경에 켜진 세션을 PUT하면 403이고 파일이 바뀌지 않는다.
  - 잘못된 환경 값, 로그인 세션 없는 요청, 다른 사이트 출처의 PUT은 기존 규칙대로 거부되고 파일이 생기거나 바뀌지 않는다.
  - 로그에 저장·거부 이벤트가 환경·결과·개수와 함께 남는다.
- 기존 SL / TP 감시 테스트가 모두 통과해, 저장소를 바꿔도 감시 동작이 그대로임을 확인한다.
- Prior art: SL / TP 설정 API 테스트(환경별 저장, 검사 규칙, 실전 차단, 깨진 파일)와 로그 이벤트를 확인하는 기존 테스트.

**화면 (Playwright e2e, 가짜 `/api` 응답, 기존 SL / TP e2e와 같은 방식)**

- "자동매매" 묶음에서 SL / TP 아래에 "Trailing Stop" 메뉴가 데스크톱 메뉴와 모바일 서랍에 보이고, 누르면 GET 요청이 나간다.
- 두 안내 문구가 보인다. 실전 환경에서는 ON 불가 안내가 보이고 스위치가 눌리지 않는다.
- 제외종목: 검색, 추가, "추가됨" 표시, 삭제를 확인한다. 미국은 거래소가 보인다.
- 세션: 다음을 확인한다.
  - 빈 상태 안내
  - 추가 시 기본 시각
  - 정규장 끝까지 차면 추가가 막힘
  - 시각 오류·겹침 안내와 저장 막힘
  - 켜진 세션에 값이 빠졌을 때와 범위 밖일 때의 안내
  - 하락률이 활성화 수익률보다 커도 저장됨
  - 삭제
- 미국 환경에서는 뉴욕시간 표시와 09:30–16:00 범위가 보인다.
- 저장: 다음을 확인한다.
  - 변경이 없으면 저장이 막힘
  - PUT 본문이 화면 값과 같음
  - 성공 토스트
  - 실패 응답이면 실패 토스트와 입력 유지
  - 응답을 늦게 주는 동안 편집이 막힘
- 저장하지 않은 변경이 있을 때 환경 전환이나 SL / TP 메뉴로 이동하면 확인 창이 뜬다. 취소하면 그대로 남는다.
- 불러오기 실패면 원인과 "다시 시도"가 보인다.
- 모바일 폭에서 가로 스크롤이 없다.
- 공통 부품을 빼낸 뒤에도 기존 SL / TP e2e가 모두 통과한다.

## Out of Scope

- 시세 감시, 활성화 판정, 고점 추적, 매도 주문 등 실제 Trailing Stop 자동 매도 동작.
- 실전투자 환경에서 Trailing Stop 세션 켜기.
- 휴장일·단축 거래일 같은 특별한 정규장, 장전·장후 시간.
- 종목별로 다른 기준, 세션별 제외종목, SL / TP와 같이 쓰는 제외종목.
- 고점 대비 하락률이 활성화 수익률보다 클 때 경고하기.
- 두 탭 동시 편집의 충돌 감지.
- 예전 SL / TP 파일 지우기.
