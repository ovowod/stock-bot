# 03: Trailing Stop 세션, 스위치, 활성화 수익률과 고점 대비 하락률

**What to build:** Trailing Stop 화면의 제외종목 아래에 Trailing Stop 세션 목록이 생긴다. 세션을 추가·삭제하고 시각을 고친다. 세션마다 ON/OFF 스위치, 활성화 수익률, 고점 대비 하락률을 정한다. 실전투자 환경에서는 스위치를 켤 수 없고, 서버도 켜진 세션 저장을 거부한다.

Spec: `.scratch/trailing-stop/spec.md` (Trailing Stop 검사 규칙, 자체 서버 API, 화면)

**Blocked by:** 02

**Status:** ready-for-agent

- [x] 세션 시각 검사(`HH:MM`, `start < end`, 정규장 안, 앞 세션과 겹치지 않음, 맞닿음 허용)는 SL / TP와 같은 규칙을 함께 쓴다. SL/TP 세션과 시간이 겹쳐도 받는다.
- [x] `activation_profit`은 `null` 또는 0.01~1000, `drop_from_peak`은 `null` 또는 0.01~99.99이고, 둘 다 소수점 둘째 자리까지의 양수 문자열이다. 켜진 세션은 두 값이 모두 있어야 한다. 두 값의 크기는 서로 비교하지 않는다.
- [x] 어긋나면 화면은 그 칸이나 세션에 안내를 보이고 저장을 막는다. 서버는 400 `invalid_trailing_stop_settings`에 몇 번째 Trailing Stop 세션인지 담는다.
- [x] 실전 환경에 켜진 세션을 PUT하면 403 `trailing_stop_enable_not_allowed`이고 파일은 바뀌지 않는다. 실전 파일의 `trailing_stop` 칸에 켜진 세션이 있으면 두 기능의 GET이 모두 500이다.
- [x] 화면: 빈 상태 안내("Trailing Stop 세션이 없습니다")와 "세션 추가"가 있다. 추가 시 기본 시각과 정규장 끝 상한, 다 차면 추가 막힘, 정규장·시간대 표시(미국은 한국시간 병기)를 SL / TP와 함께 쓰는 부품으로 보인다.
- [x] 화면: 새 세션은 OFF이고 두 값이 비어 있다. 칸 이름은 "활성화 수익률"·"하락률"이고, 활성화 수익률은 "+5%", 고점 대비 하락률은 "고점 대비 −3%"처럼 보인다. 좁은 화면에서는 두 칸을 한 줄에 하나씩 두어 가장 긴 값도 칸 안에 보인다. 실전 환경에서는 스위치가 OFF로 고정되고 ON 불가 안내가 보인다.
- [x] 세션 시각 입력, 검사, "세션 추가" 기본값 계산을 SL / TP 화면과 공통 부품으로 빼서 함께 쓴다. SL / TP 화면의 겉모습과 동작은 바뀌지 않는다.
- [x] 테스트(pytest): 정규장 경계(국내 09:00·15:30 허용, 08:59·15:31 거부, 미국 09:30·16:00 허용, 09:29·16:01 거부), 겹침 거부, 기준 값 오류(셋째 자리, 0, 음수, 범위 초과, 숫자 아님), 켜진 세션의 값 누락, 하락률 > 활성화 수익률 허용, 실전 ON 거부와 파일 유지, 네 환경 분리를 확인한다.
- [x] 테스트(Playwright): 세션 추가·편집·삭제, 시각·값 오류 안내와 저장 막힘, 하락률 > 활성화 수익률 저장, 미국 뉴욕시간 표시, 실전 스위치 막힘, PUT 본문이 화면 값과 같음, 모바일 폭을 확인한다. 기존 SL / TP e2e가 모두 통과한다.
- [x] 기존 테스트, lint, 타입 검사, 화면 빌드가 모두 통과한다.
