# 01: 자동매매 설정 파일 합치기와 예전 SL / TP 파일 이전

**What to build:** SL / TP 설정을 투자 환경마다 하나인 자동매매 설정 파일(버전 2)의 `sl_tp` 칸에 저장하게 바꾼다. 서버가 시작할 때 예전 SL / TP 파일을 새 파일로 옮긴다. 사용자가 보는 SL / TP 화면과 API 동작, SL / TP 감시는 바뀌지 않는다. 아직 `trailing_stop` 칸은 쓰지 않는다. 다만 파일에 그 칸이 없으면 빈 설정으로 보고, 알 수 없는 칸은 무시한다.

Spec: `.scratch/trailing-stop/spec.md` (자동매매 설정 저장소, 예전 SL / TP 파일 이전, 로그)
ADR: `docs/adr/0004-one-auto-trading-settings-file-per-environment.md`

**Blocked by:** 없음

**Status:** ready-for-agent

- [x] SL / TP 저장은 데이터 폴더의 `auto-trading/<환경 값>.json`에 버전 2 형식으로 쓰고, `sl_tp` 칸과 그 칸의 `updated_at`만 바꾼다. 파일의 다른 칸은 읽은 그대로 다시 쓴다.
- [x] 파일이 없거나 `sl_tp` 칸이 없으면 빈 설정이다. 깨진 JSON, 버전이 2가 아닌 파일, 규칙에 맞지 않는 `sl_tp` 칸, 실전에서 켜진 세션은 지금처럼 500 `sl_tp_settings_unreadable`이고 파일은 그대로다.
- [x] SL / TP API의 요청·응답·오류 종류·메시지, 저장 뒤 감시 쪽에 알리는 동작이 그대로다. 단, 깨진 파일 위의 PUT은 이제 500 `sl_tp_settings_unreadable`이고 파일은 그대로다.
- [x] 감시가 깨진 파일 때문에 멈출 때의 알림 문구를 spec 문구로 바꾼다. 파일을 고치거나 지운 뒤 SL / TP 화면에서 다시 저장하라는 순서와, 지우면 Trailing Stop 설정도 사라진다는 점을 담는다.
- [x] 테스트 도우미는 새 위치에 버전 2 파일을 쓰도록 바꾼다. 기존 SL / TP API·감시 테스트가 확인하던 동작은 모두 계속 확인된다.
- [x] 깨진 파일을 두는 기존 테스트 두 개(`test_unreadable_settings_answer_no_until_a_valid_save`, `test_unreadable_settings_file_stops_the_environment`)는 깨진 파일을 새 위치에 둔다. 앞의 테스트는 "깨진 파일에 PUT하면 500이고 파일은 그대로 → 파일을 고친 뒤 PUT하면 감시가 다시 동작한다"로 바꾼다.
- [x] 앱을 만들 때 환경마다 다음을 한다. 새 파일이 없고 예전 `sl-tp/<환경 값>.json`이 있으면, 지금의 SL / TP 규칙으로 검사한 뒤 `sl_tp` 칸(`updated_at` 포함)에 옮긴 새 파일을 쓴다. 예전 파일은 바이트 그대로 남긴다. 새 파일이 이미 있으면 예전 파일은 보지 않는다.
- [x] 예전 파일을 읽지 못하거나 규칙에 맞지 않으면(실전 환경에 켜진 세션 포함) 새 파일을 쓰지 않는다. 경로와 원인을 로그에 남기고 앱 만들기를 실패시킨다.
- [x] 이전 성공·실패를 투자 환경, 예전 경로, 새 경로, 실패 원인과 함께 로그에 남긴다. 옮길 것이 없으면 남기지 않는다.
- [x] 테스트: 위 경우를 pytest로 확인한다(예전 파일 이전 후 GET 결과·`updated_at`·원본 유지, 새 파일 우선, 깨진 예전 파일과 실전 ON 예전 파일이면 앱 만들기 실패와 새 파일 없음, 다른 칸 보존). 가짜 키움은 "부르면 실패"로 둔다.
- [x] 구현 직전에 실제 데이터 폴더의 예전 파일 세 개가 이전 규칙에 맞는지 다시 확인한다. 맞지 않으면 구현을 멈추고 사용자에게 알린다.
- [x] 기존 테스트, lint, 타입 검사가 모두 통과한다.
