# 키움 호출 한도 근거

`spec.md`의 결정이 기대는 사실과 그 출처를 모은다. 2026-10-24에 확인했다.

## 1. 공식 기준

- 출처: [키움 REST API 소개 페이지](https://openapi.kiwoom.com/intro), "API 호출 횟수 제한" 항목
- 확인 방법: 페이지를 직접 받아 해당 항목을 읽었다. TR 명세(kra-docs), [API 가이드](https://openapi.kiwoom.com/guide/apiguide), [메인](https://openapi.kiwoom.com/main/home)에는 숫자가 없다.
- 페이지에 적용 시작일은 없다. "유량과 관련된 내용이 변경될 경우 업데이트 예정입니다."라고만 적혀 있다.

### 원문 (항목별 인용)

**1. 국내주식**: "계좌별(토큰별) 호출가능 횟수"

| 일반 | 10회 | 5회 | 1회 |
| 피크타임 | 3회 | 3회 | 1회 |

  - "미국주식(대분류) > 차트(중분류)의 계좌별(토큰별) 1초당 전체 호출 한도는 20회로 제한됩니다."
  - "미국주식 종목리스트(usa10099) TR은 계좌별(토큰별) 1분당 5회로 제한됩니다."

**3. 국내/미국 공통 적용사항**

- "계좌별(토큰별) 세션 1개"

## 2. 오류 코드

- 출처: kra-docs `.claude/skills/kra-docs/errors.md` (원본은 `data/kiwoom-rest-api-spec.json`)
- `1700`: "허용된 API 요청 개수를 초과하였습니다. 유량={?}, API ID={?}"
- `1701`: "허용된 전체 요청 개수를 초과하였습니다. 총유량={?}"
- `1702`: "허용된 그룹 요청 개수를 초과하였습니다. 총유량={?}, API_ID={?}"
- 모의 서버는 이 코드를 `return_code=5`, HTTP 429와 함께 메시지 안에 `[1700:...]` 형태로 보냈다. 자세한 내용은 `.scratch/account-dashboard/spec.md`에 있다.

## 3. 앱이 쓰는 TR의 분류

- 출처: kra-docs 메타데이터 `.claude/skills/kra-docs/data/meta.json`의 `market`, `category` 필드. 이 파일은 생성 파일이라 git에 올라가지 않는다.
- 공식 페이지에는 "어느 TR이 주문TR·조회TR·환전TR인지"를 적은 목록이 없다. 아래 "한도 구분" 열은 kra-docs 메뉴로 추정한 값이다. 주문 메뉴는 주문TR, 나머지는 조회TR로 보았다.

| TR | 쓰는 곳 | kra-docs 분류 | 한도 구분(추정) |
|---|---|---|---|
| `au10001` | 토큰 발급 | 공통 > OAuth 인증 | 공식 언급 없음 |
| `kt10000`, `kt10001`, `kt10003` | 국내 매수·매도·취소 | 국내주식 > 주문 | 주문 |
| `ust20000`, `ust20001`, `ust20003` | 미국 매수·매도·취소 | 미국주식 > 주문 | 주문 |
| `ka00001` | 계좌번호 확인 (국내·미국 모두) | 국내주식 > 계좌 | 조회 |
| `kt00018`, `kt00001`, `ka10075`, `ka10077` | 국내 잔고·예수금·미체결·매입가 | 국내주식 > 계좌 | 조회 |
| `ka10001`, `ka10099`, `ka00198` | 국내 현재가·종목 목록·인기 종목 | 국내주식 > 종목정보 | 조회 |

- `ka00001`은 미국 투자 환경의 계좌 확인에서도 국내 계좌 경로(`/api/dostk/acnt`)로 부른다.

## 4. 앱 로그에서 본 동작 (모의투자)

- 출처: `logs/stock-bot.log.*`. 시각은 모두 로그에 찍힌 UTC다(한국시간은 +9시간).
- 2026-10-05~08: `1700`이 100번 넘게 남았다. 모두 같은 인증정보로 같은 TR을 1초 안에 다시 부른 경우다. 메시지에는 "유량=1, API ID=…"가 찍혔다.
- 2026-10-10 14:08:44: `ust21070` 1페이지를 보낸 지 0.4초 뒤에 보낸 연속조회 2페이지가 `1700`으로 거부됐다. 연속조회 페이지도 한도에 세어진다.
- 같은 TR 1초 간격(연속조회 포함)을 적용한 뒤의 집계. 기간은 2026-10-10 14:10:30(수정이 반영된 서버 시작)부터 10-11 19:53까지다. 이벤트 `kiwoom_request`는 154건, 메시지에 `[170`이 든 `kiwoom_response`는 2건이었다.
  - 14:11:28.264 `ust21070` 2페이지: 1페이지(27.248) 뒤 간격 맞추기로 271ms를 기다려 28.250에 보냈다. 1.002초 간격이었는데도 `1700`이 났다.
  - 14:23:54.428 `au10001`: 앱이 재시작된 직후, 이전 프로세스가 1초 안에 같은 토큰을 받은 뒤라 `1700`이 났다.
  - 반대로 1.000초(14:11:59.949 → 14:12:00.949)와 1.001초(14:11:41.887 → 14:11:42.888) 간격의 `ust21070` 2페이지는 통과했다. "정확히 1초"는 경계선이다.
  - 실전 요청은 토큰 발급뿐이었다.

## 6. 확인하지 못한 것

- 어느 TR이 주문TR·조회TR·환전TR인지 적은 공식 목록
- 토큰 발급(`au10001`)이 어느 한도에 세어지는지
- 같은 토큰을 쓰는 국내 실전과 미국 실전이 한도를 함께 세는지. 공식 표는 시장별로 따로 있다.
- "계좌별(토큰별)"이 앱 키별과 같은 뜻인지
- `1702`의 "그룹"이 무엇인지
- 실전 서버에서의 실제 동작. 실전 서버에 일부러 요청을 몰아 확인하지 않았다.
