# SL / TP 설정 화면 (매도 동작 제외)

Status: ready-for-agent

## Problem Statement

보유종목이 정해 둔 수익률이나 손실률에 닿으면 자동으로 팔고 싶다. 지금은 대시보드를 계속 보면서 직접 매도 주문을 넣어야 한다. 자동매도를 만들기 전에, 언제(하루 중 어느 시간 동안) 어떤 기준으로 팔지, 어떤 종목은 팔지 않을지를 투자 환경마다 정해 두는 화면과 저장 기능이 먼저 필요하다. 설정이 시장의 정규장을 벗어나거나 서로 겹치면 나중에 매도 동작이 헷갈리므로 저장할 때부터 막아야 한다. 매도 동작이 붙기 전에 실전투자 환경에 켜 둔 설정이 남아, 나중에 실제 매도가 갑자기 시작되는 일도 없어야 한다.

## Solution

왼쪽 메뉴에 새 묶음 **자동매매**를 만들고 그 안에 **SL / TP** 메뉴를 둔다. 화면은 선택한 투자 환경의 설정을 보여준다.

- 맨 위에 **매도 방식 안내**와 **준비 중 안내**가 있다.
- 그 아래 **제외종목**: 기존 종목 검색으로 찾아 추가하고 삭제한다.
- 그 아래 **SL/TP 세션** 목록: 처음에는 비어 있다. "세션 추가"로 시작·종료 시각을 정한 세션을 더한다. 세션은 그 시장의 **정규장** 안에만 둘 수 있고, 다음 세션은 이전 세션의 종료 시각 이후에만 시작한다. 시각은 국내는 한국시간(Asia/Seoul), 미국은 뉴욕시간(America/New_York)으로 보여준다.
- 세션마다 ON/OFF 스위치(기본 OFF), **익절 기준**, **손절 기준**을 정한다.
- 화면의 **저장** 버튼을 눌러야 서버에 저장된다. 서버는 네 투자 환경별로 따로 JSON 파일에 저장한다.
- **실전투자** 환경에서는 설정을 저장할 수 있지만 ON 스위치는 켤 수 없다.

이번에는 실제 시세 감시와 매도 주문을 하지 않는다. 설정만 저장한다.

## User Stories

**메뉴와 화면 진입**

1. As a 투자자, I want 왼쪽 메뉴에 "자동매매" 묶음과 그 안의 "SL / TP" 메뉴가 보이기를, so that 자동매매 설정을 시세·자산 기능과 구분해 찾는다.
2. As a 투자자, I want 모바일 메뉴(서랍)에도 같은 메뉴가 보이기를, so that 휴대폰에서도 설정한다.
3. As a 투자자, I want SL / TP 화면이 지금 선택한 투자 환경의 설정만 보여주기를, so that 다른 환경의 설정과 섞이지 않는다.
4. As a 투자자, I want 투자 환경을 바꾸면 그 환경에 저장된 설정을 새로 불러오기를, so that 네 환경을 오가며 각각 확인한다.
5. As a 투자자, I want 설정을 불러오는 동안 불러오는 중임이 보이기를, so that 빈 화면을 설정이 없는 것으로 착각하지 않는다.
6. As a 투자자, I want 설정을 불러오지 못하면 원인과 "다시 시도" 버튼이 보이고 편집할 수 없기를, so that 잘못된 상태 위에 덮어쓰지 않는다.
7. As a 투자자, I want 한 번도 저장하지 않은 환경은 제외종목도 세션도 없는 빈 설정으로 열리기를, so that 처음부터 설정을 시작한다.

**안내 문구**

8. As a 투자자, I want 화면 위쪽에 "평균 매입가 대비 수익률이 익절 기준 이상이거나 손절 기준 이하가 되면, 그 종목의 매도 가능 수량 전량을 시장가로 매도합니다. 제외종목은 매도하지 않습니다." 안내가 늘 보이기를, so that 어떤 방식으로 팔리는지 안다.
9. As a 투자자, I want "자동매도는 아직 동작하지 않습니다. 지금은 설정만 저장됩니다." 안내가 보이기를, so that 켜 둔 세션이 지금 실제로 매도한다고 오해하지 않는다.
10. As a 투자자, I want 실전투자 환경에서는 "실전투자에서는 SL/TP 세션을 켤 수 없습니다" 안내가 보이기를, so that 스위치가 왜 막혔는지 안다.

**제외종목**

11. As a 투자자, I want 화면 맨 위에 제외종목 검색창이 있기를, so that 팔지 않을 종목을 먼저 정한다.
12. As a 투자자, I want 종목명이나 종목코드(티커)로 검색하면 종목 검색과 같은 결과가 입력창 아래에 펼쳐지기를, so that 익숙한 방식으로 찾는다.
13. As a 투자자, I want 결과의 종목을 누르면 제외종목에 추가되기를, so that 한 번에 추가한다.
14. As a 투자자, I want 이미 추가된 종목은 결과에 "추가됨"으로 보이고 다시 추가되지 않기를, so that 같은 종목이 두 번 들어가지 않는다.

16. As a 투자자, I want 제외종목마다 삭제 버튼이 있기를, so that 다시 팔 대상으로 돌린다.

19. As a 투자자, I want 검색이 실패하면 제외종목 영역에 원인이 보이기를, so that 다시 검색할지 판단한다.
20. As a 투자자, I want 제외종목이 없으면 "제외종목이 없습니다"가 보이기를, so that 모든 보유종목이 대상임을 안다.

## Implementation Decisions

**용어**

- `CONTEXT.md`에 **SL / TP**, **SL/TP 세션**, **익절 기준 / 손절 기준**, **제외종목**, **정규장**을 더했다. 로그인 세션은 늘 "로그인 세션"으로 쓰고 "세션"을 단독으로 쓰지 않는다. 코드·로그·화면 문구도 이 이름을 따른다.

**키움 TR**

- 설정 조회·저장은 키움을 부르지 않는다.
- 제외종목 검색은 기존 종목 검색 API(`GET /api/environments/{environment}/stocks?q=`)를 그대로 쓴다. 그 API가 쓰는 목록 TR(국내 `ka10099`, 미국 `usa10099`) 외에 새 TR은 없다.

**설정 모듈 (서버, 새로 만든다)**

- 투자 환경 하나의 SL / TP 설정을 읽고, 검사하고, 저장하는 모듈 하나를 둔다. 정규장 정의, 검사 규칙, 파일 읽기·쓰기를 이 모듈이 갖는다.
- 정규장은 시장마다 고정값이다. 국내 09:00–15:30 Asia/Seoul, 미국 09:30–16:00 America/New_York. 휴장일·단축 거래일은 다루지 않는다.
- 저장 위치는 프로젝트 최상위의 `data/sl-tp/<환경 값>.json`(예: `domestic_paper.json`)이다. `data/`는 git에서 제외한다. `.env`에 새 변수는 없다.
- 저장 폴더는 앱을 만들 때 넘길 수 있다(로그 폴더를 넘기는 것과 같은 방식). 테스트는 임시 폴더를 넘긴다.
- 파일이 없으면 빈 설정(제외종목·세션 없음, 저장 시각 없음)이다.
- 파일을 읽지 못하거나(권한, 깨진 JSON, 형식이 맞지 않음) 내용이 검사 규칙에 맞지 않으면 조회는 실패한다. 실전 환경 파일에 켜진 SL/TP 세션이 있는 것도 규칙에 맞지 않는 것으로 본다. 빈 설정으로 대신하지 않는다. 로그에 경로와 원인을 남긴다. 사용자가 파일을 고치거나 지워야 다시 열린다.
- 쓰기는 같은 폴더의 임시 파일에 쓴 뒤 바꿔치기해, 쓰다 끊겨도 반쯤 쓴 파일이 남지 않게 한다. 같은 환경의 저장은 서버 안에서 한 번에 하나씩 처리한다.
- 두 탭에서 따로 저장하면 나중 저장이 이긴다. 충돌 검사는 하지 않는다.
- 파일 형식(서버 응답과 같은 값, 버전 칸 포함):

```json
{
  "version": 1,
  "updated_at": "2026-10-24T01:23:45+00:00",
  "excluded": [
    { "code": "005930", "name": "삼성전자", "exchange": null }
  ],
  "sessions": [
    { "start": "09:00", "end": "10:30", "enabled": false, "take_profit": "5", "stop_loss": "3" },
    { "start": "10:30", "end": "15:30", "enabled": false, "take_profit": null, "stop_loss": "2.5" }
  ]
}
```

**검사 규칙 (화면과 서버가 같다. 서버가 최종 판정)**

- 제외종목
  - `code`는 비어 있지 않은 종목코드(티커)이고, 같은 `code`가 두 번 나오면 거부한다.
  - `name`은 비어 있지 않은 문자열이다.
  - `exchange`는 국내는 `null`, 미국은 `NYSE`·`NASDAQ`·`AMEX` 중 하나다(종목 검색 결과의 값).
  - 종목이 종목 목록에 실제로 있는지는 확인하지 않는다(키움 호출 없음).
- SL/TP 세션
  - `start`·`end`는 `HH:MM`(00–23시, 00–59분)이다.
  - `start < end`, 둘 다 정규장 안(`정규장 시작 ≤ start`, `end ≤ 정규장 끝`).
  - 목록 순서대로 각 세션의 `start`는 바로 앞 세션의 `end` 이상이다. 같으면 맞닿은 것으로 허용한다. 시작 시각은 포함하고 종료 시각은 빼므로 맞닿은 시각은 뒤 세션에 속한다.
  - `take_profit`·`stop_loss`는 `null` 또는 소수점 둘째 자리까지의 양수 문자열이다. 익절 0.01~1000, 손절 0.01~99.99. 손절은 양수로 저장하고 손실률을 뜻한다.
  - `enabled`가 true이면 둘 중 하나 이상이 `null`이 아니어야 한다.
- 화면은 목록 순서를 사용자가 정한 대로 두고(편집 중 자동 정렬하지 않음), 순서 규칙이 맞아야 저장할 수 있으므로 저장된 목록은 늘 시간 순서다.

**자체 서버 API**

- `GET /api/environments/{environment}/sl-tp`
  - 응답: `environment`, `market`, `timezone`(`Asia/Seoul`·`America/New_York`), `regular_hours`(`start`·`end`), `can_enable`(실전이면 false), `updated_at`(없으면 `null`), `excluded`, `sessions`.
  - 화면은 정규장·시간대·ON 가능 여부를 이 응답에서 받아 쓴다. 화면에 따로 두지 않는다.
  - 파일 읽기 실패: 500, 오류 종류 `sl_tp_settings_unreadable`, 메시지 "SL / TP 설정 파일을 읽지 못했습니다".
- `PUT /api/environments/{environment}/sl-tp`
  - 요청: `excluded`, `sessions`(위 형식). 그 밖의 칸은 무시한다.
  - 처리 순서: 환경 검사 → 입력 검사(400) → 실전이고 켜진 세션이 있으면 403 → 저장 → GET과 같은 응답.
  - 입력 검사 실패: 400, 오류 종류 `invalid_sl_tp_settings`, 메시지에 위치를 담는다(예: "2번째 SL/TP 세션: 시작 시각이 앞 세션의 종료 시각보다 이릅니다").
  - 실전 ON 거부: 403, 오류 종류 `sl_tp_enable_not_allowed`, 메시지 "실전투자에서는 SL/TP 세션을 켤 수 없습니다". 파일은 바뀌지 않는다.
  - 쓰기 실패: 500, 오류 종류 `sl_tp_settings_write_failed`. 기존 파일은 그대로다.
- 둘 다 로그인 세션이 있어야 하고, 잘못된 환경 값은 기존 규칙대로 거부한다(기본 환경으로 대신하지 않음).
- 다른 사이트에서 온 요청 거부(지금은 POST에만 적용)를 GET이 아닌 모든 요청으로 넓혀 PUT도 받게 한다. 거부되면 403 `forbidden_origin`이고 파일은 바뀌지 않는다.
- 오류 응답 형식은 기존 `AppError` 형식(오류 종류, 메시지, 요청 ID)을 따른다.

**로그**

- 조회·저장마다 이벤트를 남긴다: 투자 환경, 요청 ID, 결과(성공·검사 실패·실전 ON 거부·읽기 실패·쓰기 실패), 제외종목 수, 세션 수, 켜진 세션 수, 실패 원인과 위치. 설정 내용 전체는 남기지 않는다.

**화면**

- 메뉴 목록에 새 묶음 "자동매매"와 그 안의 기능 `SL / TP` 하나를 더한다. 다른 기능과 같이 투자 환경을 key로 묶어 환경이 바뀌면 새로 그린다.
- 화면 상태: 불러오는 중 → 불러옴(편집 가능) / 불러오기 실패(다시 시도). 불러온 값과 편집 중인 값을 따로 두고, 둘이 다르면 "저장하지 않은 변경"이다.
- 제외종목 검색은 기존 종목 검색 훅을 그대로 쓴다(입력을 멈춘 뒤 검색, 진행 중 요청 취소). 결과 목록은 입력창 바로 아래에 펼친다. 추가하면 검색어를 비운다.
- 시각 입력은 분 단위 시각 입력칸이고 정규장 시작·끝을 범위로 둔다. 범위 밖 값은 입력칸이 막는 것과 별개로 검사 규칙으로도 판정한다.
- 실전 환경(`can_enable=false`)은 스위치를 OFF로 고정하고 누를 수 없게 한다.
- "저장하지 않은 변경" 상태를 앱 껍데기(투자 환경 전환, 메뉴 이동, 로그아웃)가 알 수 있어야 한다. 변경이 있으면 이동 전에 브라우저 확인 창으로 묻고, 취소하면 이동하지 않는다. 새로고침·탭 닫기는 브라우저 기본 경고를 쓴다. 변경이 없으면 묻지 않는다. 로그인 만료(401 응답, 입력 없음 만료)는 사용자가 한 이동이 아니므로 묻지 않고 기존대로 로그인 화면으로 가며, 저장하지 않은 입력은 버린다(되살리지 않음).
- 저장 중에는 저장 버튼과 모든 편집을 막는다. 저장 성공·실패는 기존 토스트로 알린다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 검증한다. 서버는 자체 API의 요청·응답과 저장 폴더에 남은 파일을, 화면은 사용자가 보는 것과 나간 `/api` 요청을 본다. 내부 함수나 상태 이름은 검증하지 않는다.
- 키움 서버(실전·모의)는 호출하지 않는다. 설정 API 테스트의 가짜 키움은 "부르면 실패"인 기본값을 그대로 둬서, 키움 호출이 없음을 함께 확인한다.

**서버 API (pytest, 기존 `create_app` + `TestClient` 방식에 저장 폴더만 임시 폴더로 넘김)**

- 파일이 없으면 GET은 빈 설정, `updated_at=null`, 그 시장의 정규장·시간대, 실전이면 `can_enable=false`·모의면 true다.
- PUT으로 저장한 값이 GET과 새로 만든 앱(같은 폴더)에서 그대로 읽힌다.
- 네 환경에 각각 다른 값을 저장해도 서로 덮어쓰지 않고, 환경별 파일이 생긴다.
- 정규장 경계: 국내 09:00–15:30, 미국 09:30–16:00은 받고, 국내 08:59 시작·15:31 종료, 미국 09:29 시작·16:01 종료는 400이다.
- `start ≥ end`는 400, 맞닿은 세션은 받고, 앞 세션 종료보다 이른 시작은 400이며 메시지에 몇 번째 세션인지 담긴다.
- 기준 값: 소수점 셋째 자리, 0, 음수, 범위 초과, 숫자가 아닌 값은 400. 한쪽만 있는 세션은 받는다. 켜진 세션에 기준이 둘 다 없으면 400, 꺼진 세션은 받는다.
- 제외종목: 같은 코드 두 번, 빈 코드·이름, 국내에 거래소 값, 미국에 목록 밖 거래소는 400.
- 실전 환경에 켜진 세션을 PUT하면 403이고 파일이 바뀌지 않는다. 꺼진 세션만 있으면 저장된다.
- 실전 환경 파일에 켜진 세션이 있으면 GET은 500 `sl_tp_settings_unreadable`이고 파일은 그대로다.
- 깨진 JSON 파일이 있으면 GET은 500 `sl_tp_settings_unreadable`이고 파일은 그대로다.
- 잘못된 환경 값, 로그인 세션 없는 요청은 GET·PUT 모두 기존 규칙대로 거부되고, 설정 파일이 생기거나 바뀌지 않는다.
- 다른 사이트 출처의 PUT은 로그인돼 있어도 403 `forbidden_origin`이고 파일이 바뀌지 않는다.
- 로그에 저장·거부 이벤트가 환경·결과·개수와 함께 남는다.
- Prior art: 종목 검색·주문 API 테스트(환경별 동작, 실전 차단, 오류 분류), 로그 이벤트를 확인하는 기존 테스트.

**화면 (Playwright e2e, 가짜 `/api` 응답, 기존 종목 검색·주문 패널 e2e와 같은 방식)**

- "자동매매" 묶음 아래 "SL / TP" 메뉴가 데스크톱 메뉴와 모바일 서랍에 보이고, 누르면 GET 요청이 나간다.
- 두 안내 문구가 보인다. 실전 환경에서는 ON 불가 안내가 보이고 스위치가 눌리지 않는다.
- 제외종목: 검색어 입력 → 종목 검색 요청 → 결과 클릭으로 추가, "추가됨" 표시, 삭제. 미국은 거래소가 보인다.
- 세션: 빈 상태 안내, 추가 시 기본 시각(정규장 시작 또는 앞 세션 종료, +1시간, 정규장 끝 상한), 정규장 끝까지 차면 추가 막힘, 시각 오류·겹침·기준 오류 안내와 저장 막힘, 삭제.
- 미국 환경에서는 뉴욕시간 표시와 09:30–16:00 범위가 보인다.
- 저장: 변경 없으면 저장 막힘, 변경하면 "저장하지 않은 변경" 표시, 저장 시 PUT 본문이 화면 값과 같고 성공 토스트, 실패 응답이면 실패 토스트와 입력 유지.
- 저장 응답을 늦게 주는 동안 제외종목·세션 편집이 막혀 있다.
- 저장하지 않은 변경이 있을 때 환경 전환·메뉴 이동에서 확인 창이 뜨고, 취소하면 그대로, 확인하면 이동한다. 변경이 없으면 확인 창이 없다.
- 불러오기 실패면 원인과 "다시 시도"가 보이고, 누르면 다시 요청한다.
- 모바일 폭에서 가로 스크롤이 없다.

## Out of Scope

- 시세 감시, 수익률 계산, 매도 주문 등 실제 자동매도 동작.
- 실전투자 환경에서 SL/TP 세션 켜기.
- 휴장일·단축 거래일·새해 첫 거래일·수능일 같은 특별한 정규장, 장전·장후 시간.
- 종목별로 다른 기준, 세션별 제외종목.
- 자동매도 결과의 Discord 알림.
- 두 탭 동시 편집의 충돌 감지.
- 제외종목이 종목 목록에 실제로 있는지, 보유 중인지 확인.

## Further Notes

- Docker로 배포한다면 `logs/`처럼 `data/`도 볼륨으로 연결해야 재배포 후에도 설정이 남는다. 사용자가 직접 설정한다.
- 매도 동작을 붙일 때 할 일: "준비 중 안내" 지우기, 실전 ON 차단을 어떻게 풀지 정하기, 맞닿은 시각에서 어느 세션을 쓸지(뒤 세션) 지키기, 정규장 특별일 처리, 평균 매입가 대비 수익률에 수수료·세금을 넣을지 정하기.
- 저장 파일에 `version`을 두어, 나중에 형식이 바뀌면 옮길 수 있게 한다.
