# 02: SL/TP 세션 시각 편집

**What to build:** SL / TP 화면의 제외종목 아래에 SL/TP 세션 목록이 생긴다. "세션 추가"로 시작·종료 시각을 정한 세션을 더하고, 시각을 고치고, 삭제하고, 저장한다. 세션은 그 시장의 정규장 안에만 둘 수 있고 다음 세션은 이전 세션의 종료 시각 이후에만 시작한다. 시각은 국내는 한국시간, 미국은 뉴욕시간으로 보인다. 이 티켓에서 세션은 늘 OFF이고 익절·손절 기준은 비어 있다(편집은 03에서).

Spec: `.scratch/sl-tp/spec.md` (검사 규칙의 SL/TP 세션, 자체 서버 API, 화면)

**Blocked by:** 01

**Status:** ready-for-agent

- [x] 정규장은 국내 09:00–15:30 Asia/Seoul, 미국 09:30–16:00 America/New_York 고정값이고, 화면은 GET 응답의 `regular_hours`·`timezone`으로 정규장과 시간대를 보여준다.
- [x] 세션이 없으면 "SL/TP 세션이 없습니다" 안내와 "세션 추가"가 보인다.
- [x] "세션 추가"는 마지막 세션의 종료 시각(없으면 정규장 시작)에서 시작해 1시간 뒤(정규장 끝 상한)에 끝나는 OFF 세션을 더한다. 마지막 세션이 정규장 끝까지 차 있으면 추가가 막히고 이유가 보인다.
- [x] 시작·종료 시각을 분 단위로 고칠 수 있고, 세션마다 삭제 버튼이 있다. 편집 중 목록을 자동 정렬하지 않는다. 저장 중에는 세션 추가·삭제·시각 편집이 막힌다.
- [x] 화면과 서버 모두: `HH:MM` 형식, `start < end`, 정규장 안, 목록 순서대로 `start ≥ 앞 세션의 end`(같으면 허용)를 검사한다. 어긋나면 화면은 그 세션에 안내를 보이고 저장을 막고, 서버는 400 `invalid_sl_tp_settings`에 몇 번째 세션인지 담는다.
- [x] 01의 "세션은 빈 목록만" 제한을 풀고, 이 티켓에서는 `enabled=false`, `take_profit=null`, `stop_loss=null`인 세션만 받는다.
- [x] 저장한 세션이 다시 불러와도 같은 순서·시각으로 보인다.
- [x] 테스트에 정규장 경계(국내 09:00·15:30 허용, 08:59 시작·15:31 종료 거부, 미국 09:30·16:00 허용, 09:29·16:01 거부), 맞닿은 세션 허용, 겹침 거부, 미국 환경의 뉴욕시간 표시를 포함한다.
- [x] pytest와 Playwright로 위 동작을 검증하고, 모바일 폭에서 가로 스크롤이 없다. 기존 테스트가 모두 통과한다.
