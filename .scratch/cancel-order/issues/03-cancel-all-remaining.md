# 03: 미체결 주문 전부 취소

**What to build:** 취소할 수 있는 미체결 주문 줄에 **취소** 버튼이 생긴다. 누르면 **최종 확인**이 열리고, 미체결을 다시 조회해 그 주문의 최신 상태를 보여준다. "주문 취소하기"를 누르면 서버가 미체결을 한 번 더 확인한 뒤 남은 수량 전부를 키움에 한 번만 **주문 취소**로 보낸다. 접수되면 토스트를 띄우고 계좌와 목록을 새로 조회한다. 중복 전송과 접수 여부를 알 수 없는 경우는 매수·매도와 같은 규칙으로 막고 안내한다. 수량 입력은 04에서 붙인다.

Spec: `.scratch/cancel-order/spec.md` (User Stories 24–30, 35–45, Implementation Decisions > 주문 취소·화면)

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [ ] 자체 서버에 `POST /api/environments/{environment}/cancellations`가 있다. 본문은 `order_key`, `order_no`, `quantity`다.
- [ ] 실전투자는 입력 검사보다 먼저 403 `order_not_allowed`("실전투자에서는 주문 취소를 할 수 없습니다.")이고 토큰 발급을 포함해 키움 요청이 없다. 미국 환경은 400이다.
- [ ] 입력 오류(키 없음·64자 초과, 원주문번호 없음, 수량이 1 이상의 12자리 이하 정수가 아님)는 400이고 키움을 부르지 않는다.
- [ ] 매수·매도와 같은 투자 환경별 주문 키 저장소를 쓴다. 같은 키로 다시 오면 409 `duplicate_order`이고, 동시에 두 요청이 와도 `kt10003`은 한 번뿐이다.
- [ ] 같은 원주문번호의 취소는 재확인부터 키움 응답까지 하나씩 처리한다.
- [ ] 보내기 직전에 `ka10075`로 다시 조회한다. 실패면 502 `open_orders_check_failed`, 주문이 없으면 400 `open_order_not_found`, `cancelable`이 아니면 400 `cancel_not_supported`이며, 모두 `kt10003` 요청이 없다.
- [ ] 이 티켓에서는 요청 수량이 재조회한 미체결 수량과 같을 때만 보낸다(`cncl_qty="0"`). 다르면 400이다. 일부 취소는 04가 연다.
- [ ] `kt10003` 본문은 `dmst_stex_tp=KRX`, `orig_ord_no`, 재조회에서 찾은 `stk_cd`, `cncl_qty`이고 재시도 없이 한 번만 나간다.
- [ ] `ord_no`가 없는 응답과 연결 실패는 502 `order_result_unknown`("접수 여부를 확인할 수 없습니다. 키움에서 주문 내역을 확인한 뒤 다시 시도하세요.")이고 다시 보내지 않는다. 키움 거부는 기존 오류 분류를 따른다.
- [ ] 접수 응답은 `order_key`, `order_no`(새 주문번호), `original_order_no`, `cancel_quantity`(응답 `cncl_qty`를 정수로, 0이면 `null`), `accepted_at`이다. 화면은 `null`을 "남은 수량 전부"로 표시한다.
- [ ] 화면: `cancelable` 줄에만 취소 버튼이 있다. 누르면 01의 시트로 최종 확인이 열려 투자 환경, 종목, 매수/매도, 주문 유형, 주문가격, 주문 수량, 원주문번호, 최신 미체결 수량을 보여준다.
- [ ] 최종 확인을 열면 open-orders를 다시 요청한다. 조회 중에는 "확인하는 중"과 함께 "주문 취소하기"가 막힌다. 주문이 없으면 "이미 체결되었거나 취소된 주문입니다", 실패면 "미체결을 확인하지 못했습니다"와 "다시 확인"이 보이고 막힌다. 닫으면 진행 중인 조회 결과를 버린다.
- [ ] 버튼은 "주문 취소하기"와 "닫기"다. 연타해도 요청은 하나이고, 보내는 동안 닫기·Esc·바깥 클릭이 동작하지 않는다.
- [ ] 접수되면 "주문 취소가 접수되었습니다" 토스트와 새 주문번호가 보이고, 최종 확인이 닫히고, account와 open-orders가 다시 요청된다.
- [ ] 400 거부와 502 `open_orders_check_failed`는 실패 토스트이고 최종 확인이 남는다. 같은 창에서 다시 보내면 새 주문 키로 요청이 나간다.
- [ ] `open_order_not_found` 거부 뒤에는 최종 확인이 open-orders를 다시 요청해 "이미 체결되었거나 취소된 주문입니다" 안내를 보여준다.
- [ ] 409·502 확인 불가·연결 끊김·HTML 응답·시간 초과는 확인 불가 토스트이고, 최종 확인이 닫히고 account와 open-orders가 다시 요청되며 재전송이 없다.
- [ ] 로그에 취소 요청·재확인·차단·접수·거부·확인 불가가 주문 키·원주문번호와 함께 남고 비밀값은 가려진다.
- [ ] pytest와 Playwright로 위 동작을 검증한다. 기존 테스트, ruff, mypy, 빌드가 모두 통과한다.
