# 04: 일부 수량 취소

**What to build:** 최종 확인에서 취소할 수량을 고를 수 있다. 수량 칸은 최신 미체결 수량 전부로 채워진 채 시작하고, 줄이면 그만큼만 거둬들인다. "전부" 버튼으로 남은 수량 전부로 되돌린다. 남은 수량 전부를 고르면 키움에 "잔량 전부"로 보내 그사이 일부가 체결되어도 남은 만큼만 취소된다.

Spec: `.scratch/cancel-order/spec.md` (User Stories 30–34, 44–45, Implementation Decisions > 주문 취소)

**Blocked by:** 03

**Status:** ready-for-agent

- [x] 서버: 요청 수량이 재조회한 미체결 수량과 같으면 `cncl_qty="0"`, 적으면 요청 수량을 보낸다. 넘치면 400 `cancel_quantity_exceeded`이고 detail에 최신 미체결 수량을 담으며 `kt10003` 요청이 없다.
- [x] 화면: 최종 확인에 취소 수량 칸과 "전부" 버튼이 있다. 칸은 재조회한 미체결 수량으로 채워진다.
- [x] 1주 미만, 정수가 아닌 값, 미체결 수량을 넘는 값은 안내와 함께 "주문 취소하기"가 막힌다.
- [x] 서버가 `cancel_quantity_exceeded`로 거부하면 실패 토스트와 함께 open-orders를 다시 요청한다. 입력 값은 그대로이고, 최대 수량과 "전부" 값은 최신 미체결 수량으로 바뀐다.
- [x] 다시 확인한 미체결 수량이 입력한 수량보다 적으면 "미체결 수량이 N주로 줄었습니다" 안내와 함께 막힌다.
- [x] 요청 본문의 `quantity`는 칸의 값이다.
- [x] pytest(전부→0, 일부→그 수량, 초과→400·요청 없음)와 Playwright(기본값, 전부 버튼, 0·초과 막힘, 수량 초과 거부 뒤 재조회와 줄어듦 안내, 요청 본문)로 검증한다. 기존 테스트, ruff, mypy, 빌드가 모두 통과한다.
