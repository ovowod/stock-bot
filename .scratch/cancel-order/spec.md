# 국내 미체결 주문 목록과 주문 취소 (모의투자)

Status: ready-for-agent

## Problem Statement

계좌 확인에서 자산과 보유종목은 보이지만, 걸어 둔 **미체결 주문**은 보이지 않는다. 지정가 주문이 체결되지 않고 남아 있는지 보려면 키움 앱을 따로 열어야 하고, 잘못 걸었거나 더는 필요 없는 주문을 거둬들이는 것도 키움 앱에서만 할 수 있다. 모의투자에서 매수·매도를 연습하는 흐름이 대시보드 안에서 끝나지 않는다. 취소는 키움에 새 주문으로 접수되는 요청이라, 두 번 나가거나 화면이 오래된 수량으로 보내서도 안 된다.

## Solution

국내 투자 환경의 계좌 확인 맨 아래에 **미체결 주문** 패널을 둔다. 앱 밖(MTS·HTS)에서 낸 주문도 포함해 그 계좌의 미체결 주문을 모두 보여준다. 주문마다 **취소** 버튼이 있고, 누르면 **최종 확인**이 열린다. 최종 확인은 미체결을 다시 조회해 최신 미체결 수량을 보여주고, 취소할 수량(기본값은 남은 수량 전부)을 받는다. "주문 취소하기"를 누르면 서버가 미체결을 한 번 더 확인한 뒤 키움에 **주문 취소**를 한 번만 보낸다. 접수되면 토스트로 알리고, 계좌와 미체결 목록을 새로 조회하고, Discord로 **알림**을 보낸다.

**모의투자**에서만 취소할 수 있다. **실전투자**에서는 목록만 보여주고, 화면과 서버 양쪽에서 취소를 막는다. 신용주문과 KRX가 아닌 거래소(NXT·통합)의 주문은 목록에 표시만 하고 취소 버튼을 두지 않는다.

## Implementation Decisions

**미체결 주문 조회 (서버)**

- 국내 투자 환경의 미체결 주문을 돌려주는 자체 API를 새로 둔다: `GET /api/environments/{environment}/open-orders`. 응답은 주문 목록과 조회 시각이다.
- 키움 `ka10075`(미체결요청, `/api/dostk/acnt`)을 `all_stk_tp=0`, `trde_tp=0`, `stk_cd` 빈 값, `stex_tp=0`(통합)으로 부른다. 연속조회는 기존 키움 클라이언트가 최대 10페이지까지 이어 받는다. 넘으면 기존 `incomplete_result` 오류로 목록 조회와 취소 재확인이 실패한다.
- 미국 투자 환경으로 부르면 400으로 거부하고 키움을 부르지 않는다.
- 실전투자에서도 조회는 된다(목록 보기는 허용).
- 주문 한 건의 응답 모양:
  - `order_no` 주문번호(`ord_no`), `code` 종목코드(`stk_cd`), `name` 종목명(`stk_nm`)
  - `side`: `buy` | `sell`. `io_tp_nm`에 "매수"가 있으면 buy, "매도"가 있으면 sell이다.
  - `side_label`: `io_tp_nm`에서 색 표시용 +·-를 뺀 값(매수, 매도정정, 매수신용 등)
  - `order_type`: `trde_tp` 값. "보통"은 "지정가"로 바꾼다(기존 체결 알림과 같은 규칙).
  - `price`: 주문가격(`ord_pric`) 절댓값. 0이면 `null`(시장가 등).
  - `ordered_quantity`(`ord_qty`), `remaining_quantity`(`oso_qty`)
  - `time`: `tm`(HHmmss)을 HH:MM:SS로. 바꾸지 못하면 받은 그대로.
  - `exchange`: `stex_tp_txt`(KRX·NXT·통합)
  - `cancelable`: 이 앱에서 취소할 수 있는지
  - `blocked_reason`: `real` | `credit` | `exchange` | `null`. 실전투자면 `real`, `io_tp_nm`에 "신용"이 있으면 `credit`, KRX 주문(`stex_tp=1`이고 `sor_yn`이 Y가 아님)이 아니면 `exchange`다. 여러 이유가 겹치면 이 순서로 하나만 준다.
- 주문번호·종목코드·미체결 수량이 비었거나 숫자가 아니면 응답 형식 오류로 처리한다.

**주문 취소 (서버)**

- 자체 API `POST /api/environments/{environment}/cancellations`를 새로 둔다. 본문은 `order_key`(화면이 최종 확인을 열 때마다 새로 만드는 키), `order_no`(원주문번호), `quantity`(1 이상의 정수 문자열)이다.
- 처리 순서는 다음과 같다.
  1. 실전투자면 입력 검사보다 먼저, 키움을 부르기 전에 403으로 막는다(`order_not_allowed`, "실전투자에서는 주문 취소를 할 수 없습니다.").
  2. 미국 투자 환경이면 400으로 막는다.
  3. 입력 검사. 잘못되면 400(`invalid_request`).
  4. 주문 키 중복 검사. 매수·매도와 같은 투자 환경별 주문 키 저장소를 함께 쓴다. 이미 받은 키면 409(`duplicate_order`)를 돌려주고 키움을 부르지 않는다.
  5. 같은 원주문번호의 취소는 하나씩 처리한다(잠금). 재확인부터 키움 응답까지가 한 단위다.
  6. `ka10075`로 미체결을 다시 조회해 그 원주문번호를 찾는다.
     - 조회 실패면 502(`open_orders_check_failed`). 취소 TR 전이므로 확인 불가가 아니라 실패다.
     - 주문이 없으면 400(`open_order_not_found`, "이미 체결되었거나 취소된 주문입니다.").
     - `cancelable`이 아니면 400(`cancel_not_supported`).
     - 요청 수량이 미체결 수량보다 많으면 400(`cancel_quantity_exceeded`, 최신 미체결 수량을 detail에 담는다).
  7. 키움 `kt10003`(주식 취소주문, `/api/dostk/ordr`)을 재시도 없이 한 번만 부른다. 본문은 `dmst_stex_tp=KRX`, `orig_ord_no`, `stk_cd`(재조회에서 찾은 값), `cncl_qty`다. 요청 수량이 재조회한 미체결 수량과 같으면 `cncl_qty="0"`(잔량 전부)을, 적으면 요청 수량을 보낸다.
  8. 응답에 `ord_no`가 없으면 응답 형식 오류다. 연결 실패와 응답 형식 오류는 매수·매도와 같은 502(`order_result_unknown`)로 돌려준다. 문구는 "접수 여부를 확인할 수 없습니다. 키움에서 주문 내역을 확인한 뒤 다시 시도하세요."다. 키움이 거부한 경우는 기존 오류 분류를 그대로 쓴다.
- 접수 응답: `order_key`, `order_no`(새 주문번호), `original_order_no`, `cancel_quantity`, `accepted_at`. `cancel_quantity`는 키움 응답의 `cncl_qty`(부호 포함 0 채움 12자리)를 정수로 바꾼 값이다. 0이면(잔량 전부로 보냈을 때 키움이 0을 돌려준 경우) `null`이다. 재조회 뒤 일부가 체결됐을 수 있으므로 재조회한 미체결 수량으로 채우지 않는다. 화면과 알림은 `null`을 "남은 수량 전부"로 표시한다.
- 미체결 조회와 그 해석은 한 서비스가 맡고, 목록 API와 취소의 재확인이 같은 서비스를 쓴다. 취소 서비스는 기존 주문 서비스처럼 이 조회 기능을 함수로 받는다.

**Discord 알림**

- 취소가 접수됐을 때만 보낸다. 거부·확인 불가·차단은 보내지 않는다.
- 로그인 알림처럼 응답을 기다리지 않는 별도 작업으로 보낸다. 실패는 notifier가 로그로 남기고, 취소 응답에는 영향이 없다.
- embed 제목은 "주문 취소 접수"다. 필드는 투자 환경, 종목(종목명과 코드), 원래 주문(매수·매도 표시는 `side_label`), 취소 수량(`null`이면 "남은 수량 전부"), 원주문번호 → 새 주문번호, 시각(KST)이다.

**화면**

- 계좌 확인 레이아웃에 맨 아래 전체 너비 칸을 더한다. 모바일에서는 보유종목 다음에 온다. 국내 투자 환경에서만 미체결 주문 패널을 그린다.
- 미체결 목록은 계좌와 별도의 상태(로딩·오류·준비)를 가진다. 상단 "새로고침", 매도 접수, 취소 접수는 계좌와 미체결을 모두 다시 부른다.
- 목록 모양은 보유종목 목록의 줄 모양과 기존 Panel·배지 스타일을 따른다. 매수는 상승색, 매도는 하락색 배지를 쓴다.
- 취소할 수 없는 줄에는 이유별 배지를 단다(신용, NXT·통합 거래소)와 "키움 앱에서 취소하세요" 안내를 붙인다. 실전투자면 줄마다 붙이지 않고 패널에 안내를 한 번만 보여준다.
- 취소의 최종 확인은 주문 패널과 같은 시트(모바일은 아래에서 올라오는 시트, 넓은 화면은 오른쪽 패널)와 같은 잠금 규칙을 쓴다. 열 때 `open-orders`를 다시 불러 그 주문을 찾고, 닫으면 진행 중인 조회를 버린다.
- 화면의 결과 분류는 주문 패널과 같다. 409 중복, 502 `order_result_unknown`, 연결 끊김, 형식이 다른 응답, 30초 시간 초과는 "접수 여부를 확인할 수 없습니다"로 처리한다. 그 밖의 오류는 실패 토스트다.
- 주문 키: 최종 확인을 열 때 새로 만든다. 서버는 재확인 전에 키를 등록하므로, 확실한 실패(400, 502 `open_orders_check_failed` 등 확인 불가가 아닌 오류) 뒤에는 최종 확인을 남긴 채 다음 전송에 쓸 새 키를 만든다. 확인 불가 뒤에는 최종 확인을 닫고 계좌와 미체결 목록을 다시 부른다. 다시 취소하려면 최종 확인을 다시 열어 재조회를 거친다.
- 서버의 `cancel_quantity_exceeded`·`open_order_not_found` 응답을 받으면 실패 토스트와 함께 최종 확인의 재조회를 다시 실행한다. 입력 값은 그대로 두고 최대 수량과 "전부" 값을 최신 값으로 바꾸며, 줄어듦·주문 없음 안내는 처음 재조회와 같은 규칙을 따른다.
- 성공 토스트는 "주문 취소가 접수되었습니다"와 새 주문번호다.

**용어**

- 이 기능은 CONTEXT.md의 **미체결 주문**, **주문 취소**, **최종 확인**, **알림**, **토스트**를 쓴다. 화면 문구에 "확인창", "취소주문"을 쓰지 않는다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 검증한다. 서버는 자체 API의 요청·응답과, 가짜 키움·가짜 Discord에 실제로 나간 요청을 본다. 화면은 사용자가 보는 것을 본다. 내부 함수나 상태 이름은 검증하지 않는다.
- 키움 서버(실전·모의)와 Discord는 자동 테스트에서 호출하지 않는다.

**서버 API (pytest + 가짜 키움 + 가짜 Discord, 기존 매도·로그인 알림 테스트와 같은 방식)**

- open-orders: 문서 예제 모양의 `ka10075` 응답이 위 응답 모양으로 바뀐다(+·- 제거, 보통→지정가, 시장가 가격 null, HH:MM:SS). 요청 본문은 `all_stk_tp=0`, `trde_tp=0`, `stk_cd` 빈 값, `stex_tp=0`이고 모의 도메인으로 나간다.
- 여러 페이지면 이어 받아 모두 돌려준다. 빈 목록은 빈 배열이다.
- `blocked_reason`: 신용(`+매수신용`), NXT, 통합(SOR), 실전이 각각 맞게 나오고 KRX 현금 주문만 `cancelable`이다.
- 필수 칸이 깨지면 응답 형식 오류다. 미국 환경은 400이고 키움 요청이 없다.
- 취소: 전부 취소는 `cncl_qty="0"`, 일부 취소는 그 수량으로 `kt10003`이 한 번 나가고, 앞에 `ka10075` 재조회가 나간다. 응답의 새 주문번호와 취소 수량이 돌아온다.
- 실전 환경 취소는 403이고 토큰 발급을 포함해 키움 요청이 하나도 없다.
- 입력 오류(키 없음, 수량 0·문자·13자리)는 400이고 키움 요청이 없다.
- 같은 주문 키로 두 번 보내면 두 번째가 409이고 `kt10003`은 한 번뿐이다. 동시에 두 요청이 와도 한 번뿐이다.
- 재조회에 주문이 없으면 400, 신용·NXT면 400, 수량이 넘치면 400(detail에 최신 미체결 수량)이고, 셋 다 `kt10003` 요청이 없다.
- 재조회 실패는 502 `open_orders_check_failed`이고 `kt10003` 요청이 없다.
- `kt10003`의 연결 실패·`ord_no` 없는 응답은 502 `order_result_unknown`이고 다시 보내지 않는다. 키움 거부(`return_code`≠0)는 기존 오류 분류를 따른다.
- 접수 응답의 `cancel_quantity`는 키움 `cncl_qty`가 0이 아니면 그 값, 0이면 `null`이다.
- 접수되면 Discord에 "주문 취소 접수" embed가 한 번 가고 필드가 맞다. 거부·확인 불가·차단은 Discord 요청이 없다. Discord가 실패해도 취소 응답은 200이고, 가짜 Discord 응답을 붙잡아 둔 동안에도 취소 응답이 먼저 끝난다.
- 로그에 위 이벤트가 주문 키·원주문번호와 함께 남고, 비밀값은 가려진다.

**화면 (Playwright e2e + 가짜 `/api` 응답, 기존 매도·계좌 e2e와 같은 방식)**

- 국내 모의 계좌 확인 아래에 미체결 패널과 개수가 보이고, 줄마다 종목·매수/매도·유형·가격(시장가 표시)·수량·시각·거래소가 보인다. 비면 "미체결 주문이 없습니다"가 보인다.
- 미체결 조회가 실패해도 계좌는 보이고 패널에 오류와 "다시 시도"가 보인다. 누르면 다시 요청한다.
- 상단 새로고침이 account와 open-orders를 모두 다시 요청한다.
- 신용·NXT 줄에는 배지와 안내만 있고 취소 버튼이 없다. 실전 환경에서는 안내가 한 번 보이고 취소 버튼이 없다. 미국 환경에는 패널이 없고 open-orders 요청이 나가지 않는다.
- 취소 버튼 → 최종 확인이 열리며 open-orders 재요청이 나가고, 최신 미체결 수량이 수량 칸에 채워진다.
- 재조회 결과가 없음·줄어듦·실패면 각각의 안내와 함께 "주문 취소하기"가 막히고, 실패면 "다시 확인"이 다시 요청한다.
- 수량 0·초과 입력은 막히고, "전부"가 남은 수량으로 되돌린다.
- 요청 본문에 `order_key`, `order_no`, `quantity`가 들어간다. 연타해도 요청은 하나다. 보내는 동안 닫기·Esc·바깥 클릭이 동작하지 않는다.
- 접수되면 성공 토스트와 새 주문번호가 보이고, 최종 확인이 닫히고, account와 open-orders가 다시 요청된다.
- 400 거부는 실패 토스트이고 최종 확인이 남는다. 같은 창에서 다시 보내면 새 주문 키로 요청이 나간다.
- 수량 초과·주문 없음 거부 뒤에는 open-orders 재요청이 나가고, 입력 값은 그대로이며 줄어듦·주문 없음 안내가 보인다.
- 409·502 확인 불가·연결 끊김·HTML 응답은 확인 불가 토스트이고, 최종 확인이 닫히고 account와 open-orders가 다시 요청되며 재전송이 없다.
- 모바일 폭에서 패널과 최종 확인이 가로 스크롤을 만들지 않는다.

## Out of Scope

- 실전투자 주문 취소.
- 정정 주문(`kt10002`), 신용 취소(`kt10009`).
- NXT·통합(SOR) 주문 취소. 모의투자가 KRX만 지원해 확인할 수 없다.
- 미국 미체결 주문 목록과 취소(`ust21050`, `ust20003`).
- 여러 주문 한 번에 취소, 실시간으로 목록 자동 갱신.
- 체결 알림 기능이 쓰는 미체결 조회를 이번 서비스로 바꾸는 정리.

## Further Notes

- 모의투자에서 장중에 직접 확인할 것(실전 도메인으로 나가지 않는 것을 먼저 확인한 뒤 진행한다):
  - `ka10075`의 `stex_tp=0`(통합)을 모의 서버가 받아들이는지. 거부하면 결과를 기록하고 모의투자에서 쓸 값을 정한다(fill-notify 이슈 01과 같은 확인).
  - 모의 주문의 `stex_tp`·`stex_tp_txt`·`sor_yn`이 어떻게 오는지(모의 주문이 KRX로 표시되어 취소 가능으로 분류되는지).
  - 시장가에서 먼 지정가 매수로 미체결을 만들고 일부 취소와 전부 취소(`cncl_qty=0`)가 접수되는지, 응답 `cncl_qty`가 실제 취소 수량인지 0인지.
  - 취소 접수 직후 다시 조회한 미체결 목록에 그 주문이 남는지, 남는다면 얼마나 오래 남는지. 서버는 원주문별 "반영 대기" 상태를 두지 않는다. 취소는 키움에 남은 수량보다 많이 거둬들일 수 없고, 반영 전에 다시 보내는 것은 사용자가 최종 확인을 다시 연 새 요청이기 때문이다. 지연이 길면 이 결정을 다시 다룬다.
  - 미체결보다 많은 수량을 취소하면 키움이 어떻게 응답하는지(서버가 막으므로 직접 키움에 보내 볼 때만).
- 문서로 확인하지 못한 것: `stex_tp_txt`·`sor_yn`과 `dmst_stex_tp`(KRX·NXT·SOR)의 대응, 취소 TR의 호출 한도.
