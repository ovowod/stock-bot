# 03: 다음 세션에 다시 시도와 보내기 직전 확인

**What to build:** 트리거된 종목을 아직 보유하고 있으면, 켜진 Trailing Stop 세션이 새로 시작될 때마다(다음 세션, 다음 날, 서버 재시작) 그 세션의 첫 정규장 시세 체결에서 자동 매도를 한 번 더 낸다. 실패한 종목도, 접수 뒤 일부만 체결되고 남은 수량도 이렇게 정리된다. 키움에 보내기 직전에 상황이 바뀌었으면 보내지 않는다. 계좌 확인의 Trailing Stop 보기에서 아직 시도하지 않은 트리거 종목은 "다음 시세에서 매도", 세션 밖에서는 "세션 밖 · 다음 세션에 매도"로 보인다.

Spec: `.scratch/trailing-stop-auto-sell/spec.md` (언제 파는가, 결과별 처리, 화면, 로그)

**Blocked by:** 02

**Status:** ready-for-agent

- [x] 이미 트리거된 종목이고 이번 세션 실행에서 아직 시도하지 않았으면, 판정을 건너뛰지 않은 첫 정규장 시세 체결에서 자동 매도를 낸다(attempt=`retry`, 새 요청 ID). 결과와 상관없이 그 실행에서는 다시 내지 않는다.
- [x] 세션 기준만 바꿔 저장한 것은 같은 실행이라 다시 내지 않는다.
- [x] 새 실행이 시작되면 상태 API의 `auto_sell`이 모두 `null`로 돌아간다.
- [x] 자동 매도 결과는 그 매도를 시작한 세션 실행에 속한다. 앞 실행의 매도 결과가 새 실행이 시작된 뒤 나오면 로그와 Discord 알림만 남기고, 지금 실행의 시도 기록과 `auto_sell`은 바꾸지 않는다.
- [x] 보내기 직전 확인: 감시 멈춤, 세션 실행 바뀜, 제외종목이 됨, 기억이 지워짐 가운데 하나면 보내지 않고(`cancelled`) `trailing_stop_send_refused`를 남긴다. 연결이 끊긴 것만으로는 막지 않는다.
- [x] 다시 시도 알림은 기억의 트리거 시각·가격과 고점, 지금 켜진 세션의 기준을 담고, 다시 시도라는 것을 보인다.
- [x] 화면: 감시 중이고 `auto_sell`이 `null`인 매도 조건 충족 종목은 "다음 시세에서 매도", 감시 안 함 이유가 `no_session`이면 "세션 밖 · 다음 세션에 매도", 그 밖의 멈춘 이유면 자동 매도 줄 없이 지금처럼 멈춘 이유를 보인다.
- [x] 테스트(pytest, 앱 전체를 HTTP로): 거부·결과 모름·매도 가능 수량 0·SL / TP 진행 중·보내기 전 취소 뒤 다음 세션, 다음 날, 재시작에서 한 번 더 냄. 접수 뒤 전량 체결이면 다시 내지 않음. 일부만 체결되면 다음 실행에서 남은 수량을 팖. 기준만 바꾼 저장으로는 다시 내지 않음. 보내기 직전 세션 끝, 제외종목 추가, 기억 삭제, 감시 멈춤이면 주문 TR이 나가지 않음. 접수 뒤 미체결 매도가 남아 있으면 다음 실행에서 매도 가능 수량 0으로 보내지 않음. 접수됐지만 체결 없이 주문이 사라지면 다음 실행에서 다시 팖. 주문 응답을 세션 경계 뒤로 늦추면 앞 실행의 결과가 새 실행의 `auto_sell`과 다시 시도를 바꾸지 않음.
- [x] 테스트(Playwright): "다음 시세에서 매도", "세션 밖 · 다음 세션에 매도", 장애로 멈춘 경우 자동 매도 줄 없음을 확인한다.
- [x] 기존 테스트, lint, 타입 검사, 화면 빌드, e2e가 모두 통과한다.

## Comments

- 화면의 "다음 시세에서 매도", "세션 밖 · 다음 세션에 매도", 장애 때 자동 매도 줄 없음과 그 e2e는 02에서 함께 넣었다.
- 앞 실행의 늦은 결과는 결과를 매도를 시작한 실행 객체에 적는 구조라 지금 실행의 상태를 바꾸지 않는다.
