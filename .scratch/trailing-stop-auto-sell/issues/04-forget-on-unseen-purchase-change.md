# 04: 체결 없이 평균 매입가가 바뀐 종목의 기억 지우기

**What to build:** 서버가 꺼졌거나 연결이 끊긴 사이 팔고 다시 산 종목이 예전 고점 때문에 곧바로 팔리지 않게 한다. 보유종목을 읽을 때마다 기억이 있는 종목의 평균 매입가를 마지막으로 확인한 값과 비교한다. 지난 확인 이후 앱이 그 종목의 내 계좌 체결을 받지 않았는데 값이 바뀌었으면 활성화를 풀고, 그 종목은 활성화 대기부터 다시 판정한다. 앱이 받은 체결(추가 매수, 일부 매도)로 바뀐 것은 유지한다.

Spec: `.scratch/trailing-stop-auto-sell/spec.md` (평균 매입가 비교, 로그)

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [x] 기억마다 지난 확인 이후 그 종목의 내 계좌 체결을 받았는지 안다. 세션 밖에서 기억이 있는 종목의 체결을 받아 다시 읽을 때도 같다.
- [x] 체결 수신에 공백이 생기면(서버 시작, 다시 연결, 체결 실시간 등록 거부) 다음 비교 한 번은 받은 체결을 인정하지 않는다. 공백 전에 받은 체결도, 공백 뒤 첫 비교 전에 받은 체결도 마찬가지다.
- [x] 보유종목을 읽을 때: 체결을 받았으면 새 평균 매입가로 바꾼다. 받지 않았는데 다르면 기억을 지운다(`trailing_stop_memory_forgotten`, reason=`purchase_price_changed`, 이전 값과 새 값). 같으면 그대로 둔다.
- [x] 지운 뒤에는 고점 기록 파일에 바로 쓴다.
- [x] 공용 자동 매도 경로에 선택 항목 "다시 읽은 보유종목 확인"을 더한다. 매도 가능 수량을 읽은 바로 뒤, 키움에 보내기 전에 부르고, 거절하면 보내지 않고 `cancelled`로 끝낸다. SL / TP는 넘기지 않아 동작이 그대로다.
- [x] Trailing Stop은 이 확인에서 다시 읽은 평균 매입가를 위와 같은 규칙으로 판단한다. 같으면 보내고, 인정되는 체결로 설명되면 새 값으로 바꾸고 보내며, 설명되지 않으면 기억을 지우고 보내지 않는다.
- [x] 테스트(pytest, 앱 전체를 HTTP로): 활성화된 종목을 둔 채 서버를 내리고, 평균 매입가가 다른 잔고로 다시 띄우면 기억이 사라지고 고점 대비 하락 가격의 시세 체결에도 트리거나 주문이 없음. 같은 평균 매입가면 유지됨. 앱이 받은 매수 체결 뒤 평균 매입가가 바뀌면 유지됨. 체결 등록이 거부된 사이 바뀐 경우도 지워짐. 매수 체결을 받음 → 다시 읽기 실패 → 연결이 끊겼다 다시 연결 → 다른 평균 매입가로 읽힘이면 지워짐. 다시 연결 뒤 첫 비교 전에 매수 체결을 받아도 다른 평균 매입가면 지워짐. 트리거 뒤 주문 직전 잔고가 다른 평균 매입가면 주문 TR이 나가지 않고 기억이 지워짐, 같은 평균 매입가거나 공백 없이 받은 매수 체결 뒤면 주문이 나가고 SL / TP 자동 매도는 그대로 동작함. 받은 체결로 평균 매입가가 바뀌고 파일에 쓰인 뒤 재시작하면 유지됨.
- [x] 기존 테스트, lint, 타입 검사가 모두 통과한다.

## Comments

- 체결 등록 거부 사이의 변경은 서버 시작 뒤 거부된 채 시작하는 경우로 확인했다. 거부가 일어난 것 자체를 공백으로 표시하는 규칙은 다시 연결과 같은 자리에서 다룬다.
- 자동 매도 결과가 cancelled면 SL / TP와 같이 WARNING으로 남는다.
