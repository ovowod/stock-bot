# 01: 고점 기록 버전 2와 배포 때 기억 정리

**What to build:** 고점 기록에 종목마다 마지막으로 확인한 평균 매입가를 적는다. 상태만 계산하던 때 남은 버전 1 파일을 처음 읽으면 기억을 모두 지우고 빈 버전 2로 다시 쓴다. 그래서 자동 매도를 붙였을 때 예전 트리거나 평균 매입가를 확인할 수 없는 예전 고점으로 배포 직후 팔리지 않는다. 계좌 확인의 Trailing Stop 보기에서 모든 종목이 활성화 대기로 보인다. 매도 주문은 아직 내지 않는다.

Spec: `.scratch/trailing-stop-auto-sell/spec.md` (고점 기록 파일 (버전 2), 로그)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 고점 기록 형식을 버전 2로 올린다. 종목마다 `purchase_price`(문자열 소수, 늘 값이 있음)를 더한다. 그 밖의 칸과 쓰기 규칙은 그대로다.
- [x] 활성화할 때 그 시점의 평균 매입가를 기억에 적는다. 앱이 받은 체결 뒤 다시 읽어 평균 매입가가 바뀌었으면 새 값으로 바꾼다. 체결 없이 바뀐 경우의 처리는 04에서 한다. 이 티켓에서는 지금처럼 유지한다.
- [x] `purchase_price`를 바꾸면 고점 기록 파일에 바로 쓴다.
- [x] 버전 1 파일을 읽으면 기억을 모두 지우고 빈 버전 2로 바로 다시 쓴다. 지운 종목코드를 `trailing_stop_record_migrated` 로그로 남긴다. Discord로는 알리지 않는다.
- [x] 버전 1도 2도 아니거나 형식이 맞지 않으면 지금처럼 `state_unreadable`로 판정을 멈추고 알린다.
- [x] 테스트(pytest, 앱 전체를 HTTP로): 버전 1 파일의 기억(트리거된 종목, 활성화만 된 종목)이 모두 사라지고 상태 API에서 활성화 대기로 보인다. 파일이 빈 버전 2로 다시 쓰이고, 그 뒤 활성화하면 `purchase_price`가 적힌다. 재시작해도 옮기기가 다시 일어나지 않는다. 트리거된 종목을 추가 매수해 평균 매입가가 바뀐 뒤 재시작해도 파일에 새 평균 매입가가 남아 있다. 깨진 파일과 모르는 버전은 판정을 멈춘다.
- [x] 기존 테스트, lint, 타입 검사가 모두 통과한다.
