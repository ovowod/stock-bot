# 05: 실시간 연결 유지 (재연결, 토큰 재발급, 종료)

**What to build:** 키움 실시간 연결이 끊기거나 접근 토큰이 만료돼도 서버가 알아서 다시 연결하고 다시 등록해서 체결 알림이 이어진다. 다시 연결하는 간격은 점점 늘어나되 60초를 넘지 않는다. 끊긴 동안의 체결은 알리지 않는다.

Spec: `.scratch/fill-notify/spec.md` (연결 단위, 로그)

**Blocked by:** 02

**Status:** ready-for-agent

- [x] 연결이 끊기거나 연결에 실패하면 1초부터 두 배씩, 최대 60초 간격으로 다시 연결한다. `LOGIN`과 `REG`가 모두 성공해야 간격을 처음으로 되돌린다. WebSocket 연결만 되고 `LOGIN`이나 `REG`가 실패하거나 제한 시간 안에 응답이 없으면 간격은 계속 늘어난다.
- [x] 다시 연결하면 `LOGIN`과 `REG`를 다시 보내고, 그 뒤의 체결 이벤트는 정상적으로 알림이 된다.
- [x] `LOGIN` 실패 응답을 받으면 그 토큰을 캐시에서 버리고 새로 발급받아 다시 연결한다.
- [x] REG 실패 응답을 받거나, `LOGIN`·`REG` 응답이 10초 안에 오지 않으면 오류 로그를 남기고 다시 연결한다.
- [x] 한 연결의 오류가 다른 연결이나 웹 API를 멈추지 않는다.
- [x] 앱이 끝나면 대기 중인 재연결도 멈추고 연결을 닫는다.
- [x] 끊김(원인), 재연결 대기 시간, 재연결 성공, 토큰 재발급이 로그에 남는다.
- [x] 테스트는 가짜 키움 실시간 서버에서 연결 끊기, 연결 거부, LOGIN 실패, LOGIN·REG 무응답, 계속되는 REG 실패(간격이 계속 늘어나는지)를 일으켜 다시 보낸 `LOGIN`·`REG`, 새 토큰 발급 요청, 재연결 뒤 알림을 검증한다. 대기 시간은 테스트에서 줄일 수 있게 한다.
- [x] 기존 테스트, lint, format 검사, type 검사가 모두 통과한다.
