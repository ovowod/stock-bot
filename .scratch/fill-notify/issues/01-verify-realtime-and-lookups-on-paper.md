# 01: 모의 서버로 실시간 체결과 조회 TR 동작 확인

**What to build:** 구현에 앞서, 키움 문서만으로 확정하지 못한 실시간 체결(`00`, `F5`)과 미체결·매입가 조회 TR의 실제 동작을 국내 모의와 미국 모의 서버에서 확인하고 결과를 spec에 기록한다. 앱 기능은 만들지 않는다. 확인용 스크립트는 저장소에 남기지 않는다. 확인 결과로 03·04·06의 내용이 바뀌면 다음 ticket으로 넘어가기 전에 사용자에게 보고하고 결정을 받는다.

Spec: `.scratch/fill-notify/spec.md` (Further Notes)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 국내 모의와 미국 모의 서버만 쓴다. 실전 서버로는 조회와 실시간 연결을 포함해 어떤 요청도 보내지 않는다.
- [ ] 장 시간(국내 KRX, 미국 정규장)에 진행한다. 장 시간이 아니면 시작하지 않고 사용자에게 알린다.
- [ ] 국내 모의 실시간에 `LOGIN` 후 `00`을 `item: [""]`로 등록하고, 1주 지정가 매수·매도를 넣어 접수·체결 이벤트의 실제 값을 기록한다. `913` 주문상태 값, `910`·`903` 등에 `+`/`-` 부호가 붙는지 본다.
- [ ] 미국 모의 실시간에 `F5`를 `item: [""]`로 등록해 보고, 안 되면 문서 예제처럼 종목 객체로 등록해 본다. 어느 쪽이 계좌 전체 체결을 받는지 기록한다.
- [ ] 미국 모의에서 1주 매수·매도를 넣어 `F5`의 `913` 주문상태 값(접수·체결 단계별), `8018`·`8019` 값을 기록한다.
- [ ] 여러 주를 시장가로 사서 분할 체결이 생기면 이벤트가 몇 번 오는지, `903`이 주문 단위 누계인지 기록한다. 분할 체결이 생기지 않으면 `903` 의미는 "미확인"으로 기록한다(04는 이 경우 서버에서 체결 금액을 더하는 방식으로 간다).
- [ ] 키움이 보내는 `PING` 메시지 모양과 간격, `LOGIN` 응답 모양(성공·실패)을 기록한다. (2026-10-08: 국내 모의 LOGIN 성공 응답 확인, spec Implementation Notes. PING과 실패 응답은 남음)
- [ ] `ka10075`를 `all_stk_tp=0`, `trde_tp=0`, `stk_cd` 빈 값으로 호출할 수 있는지, `stex_tp`는 `0`(통합)과 `1`(KRX) 중 무엇이 되는지 확인한다.
- [ ] `ust21050`을 모두 빈 값과 `slby_tp=0`으로 호출해 미체결 주문이 오는지 확인한다.
- [ ] 매도 체결 직후 `ka10077`(종목코드 지정)과 `ust21630`(티커, 거래소, `fc_krw_tp=0`)을 호출해 방금 체결이 반영되는지, 같은 종목 줄이 몇 개인지, 매입가 값이 계좌 확인의 매입가와 같은지 확인한다. 오늘 산 종목을 바로 판 경우도 확인한다.
- [ ] 결과를 spec 끝의 `## Implementation Notes`에 날짜와 함께 기록한다. 로그나 기록에 인증정보·토큰·계좌번호가 남지 않게 한다.
- [ ] 확인 결과로 spec을 바꿔야 할 점이 있으면 정리해서 결정을 받는다.
