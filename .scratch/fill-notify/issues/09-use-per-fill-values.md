# 09: 국내 체결 알림이 이번 체결분 값을 쓰게 하기

**What to build:** 국내 체결 알림의 "이번 체결"과 매도 손익이 실제 이번 체결분으로 계산된다. 지금은 모의 서버가 누적값으로 보내는 `910`·`911`을 이번 체결분으로 써서, 분할 체결된 매도의 손익이 모두 "조회 실패"로 나가고 "이번 체결" 칸도 누적값으로 보인다.

Spec: `.scratch/fill-notify/spec.md` (알림 모양, 매도 손익)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

## 발견한 동작 (2026-10-26 국내 모의 로그, `logs/stock-bot.log`의 `fill_received`)

- `00` 주문체결의 `910`(체결가)·`911`(체결량)이 그 주문의 누적 평균 체결가·누적 체결 수량으로 온다.
  - 예: 주문 0170352(16주 시장가 매도)의 이벤트마다 `911`이 1, 2, 3, 4, 6, 7, 8, 10, 12, 13, 16으로 늘고, `902`(미체결수량)가 15, 14, …, 0으로 줄어 늘 `911 + 902 = 900`(주문수량)이다.
  - `910`은 1,278,500 → 1,278,250 → 1,278,167처럼 평균처럼 움직인다.
- kra-docs `00`에는 따로 `914` 단위체결가, `915` 단위체결량이 있다. 이번 체결분은 이쪽으로 보인다.
- 지금 코드(`src/stock_bot/fill_watch.py`의 `_domestic_fill`)는 가격을 `910`, 수량을 `911`로 읽고, `_sell_profit`이 주문번호별로 `911`을 더한다. 그래서 더한 수량이 실제 누적 체결 수량과 맞지 않아 `sell_profit_failed cause=missed_fills`로 끝난다(2026-10-26 국내 매도 체결 18건 중 주문별 첫 체결 3건을 뺀 15건).
- SL / TP는 `00`을 보유종목 다시 읽기 계기로만 써서 영향이 없다.

- kra-docs `00`에 `910` 체결가, `911` 체결량, `914` 단위체결가, `915` 단위체결량이 있다. 문서에는 누적 여부가 없고, 누적은 위 모의 로그로 판단했다.
