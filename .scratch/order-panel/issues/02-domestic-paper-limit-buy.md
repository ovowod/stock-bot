# 02: 국내 모의투자 지정가 매수 주문 접수

**What to build:** 국내 모의 환경에서 주문 패널의 매수 버튼을 누르면 최종 확인이 열리고, "주문하기"를 누르면 키움 `kt10000`으로 지정가 매수 주문을 보낸다. 결과는 앱 전체의 화면 알림으로 보여준다. 최종 확인마다 주문 키를 만들어 요청·응답·알림·로그에서 그 주문을 추적한다. 접수되면 주문번호를 알리고 패널을 닫으며, 키움이 거부하면 키움 메시지를 알리고 입력 화면으로 돌아간다. 실전투자 환경에서는 화면과 서버 양쪽에서 주문을 막는다.

Spec: `.scratch/order-panel/spec.md` (주문 접수, 실전투자 차단, 최종 확인과 화면 상태, 결과 분류와 알림, 로그)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 자체 서버에 주문 API(`POST /api/environments/{environment}/orders`)가 있고, 국내 지정가는 `kt10000`에 `dmst_stex_tp=KRX`, `stk_cd`, `ord_qty`, `ord_uv`, `trde_tp=0`, `cond_uv` 빈 값으로 보낸다. 계좌번호는 본문에 넣지 않는다.
- [ ] 투자 환경이 실전이면 입력 검사보다 먼저 403으로 거부하고, 토큰 발급을 포함해 키움 요청이 하나도 나가지 않는다. 거부는 로그에 남는다.
- [ ] 서버가 화면과 같은 입력 검사(수량은 1 이상, 12자리 이하 정수, 국내 가격은 1원 이상, 12자리 이하 정수)를 하고, 어기면 400이며 키움을 부르지 않는다.
- [ ] 화면은 수량·가격을 쉼표를 뺀 입력 문자열 그대로 보내고, 서버는 검사를 통과한 문자열을 그대로 키움 본문에 넣는다. 화면 입력 검사도 같은 길이 제한을 적용해, 너무 긴 값은 입력 오류로 안내하고 매수 버튼을 막는다.
- [ ] 주문 TR 호출은 자동으로 다시 보내지 않는다. 토큰 무효 응답도 재시도하지 않는다. 기존 조회 TR의 재시도 동작은 바뀌지 않는다.
- [ ] 토큰 무효 응답을 받으면 그 주문에 쓴 토큰이 아직 보관 중일 때 버리고, "토큰이 만료되어 주문하지 못했습니다. 다시 주문하세요."로 실패를 알린다. 다음 주문은 새 토큰으로 보낸다.
- [ ] 화면은 최종 확인을 열 때마다 새 주문 키를 만들어 주문 요청에 담는다. 서버는 요청을 받는 즉시 주문 키를 로그(주문 요청 수신)에 남긴다. 주문 키가 없으면 400이다.
- [ ] 접수되면 주문 키, 주문번호, 접수 시각을 돌려준다. 키움 거부(`return_code≠0`)는 기존 오류 분류(502·429·503)대로 돌려준다.
- [ ] 실전투자 환경의 패널은 매수 버튼 대신 "실전투자에서는 주문할 수 없습니다"를 보여주고 최종 확인을 열지 않는다. 입력 칸과 현재가는 그대로 보인다.
- [ ] 모의투자 환경에서 매수를 누르면 패널 안에 최종 확인이 열리고, 투자 환경, "모의투자 주문" 표시, 종목명, 종목코드, 거래소(국내는 KRX), 주문 유형, 가격, 수량, 예상 주문금액을 보여준다.
- [ ] 최종 확인에서 "취소"하면 입력 값이 그대로 남은 입력 화면으로 돌아간다.
- [ ] "주문하기"를 누르면 결과가 올 때까지 버튼이 잠기고 전송 중임이 보인다.
- [ ] 앱 전체에 알림 영역이 하나 있다(데스크톱 오른쪽 위, 모바일 위쪽 가운데, 주문 패널보다 위, `inert` 대상 아님). 여러 알림은 최신이 위에 쌓인다. 성공 알림은 `status`, 실패 알림은 `alert` 역할이다. 주문 알림은 주문 키를 보여주고, 응답을 받았으면 요청 ID도 보여준다.
- [ ] 접수 성공 알림("매수 주문이 접수되었습니다 · 주문번호 N")은 5초 뒤 사라지고 패널이 닫힌다. 실패 알림은 닫기를 누를 때까지 남고 패널은 입력 값과 함께 남는다.
- [ ] 주문 요청 수신(주문 키), 실전 차단, 토큰 폐기, 접수(주문번호), 거부(return_code, 메시지)가 기존 로그 형식으로 남고, 비밀값은 가려진다.
- [ ] `CONTEXT.md`의 최종 확인·주문 접수 용어와 화면 문구가 맞다.
- [ ] pytest와 Playwright로 위 동작을 검증하고, 데스크톱·모바일에서 알림이 가로 스크롤을 만들지 않는다. 기존 테스트가 모두 통과한다.
