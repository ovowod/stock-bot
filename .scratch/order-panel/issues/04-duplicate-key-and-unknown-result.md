# 04: 중복 주문 거부와 접수 여부 확인 불가

**What to build:** 같은 주문 키(02에서 도입)로 주문이 서버에 두 번 도착해도 키움에는 한 번만 전송되게 한다. 전송 중에는 패널을 닫을 수 없게 한다. 서버와 키움 사이 또는 브라우저와 서버 사이에서 접수 여부를 알 수 없게 되면, 실패와 구별되는 "접수 여부를 확인할 수 없음" 알림으로 키움에서 먼저 확인하라고 안내한다. 어떤 경우에도 자동으로 다시 보내지 않는다.

Spec: `.scratch/order-panel/spec.md` (중복 주문 방지, 최종 확인과 화면 상태, 결과 분류와 알림)

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 서버는 주문 키를 투자 환경별로 메모리에 보관하고, 이미 받은(처리 중 포함) 키로 다시 오면 409 "중복 주문"으로 거부하며 키움을 부르지 않는다. 중복 거부는 주문 키와 함께 로그에 남는다.
- [ ] 같은 키로 동시에 두 요청이 와도 키움 주문 요청은 한 번뿐이다.
- [ ] 서버-키움 연결 실패와 응답 형식 오류(`return_code=0`인데 `ord_no`가 없는 경우 포함)는 502 "접수 여부 확인 불가"로 돌려주고 재시도하지 않는다. 로그에 이 결과와 원인이 남는다.
- [ ] 화면은 다음을 모두 "접수 여부 확인 불가"로 처리한다: 서버의 502 "접수 여부 확인 불가", 409 중복, 브라우저 연결 끊김, 형식이 다른 응답(HTML 오류 페이지 등), 30초 시간 초과(요청을 끊는다).
- [ ] 확인 불가 알림은 실패와 다른 문구("접수 여부를 확인할 수 없습니다. 키움에서 주문 내역을 확인한 뒤 다시 주문하세요.")와 주문 키를 보여주고, 닫기를 누를 때까지 남는다. 패널은 입력 값과 함께 입력 화면으로 돌아간다.
- [ ] 위 어느 경우에도 화면이 주문 요청을 다시 보내지 않는다.
- [ ] 전송 중에는 "주문하기"·"취소"·닫기 버튼, 바깥 영역 클릭, Esc가 동작하지 않는다.
- [ ] "주문하기"를 여러 번 눌러도 주문 요청은 하나만 나간다.
- [ ] pytest(같은 키 두 번, 동시 요청, 연결 실패, 형식 오류, 중복 거부 로그)와 Playwright(연타, 전송 중 닫기 불가, 409·연결 끊김·HTML 응답·시간 초과의 확인 불가 알림, 재전송 없음)로 검증한다. 기존 테스트가 모두 통과한다.
