# 주문 패널 (모의투자 매수 주문)

Status: ready-for-agent

## Problem Statement

순위나 종목 검색에서 관심 종목을 찾아 주문 패널을 열 수는 있지만, 아직 주문을 보낼 수 없다. 가격 칸도 순위에서 넘겨받은 값에만 의존해서, 종목 검색이나 인기 종목에서 열면 비어 있고 수량도 매번 직접 입력해야 한다. 자동매매로 가기 전에 모의투자에서 실제로 매수 주문을 넣어 보고 접수 결과를 확인하고 싶다. 동시에 개발 중인 기능이 실수로 실제 돈을 쓰거나, 같은 주문이 두 번 들어가는 일은 없어야 한다.

## Solution

**모의투자** 환경에서는 주문 패널에서 **매수 주문**을 보낼 수 있다. 매수 버튼을 누르면 **최종 확인**에서 주문 내용을 다시 보여주고, "주문하기"를 눌러야 전송한다. 전송 중에는 버튼을 잠그고, 서버도 같은 주문을 두 번 받지 않는다. 결과는 화면 알림으로 보여준다. 접수되면 주문번호를, 거부되면 이유를, 연결이 끊겨 결과를 모르면 확인 방법을 안내한다. **실전투자** 환경에서는 화면과 서버 양쪽에서 주문을 막는다.

종목을 눌러 패널이 열리면 그 종목의 현재가를 키움에서 조회해 가격 칸에 채우고, 수량은 1로 시작한다.

## User Stories

**패널 열기와 기본값**

1. As a 투자자, I want 순위 카드나 종목 검색 결과의 종목을 누르면 주문 패널이 열리기를, so that 보던 화면에서 바로 매수한다.
2. As a 투자자, I want 패널이 열리면 그 종목의 현재가가 가격 칸에 채워지기를, so that 어느 화면에서 열든 가격을 처음부터 입력하지 않아도 된다.
3. As a 투자자, I want 현재가를 불러오는 동안 가격 칸에 불러오는 중임이 보이기를, so that 빈칸이 오류인지 기다리는 중인지 안다.
4. As a 투자자, I want 현재가를 불러오기 전에 가격을 직접 입력했다면 그 값이 덮어쓰이지 않기를, so that 입력한 값을 잃지 않는다.
5. As a 투자자, I want 현재가를 불러오지 못하면 이유를 짧게 보고, 가격을 건드리지 않았다면 가격 칸은 비어 있기를(이미 입력한 가격은 그대로), so that 직접 입력하면 된다는 것을 알고 입력한 값도 잃지 않는다.
6. As a 투자자, I want 수량이 1로 채워진 채 시작하기를, so that 한 주만 사 볼 때 바로 주문한다.
7. As a 미국 모의투자 사용자, I want 매수할 수 없는 거래소의 종목에서는 현재가 조회도 하지 않기를, so that 쓸모없는 호출로 호출 한도를 쓰지 않는다.

**실전투자 차단**

8. As a 투자자, I want 실전투자 환경에서는 매수 버튼 대신 "실전투자에서는 주문할 수 없습니다" 안내를 보기를, so that 실수로 실제 돈을 쓰지 않는다.
9. As a 투자자, I want 화면을 우회해 실전투자 주문 요청이 서버에 와도 키움을 부르지 않고 거부되기를, so that 화면 버그가 있어도 실제 주문이 나가지 않는다.
10. As a 투자자, I want 실전투자에서도 주문 패널의 입력 칸과 현재가는 그대로 보기를, so that 주문 내용을 가늠하는 데는 쓸 수 있다.

**최종 확인**

11. As a 모의투자 사용자, I want 매수 버튼을 누르면 바로 전송되지 않고 최종 확인이 열리기를, so that 잘못 누른 주문이 나가지 않는다.
12. As a 모의투자 사용자, I want 최종 확인에서 투자 환경, 종목명, 종목코드(티커), 거래소, 주문 유형, 가격(지정가) 또는 "시장가", 수량, 예상 주문금액(지정가)을 보기를, so that 보낼 내용을 마지막으로 확인한다.
13. As a 모의투자 사용자, I want 최종 확인에 "모의투자 주문"이라고 표시되기를, so that 어느 환경의 주문인지 헷갈리지 않는다.
14. As a 모의투자 사용자, I want 최종 확인에서 "취소"를 누르면 입력하던 값 그대로 돌아가기를, so that 고쳐서 다시 주문한다.
15. As a 모의투자 사용자, I want 입력 값이 올바르지 않으면 매수 버튼이 눌리지 않기를, so that 거부될 주문을 보내지 않는다.

**중복 주문 방지**

16. As a 모의투자 사용자, I want "주문하기"를 누르면 결과가 올 때까지 버튼이 잠기고 전송 중임이 보이기를, so that 여러 번 눌러도 주문이 한 번만 나간다.
17. As a 모의투자 사용자, I want 전송 중에는 패널을 닫을 수 없기를, so that 결과를 확인하지 못한 채 같은 주문을 다시 열어 보내지 않는다.
18. As a 모의투자 사용자, I want 같은 최종 확인에서 나간 요청이 네트워크 문제로 서버에 두 번 도착해도 키움에는 한 번만 전송되고, 두 번째 요청의 결과는 실패가 아니라 "접수 여부 확인 불가"로 보기를, so that 이미 접수됐을 수 있는 주문을 다시 보내지 않는다.
19. As a 모의투자 사용자, I want 주문 전송이 실패해도 서버가 자동으로 다시 보내지 않기를, so that 접수됐는지 모르는 주문이 두 번 들어가지 않는다.

**결과 알림**

20. As a 모의투자 사용자, I want 주문이 접수되면 주문번호가 담긴 성공 알림을 보기를, so that 나중에 체결 내역에서 찾는다.
21. As a 모의투자 사용자, I want 접수 성공 알림이 "체결"이 아니라 "접수"라고 말하기를, so that 아직 체결되지 않았을 수 있다는 것을 안다.
22. As a 모의투자 사용자, I want 접수에 성공하면 주문 패널이 닫히기를, so that 같은 주문을 실수로 다시 보내지 않는다.
23. As a 모의투자 사용자, I want 키움이 주문을 거부하면 키움이 준 이유가 담긴 실패 알림을 보기를, so that 장 시간, 호가 단위, 잔고 부족 등 무엇이 문제인지 안다.
24. As a 모의투자 사용자, I want 실패하면 패널이 입력 화면으로 돌아와 값이 남아 있기를, so that 고쳐서 다시 주문한다.
25. As a 모의투자 사용자, I want 서버와 키움 사이 또는 브라우저와 서버 사이에서 연결이 끊기거나, 응답을 해석하지 못하거나, 응답이 너무 오래 오지 않아 접수 여부를 모르면, 실패가 아니라 "접수 여부를 확인할 수 없음" 알림을 보기를, so that 바로 다시 주문하지 않고 키움에서 먼저 확인한다.
26. As a 모의투자 사용자, I want 호출 한도 초과로 거부되면 잠시 후 다시 시도하라는 알림을 보기를, so that 기다렸다가 다시 보낸다.
27. As a 투자자, I want 주문 알림에 주문 키가 함께 보이기를(응답을 받지 못한 경우도), so that 문제가 생기면 로그에서 그 주문을 찾는다.
28. As a 투자자, I want 성공 알림은 잠시 뒤 저절로 사라지고 실패·확인 불가 알림은 내가 닫을 때까지 남기를, so that 중요한 실패를 놓치지 않는다.
29. As a 모바일 사용자, I want 알림이 화면을 가리지 않는 위치에 나오고 가로 스크롤을 만들지 않기를, so that 휴대폰에서도 결과를 본다.

**기록**

30. As a 투자자, I want 아주 큰 수나 지나치게 긴 수량·가격이 다른 값으로 바뀌어 주문되지 않고 입력 단계에서 거부되기를, so that 입력한 그대로만 주문된다.
31. As a 투자자, I want 토큰이 무효가 되어 주문이 실패해도 다음 주문은 새 토큰으로 정상 전송되기를, so that 한 번 실패한 뒤 계속 실패하지 않는다.
32. As a 투자자, I want 주문 요청, 키움 응답, 거부·확인 불가 결과가 로그에 남기를, so that 문제가 생겼을 때 어느 단계에서 무엇이 일어났는지 안다.

## Implementation Decisions

**기존 주문 패널에서 유지하는 것**

- 앱 전체에 주문 패널 하나를 두고 어느 화면에서든 종목 정보만 넘겨 연다. 투자 환경이 바뀌면 닫는다.
- 주문 유형은 지정가(국내 `trde_tp=0`, 미국 `00`)와 시장가(국내 `3`, 미국 `03`)만 지원한다. 나머지 매매구분은 이후 지원한다.
- 입력 검사: 수량은 1 이상의 정수. 가격(지정가만)은 0보다 큰 수이고 국내는 원 단위 정수다. 가격은 천 단위 쉼표로 보여준다.
- 주문을 보내게 되므로 길이 제한을 더한다. 키움 문서의 `ord_qty`·`ord_uv` 길이(12)를 따라 수량은 12자리 이하 정수, 가격은 소수점 포함 12글자 이하다. 이 범위의 값은 화면에서도 정확히 표현되므로 반올림되지 않는다. 화면과 서버가 같은 규칙으로 검사한다.
- 매수 가능 여부: 미국은 NYSE·NASDAQ·AMEX 종목만. 국내는 KRX로 주문한다. 종목 상태는 경고만 보여준다.
- 뒤쪽 화면 `inert`, 닫을 때 초점 복원, 매수 버튼을 패널 맨 아래에 두는 배치는 그대로 둔다.
- 패널은 넘겨받은 정보만 보여준다. 국내 순위에서 연 종목은 종목 구분과 상태를 모른다.

**현재가 조회 (새 기능: 현재가 서비스)**

| 시장 | TR | 요청 본문 | 쓰는 응답 필드 |
|---|---|---|---|
| 국내 | `ka10001` 주식기본정보요청 (`/api/dostk/stkinfo`) | `stk_cd` | `cur_prc` (원, 부호 포함) |
| 미국 | `usa20101` 미국주식 현재가 10호가 (`/api/us/mrkcond`) | `stex_tp`(`NY`·`ND`·`NA`), `stk_cd` | `cur_prc` (USD, 소수 넷째 자리, 부호 포함) |

- 둘 다 모의투자를 지원한다(국내 KRX, 미국 O). 응답은 목록이 아닌 단건이라 연속조회를 쓰지 않는다.
- 가격의 부호는 등락 방향이므로 절댓값을 쓴다(순위와 같다). 빈 값이면 현재가 없음(`null`)이다. 필드가 없거나 숫자가 아니면 응답 형식 오류다.
- 자체 서버 API: `GET /api/environments/{environment}/quote?code=<종목코드>&exchange=<거래소>`. 미국은 거래소가 필수이고 NYSE·NASDAQ·AMEX만 받으며, 그 밖이면 400이다. 응답은 종목코드, 현재가, 조회 시각이다. 실전·모의 모두 조회할 수 있다.
- 화면: 패널이 열릴 때 한 번 조회한다. 미국 미지원 거래소 종목은 조회하지 않는다. 패널을 닫거나 다른 종목으로 바꾸면 진행 중인 요청을 취소하고 그 응답은 반영하지 않는다.
- 조회 결과는 사용자가 가격 칸을 아직 건드리지 않았을 때만 채운다. 조회가 실패하면 성공 때와 같은 규칙으로 가격 칸을 건드리지 않고, "현재가를 불러오지 못했습니다" 안내는 입력 여부와 관계없이 보여준다. 순위에서 넘겨받던 가격은 더 이상 가격 칸에 쓰지 않는다. 인기 종목의 집계 시점 가격 문제도 이것으로 해소된다.
- 수량 칸은 1로 시작한다.

**주문 접수 (새 기능: 주문 서비스)**

| 시장 | TR | 요청 본문 |
|---|---|---|
| 국내 | `kt10000` 주식 매수주문 (`/api/dostk/ordr`) | `dmst_stex_tp=KRX`, `stk_cd`, `ord_qty`, `ord_uv`(시장가는 빈 값), `trde_tp`(`0`·`3`), `cond_uv` 빈 값 |
| 미국 | `ust20000` 미국주식 매수 주문 (`/api/us/ordr`) | `stex_tp`(`NY`·`ND`·`NA`), `stk_cd`, `ord_qty`, `ord_uv`(시장가는 빈 값), `trde_tp`(`00`·`03`) |

- 응답에서 주문번호 `ord_no`를 꺼낸다. `return_code=0`인데 `ord_no`가 없으면 응답 형식 오류로 보고, 아래의 "접수 여부 확인 불가"로 처리한다.
- 계좌는 접근 토큰이 정하므로 요청 본문에 계좌번호를 넣지 않는다.
- 자체 서버 API: `POST /api/environments/{environment}/orders`
  - 요청: 주문 키, 종목코드, 거래소(미국만), 주문 유형(`limit`·`market`), 수량, 가격(지정가만). 수량과 가격은 숫자가 아니라 입력한 그대로의 문자열로 보내고, 서버는 검사를 통과한 문자열을 그대로 키움에 넘긴다. 쉼표는 화면이 지운 뒤 보낸다.
  - 성공 응답: 주문 키, 주문번호, 접수 시각.
  - 주문 키는 서버가 요청을 받는 즉시 로그(주문 요청 수신)에 남긴다. 그래서 응답을 받지 못해도 주문 키로 로그에서 그 주문과 요청 ID를 찾을 수 있다.
- 서버는 화면과 같은 입력 검사를 다시 한다. 어기면 400이고 키움을 부르지 않는다. 시장가에 가격이 오면 400이다.

**실전투자 차단**

- 서버는 투자 환경이 실전이면 입력 검사보다 먼저 거부한다. 403, 오류 종류 "주문 불가 환경"이며 키움을 부르지 않는다. 이 거부도 로그에 남긴다.
- 투자 환경 값이 없거나 잘못되면 기존처럼 404이고, 실전으로 넘어가지 않는다.
- 화면은 실전투자 환경에서 매수 버튼 대신 안내를 보여주고 최종 확인을 열지 않는다.

**최종 확인과 화면 상태**

- 패널 안에서 단계가 바뀐다: 입력 → 최종 확인 → 전송 중 → (성공: 패널 닫힘 / 실패·확인 불가: 입력으로 돌아감).
- 최종 확인은 패널 안의 별도 화면이고 새 창을 띄우지 않는다. 버튼은 "취소"와 "주문하기"다.
- 전송 중에는 "주문하기"·"취소"·닫기 버튼, 바깥 영역 클릭, Esc가 모두 동작하지 않는다.
- 화면은 주문 요청을 30초 기다린다. 넘으면 요청을 끊고 "접수 여부 확인 불가"로 처리한다. 어떤 경우에도 화면이 주문을 자동으로 다시 보내지 않는다.

**중복 주문 방지**

- 화면은 최종 확인을 열 때마다 새 주문 키(무작위 고유 값)를 만들고, 그 확인에서 나가는 요청에 같은 키를 쓴다.
- 서버는 받은 주문 키를 투자 환경별로 메모리에 보관한다. 이미 받은 키(처리 중 포함)로 다시 오면 409 "중복 주문"으로 거부하고 키움을 부르지 않는다. 보관은 서버가 다시 시작될 때까지만 한다.
- 주문 TR 호출은 자동으로 다시 보내지 않는다. 토큰 무효 응답도 다시 보내지 않고 실패로 돌려준다. 기존 조회 TR의 토큰 재발급 후 재시도는 주문에 적용하지 않는다.
- 다만 토큰 무효 응답을 받으면, 그 주문에 쓴 토큰이 아직 보관 중일 때 버린다(기존 토큰 폐기 규칙과 같다). 다음 주문은 새 토큰을 받아 보낸다. 실패 알림은 "토큰이 만료되어 주문하지 못했습니다. 다시 주문하세요."다.

**결과 분류와 알림**

| 결과 | 서버 응답 | 알림 |
|---|---|---|
| 접수 | 200, 주문번호 | 성공: "매수 주문이 접수되었습니다 · 주문번호 N" |
| 키움 거부 (`return_code≠0`) | 기존 분류(502 키움 오류, 429 호출 제한, 503 인증정보 불일치) | 실패: 키움 메시지 그대로 |
| 서버-키움 연결 실패, 키움 응답 형식 오류 | 502, 오류 종류 "접수 여부 확인 불가" | 확인 불가: "접수 여부를 확인할 수 없습니다. 키움에서 주문 내역을 확인한 뒤 다시 주문하세요." |
| 중복 키 | 409 | 확인 불가(같은 문구). 같은 키의 이전 요청이 처리 중이거나 이미 접수됐을 수 있기 때문이다. |
| 브라우저가 응답을 받지 못함: 연결 끊김, 형식이 다른 응답(HTML 오류 페이지 등), 30초 시간 초과 | 없음 | 확인 불가(같은 문구) |
| 실전 환경, 입력 오류 | 403, 400 | 실패: 서버 메시지 |

- 주문 알림에는 주문 키를 보여준다. 응답을 받은 경우에는 요청 ID도 함께 보여준다.
- 확인 불가와 실패는 모두 입력 화면으로 돌아가고 입력 값을 남긴다.
- 화면 알림은 앱 전체에 하나의 알림 영역을 둔다. 데스크톱은 오른쪽 위, 모바일은 위쪽 가운데다. 여러 알림이 쌓이면 최신이 위에 온다.
- 성공 알림은 5초 뒤 사라진다. 실패·확인 불가 알림은 닫기 버튼을 누를 때까지 남는다. 성공은 `status`, 실패·확인 불가는 `alert` 역할로 읽힌다.
- 알림 영역은 주문 패널보다 위에 그려지고 `inert` 대상이 아니다.

**로그**

- 기존 로그 형식(시각, 수준, 모듈, 투자 환경, API ID, 대상, 결과, 원인, 요청 ID)을 따른다.
- 주문 이벤트: 주문 요청 수신(주문 키, 종목, 주문 유형, 수량, 가격), 실전 차단, 중복 거부(주문 키), 토큰 폐기, 키움 요청·응답(기존 키움 로그), 접수(주문번호), 거부(return_code, 메시지), 접수 여부 확인 불가(오류 종류, 원인).
- 인증 헤더와 앱 키·계좌번호는 기존 마스킹을 따른다.

**용어**

- `CONTEXT.md`에 **주문 접수**(키움이 주문을 받아 주문번호를 돌려준 상태. 체결과 다르다)와 **최종 확인**을 더한다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 검증한다. 서버는 자체 API의 요청과 응답, 키움에 실제로 나간 요청을 본다. 화면은 사용자가 보는 것을 본다. 내부 함수나 상태 이름은 검증하지 않는다.
- 키움 서버(실전·모의)는 호출하지 않는다.

**서버 API (pytest, 기존 seam)**

- 앱을 만들 때 가짜 키움 서버를 붙여 자체 API를 호출한다. 순위·종목 검색·계좌 테스트와 같은 방식이다.
- 현재가 조회
  - 국내는 `ka10001`, 미국은 `usa20101`이 모의 도메인으로 맞는 본문과 함께 나간다.
  - 부호 있는 가격을 절댓값으로 바꾸고, 빈 값은 `null`로 돌려준다.
  - 미국에서 거래소가 없거나 미지원이면 400이고 키움을 부르지 않는다.
- 주문 접수
  - 국내 지정가·시장가, 미국 지정가·시장가 각각 키움 요청 본문(`trde_tp`, `ord_uv` 빈 값, `dmst_stex_tp=KRX`, `stex_tp`)이 맞다.
  - 실전 환경 주문은 403이고 키움 요청이 하나도 없다. 토큰 발급 요청도 없다.
  - 입력 오류는 400이고 키움을 부르지 않는다.
  - 같은 주문 키로 두 번 보내면 두 번째는 409이고 키움 주문 요청은 한 번뿐이다. 첫 요청이 처리 중일 때 같은 키가 와도 409다.
  - 키움 거부(`return_code≠0`)는 기존 오류 분류대로 돌려주고, 주문 요청은 한 번뿐이다(토큰 무효도 재시도 없음).
  - 토큰 무효로 실패한 뒤 다음 주문은 새 토큰을 발급받아 보낸다.
  - 12자리를 넘는 수량, 12글자를 넘는 가격은 400이다. 검사를 통과한 수량·가격 문자열이 그대로 키움 본문에 들어간다.
  - 연결 실패와 응답 형식 오류는 "접수 여부 확인 불가"이고 재시도하지 않는다.
  - 로그에 주문 접수·거부·확인 불가 이벤트가 남고, 비밀값은 가려진다.

**화면 (Playwright e2e, 기존 seam)**

- 브라우저의 `/api` 요청을 가짜 응답으로 대체한다. 기존 주문 패널 e2e와 같은 방식이다.
- 패널을 열면 현재가 요청이 나가고 가격 칸이 채워진다. 수량은 1이다.
- 불러오는 중 표시가 보인다. 실패하면 빈칸과 안내가 보인다. 먼저 입력한 가격은 성공·실패 모두 덮어쓰지 않는다(입력 뒤 늦게 오는 실패 포함).
- 미국 미지원 거래소 종목은 현재가 요청을 보내지 않는다.
- 실전 환경에서는 매수 버튼 대신 안내가 보이고 주문 요청이 나가지 않는다.
- 최종 확인에 주문 내용이 보이고, "취소"하면 입력 값이 남는다.
- "주문하기"를 여러 번 눌러도 주문 요청은 하나다. 전송 중에는 닫기·Esc·바깥 클릭이 동작하지 않는다.
- 접수 성공 알림과 주문번호가 보이고 패널이 닫힌다. 성공 알림은 저절로 사라진다.
- 거부·확인 불가 알림은 문구가 서로 다르고 닫을 때까지 남으며, 패널은 입력 값과 함께 남는다.
- 브라우저 연결 끊김, HTML 오류 응답, 30초 시간 초과, 409는 모두 확인 불가 알림이고 주문 키가 보이며, 주문 요청은 다시 나가지 않는다.
- 너무 긴 수량·가격은 입력 오류로 안내되고 매수 버튼이 눌리지 않는다.
- 데스크톱·모바일에서 알림이 가로 스크롤을 만들지 않는다.

## Out of Scope

- 실전투자 주문. 실전 주문을 열 때는 별도 spec으로 이중 확인 등 추가 안전장치를 정한다.
- 지정가·시장가 외 주문 유형. 이후 지원할 예정이다.
  - 국내 `kt10000`: `5` 조건부지정가, `6` 최유리지정가, `7` 최우선지정가, `10`·`13`·`16` IOC, `20`·`23`·`26` FOK, `28` 스톱지정가(`cond_uv`), `29`·`30`·`31` 중간가, `40`·`46`·`47` GTP, `61` 장시작전시간외, `81` 장마감후시간외.
  - 미국 `ust20000`: `26` VWAP지정가, `27` TWAP지정가, `30` LOC, `36` VWAP시장가, `37` TWAP시장가. 예약 매수(`ust21200`)도 이후 다룬다.
- 호가 단위 검사와 ▲▼ 호가 이동 버튼. 단위가 맞지 않으면 키움 거부 메시지로 알린다.
- 상한가·하한가 검사, 주문가능수량 조회(`kt00011`, `ust31490`).
- 국내 NXT·SOR 거래소 주문.
- 체결 확인, 미체결 조회, 정정·취소 주문, 매도 주문과 보유종목 연결.
- 주문 키를 서버 재시작 뒤에도 기억하는 저장소.
- 현재가 실시간 갱신(WebSocket). 패널을 열 때 한 번만 조회한다.

## Further Notes

- 모의투자에서 직접 확인할 것:
  - 시장가 주문이 모의투자에서 접수되는지.
  - 장 시간 밖 주문의 거부 메시지.
  - 국내 `kt10000` 응답에 `dmst_stex_tp`가 오는지. 예제에는 없으므로 쓰지 않는다.
  - 미국 주문 가격의 허용 소수 자릿수.
- 문서로 확인하지 못한 것: `cond_uv`를 쓰는 매매구분, 모의투자·거래소별로 허용되는 매매구분, 주문 TR의 호출 한도.
- 주문 TR의 토큰 무효 재시도를 막는 이유: 토큰 오류는 접수 전에 거부될 가능성이 높지만 문서로 확인되지 않는다. 중복 주문 위험을 지지 않기 위해 다시 보내지 않는다.
